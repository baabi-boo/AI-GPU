## Next bounded development

### 1. Specify a separately selected qualified warm envelope

Define the producer, reader and report contract for a complete qualified warm
attempt before adding an execution path. Reuse the unchanged frozen warm
workload and performance predicates, while explicitly specifying how complete
qualification is admitted and reconstructed for every planned process. The
[current qualification implementation](../../ci/project/p06_counter_qualification_execute.py)
and [reader](../../ci/project/p06_counter_qualification_replay.py) provide the
reviewed prelaunch and retained-consistency pattern.

Keep historical warm-v1 entry points and their high-half rejection intact. A
packet's self-reported metadata must not select a permissive reader mode. Do
not strip fields, attach a new label to an old archive or promote a nested
historical `qualified` flag to create the new result. Use explicit caller
selection, exact outer schemas and independently selected identities.

Review the actual future source/build projection against the frozen proof.
Reuse a source premise only when its pinned inputs and conditions still match.
If the warm path changes those inputs, review and version the new projection
explicitly while retaining the existing proof and historical originals. A
passing four-process record does not prove a future process's lifetime.

### 2. Bind every warm process before it starts

Admission must fully validate the selected proof and complete original
prerequisite packets before recorded compilation or execution. Extend the
reviewed build and process identities to include the explicit warm sampling
identity and the reconstructed qualification admission. Bind the exact proof
digest before computing each process's canonical ID and before passing the
existing native `--qualification-id` argument.

Use the frozen format, phase, pair index and allocation-policy order. Both
policies must use the same guarded binary within each format. Preserve complete
compiler, generated-header, dependency, link and loaded-library validation,
source/product stability checks and the existing resource guards. Any missing
proof, changed prerequisite, stale product, failed prime, invalid cleanup or
incomplete population must fail the whole attempt without falling back to an
older route.

### 3. Reconstruct complete qualification and numerical validity

The trusted reader must reconstruct every process binding, raw numerical and
lifetime record, terminal vector, required pending balance and destruction.
Require complete dependency/source/build/load joins and final input stability.
Continue treating unavailable selectors as unavailable; pending reads remain a
separate transient invariant. Preserve the ten-premise source argument and
the no-update suffix through destruction for each actual process.

Build on the existing strict validators through an explicit reviewed extension.
Do not infer qualification from matching counts or from a producer's Boolean
assertion. Reconstruct the archive's exact population and its independently
selected source/report/proof/dependency identities without executing retained
scripts, commands or binaries. Retain the reader's complete trusted-input
inventory before and after validation.

Before native execution, independently review route separation and add focused
tests for omitted or duplicated phases/pairs, reordered policies, stale or
cross-process bindings, wrong proof/dependency inputs, interior stability drift,
invalid prime/cleanup records, partial terminal observations and repaired
semantic contradictions. Historical-route rejection must keep passing. Tests
using synthetic packets must state their mocked boundaries separately from
the later complete original replay.

### 4. Execute the fixed population and evaluate the frozen predicates

The unchanged [warm contract](../../ci/project/p06_warm_contract.json) has raw
SHA-256 `893d85401b1d5f7757d82cb7c743a89b36264fe19c7d08c239b7f216b7a8cbbd`.
The [warm design](../designs/warm_workspace_benchmark_v1.md) describes the
experiment. Its population is:

| Sampling dimension | Fixed requirement |
| --- | --- |
| Formats and allocation policies | FP16 and BF16; reference `per_operation` and candidate `reusable_single_tile` |
| Paired batches per format | One warm-up pair, then five measured pairs |
| Process/context policy | One fresh process and context per policy batch |
| Operations per process | One excluded prime, followed by 32 serial operations, each explicitly closed |
| Complete attempt | 24 processes, 792 launches, 25,344 exact checked FP32 words |
| Measured population | 20 processes, 640 operations, 20,480 checked words |
| Sampling order | FP16 then BF16; ascending pair indices; alternating reference-first order beginning at pair zero |
| Failure and selection policy | Retain and fail the entire attempt; no replacement samples, outlier removal or optional stopping |

The primary metric remains instrumented host nanoseconds per validated
operation, with the existing boundaries including submit, wait, exact output
comparison, explicit close and success checks. Counter and memory queries stay
outside that interval. The batch statistic remains the arithmetic mean of its
32 primary intervals. Five measured batch means per format and policy support
the frozen descriptive analysis; do not claim physical-device latency or
statistical independence from process separation.

Preserve all conditional performance predicates: the candidate's median must
be at most **95% of the reference median**, every measured candidate pair must
not be slower in host time, every measured candidate pair's reported cycles
must not increase, and both formats must improve. Numerical, dispatch,
ownership, cleanup, provenance and resource validity remain prerequisites.
Evaluate those predicates only after complete qualified evidence is admitted.
Do not lower the bar, drop a failing sample or choose new thresholds after
seeing results. The frozen analysis decision is explicitly not phase
acceptance.

Once the route and independent review are complete, freeze an exact published
execution revision, use fresh dedicated source/build/work directories and the
selected pinned dependency inputs, then preserve the full attempt and any
failure. Retain the original archive unchanged and run complete inert replay
with independently chosen external pins. Do not reuse populated execution
trees or substitute prior diagnostic/control populations for new warm
processes. Review actual raw numerical, lifetime and source/build/load evidence
in addition to the summary result.
