## Implementation boundaries

- Use an explicit new entry point and new outer contract. Preserve historical
  warm-v1 rejection and all original evidence and acceptance identities.
- Bind the reviewed qualification digest into build and process bindings before
  launch. The existing native `--qualification-id` echo supplies that binding;
  no C++ API change is needed.
- Reuse the existing complete build, dependency, lifetime, numerical, resource
  and archive validators. A separately selected trusted reader may share
  implementation, but must not infer its mode from untrusted packet metadata.
- Keep inner historical observation records and their false claims unchanged.
  Any new qualification result must be derived from all required evidence;
  attaching metadata to an earlier archive does not qualify it.
- A four-process qualification preflight is separate from the unchanged
  24-process warm experiment and from P06-A02/A03 acceptance.
