**F0, high confidence, static proof — timeout and retention boundary.** Each
requested operation wait and close uses 120 seconds. The existing operation
destructor drains indefinitely rather than freeing in-flight resources. When
bounded close returns a rejected operation, the caller prints its retained
operation records and flushes `P06_WARM_FAILURE` before `operation.reset()`.

the native failure prefix is reached; the retained supervised timeout receipt
then establishes the failed attempt. The review does not claim every killed
process emits a native prefix or that destruction is internally bounded.
