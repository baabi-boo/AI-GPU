## Implemented behavior

The reader exposes `verify_output(text, *, case, fmt, policy, binding_id,
sample_id, pair_index, phase, contract)`. It first validates the frozen contract,
its trusted source inputs, exact process identity and the independently selected
format fixture. Caller-provided expected words cannot replace the trusted
fixture. No source, policy or binding fallback is provided.

The bounded log requires exactly 33 ordered operation records, one summary and
one final success marker. It rejects failure tokens, unsafe text controls,
duplicate JSON keys, malformed or foreign reserved markers, extra records,
unknown fields and invalid numeric types. Existing workspace dispatch, status
and allocation-count validators and the existing cold counter-snapshot reader
are reused without modifying those files.

Every operation checks all 32 expected FP32 words, exact fixture and shape,
alternating poison, native argument ABI, disjoint aligned tensor ranges, event
statuses and explicit close. Resident tensor addresses must remain stable.
Default allocation counts reach 99 creates/releases; resident counts reach
three creates/releases. Both policies must release every resource and their
single device, with no observer errors or premature releases.

All 33 primary intervals must be positive and ordered. Creation, prime,
post-prime snapshot, timed batch, post-batch snapshot and teardown must have the
frozen chronology. Creation and teardown contain their device snapshots. All
four counter snapshots have exact capabilities and descriptors, and available
counters cannot decrease. Batch deltas require positive cycles/instructions;
the 12 unavailable rows remain explicit null observations.

All five memory queries must succeed, conserve reported capacity, restore idle
context usage after the prime and batch, and restore the open-device baseline
before release. Resident accounting must include its requested tensor payload;
the reader does not equate the total simulator memory usage with 320 bytes.

The result contains the validated native operations and summary, raw-log
SHA-256, all 33 operation durations, the 32 timed durations, 45 batch counter
deltas and fixed workload accounting. `performance_acceptance` and
`phase_acceptance` remain false: a valid individual process does not evaluate
the paired speedup hypothesis or accept a development phase.
