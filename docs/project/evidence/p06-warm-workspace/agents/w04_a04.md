## Resolved review finding

The first 25-test suite passed, but an additional malformed-input probe found a
standalone CLI strictness gap. The JSON constant callback rejected `NaN` and
`Infinity`, while the default floating parser converted an ordinary exponent
token such as `1e400` to infinity. Placing that token in an otherwise valid
synthetic envelope's `processes[0].binding.size_bytes` caused `_read_input` to
return infinity and the CLI to exit zero with a supported hypothesis.

The finding had high confidence: the parser code showed the missing finite
check, and the full CLI probe reproduced the behavior. The field is not used
by the analyzer's arithmetic. This did not establish a bypass of complete
archive validation, which separately validates binding descriptors, and no
native or performance acceptance was claimed.

Root corrected the production analyzer with a finite-checking `parse_float`
callback. This agent changed no production file. The regression now rejects
`1e400`, `-1e400` and `1e999999`, including in fields that the analyzer does not
interpret. It also verifies that a finite fractional supervisor duration and
the literal string `"1e400"` remain readable. The full suite passed on the
corrected analyzer bytes.
