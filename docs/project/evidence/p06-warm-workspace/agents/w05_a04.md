## Scope and findings

### Resolved F1-MEASUREMENT-01 — avoid an unestablished independence adjective

- **Severity:** F1; **confidence:** high; **evidence type:** static-proof.
- **Locations:** the design's analysis section and the analyzer's limitation
  string describing the five measured batch means as independent.
- **Scenario:** a reader could interpret “independent” as established statistical
  independence. The implementation fixes sequential, alternating paired process
  order on the same host. Distinct processes define separate batch experimental
  units; they do not prove that host or simulator state creates independent
  observations.
- **Suggested follow-up:** say “five measured batch means per format and policy”
  without claiming statistical independence. Keep the explicit statement that
  the 640 serial operation intervals are not 640 independent samples.
- **Impact:** wording only. The implementation uses descriptive statistics and
  exact predetermined guards; it does not compute confidence intervals or use
  640 operations as independent replicates. This is not a decision-arithmetic
  defect or a request to change the frozen sample size or threshold.
- **Resolution:** the coordinating agent changed both descriptions to “five
  measured batch means” and explicitly stated that process separation does not
  establish statistical independence. The design continues to reject treating
  640 serial calls as 640 independent batches. This reviewer inspected the final
  diff and wording and hashed both corrected files. Only that caveat changed;
  sampling, calculations, thresholds and acceptance behavior are unchanged.

No production edit was made by this reviewer. The coordinating reviewer owns
any later source changes.

## What the observations establish

The primary interval is instrumented host time around submission, wait, the
actual exact 32-word comparison, completed explicit operation close, success
checks, and fixed observer bookkeeping. It excludes owner setup/teardown,
input packing, retained-output/trace copying, serialization, and explicit
memory/counter queries. The 1,000 ns supervisor allowance validates containment
of the owner lifetime; it is not an overhead correction or subtraction.

The independently enumerated counter inventory contains 45 distinct rows:
33 are available for the frozen ISA and 12 L2/L3 rows are unavailable. Their
native scopes and units remain intact: active core cycles, retired
macroinstructions, warp cycles, issued requests, request cycles, and other
specific event counts are not collapsed into a single latency interpretation.
Unavailable entries require `enabled=false`, `status=null`, and `value=null`;
they are not zero measurements.

Every available counter must be monotonic across all four retained snapshots.
The batch delta is after-batch minus after-prime, with positive cycles and
instructions. Cycles per useful FLOP divide that batch delta by 16,384. These
are cumulative modeled batch observations, not individual-kernel timing,
physical throughput, bandwidth, power, energy, or proof of cache/thermal state.

The host parser establishes the recorded chronology of the four counter
snapshots and operation intervals. Memory records have statuses and values,
but do not carry their own query timestamps. Their query placement, timer
placement, actual cumulative producer behavior, and absence of extra timed
wrapper work also depend on the independently reviewed compiled caller and
observer sources. This receipt does not substitute synthetic raw records for
that producer evidence.

## Record and analysis trust boundaries

The record validator checks exact field inventories and scalar types,
externally selected sample/binding/format/policy/pair/phase identity, all 33
operation positions, all 32 actual FP32 words against independent fixtures,
and the complete native ABI including nonoverlapping aligned address extents.
Resident addresses are stable across the process. Successful submit, wait and
close statuses have their distinct completion states; profiling remains false.

Before/after/final lifetime counts are exact. Memory observations require
successful queries, a constant valid capacity, restoration to after-create at
both idle checkpoints, and restoration to after-open before release. The
resident accounting includes at least 320 requested payload bytes; unrelated
native context overhead is not falsely fixed to a 320-byte allocator delta.
Final tensor handles and requested payload are zero, with one successful
device release and no observer errors or premature releases.

The analyzer requires the exact ordered 24-process plan and full raw log
inventory. It reconstructs same-build process identities, reparses every raw
log, and compares the resulting observation recursively to the supplied
summary. Rehashing a corrupted numerical record does not make its values valid.
Warm-up and prime exclusions are explicit, while all raw durations survive in
diagnostics. There is no replacement, retry, outlier filtering, optional
stopping, or post-observation threshold change in this reducer.

For each format and policy, five totals are divided by 32 to form the batch
means. Minimum, maximum, median and population variance use exact fractions;
the standard deviation and displayed ratios may be floating values. Decision
boundaries use integer totals: candidate median times 100 must be at most
reference median times 95, every paired candidate total must be no larger,
and every paired candidate cycle delta must be no larger. All three guards
must hold separately for FP16 and BF16.

Malformed/incomplete raw experiments raise an analysis error. A valid complete
experiment missing a performance guard remains a valid negative result. CLI
exit zero means the supplied analysis completed; it does not mean the
hypothesis passed. The analyzer deliberately returns
`archive_provenance_validation=required_from_caller`, `native_execution=not_run`,
and false acceptance/performance/phase flags. Exact same-build identities here
cannot authenticate invented tool, binary, resource or binding descriptors;
the complete archive verifier remains responsible for those obligations.
