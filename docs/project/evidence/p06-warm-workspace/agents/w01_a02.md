## Findings

1. **F2 / high confidence / missing-test:** no reusable offline workspace packet verifier exists. The workspace runner validates observations while executing, but a later reviewer cannot independently qualify a published ZIP by invoking the current tooling. In particular, `verify_output` only validates process records: it does not verify archive identity, retained-source descriptors, compiler log provenance, command success, or complete four-variant coverage. Calling that parser on `report["processes"][i]["observation"]` would trust a derived report instead of original output. Concrete failure scenario: a truncated artifact with intact report and embedded observations could be treated as qualified by a summary-only review while its original native log or runtime build stamps are absent. This is a qualification-tooling gap, not an observed native execution failure or a demonstrated runner defect.
2. **F0 / high confidence / static-proof:** the output parser is already strong. It checks exact recursive types/keys, all 32 output words per operation, the four-row changed-input/poison sequence, the 56-byte ABI, disjoint bound extents, successful wait/close, forbidden competing-owner/work submission, complete buffer/device inventories, event-derived requested-payload peak and contiguous allocator deltas. It deliberately permits default allocator address reuse only with separate complete lifetimes.
3. **F0 / high confidence / static-proof:** retained workspace correctness records contain no performance timing/counter contract. They cannot substantiate warm speedup or per-operation device latency. The warm experiment needs its own schema and original measurement records; do not add timing conclusions by interpreting supervisor process duration.
4. **F0 / high confidence / static-proof:** the runner retains the needed ingredients for a new offline verifier: original raw logs and hashes; manifest/selected fixtures; before/after source, tools and dependency snapshots; staged generated bodies and original compiler stamps; effective-header raw logs; binary identities; per-policy binding bodies and source-bound qualification IDs. Binaries themselves are intentionally not retained. A reader must state that limitation.

## Recommended minimal implementation

Add a separate `ci/project/p06_workspace_replay.py`; leave historical cold-baseline readers and accepted source pins unchanged. Reuse the digest-pinned trusted `ArchiveReader` implementation by importing only the trusted repository copy. Never extract or execute archive members, imported retained helpers, native binaries, commands or recorded absolute paths.

Suggested API: `replay_archive(path, sha256, expected_revision, expected_backend, expected_format, prefix="workspace")`, with explicit externally obtained expected identities. Return a fresh checked summary whose native-execution field is `not_run` because the reader performs replay, not another GPU run.

The verifier should:

1. Verify original ZIP digest before parsing; use bounded regular files, safe member names, duplicate/ambiguous member rejection and strict JSON. Validate exact report fields and success/error/completion states.
2. Verify every selected source/build/snapshot/log descriptor against original member bytes. Reconcile before/after source, tools and dependencies and retained stability observations. Require a clean expected source revision/tree, the selected backend/format, the immutable profile/kernel/fixture identities and unchanged frozen manifest. Bind the trusted local readers and independent fixture producers separately from retained execution sources.
3. Reconstruct the ordered command plan from trusted semantics. Require each command's exact ID, argv, cwd, environment, bounded timeout/RSS/log policy, exit status and cleanup completion. Treat recorded absolute paths syntactically only. Validate effective-header logs and original compiler stamps independently for runtime, backend, kernel and host using `p06_workspace_compiler_records.validate_records` and the existing header validator. Compare regenerated validation results to reported compiler metadata.
4. Reconstruct each policy binding from independently checked inputs, calculate `qualification_id`, and check its equality to the raw caller log. Run `p06_workspace_records.verify_output` on the actual original raw log with the trusted independent fixtures; then compare the result to the embedded observation. Never accept embedded observations alone.
5. Derive counts from verified processes: per variant two processes, eight launches, 256 exact words. An aggregator must require exactly all four distinct backend/format combinations, each with both policies, at one expected source revision/tree and compatible tool/dependency/configuration identities. Require same workflow run/attempt if claiming one hosted matrix. Reject duplicates, missing variants, mixed sources and partial selections labelled complete.
6. Validate optional hosted `job.json`, workflow bytes and Python provisioning against retained source and actual packet identities. Report absence distinctly for non-hosted packets.

Mutation tests should cover missing logs/stamps/snapshots, stale raw-log or source digests, all bool-as-int fields, bad compiler/header records, altered source/tree/binding IDs, reordered/duplicated/missing policy processes, invalid resource receipts, wrong matrix combinations and hosted identity mismatches. Existing output tests already exercise numerical/lifetime mutations; reuse their synthetic transports and label them as synthetic.
