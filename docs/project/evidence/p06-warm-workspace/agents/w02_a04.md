# W02-A04 — warm-workspace native caller

## Scope and source

- Assignment: wave 2, agent 4; assignment 10 of the requested 60.
- Source base: `13dc0d1fdb6d5322104e381aa342dc139c7bb80c`.
- Owned implementation: `tests/regression/ai_warm_workspace/main.cpp` and
  `tests/regression/ai_warm_workspace/Makefile`.
- This receipt records implementation and host compilation. It does not establish
  native correctness, measured performance, or acceptance of a project gate.

The caller implements the frozen `p06-warm-workspace-v1` contract. It selects the
existing dense-boundaries FP16 or BF16 fixture at compile time, then selects
`per_operation` or `reusable_single_tile` at runtime. One native owner executes
one priming operation and 32 samples. All actual matrix work uses the existing
managed native runtime and the existing AI matmul kernel.

The six required command-line options are checked strictly, including the exact
qualification hash syntax, sample identity, pair index, and warmup/measured phase
relationship. Packed fixture inputs and fixed record storage are prepared before
the measured operations. Each operation interval includes submit, bounded wait,
comparison of every output word against the unchanged independent fixture, and
explicit close. Trace/output copies, observer counts, native counter queries,
memory queries, and printing occur outside that interval. Successful submit must
be incomplete; wait and close must complete successfully.

The records preserve actual dispatch bytes, addresses, output words, return
statuses, and observer counts. Checks cover both policies' exact allocation and
release totals, resident address stability, idle and final memory state, four
counter snapshots, explicit owner close, and the actual device-release status.
Destructors must not perform additional native cleanup after a successful
explicit operation or owner close. Failure retains the available record prefix
before potentially blocking operation drainage; it never substitutes a retry or
CPU-computed answer for an operation.

The new Makefile reuses the native AI sources and kernel, includes the shared
counter header, and applies exactly the four specified native wrapper flags.
`PERF=1` remains a runner-provided build selection.

## Verification

The final source was compiled independently for FP16 and BF16 with the generated
RV64 `p02-tfr` host flags, including `-Wall -Wextra -pedantic -Wfatal-errors
-Werror`. Both compilations returned **0 with zero diagnostic bytes**. The checks
were compilation only: neither host linking, RISC-V kernel compilation, native
execution, nor fake-runtime execution was performed by this assignment.

The separate scratch build was configured with:

```sh
/workspace/scratch/4dab691e69d0/AI-GPU/configure --xlen=64 --profile=p02-tfr \
  --osversion=ubuntu/focal \
  --tooldir=/workspace/scratch/4dab691e69d0/unused-tools
```

Working directory:
`/workspace/scratch/4dab691e69d0/w02-caller-build`.
For each format, `CONFIGS=-DITYPE=<format> -DOTYPE=fp32 -DKUNROLL=1`, `PERF=1`, and
`CCACHE_DISABLE=1` were supplied when generating the app's `config.stamp` through
the configured build-tree Makefile. Compiler variables were set to `/bin/false`
for this stamp-only invocation, preventing it from silently compiling a kernel
or native runtime. The host flags on the second stamp line were parsed with
`shlex.split`, then passed as an argument vector to:

```text
c++ <generated host flags> -c <source>/tests/regression/ai_warm_workspace/main.cpp
    -o <scratch build>/caller-<format>.o
```

Scratch-only `caller-compile-report.json` retains the exact argument vectors and
exit codes; `host-flags-fp16.txt`, `host-flags-bf16.txt`, `compile-fp16.log`, and
`compile-bf16.log` retain the flags and empty compiler diagnostics.

Two setup mistakes preceded these successful checks and are not counted as
validation: the initial configure invocation ran from the scratch parent rather
than the intended scratch build directory, and initial manually assembled host
flags failed the profile guard because resolved configuration macros were absent.
The configure mistake generated disposable scaffolding outside the repository;
it did not change tracked source. The successful checks used the intended
configured directory and its complete generated flags.

The owned source and Makefile also passed final-newline and trailing-whitespace
checks. No commit, push, gate update, or additional agent was performed by this
assignment. Actual output still requires independent linked execution and strict
parser validation in the subsequent integration assignments.
