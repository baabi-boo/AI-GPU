## Actual validation

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=ci/project python3 -m unittest test_p06_warm_observer -v
```

Result: **8 unittest methods, 43 fresh bounded child processes, 4.451 seconds,
exit 0**. Every child emitted exactly one final JSON record; there were no UBSan
diagnostics or unexpected stdout/stderr. A fresh out-of-tree RV64 `p02-tfr`
configuration generated the headers. The fixture and production observer were
compiled together with C++17, `-Wall -Wextra -Werror -pedantic`, UBSan and
`-fno-sanitize-recover=undefined`. No RISC-V compiler, kernel or simulator ran.
Host commands use the existing bounded host supervisor, with one compile job,
45-second compiler timeout and 10-second child timeout. Source hashes are checked
after each test. Whitespace checks returned no diagnostics, including the two
new files checked explicitly against `/dev/null`.

| Scope | Fresh processes | Observed result |
|---|---:|---|
| Full default and resident lifecycles | 2 | Default performs 99 creates/releases; resident performs three. Both peak at 320 requested bytes, have three simultaneous tensor handles and finish with zero tracked/native fake tensor allocations. |
| Device-open index, phase, duplicate, null-output/null-handle, status and exception faults | 7 | Every invalid open records an error; every requested open reaches the fake native function with its original index. |
| Allocation device, size, flags, three invalid phases, duplicate handle, three-slot overflow, 100th create and null-output/null-handle faults | 12 | Errors are observed immediately at the faulty call, before cleanup can introduce a second failure. |
| Allocation status and exception faults | 2 | Failure cannot produce successful observer counts; forwarding remains exactly once. |
| Buffer-release phase, absent device, unknown/null handle, status and exception faults | 8 | Cleanup is forwarded exactly once with the original handle despite the fault. |
| Device-release phase, live buffers, unknown/null handle, status and exception faults | 6 | Cleanup is forwarded exactly once; the actual release status is retained and invalid counts remain visible. |
| Memory, capability and counter status/exception faults | 6 | Errors are retained. Invalid capability snapshots issue no counter queries; individual counter failures do not hide the remaining query inventory. |

For every buffer-create and buffer-release call, including the 99-allocation
batch and the rejected 100th create, the harness compares native memory,
capability, counter and address query counts before and after the production
wrapper. All remain unchanged. Global `new` and `new[]` sentinels likewise remain
unchanged around these wrappers. The one-record output assertion catches any
unexpected formatting or diagnostics from the observer. Static inspection of
the production buffer wrappers confirms the three-element `std::array` scans,
scalar bookkeeping and absence of heap-allocation/query/output calls; scan
length does not depend on historical allocation count.

Each successful lifecycle makes exactly five memory queries, 52 capability
queries and 132 counter queries: four snapshots of the 13 capabilities and 33
available counters. All 12 unavailable counter rows remain unqueried and
unreturned. The fake native address query is never called. The availability
mask is synthetic ICACHE/DCACHE/LMEM/TCU support and deliberately does not claim
that a real device was queried.

The failed buffer-release cases explicitly check that fake native buffers can
remain live after the native failure even though observer bookkeeping changes.
The test requires an immediate observer error and forwards subsequent cleanup;
it does not reinterpret zero observer payload as successful native reclamation.

## Findings and limits

No concrete production defect was found in this scope. The tests call the actual
compiled wrapper functions directly, with test implementations of their
`__real_*` destinations. Actual linker substitution, managed-runtime ownership,
fixture transport and full caller serialization are covered separately by
W03-A03; this test isolates the observer's own failure and observation behavior.

These are host-only synthetic fault checks. They prove neither native tensor
arithmetic nor physical memory reclamation, uninstrumented runtime speed,
FPGA behavior, performance acceptance or phase acceptance. Native SimX evidence
and complete archive provenance remain separate obligations. No production
file, fixture golden, resource budget, commit or remote ref was changed here.
