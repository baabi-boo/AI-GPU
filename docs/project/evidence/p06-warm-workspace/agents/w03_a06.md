## Scope and result

Added only `ci/project/p06_warm_test_fixture.py`,
`ci/project/test_p06_warm_records.py`, and this receipt. The production parser,
contract, numerical fixtures, runtime, observer, kernel, workflows and historical
evidence were not modified. No commit or push was performed.

The reusable helper derives expected words through the trusted independent
numerical fixture producer, then invents transport observations, lifetimes,
counter values and timestamps. `raw_records` accepts format, allocation policy,
pair index, binding ID, one duration or 33 durations, and selected available
counter deltas. Its adaptive timestamps keep the prime and batch snapshots
outside all operation intervals. `render_log` emits all 33 operation records,
one summary and the final marker. `synthetic_log` is a convenience wrapper.
These inputs are host test fixtures, never native execution or performance proof.

The 32 test methods exercise:

- Successful complete logs for both formats and both policies, recomputed counts,
  raw-log digest, all retained observations, 32 measured durations and unavailable
  counter handling. Parameterized identities, unequal durations and exact deltas
  also pass.
- Exact top-level and nested field inventories, externally selected identities,
  false acceptance shortcuts, independently checked numerical fixtures, every
  operation position and all 32 output-word positions.
- Dispatch counts, all ABI fields, aligned/disjoint/nonoverflowing addresses,
  resident address stability, default address recycling, five event results,
  disabled profiling and distinct submit/wait/close completion states.
- Before/after/final allocation and device lifetimes for both policies, failed
  memory queries, constant capacity, idle restoration and final restoration.
- Positive unsigned operation intervals, nonoverlap and every boundary around
  creation, prime, measured batch, snapshots and teardown.
- Every one of the 45 counter descriptors, all 13 capability values, all 12
  unavailable rows, native statuses, exact inventories, cumulative reset/wrap
  rejection and positive required batch deltas. Zero optional deltas and values
  near the uint64 maximum remain valid and exact.
- Missing, duplicated, reordered or misrouted records, hidden failure tokens,
  unknown markers, controls, ambiguous Unicode separators, trailing output,
  duplicate JSON keys, floats/nonfinite values, wrong numeric types, nesting and
  byte bounds. Ordinary diagnostics and CRLF transport remain accepted.

**No concrete production parser defect was found by these tests.**
