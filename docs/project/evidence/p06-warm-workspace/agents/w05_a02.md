## Resolved finding: final disk reserve was recorded but unenforced

**F2; high confidence; `static-proof`, corroborated by an executed synthetic
resource-boundary reproducer.** Before the correction, the final-resources
block called `base._resources(paths)` but did not require that snapshot to
satisfy the 15-GiB reserve. A disk crossing below the reserve after the final
supervised process therefore left a complete attempt passing. The inherited
replay budget validator rejects the same final snapshot, so runner success
contradicted its retained resource contract.

The reachable reproducer used `WarmHarness` and changed only its final output
disk observation after `LAST_PROCESS`. No actual disk was filled. With runner
SHA-256 `c470eaf930a6b3924460751092cc011ef98c2e1a507ecd6f01577cef85eb2e84`,
the executed probe returned:

```json

  "completed_processes": 24,
```

The finding was reported immediately. Root added an `all(...)` reserve check
inside the existing final-resources `try`/failure boundary. Any final root
below the reserve now records a `final-resources` failure. No reserve was
lowered and no final global available-memory requirement was added.

The new regression sets initial free space to exactly 15 GiB and final output
free space to one byte below it. It verifies a finished failed report while
retaining **53 command attempts, all 24 successful process records, 792 verified
