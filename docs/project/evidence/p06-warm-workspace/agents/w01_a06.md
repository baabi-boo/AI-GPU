## Result

**Pass within the recorded provenance scope; no concrete F2/F3 finding.**
The independent checker and machine-readable result are
[`workspace_provenance_audit.py`](../reviews/workspace_provenance_audit.py) and
[`workspace-provenance.json`](../reviews/workspace-provenance.json).

The checker reread ZIP bytes directly and verified their sizes and SHA-256
against the downloaded artifact metadata. It rejected duplicate/unsafe ZIP
members and duplicate JSON keys. It checked clean source revision/tree,
before/after source/tool/dependency snapshots, intermediate snapshot hashes,
all retained source/build/log descriptors, generated-config identities,
per-policy binding hashes and referenced source/build identities.

Each packet contains 971 retained source bodies. Of these, **778 match Git blob
objects in the recorded root commit**, and 193 are retained submodule source
bodies whose bytes match their source-inventory hashes. The five top-level
submodule commit pins match Git links. These are the same source inventory
across four variants, not 3,884 unique sources.

All **80 command receipts** record exit 0, completed cleanup, bounded logs and

The four application linker records separately require exactly the four native
observer wrappers and the intended generated runtime library search path;
linker text is never interpreted as compiler options. All eight process-binding
hashes were recomputed from their retained data.

The budgets match exactly: two build jobs, 4 GiB polled process-group RSS,
15 GiB disk reserve, 16 MiB command logs, 1,800-second build commands,
120-second configure commands and 180-second invocations. Maximum observed RSS
was **1,685,082,112 bytes**; minimum recorded free disk across the source,
work, output and tools roots was **86,283,169,792 bytes**. These observations do
not establish hard-quota enforcement or exclude peaks between polls.

Job files bind repository `baabi-boo/AI-GPU`, `refs/heads/master`, source revision,
run/attempt, backend and format. Their retained workflow bytes match the
source snapshot and keep the 90-minute deadline and two-job parallelism cap.
The interpreter record selects CPython 3.12.14 and the same recorded executable
used by native preparation/execution. Preparation and job `native_execution:
not_run` fields describe initial setup; the completed command records and final
workspace report carry execution observations. They must not be conflated.

## Commands actually executed

```sh
python3 docs/project/evidence/p06-warm-workspace/reviews/workspace_provenance_audit.py
```

The first invocation exited 1 because the review script initially tried to find
all retained submodule files in the root Git tree. That was an audit-script
assumption error, not a native result. The checker was corrected to distinguish
root Git blob checks from submodule-body hash checks, with this limitation
explicitly recorded. The subsequent invocation exited 0 and wrote the passing
review above. Production validators and native records were unchanged.

Source inspection additionally used `cat AGENTS.md`, focused `sed` reads of the
workspace compiler/runner and earlier replay contracts, and read-only Python
JSON inventory summaries. Git tree membership was read with `git ls-tree -r -z`
and the exact revision tree was checked with `git rev-parse`.

## Limits and remaining work

- Numerical outputs and allocation/lifetime semantics belong to the separate
  W01-A04/W01-A05 reviews; this result does not substitute for those checks.
- Tool, dependency and binary bodies are not retained. Their unchanged recorded
  identities are checked, but unavailable binary bodies cannot be rehashed or
  executed by this audit. Seven binary identities per variant remain
  hash-record-only; their paths are listed in the JSON result.
- The local checkout does not contain the submodule Git object databases.
  Retained submodule bodies are hash-verified, while nested-commit membership
  is not independently fetched or replayed here.
- Generated header *records and recorded reproductions* agree; this audit did
  not rerun the original native compiler, dependency build or processor model.
- The next reusable workspace replay tool should encode the complete archive
  obligations and hostile-input tests rather than relying on this one-shot
  reviewer script as a general-purpose acceptance tool.
- No performance, full-AFU/vendor XRT, physical hardware, synthesis, P06-A02/A03
  or phase acceptance follows from this review.
