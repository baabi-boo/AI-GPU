## Exact native comparator reuse

Import only current trusted parser modules, never files in `artifacts/source`.
Avoid importing producer runners merely for aliases. The direct APIs are:

```python
from p03_execution_records import qualification_id, verify_output as verify_matmul
from p04_execution_records import verify_output as verify_model

native_matmuls = {
    case["id"]: verify_matmul(
        read_text("python/logs/native-" + case["id"] + ".log"),
        case, 2, validated_matmul_binding_id,
    )
    for case in matmul_cases
}
native_models = {
    case["id"]: verify_model(
        read_text("native-model/logs/simx-" + fmt + "-" + case["id"] + ".log"),
        case, 2, validated_model_binding_id,
        backend="simx", source_revision=independently_expected_revision,
        fixture_sha256=independently_pinned_fixture_sha256,
    )
    for case in model_cases
}
```

Here `read_text` means a bounded archive-reader UTF-8 decoder. P04 already
bounds its log and record sizes; put the same archive/log bounds around P03,
whose current parser does not independently enforce a total input-size bound.

Both helpers are inert parsers. P03 checks expected words, exact case/iteration
membership, the two poisons, transfer/launch counts, resource restoration,
aligned disjoint allocations, and the 56-byte little-endian ABI.
P04 additionally checks three ordered model stages, actual input/weight bytes,
hidden output, packed host bridge, both output row blocks and assembled output,
owner/stage cleanup, completion, five-event profile ordering, and trace identity.
They reject failure markers and require one terminal `PASSED!`.

Compare parsed dictionaries exactly against report observation arrays after
validation. Do not return report observations as the comparator dictionary.
Keep `case_id` dictionary keys and each two-element iteration list in canonical
order.

## Python/framework continuation and live-path barriers

The numerical body of `p05_execution_records.verify_observations` can consume
these dictionaries unchanged. It joins raw marker rows to the observation file,
adapts installed matmul dispatch fields to P03 fields, checks model records
through P04, compares native/installed actual words and model data lineage, and
derives counts. Three existing filesystem-dependent operations need explicit
inert counterparts:

1. `p05_execution_records._installation` calls `Path.resolve(strict=True)` and
   `is_file()` for executable/package/extension. Preserve its identity/layout,
   CPython 3.12, distribution 0.1.0, bundle/source build-info and five runtime
   library checks. Replace filesystem existence with strict lexical POSIX path
   joins plus validated retained installation/interpreter inventory evidence.
2. `p05_torch_records.validate_request` defaults to
   `p05_installed_check.validate_request`; the latter resolves and opens
   existence checks on `bundle_root` and `expected_prefix`. The framework
   validator already accepts `base_validator=`: pass a current trusted inert
   request validator that preserves exact fields, pins, fixed cases, order,
   format and two iterations. The current framework `verify_observations`
   calls `validate_request(request)` without that option, so its API must expose
   the safe seam or its pure numerical portion must be separated.
3. `p05_torch_records._framework` resolves/stats/reads the installed
   `torch_ops.py`. Compare the lexical adapter path to the installed package
   path, then hash the archive-retained adapter bytes and reconcile request,
   raw identity record, framework inventory and installed inventory instead.

Prefer an explicit trusted callback/read interface or a separated pure
comparison function over monkeypatching global `Path` methods. Preserve the live
producer validators' checks for live execution; an inert route must not silently
turn those checks into no-ops.

Do **not** invoke `p05_execute.execute`,
`p05_torch_execute._verify_python_packet`, or `p05_bundle.create_bundle`.
The latter live replay reopens producer paths, inventories original tools and
builds, recreates a bundle, and extracts an sdist. Its field relationships are
useful specifications, but its execution path is unsuitable for inert replay.

The framework base request differs from the plain Python request only in its
bundle root (`.../evidence/torch/artifacts/bundle`) and expected prefix
(`.../torch-work/venv`). The model/matmul cases and immutable binding pins are
unchanged. Validate this relationship lexically; do not rewrite raw evidence.

## Scope constraints and implementation cautions

- These are one-format SimX packets with `iterations=2`, `development=false`,
  `acceptance_claimed=false`, `phase_complete=false`. P04
  `full_matrix_requested=false`. Neither selection replaces the P03 88-case
  gate or the complete P04 backend matrix.
- The fixed synthetic model uses the prescribed host bridge and three native
  launches. This does not establish arbitrary graphs, training/autograd,
  CUDA compatibility, processor RTL, vendor `hw_emu`, physical hardware or
  physical performance.
- Native model artifact retention is metadata/config/stamps; the Python packet
  adds the model host executable and bundle runtime libraries/kernel. Some
  original build artifact descriptors (for example static kernel-library and
  model ELF identities) are receipt data unless exact matching retained bytes
  can be located elsewhere. Do not claim complete independent byte verification
  of unavailable products or host system dependencies.
- Matching identities and raw observations establish retained historical
  semantics within the producer's trusted-builder/non-adversarial-filesystem
  scope. They do not authenticate the original host's claimed execution by
  themselves. Profiling records are host runtime observations.
- Keep archive trust/transport checks separate: bounded strict JSON, duplicate
  names/keys, traversal, member type, CRC, exact inventories, source pins and
  archive unchanged checks belong around the parsers. Recompute semantic
  counts rather than trusting reported pass labels.
