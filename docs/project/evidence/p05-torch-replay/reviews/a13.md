## Findings

### F2 — native source retention closure can shrink

**Confidence: high for the native entry point. Evidence: static-proof plus
executed inert-data mutation.** `_source` at lines 178–190 verifies the declared
retained-source inventory against the members currently present, with an exact
minimum only for loaded helpers. The complete native member set at lines
561–569 is then derived from that same untrusted retained-source declaration.
The four pinned fixtures and profile are separately required, but native
application source members outside those sets are not mandatory.

Starting with the pinned FP16 original, the probe removes
`native-model/artifacts/source/tests/regression/ai_mlp/main.cpp` and its
`native_report.retained_sources` descriptor. It leaves the original native
source-before/after inventory unchanged: that inventory still declares the
original `tests/regression/ai_mlp/main.cpp` identity. The probe recomputes the
native report descriptor and copied-native packet receipt, preserving exact
byte equality of all copies. `verify_native` still returns success and 36 native
comparison launches. Thus an incomplete native packet is accepted even though
the original producer's mandatory retained application source is absent.

Complete caller inspection: `_source_and_python` at driver lines 417–418 checks
the **Python** retained-source list against Torch; it does not impose native
retained-source membership. `_packet_members` uses the supplied Python
`native_input.files` at line 463 and actual native packet files at line 491.
Neither provides an independent mandatory native-source set. Installation
verification consumes `python_source` and `model_binding`, not native retained
source membership. The exercised bypass is the real `verify_native` entry
point with all its checks enabled. **A fully rewritten public ZIP was not
produced or replayed.** Public reachability additionally requires coherently
updating the outer Torch Python-copy descriptors/inventories; the downstream
absence of a mandatory native-source check is established by source inspection.

Suggested narrow fix: require a frozen historical native retained-source member
set independently of packet declarations, and apply the equivalent Python
source-set requirement at its intended ownership boundary. Add a composition
mutation that removes a required source while fixing copy receipts. Do not
import the producer to obtain the expected set. Reported immediately to the
coordinator; another owner is handling any repair.

### F1 — native/Python command time can exceed the entire report interval

**Confidence: high. Evidence: static-proof plus executed inert-data mutations.**
`_finished` only requires `started_at <= finished_at`; `_commands` bounds each
duration against its own timeout but never joins their sum to report elapsed
time. Setting `finished_at = started_at` independently in the native report
and Python report is accepted by `verify_native`. The unchanged sequential
command durations sum to **70.210087 s** and **21.461786 s**, respectively.
This is contradictory retained chronology. It does not change arithmetic or
grant acceptance, so it is narrower than the source-completeness finding.

Suggested fix: after command validation, compare the sum of sequential command
durations against the report interval with the same bounded timestamp-rounding
allowance used by the framework driver's `_report` (currently two seconds).
The public driver checks its framework report only; it has no corresponding
native/Python elapsed-time guard. No complete forged public ZIP was tested.
