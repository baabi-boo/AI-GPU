## Public seam

```python
identity = p05_execution_records.RetainedIdentity(
    request_sha256=sha256(canonical(base_request)).hexdigest(),
    installed_files=tuple((absolute_producer_path, sha256_hex, size) for ...),
)

p05_execution_records.verify_retained_observations(
    base_observations, base_request,
    retained_identity=identity,
    native_matmuls=native_matmuls, native_models=native_models,
    model_cases=model_cases, raw_log=raw_log,
)

p05_torch_records.verify_retained_observations(
    observations, framework_request,
    retained_identity=identity, adapter_bytes=adapter_bytes,
    native_matmuls=native_matmuls, native_models=native_models,
    model_cases=model_cases, raw_log=raw_log,
)
```

`canonical` means sorted compact UTF-8 JSON with `allow_nan=False`. For Torch, the identity digest binds `framework_request["base_request"]`. Verify the original raw request descriptor before deriving this digest; the helper does not substitute for the archive descriptor join.

`RetainedIdentity` is a frozen dataclass. The receipts and each row must be exact tuples, paths/hashes exact strings, and sizes exact unsigned integers (not booleans). Duplicate receipts, malformed digests, and noncanonical POSIX paths fail. Receipt order is immaterial. Required entries are the observed interpreter, package `__init__.py`, extension, and—on the Torch path—adapter. Package location is exactly `<prefix>/lib/python3.12/site-packages/vortex_ai/__init__.py`; Agent 05's original layout was confirmed by the parent. Interpreter path remains exactly `<prefix>/bin/python`.

The archive driver must independently join installed package and extension receipts to retained first-party/wheel bytes, and join framework request contract/adapter identities. Interpreter bytes are absent from the original archive; its receipt is an observation, not a fresh hash of a retained binary. Docstrings state that constructing facts does not authenticate evidence: only the complete archive driver's independent joins support that result.

## Behavior

The installed checker now exposes pure `validate_request_data`, retaining every frozen case, schema, binding, version and selection predicate. Existing `validate_request` retains its actual-directory checks and original validation order. Installation metadata and framework identity predicates are shared with dedicated live wrappers that still require real paths and adapter bytes.

The separately named retained entrypoints accept only the immutable identity record; no mode flag, validation callback or monkeypatch is added to a live path. The existing live Torch `base_validator` integration is unchanged. Retained code is never imported/executed. Producer paths are interpreted as data and never opened/resolved. Adapter bytes are bounded, hashed inertly, and matched against both request/observation identity and the exact installed digest/size receipt.

P03/P04 reconciliation, raw markers and chronology, ABI words, event ordering, ownership/cleanup, resources, count derivation, and framework tensor layouts/physical bytes use the unchanged shared bodies.
