## F2-14A — packaging-tool receipts can contradict the interpreter receipt

**Confidence:** high. **Evidence type:** static-proof, corroborated by a host-only executable probe.

`p05_replay_installation.py:535–549` checks each packaging distribution inventory separately. It verifies the selected interpreter's path string, versions, before/after equality and raw-marker equality, but never reconciles repeated absolute paths with the provisioning interpreter or other packaging distributions. Consequently, one absolute producer path can have conflicting hashes and sizes in the same admitted installation.

The independent probe replaces the setuptools file list with a descriptor for `/producer/python-runtime/bin/python3`, the exact recorded provisioning-interpreter path. Its digest is `e0c90303bd859a9b32a467f0d7309053806c8178301e436e63f26c741ec39ec0`, whereas the provisioning-interpreter digest remains `f4d2a5c4a507dccbc0b29dc19f7b4e3f66c7f9b070e777811258df4b1a52aa96`. It updates both package-tool snapshots and their raw marker logs; it does not change interpreter receipts. `verify_installations` accepts the contradiction and returns scope `retained-installation-consistency`.

**Public-driver applicability:** `p05_torch_replay.replay_archive` directly calls this helper at lines 602–603. Native replay's `_tools` validates tool snapshots and command arguments, while `_package_probe`/`_python_commands` bind the probe's literal and invocation. Neither joins packaging-distribution file hashes to tool identities. Later public-driver checks consume returned immutable identities, verify numerical observations, packet/source closure and summaries; they do not perform this missing cross-inventory join. A complete mutated packet would also need updated ordinary descriptors, nested copies and caller-selected digest. No complete-original mutation was attempted or claimed.

**Proposed narrow correction:** construct one lexical absolute-path identity map for package-tool receipts, seed it with the provisioning interpreter's path and resolved-path identity (and relevant already validated tool receipts), and reject conflicting SHA-256/size pairs. Apply the same collision rule across all packaging distributions. Identical duplicates may be treated explicitly; a single path must not claim two byte identities. Add a focused synthetic regression for this conflict.

## F2-14B — known first-party files can be assigned to another distribution

**Confidence:** high. **Evidence type:** static-proof, corroborated by a host-only executable probe.

`p05_replay_installation.py:495–507` requires nonoverlapping distribution lists, exact installed-file identities, aggregate coverage of nonseed files, and Torch's `__init__.py` in the Torch distribution. It does not require the `vortex_ai` distribution to own the known Vortex installation. The earlier first-party wheel/RECORD and installed-membership checks already establish that membership, so absent third-party wheels do not prevent this join.

The independent probe moves 13 of 14 known first-party installed rows from `vortex_ai.files` to `torch.files`, retaining one Vortex row to satisfy the nonempty-list check. It updates both framework snapshots and raw environment marker file lists. All bytes, installed inventories, locked versions, and the aggregate distribution union remain unchanged. `verify_installations` again accepts `retained-installation-consistency`.

**Public-driver applicability:** `_commands` checks the 13 distribution names/versions and uses those versions to reconstruct environment-probe arguments; this mutation preserves them. The public driver's retained-observation calls validate actual module/adapter paths and hashes, not distribution file ownership. Subsequent closure and descriptor checks cannot supply the missing semantic membership comparison. The helper-level reproduction is actual evidence; full public replay of a mutated original is an unrun extrapolation supported by the inspected call graph.

**Proposed narrow correction:** require the `vortex_ai` distribution's file-path set to equal the already validated first-party installed set (`SITE + vortex_ai/…` and `SITE + DIST…`). Existing exact identity and nonoverlap checks then cover hashes and prevent another distribution claiming those rows. Keep third-party ownership explicitly limited because its wheel bytes are absent. Add a focused synthetic reassignment regression.

## Substantive checks and safeguards reviewed

- Wheel parsing prechecks the EOCD, rejects split/unsupported directories, constrains entry count and central-directory size before `ZipFile` allocation, validates closed member names/types, and bounds decompressed member/aggregate bytes. RECORD requires exact membership, hashes/sizes for every nonself entry and an empty self-hash. Required METADATA/WHEEL values are single-valued; source members and license join retained sources.
- Source archive parsing is data-only: bounded gzip expansion, at most 1,024 exposed tar members, bounded individual/aggregate regular payloads, canonical names, expected root and no links or sparse members. Expected file membership, staged sources, manifest/source inventories and generated build header are compared. There is no extraction/import of the retained source archive.
- The manifest binds exact first-party source membership, source snapshot/tree/revision, native model binding, qualification digest and all six required bundle roles. Retained Python/framework bundles and bound wheels are byte-identical. Plain installed metadata, rewritten RECORD and direct URL are reconciled against retained wheel bytes.
- Framework installation before/after, wheel payload, seed and environment/raw-marker inventories have substantial membership, duplicate, byte-size, hash, containment and coverage checks. These checks catch ordinary changed-file and missing-entry-point cases but do not cover the two joins above.
- Interpreter receipts are joined across provisioning, copied venv interpreters and framework seed. Expected Python/framework versions, prefixes, runtime-library paths, adapter identity and checker/source bytes are checked lexically. The retained-data seam keeps live path checks separate rather than disabling live enforcement.
- Seven explicit limitations correctly retain absent third-party wheel/payload, per-wheel attribution, interpreter/OS/seed/package-tool bytes, pyvenv configuration, rewritten framework Vortex metadata, loaded Torch `_C`, and compilation/machine-code limitations. Summary fields retain `native_execution=not_run`, no retained-code execution, and false acceptance fields. Those limitations do not excuse conflicting hashes for one path or failure to join already retained first-party membership.
