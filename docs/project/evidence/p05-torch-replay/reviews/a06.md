Reviewed clean `f01c9d031` and `AGENTS.md`. Design only; no source edits, execution, downloads, or tests.

## Findings

- `p05_execution_records.verify_observations` calls `_installation`, whose only live accesses are `resolve(strict=True)` / `is_file()` for executable, package and extension. The remaining installation checks are data comparisons: CPython 3.12, distribution 0.1.0, isolated prefix/executable/layout, build pins and five runtime-library paths. Its P03/P04 comparisons, raw chronology, ownership, ABI, event ordering and independently derived totals are already suitable for inert reuse.
- `p05_installed_check.validate_request` validates exact schema/binding keys, integer versions/iterations, SimX format, digest/revision syntax, three canonical frozen-case SHA-256 values and ordered five-model inventory. Its only I/O is resolving and checking the two directories `binding.bundle_root` and `expected_prefix`. Keep these frozen case checks in the retained path; a request-hash match alone is insufficient.
- `p05_torch_records.verify_observations` reaches live I/O through `validate_request`, the base verifier, and `_framework`. `_framework` additionally resolves/stats/reads the adapter. Torch tensor representation and byte comparisons are pure. Existing `base_validator` is used by the isolated installed checker to supply its sibling-loaded checker; preserve that existing live integration, but do not use it as a replay bypass.

## Minimal refactor

1. In `p05_installed_check.py`, expose a clearly named `validate_request_data(request)` containing every structural, lexical, binding and frozen-case predicate. Keep `validate_request(request)` as the live wrapper that invokes the data checks plus the existing canonical-directory checks. Leave the checker self-contained: adding a new imported helper would otherwise change its copied-file/retained-helper contract. The new data function must never call `resolve`, `stat`, `exists`, `open`, import package payloads, or inspect the interpreter.
2. In base records, split installation metadata checks from live path checks and extract a private common observation body. Existing `verify_observations` still performs the live checks. Add `verify_retained_observations(..., *, retained_identity, native_matmuls, native_models, model_cases, raw_log)`, which validates request data, verifies all installation metadata against explicit retained identity facts, then runs the exact shared body. No `skip_files`, mode boolean, validator callback, monkeypatch, or fallback to live verification.
3. In Torch records, extract the outer request-header predicates and shared observation/tensor body. Existing entry points retain their live call chain. Add the same explicitly named retained entry point, taking `retained_identity` and `retained_framework_identity`, directly invoking the base retained entry point and data-only request validation. `_framework` becomes metadata checks plus its existing live adapter checks; retained framework checks use independently hashed archive bytes.

## Facts and trust boundary

Use immutable, exact-field fact records, not a dictionary of success flags. Base facts should bind the canonical request digest, original producer prefix/bundle-root strings, reconstructed bundle/source/qualification/revision identities, exact package/extension relative names, and verified installed-file receipts. Torch facts should bind original adapter path, observed locked version, retained contract hash and retained adapter hash. Derive these in the trusted replay driver from the SHA-pinned ZIP, complete inventories, before/after receipts, wheel members, bundle manifest and command/request bindings. Never derive expected facts solely by copying the observations being checked. Compare package and extension paths to exact retained wheel/installation membership; the current live runner makes these additional comparisons after the record helper returns.

Treat producer paths as POSIX lexical data with explicit absolute-path/containment checks; reject NUL, traversal and malformed components without consulting the host. Never join producer paths to a local root for access. Reject symlinks and nonregular archive entries in archive inventory validation. A frozen Python fact class is not authentication: complete replay is trusted only because its driver constructs facts after independent verification. Interpreter/system dependency bytes are not fully archived; preserve that limitation rather than claiming reconstruction of their runtime.

## Required negative and parity tests

- Retained verification succeeds with producer directories absent and filesystem/process/network access guarded to fail; live entry points still reject missing files, symlinks and changed adapter bytes.
- Both formats preserve exact live/retained derived results, while altered output, native comparison words, ABI bytes, ownership/cleanup, event chronology, raw markers, count fields and tensor shape/stride/device/gradient/bytes still fail.
- Wrong schema, bool iterations, changed frozen request words, reordered/missing cases, changed bundle/source/qualification/revision pins and unknown fields fail in retained validation.
- Matching request/observations cannot launder foreign prefix, extension, package, adapter or bundle paths when independently verified facts remain unchanged; reject wrong/nested/traversal paths and cross-format/archive fact substitution.
- Mutated retained adapter/contract/extension, unequal before/after inventories, missing/extra installed files and wheel-versus-installed mismatch fail before observations can pass. Rehashing an internal receipt must not defeat the original ZIP pin.
- Retained entry points never call live `validate_request`, `_installation`, `_framework`, import archived Python/native modules, execute producer commands, or invoke a caller-provided callback. Guard assertions in tests establish denial; production replay must not rely on test monkeypatches.
- Public summary must continue to distinguish validated recorded observations from new native execution, and leave acceptance claims unchanged.
