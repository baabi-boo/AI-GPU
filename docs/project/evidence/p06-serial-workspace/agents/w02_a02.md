## Implemented harness boundary

The new C++17 fixture includes the existing P03 fixture with its entry point and
selected fake C API functions renamed. It retains that fixture's deferred event
queue, dependency behavior, resource objects and base launch validation rather
than copying them. The runner links the **actual** `runtime.cpp` and
`contract.cpp`; it does not replace `ManagedMatmul`.

New fake-boundary overlays count buffer creation/release, check release order,
inject a chosen error at each release ordinal, and script wait/value-query
observations. Deferred writes compare every A/B byte and every D poison byte
against a separately retained submission snapshot after caller buffers have
been mutated and destroyed. Launch checks the resulting device-buffer contents
and writes a changing synthetic sequence marker. Saved output and trace from
closed operations remain checked during later reuse. These are data-lifetime
and ownership assertions; the synthetic markers are **not matrix arithmetic,
independent numerical fixture results, native dispatch or GPU evidence**.

Every poisoning scenario is a new executable invocation. Fake backend reset is
used only between clean scenarios; it does not reset production poison and no
production reset hook is introduced. Poison checks require `primary` to be
`VX_ERR_INTERNAL`, `cleanup` to retain the original injected
`VX_ERR_INVALID_VALUE`, and `complete=true`, without native side effects.
