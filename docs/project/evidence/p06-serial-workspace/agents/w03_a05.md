## Coverage and evidence boundary

The fixture links the actual `runtime.cpp`, `contract.cpp`, `mlp_runtime.cpp`
and `mlp_host.cpp`. It reuses the deferred P03 fake C API, replacing only input
copy checks, scripted launch output and the memory-info fault hook. Model
inputs, expected results and scripted outputs are deliberately zero: the test
establishes host control, ownership and error propagation, **not numerical or
native accelerator correctness**. There is no mocked `ManagedMatmul` class.

Both FP16 and BF16 are covered. Both direct-matmul policies are covered wherever
a direct owner supplies the guard or cleanup error. The fixed model retains its
default per-operation policy.

| Scenario group | Fresh child executions | Checked behavior |
|---|---:|---|
| Direct owner excludes models | 4 | Idle, queued, successfully waited and operation-closed direct owners reject additional direct/model contexts; owner close finally releases the reservation. |
| Operation outlives direct owner | 4 | Both queued and successfully waited operations keep the shared guard after owner destruction; timeout retains it; completed close releases it. |
| Model excludes direct/model contexts | 2 | Idle, suspended and terminal-success models reject both routes without extra native calls; explicit close permits reopening. |
| Terminal model failures | 2 | Scripted hidden-result mismatch and asynchronous native error stop dependent stages, retain the owner, and allow healthy reopening after close. |
| Partial model submission | 2 | Each enqueue failure at ordinals 2–5 retains the accepted prefix and guard through incomplete close; eventual drain preserves the primary error and permits clean reopening. |
| Model policy validation | 2 | Resident and unknown policy values reject before native open, both with no context and while a direct context exists. |
| Model setup rollback | 2 | Device open, all seven capability queries, module load, kernel lookup and initial model memory-info failures return a healthy reservation after cleanup. |
| Direct cleanup poisons model creation | 8 | Operation and owner cleanup errors under both policies suppress output where applicable, survive repeated close, and reject both creation routes. |
| Model cleanup poisons all creation | 8 | Operation close, owner close, live-model destructor and failed-setup rollback errors poison the actual shared managed-runtime instance. |
| Healthy default-shape/model handoffs | 2 | All three default shapes per format alternate with actual three-stage model control; each stage closes before the next and healthy owners release their reservation. |
| Healthy model destructor handoffs | 2 | Idle, suspended and terminal models release the reservation through destruction and allow a new real direct/model owner. |

Rejected-context probes require exact validation/primary/cleanup/completion
fields, a null returned object, unchanged fake API call counters, and unchanged
live resources, copy counts and launch counts. They test both direct policies
and the model route. Poisoned cases use separate processes; no production reset
hook was added. Passing later child processes are managed-lifetime isolation,
not physical device recovery.

### Corrected test-development expectation

The first run completed 11 methods in 6.889 seconds with six assertion failures
in the new test, across three methods and two formats. The assertions had
incorrectly treated terminal model execution completion as owner release.
`ManagedMlp::advance()` can return terminal success with `execution.complete`
and `ok()` true while still retaining its context; `owner_close_complete_`
initializes true and tracks a requested close's completion. Explicit close or
destruction releases the context. The existing model contract and source agree
on this distinction. The corrected tests assert terminal execution completion
while independently proving rejected creates and a live device until close.
No production change or weakened ownership check was needed.
