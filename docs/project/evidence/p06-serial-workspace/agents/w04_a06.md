## Review findings and reasoning

### Output, manifest, and mathematical expectations

The manifest reader checks bounded regular-file input without following a final
symlink, reads under a second byte cap, and rejects malformed UTF-8, duplicate
JSON keys, floats/nonfinite numbers, oversized integers, excessive nesting,
unknown fields, wrong types, and any mismatch with the local literal freeze.
Exact type comparisons prevent Python boolean/integer equality from satisfying
integer fields. Caller-supplied contracts and source cases do not replace the
trusted expectations: the four ordered case dictionaries are compared in full
against locally verified independent P02 producers. Each of 32 output words per
operation is then checked, independently of the reported mismatch/success totals.

Both input matrices must change at each adjacent operation; the final case
repeats the first mathematical inputs with the other poison. Submission, wait,
close, unsupported-shape, and six active-operation/owner probes require their
specified status and completion values. Every probe binds before/after resource
counters and rejects a returned object. The 56-byte little-endian argument block
is reconstructed from the frozen ABI, input format, geometry, and tracked device
addresses. Extents are aligned, bounded, and nonoverlapping within the launch.

Device and buffer inventories prove the expected observed lifetimes separately
from aggregate counts. Creation sequence, release phase, live-device release,
flags, requested sizes, and exact memory deltas are checked. Requested payload
remains 320 bytes; allocator charge may be a larger 64-byte multiple only when
the exact charge is reclaimed. Release order is reconstructed from live memory
readings and must reconcile contiguously. The same-address reuse of separate
closed default-policy lifetimes is accepted, while a resident launch cannot
borrow another group's addresses. Every reading shares a device capacity, and
the final live-device reading restores the after-open baseline.

Final success requires four ordered result records, one exact summary, and the
single final success sentinel. Contradictory failure text, duplicate/reordered
records, extra protocol markers, stale word claims, nonzero status, leaked or
premature resources, mismatched counts, and inconsistent memory are rejected.
Unrelated diagnostic lines are permitted within the bounded output envelope.
These checks validate reported observations; the runner's source/tool/process
binding and the actual observer remain separate obligations.

### Compiler records

Each original runtime/backend/kernel/host record is checked independently before
an exact role-local map is applied. No missing information is filled from
another role or from submitted values. Expanded runtime/kernel/host maps and
sparse backend maps retain their distinct contracts; in particular the RTL C++
shim does not borrow the Verilator arithmetic selectors. Profile, application,
release, diagnostic, host/kernel, and simulation macros remain role-specific.
Unknown names, missing names, changed derived values, undefinitions, conflicting
duplicates, unsupported ISA toggles (including defined zero-valued toggles),
tracing/performance changes, and unparsed transports are rejected.

The review traced operand consumption through both the shared parser and the
new strict option check. Forwarded preprocessor options cannot establish driver
ISA/ABI or swallow a driver option. Include paths, dependency target, compiler
options, Verilator package/order/make selections, and the four interposition
wrappers with runtime library binding are checked. Identical duplicate macro
definitions remain allowed where original generated stamps contain them; they
do not change the parsed macro configuration. Returned hashes describe the
original record text, without a rewritten or pooled replacement.

An independent reconstruction from the current trusted configuration sources
matched **all 279 expanded macros and all 30 raw macros exactly**, with no
duplicate literal keys. The expanded expectation was independently parsed from
the union of two fresh generator outputs using standard `shlex`, not copied
from the validator or a submitted compiler stamp. The raw expectation was built
from the profile's core/chip values, explicit false `_DISABLE` forms, and RV64.
This confirms the large literal map did not silently freeze an incomplete or
mistyped subset. The generator was trusted local source, not archived evidence
code.
