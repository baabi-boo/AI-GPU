## Contract-to-source and test mapping

| Checked claim | Evidence inspected and conclusion |
|---|---|
| Internal policy and defaults | `runtime.h` defines exactly `per_operation = 0` and `reusable_single_tile = 1`; the binding defaults to the former. `ManagedMatmul::create` validates the enum before reservation/native open. `ManagedMlp::create` rejects every non-default value before creating its owner. No new public C ABI is asserted. |
| Shape and resident payload | `supported_shape`, submit validation, `kResidentBytes`, `allocate_buffers` and `create_workspace` preserve the three default shapes in both formats, restrict resident mode to `(8,4,8)`, allocate 128/64/128 requested bytes with read/read/write access, and validate actual addresses with the existing planner before owner publication. |
| Reservation and explicit close | The atomic instance state is acquired before device open. Submit validates before taking its operation lease. Successful wait retains the lease. Busy new work reports timeout with no accepted work; owner close with a live operation reports incomplete and does not set a closing latch. Clean completed operation close returns the lease. Source placement supports the documented rejection boundary. |
| Sticky errors and retained resources | Wait records a non-timeout wait failure before the completion query, preserves earlier primary errors through drain, and leaves timeouts retryable. Cleanup consumes handles once, attempts remaining releases, records first observed errors, and poisons new work. Owner repeated-close state is retained. This source mapping does not itself establish a new native run. |
| Detached host output | `OperationState::release` resets the context after completed close. `output_words` depends on that operation's own validity/result. A later owner-teardown failure cannot mutate a healthy detached operation's result. Last-owner teardown performed during operation close does affect that operation's cleanup/output. Contract section 3 explicitly identifies the independent W04-A03 clarification before publication, rather than silently presenting the changed wording as the original freeze. |
| Terminal model context | Real `ManagedMlp::advance` can finish the model without resetting its owner; `ManagedMlp::close` releases the owner. The handoff explicitly distinguishes terminal execution from context release. |
| Host test scope | The runtime test driver links real `runtime.cpp` and dispatches policy/format fault groups covering the documented leases, default shapes, setup/partial rollback, sticky observations and cleanup. The real-model driver names both creation orders, idle/suspended/terminal models, policy rejection and cleanup poisoning. Its execution remains deferred fake-C-API host evidence, as the docs say. These test bodies were not rerun by this assignment. |
| Hidden deallocation limits | Common `Buffer::~Buffer` ignores the return from underlying `mem_free`; the public buffer release returns success after object release. The audit, frozen contract and handoff correctly promise poisoning only for observed API errors. Release counts and successful API statuses do not establish physical reclamation or recovery. |
| Native observer limits | The observer wraps native device open/release and buffer create/release. It tracks requested payload separately from memory-info deltas, and `reconciled` requires a positive allocation charge at least as large as the request and equal reversed release deltas while the device is live. It does not independently wrap queue/event/enqueue calls. The frozen contract and evidence README state this limitation explicitly. |
| Correctness matrix | The manifest and runner bind two backends, two formats, two policies, and the frozen four-call changed-input/poison sequence. The documented 2 processes / 8 launches / 256 words per selected variant and 8 / 32 / 1,024 for the complete matrix agree with that contract. These remain expected counts, not observed native results. |
| Execution instructions and limits | Handoff runner arguments match `argument_parser`; selectors retain both policies and there is no case/policy/iteration/dirty escape. Workflow uses four variant jobs, at most two concurrently, read-only contents permission and a 90-minute job deadline. Runner checks preserve two build jobs, 4 GiB memory, 15 GiB disk, bounded logs and 1,800/180-second deadlines. |

The 320-byte quantity is correctly described as **requested A/B/D payload**.
It is not rounded allocator cost, total device use or host RSS. Stable repeated
addresses alone are not accepted as proof of retained allocations. Native
queue/event totals are required behavior; native observer counters do not
independently establish those totals inside rejected calls.
