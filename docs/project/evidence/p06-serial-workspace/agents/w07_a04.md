## Finding and corrective behavior

W07-A03 identified an **F3**, high confidence, reproduced with the compiled
host fault boundary: `cleanup_failure` injects `event_release` error 10 and
already requires the operation to retain that error, but the shared final
assertion required `session.close().ok`. The serial native contract correctly
retains the observed cleanup error on the owner as well, so the optional hosted
Torch gate would fail despite correct runtime behavior.

The cleanup case now requires owner close to return `complete=true`,
`primary=0`, `cleanup=10`, and requires repeated owner close to return the same
status. It also repeats the operation close check before continuing the
existing output-suppression and blocked-submission checks. All eight other
scenario names still require successful owner close. The existing attempt to
reopen a poisoned process, no-extra-device-open check and resource accounting
remain intact.

An AST normalization check removed exactly these new assertions and the new
conditional final-close structure from a copy of the changed AST; the entire
module then matched the original AST. All **nine scenario names**, scenario
bodies outside the explicit cleanup addition, runner orchestration, CLI and
other functions are preserved. No regression was skipped or reclassified as
success.
