## Findings

1. `tests/regression/ai_bench_matmul/Makefile` compiles
   `tests/regression/ai_matmul/main.cpp` directly. The existing caller retains one
   context for one fixture, submits one or two poisons serially, explicitly closes
   each operation and checks memory return after every operation. Altering its
   behavior would also alter the cold benchmark. Preserve both callers and
   `p06_execute.py`; add a separate workspace caller.
2. `p03_execute.py` supplies the useful native build/provenance pattern: fresh
   RV64 `p02-tfr` builds, separate compiler records, unchanged P02 independent
   fixtures, module/backend/host hashes and binding IDs, raw logs and source/tool
   stability checks. Its inherited selector requires development mode for a
   partial matrix, and its inherited budget is 6 GiB. A new bounded qualification
   must explicitly select its own matrix and retain the current 4 GiB limit.
3. `p03_execution_records.verify_output` expects one fixture per invocation,
   exact two-poison ordering and resources returning to the pre-operation
   baseline. It is unsuitable unchanged for mixed fixtures and first-use
   resident allocation. Keep its contract intact and give workspace logs a new
   strict schema.
4. `p04_execute.py` and `.github/workflows/p04-model.yml` already cover
   SimX/native processor RTL × FP16/BF16 with fresh variant builds. The hosted
   workflow restores identified pinned tools/dependencies, runs
   `p04_ci_prepare.py`, limits matrix concurrency to two, and uploads hidden
   generated stamps. This is the closest hosted template. P05 workflows are
   installed SimX consumers; they do not supply resident workspace or RTL proof.
5. `p06_execute.py` binds fresh-process cold samples and performance counters.
   Its sampling, schema, analyzer and SimX-only compiler validator must not be
   reused as a warm-workspace performance contract. `p06_compiler_records.py`
   requires the frozen benchmark's performance/wrap configuration.

Freeze this four-operation sequence per format and policy in one live context:

| Index | Existing fixture suffix | Destination poison |
|---|---|---|
| 0 | `single-dense_boundaries` | `0x7fc0dead` |
| 1 | `numerical-zero` | `0xdeadbeef` |
| 2 | `single-k03` | `0x7fc0dead` |
| 3 | `single-dense_boundaries` | `0xdeadbeef` |

Prefix each ID with `fp16-` or `bf16-`. JSON inspection confirmed all are
`(8,4,8)` and both A and B differ at every adjacent transition. The return to
dense checks reuse after two different inputs with the other poison. Independent
fixture bits remain the expected outputs; do not derive expectations from the
runtime or a preceding result.

Run `per_operation` and `reusable_single_tile` in separate process invocations
for each of the four backend/format variants. This minimum is **8 processes,
32 actual launches and 1,024 exact FP32 output words**, contingent on successful
execution. It is a bounded reuse smoke, not complete numerical acceptance. The
full frozen inventory contains 38 single-tile cases per format; any later wider
workspace qualification should freeze its own bounded batching before running.

For each operation, retain case/sequence/policy identity, actual output words,
native argument bytes and addresses, 128/64/128 tensor byte extents, three writes,
one launch, one read, both poisons, and distinct validation/primary/cleanup/
completion results. Observe rejection of a competing context, a second live
operation, and resubmission after successful wait before explicit close. The
next valid submission must succeed after completed close. Unsupported resident
shapes must reject before native allocation or enqueue. Leave timeout and
injected-failure coverage in separately labelled host/native lifecycle suites.

Require three stable, disjoint resident addresses across operations, but do not
equate address reuse with retained allocation. Use a caller-only native observer
wrapping `vx_buffer_create` and `vx_buffer_release` to record creation/release
counts and sizes. The linker observer must delegate to the actual APIs and distinguish
the three tensor handles from other allocations. Per-operation policy should
observe twelve tensor creations/releases over four calls; resident policy
should observe three creations, no tensor release at intermediate operation
close, and three releases at owner teardown. The retained logical payload is
320 bytes; allocator consumption and physical reclamation are separate claims.
Record native memory snapshots before/after initialization and each completed
close without assuming the initialization is eager or that allocator overhead
is zero. For each tracked tensor handle, retain its device and query
`vx_device_memory_info` immediately around actual creation and actual release.
Require the observed released-memory delta to match the recorded allocation
delta while that device is still live, with successful query results. A count
of successful handle-release calls is insufficient. Do not query a dead device
after owner teardown or infer physical reclamation from these simulator counters.

## Scope and blockers

prerequisites remain unavailable as recorded by the workspace audit. Hosted
`rtlsim` establishes processor RTL only: it bypasses AFU integration and retains
integer DPI helpers. This plan neither closes P01-A03 nor supplies FPGA, physical
speed, synthesis, P06-A02/A03 acceptance or a speedup. Matched warm-context source
pairs and frozen measurement/rejection rules remain a separate later experiment.
