## Frozen interface and sequence

The standalone `ai_workspace` caller accepts exactly `--policy
per_operation|reusable_single_tile`, `--module PATH`, and `--qualification-id
64_HEX_DIGITS`. It compiles the unchanged `sw/kernel/ai/matmul.cpp` and uses the
unchanged independent P02 fixture words, selected by the compiled FP16/BF16
profile. The four suffixes are `single-dense_boundaries`, `numerical-zero`,
`single-k03`, `single-dense_boundaries`; the poisons are `0xdeadbeef`,
`0x7fc0dead`, `0xdeadbeef`, `0x7fc0dead`. Each call checks 32 exact FP32 words.
This order follows the root's frozen `ci/project/p06_workspace_contract.json`;
W01-A04's inverse starting poison was a proposal rather than the final contract.

The owner remains live across all four calls. Each operation is explicitly
closed before the next accepted submit. Competing context and operation
attempts are checked both before and after successful wait; each must return
validation success, primary timeout, cleanup success, complete true and no
object. Owner close at both boundaries must return timeout and complete false.
The rejected shape is `(8,4,16)` for the resident policy, proving rejection of
an otherwise supported signature, and `(7,4,8)` for the default policy.

## JSON schema agreed with the root

All enum/status fields are numeric. Every JSON boolean is a JSON boolean.
Success emits four `P06_WORKSPACE_RESULT ` records, one
`P06_WORKSPACE_SUMMARY ` record, and then exactly `PASSED!`.
Both records carry `schema_version: 1`,
`contract_id: "p06-serial-workspace-correctness-v1"`, `qualification_id`,
`policy`, and `format`.

Shared objects:

- Execution result: `{validation, primary, cleanup, complete}`. An unattempted
  result is `null` on a failed run only.
- Memory reading: `{status, free_bytes, used_bytes}`. An unqueried reading is
  `null`; no reading is taken after the actual device release.
- Counts: `{device_open_calls, device_release_calls, buffer_create_calls,
  buffer_release_calls, live_buffers, live_requested_bytes,
  peak_requested_payload_bytes, premature_releases, errors}`.
- Resource snapshot: `{memory, counts}`.
- Probe: `{result, returned_object, before, after}`, with `before` and `after`
  being Counts. An owner-close probe has `returned_object: false`.

Each result adds:

- `sequence_index`, `case_id`, `m`, `n`, `k`, `poison`, `checked`,
  `mismatches`, `actual_bits` (32 lowercase eight-digit hexadecimal strings),
  and `passed`.
- `dispatch: {a_address, b_address, d_address, a_bytes, b_bytes, d_bytes,
  writes, launches, reads, waits, timed_out_waits, argument_bytes,
  event_results, profiling_enabled}`. Argument bytes are lowercase hexadecimal;
  event results contain five statuses.
- `results: {submit, wait, close}`.
- `probes: {context_before_wait, operation_before_wait,
  owner_close_before_wait, context_after_wait, operation_after_wait,
  owner_close_after_wait}`.
- `resources: {before_submit, after_submit, after_wait, after_close}`.

The summary adds:

- `operations`, `checked`, `mismatches`, `passed`, and final `counts`.
- `results: {setup, teardown, teardown_repeat}`; setup and teardown failures
  remain distinct.
- `unsupported_shape`: a Probe with added `m`, `n`, `k` fields.
- `devices`: entries `{device_id, index, open_status, after_open,
  release_status, before_release}`.
- `buffers`: entries `{buffer_id, device_id, requested_bytes, flags, address,
  address_status, create_status, create_phase, create_sequence, create_before,
  create_after, release_status, release_phase, release_sequence,
  release_device_live, release_before, release_after}`.

Successful per-operation policy has 12 creations and 12 releases. Successful
resident policy has three eager creations during `context_create`, sequence
`-1`, and three releases during `owner_close`, sequence `-1`. Both have a
320-byte peak requested tensor payload, one actual device open/release and no
observer errors or premature releases. A/B/D roles are tied to actual observed
addresses, sizes and access flags; address equality alone is not evidence of
retention. Per-buffer measured used/free changes at creation must agree, and
the immediate release must reverse both measured changes while the device is
still live. Requested payload is not substituted for allocator cost.

## Verification

contract ID, all four fixture suffixes, exact poison order, both format-prefixed
fixture inventories, unchanged native kernel path, exactly the four approved
linker wrappers, file final newlines and whitespace all passed. Reviewed the
runtime's buffer refcounts, queue-held references, allocator accounting and
preallocated kernel-argument scratch pool to check observation placement. The
observer reads memory after each actual buffer release while retaining its live
device identity, then reads once before actual device release and never after.

The caller checks 24 rejection/close probes across the four operations, plus
the unsupported-shape probe. It independently compares the full 56 argument
bytes with the frozen ABI fields and observed addresses, verifies the actual
buffer handles' sizes/access flags, and compares native words only against the
independent fixture. It requires healthy repeated final close and exact return
to each operation's pre-submit memory baseline. Final device memory is compared
with the post-open snapshot while that device is still live; preallocated
device-owned scratch remains included on both sides.

API call counters count attempts; each per-device/per-buffer record separately
retains the real returned status, so successful creation/release counts are
derived independently rather than assumed from attempts. This native smoke
does not inject failures; failure records may have unattempted/null fields and
never print `PASSED!`.
