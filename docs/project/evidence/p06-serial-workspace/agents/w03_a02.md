## Independent samples and evidence boundary

The output sample builder has fixed synthetic device identity, memory capacity,
context baseline, buffer addresses, allocation/release order, dispatch counts,
status fields and lease probes. It does not import either validator's record
builders or expected-count helpers. The 56-byte argument payload is packed with
Python `struct` from the frozen ABI. FP32 words and A/B inputs are read directly
from the existing independent P02 fixture JSON files; no production arithmetic
or previous output supplies expected bits.

Positive transport controls cover both formats and both policies. Additional
controls accept complete default lifetimes with recycled addresses, allocator
rounding with exactly matching reclamation, and release order different from
allocation order. These prevent the negative tests from succeeding merely
because the sample itself is invalid or the validator rejects every input.

Compiler samples adapt the retained original P02 stamp samples only at the
workspace host include and exact four-wrapper linker boundary. Both backends,
both formats and both supported job budgets pass. Each original role's SHA-256,
configuration and include paths remain independently checked. These stamp
strings are parser inputs, never commands executed by this suite.

The initial output suite used the unmodified independent fixture loader for
every mutation and passed. Repeated producer verification dominated its runtime.
The final test implementation verifies the real independent fixture inventory
once, retains its serialized immutable snapshot, and deserializes a fresh copy
for each negative case. Only that fixture-loading dependency is patched during
negative calls; all positive integrations still invoke the real loader. No
validator logic, schema comparison, ABI reconstruction, numerical comparison,
lifetime check or expected rejection is bypassed. A used loader must still be
called exactly once with the original repository root.

All results here are **parser/control-only evidence**. Synthetic successful
records do not prove native execution, arithmetic, allocator reclamation,
physical recovery, performance, matrix completion or phase acceptance.

nested leaves, duplicate JSON keys even with identical values, missing/extra

individually in each format. Negative output still claims zero mismatches and
success where relevant, so independent comparisons must reject it.

Dispatch tests change sizes, write/launch/read/wait counts, event results,
profiling, addresses and argument bytes. They include misalignment, overflow,
overlap, changed resident addresses and default addresses borrowed from a prior
lifetime. Every submit/wait/close result and each setup/teardown/repeated-teardown
result is independently mutated. All 24 lease probes are tested for unexpected
objects, successful busy responses and changed device/buffer counters. The
unsupported-shape tuple and zero-work observations remain policy-specific.

Resource tests manipulate each counter at every resource phase and final
teardown, remove/fail/overflow memory queries, preserve total capacity while
forging allocation/release deltas, change capacity while preserving local
deltas, fabricate stable operation snapshots, and make context allocation
predate the recorded device baseline. Every tracked final release is challenged
for failed status, missing observation, wrong lifetime sequence and a dead

and device lifetime remain tied to actual reported dispatch addresses.

Transport tests reject failure markers, false/ambiguous/followed success,
malformed markers, floating/nonfinite/oversized numbers, excessive nesting,
bad Unicode/control characters and size excesses. Manifest tests reject changes
to every frozen leaf and missing, symlink, directory or FIFO source inputs.

Compiler tests mutate each of the nine independent role positions across SimX
and processor RTL. Coverage includes missing selectors without cross-role
pooling, profile/format/geometry/ISA/native-DPI substitutions, zero-valued

## Defect found and independent resolution

The original workspace compiler validator accepted changes to hardware macros
outside its partial checks. A bounded 45-case public-API probe appended five
flags separately to each independent compiler role. **33 malformed variants
were accepted**:

- `-DVX_CFG_EXT_C_ENABLE=0`, `-DVX_CFG_EXT_A_ENABLE`, and
  `-DVX_CFG_EXT_F_DISABLE` passed in every role across both backends: 27 cases.
  A zero-valued `*_ENABLE` still defines the feature for `ifdef` consumers.
- `-DVX_CFG_NUM_TCU_BLOCKS=2` and `-DVX_CFG_MEM_ADDR_WIDTH=32` passed in the
  three sparse SimX-backend/Verilator/RTL-C++ roles: six cases. Expanded roles
  rejected these appended conflicting duplicates, which did not establish
  complete validation of their existing derived values.

The issue was reported promptly to the root. The root assigned the production
fix separately to `/root/w03_a03_compiler_hardening`. This suite retained strict
expected rejection and expanded coverage to arbitrary unknown hardware names
and replacement of existing expanded values, not only appended duplicates.
There are no expected failures, skipped defect cases or relaxed assertions.

The separate fix now checks exact original macro maps for expanded and sparse
roles, with native selectors and nonhardware macros tied to the correct role.
Independent source review found no new role-pooling issue. The final independent
compiler test run passes all 1,149 rejection checks on that fix. No output-record
validator defect was found in the 1,507 output mutations.
