## Python guard composition and retained 107-case result

The existing extension guard and new native reservation compose in the correct
order. `resume_matmul()` acquires the Python `NativeLease`, then creates the
native context. Failure drops the lease when no native owner is published and
retains cleanup poison. Direct submissions share the session lease; a successful
wait does not release it. `operation_close()` resets its lease only on completed
native close. The native operation lease now independently enforces the same
rule for direct C++ callers.

Model handoff first calls the existing direct owner's native `close()`. An
incomplete busy close retains that owner and returns a blocking error; the new
native owner has no closing latch, so closing the active operation permits
ordinary resubmission. A healthy complete suspension resets the native owner and
Python lease before acquiring the model lease and creating the model's own
managed owner. Model close drains its active operation, closes its owner, then
releases the Python lease. Later direct use lazily reacquires a context. A
suspended session cannot bypass another active model/session. Explicit Python
`Session.close()` still sets the Python session's closing flag: that existing
public close behavior is distinct from the temporary native close attempted
during model suspension.

Primary errors and observed cleanup errors remain distinct. Non-timeout
wait/query errors now stay sticky through a later drain; cleanup failure reaches
owner close and repeated close, and both layers refuse fresh work. Existing
consumer-expectation changes strengthen those assertions, while preserving
timeouts as retryable and retaining required owners. Destructor paths retain
the native context through an outliving operation and propagate observed cleanup
poison. These are bounded single-caller guarantees; raw native clients and
separately linked managed copies are outside the reservation boundary.

Both format builds bind **63 source records**; this review independently hashed
