## Applied behavior

1. Added `WorkspacePolicy::{per_operation,reusable_single_tile}` and the
   defaulted policy member in `ExecutionBinding`. Existing create/submit
   signatures remain unchanged. Unknown policy values reject before reservation
   or native setup. The default path retains all three shapes in both formats.

2. A single atomic state for the linked managed-runtime instance represents
   available, reserved, or permanently poisoned by the first observed cleanup
   error. Context acquisition precedes device open. Competing creates cannot
   both open a device. Cleanup publishes poison immediately, and reservation
   return can transition only a healthy reserved state to available. Context
   and owner allocation exceptions return a clean reservation safely.

3. Resident creation eagerly allocates A/B/D with 128/64/128 requested payload
   bytes and READ/READ/WRITE flags. Native address queries and the existing
   planner check actual addresses and complete tracked extents before owner
   publication. Setup failure releases every acquired handle. Resident submit
   accepts only `(8,4,8)`, borrows these handles, queries/validates their actual
   addresses again, and keeps staging, queue, events and result storage local
   to the operation. All input and destination-poison bytes are rewritten.

4. Each context now holds an explicit operation lease. Argument rejection
   precedes lease acquisition and leaves another operation untouched. Queued,
   partial, timed-out and successfully waited operations keep the lease until
   completed healthy close. Construction/staging failure rolls back the lease.
   The catch path preserves completion and primary status and would publish
   an operation with accepted commands instead of marking it complete.

5. Operation cleanup consumes every event and the queue before default-policy
   buffers. Resident handles are never released by the operation. Cleanup
   continues after errors, preserving the first error in the operation,
   context and instance. Healthy completed cleanup returns the operation lease;
   failed cleanup poisons further work. Final context release frees resident
   buffers before kernel/module/device handles.

6. Owner close while an operation retains the context remains incomplete and
   does not latch a closing state. Owner destruction leaves the context owned
   by the operation. The operation's final close reports last-owner context
   teardown errors. Explicit owner close saves its result after context reset,
   so repeated close cannot erase a failure or release a handle twice.

7. Non-timeout wait errors are remembered before the completion query. Query
   errors and values below target remain primary failures through eventual
   drain. Timeout observations remain transient, including an unexpected
   timeout in a later per-event status poll; ownership is retained for retry.
   Primary or cleanup failure suppresses subsequent output access. Healthy
   completed host output and traces survive later device-buffer reuse.

8. `ManagedMlp::create` rejects every non-default workspace policy as
   `Status::invalid_argument` before allocating its model or creating its
   managed context. Its existing default execution remains unchanged.
