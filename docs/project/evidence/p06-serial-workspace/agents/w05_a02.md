### Independent expected data and cache boundary

It does not ask a workspace validator to construct its own expected results. Original per-role stamp content remains independently checked.

The real P02 loader validates the leaf, layout and numerical source documents against their separate producers byte-for-byte and checks the combined inventory; the caller tests also reproduce the complete checked-in C++ fixture header. Source JSON expected words and compiled host marker/zero outputs are never described as GPU-computed output.

The records suite's class setup calls the real trusted `load_cases(ROOT)` once and serializes the resulting inventory to an immutable JSON string. Only negative transport cases patch that loader, returning a fresh JSON deserialization for each call. Positive parser integrations use the real loader, and every negative case still executes the real validator. The tests cover supplied-case/expected-word substitution, all 128 selected output words per format, all 56 argument bytes per format, strict nested schemas, statuses, allocation lifetimes, memory reconciliation and final markers. Caching does not replace validation decisions, share mutable negative-case data or make an altered-output sample its own accepted oracle.
