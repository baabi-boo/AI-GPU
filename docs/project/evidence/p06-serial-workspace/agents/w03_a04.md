## Regression boundary

The runner harness replaces only external process observations, tool/resource
inventories and checkout identity. Missing native dependency libraries have
explicit synthetic identities. Its files and logs are labelled synthetic and
remain in disposable temporary directories. The independent P02 producers,
fixture/header consistency checks, compiler-record validators, effective-header
parser, workspace output parser, generated-input checks, source/build/log hashes,
qualification bindings, completion reduction and on-disk report writes all run
without replacement. Compiler stamps are adapted from the existing retained
probe samples; native output is constructed by the independent synthetic
workspace transport sample helper. These tests do not claim those observations
were produced by a real compiler, runtime or device.

The positive integration tests run all four backend/format variants with two
separate policy invocations each, and each of the four individual variants.
They require respectively `8/32/1024` and `2/8/256` verified
process/launch/FP32-word counts. Only the complete matrix may set
`full_matrix_completed`; every acceptance/performance/phase flag remains false.
Bindings must distinguish all eight processes and include the exact sequence,
fixture words, source, tools, dependencies, compiler records, effective headers,
generated inputs and artifacts. Native command arguments and explicit runtime
library/driver environments are checked directly.

Negative cases cover missing/reordered records, wrong exact output bits, wrong
policy or qualification ID, incomplete operation close, nonzero exits, timeout
receipts, incomplete process cleanup, missing/malformed success receipts, build
failures, stale copied Makefiles/configuration/reproduced headers, altered
compiler records and instrumentation macros. Source/tool/dependency drift,
prelaunch or in-process executable/module changes, raw-log receipt mismatches,
and retained source/build/binding tampering must leave failed attempts and raw
evidence inspectable without claiming successful completion. Final inventory
failure after eight verified processes must still clear full completion.

The suite separately verifies loaded-helper byte identities and the real
source inventory's runtime, checkout inputs, fixture producers and transitive
compiler helpers. CLI and direct-execution budget checks reject development,
case, iteration, policy and dirty-source escapes and resource expansion. Fresh,
disjoint, source-external paths are required. Injected ambient compiler, driver,
preload, make, Python and policy variables do not reach child environments.
