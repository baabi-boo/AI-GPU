## Public API and source-data boundary

`load_contract(source)` reads the source root's workspace manifest as a bounded
regular UTF-8 file, rejects ambiguous JSON, and requires the exact frozen schema,
types, sequence, poisons, shapes, counts and false acceptance flags.

`verify_output(text, *, cases, fmt, policy, binding_id, contract)` accepts the
ordered four-case list for the selected format, including the repeated dense
fixture at positions zero and three. It returns the original validated records
as `{operations: [four rows], summary: object}`. Supplied case dictionaries must
match the existing independent P02 fixtures through the trusted local loader;
both input arrays must change at each adjacent step. The runner separately binds
the ordered cases, policy, backend, source, dependencies, tools and binaries to
the qualification SHA-256. No retained source or stamp text is executed.

Every nested native record requires the exact keys and types. Booleans cannot
stand in for integer counts/statuses, floats/nonfinite numbers and duplicate JSON
keys are rejected, and records have bounded bytes/nesting. The parser requires
exactly four ordered result rows, one following summary, and one unambiguous
final `PASSED!`, with no failure marker. All 128 returned FP32 words are compared
to the independent fixture words. Every 56-byte argument block is reconstructed
from the frozen ABI and actual disjoint, aligned, nonoverflowing addresses.

Each operation requires three writes, one launch, one read, one successful wait,
five successful event results, no timed-out waits or profiling, separate healthy
submit/wait/close results, and all six busy/owner-close probes. Their 24 recorded
before/after counter pairs must be unchanged, return no object, and report exact
validation/primary/cleanup/completion values. Unsupported-shape rejection has
its separate expected tuple, status and unchanged setup counters.

## Independent allocation accounting

The reader reconciles the actual tracked buffer identities, device identity,
requested sizes, access flags, addresses, successful statuses, creation/release
phases and sequence indices. It requires exactly 12 allocations/releases for the
default policy and three eager context allocations/final releases for the
resident policy. It derives peak requested payload from those lifetimes, checks
the 320-byte bound and final zero owned payload, and ties every dispatch address
to the live buffer inventory. Resident addresses stay identical across all calls.

Every memory query must be present and successful. The actual used/free delta
around each allocation must be positive, cover the requested payload, and be a
multiple of the native allocator's 64-byte granularity. Its actual release must
reverse that exact charge while the device is still live. The reader keeps
measured allocator cost separate from requested payload, reconstructs contiguous
allocation/release readings, reconciles them with operation snapshots, preserves
a constant live-device capacity, and requires both per-operation restoration and
the final pre-device-release baseline. Missing/failed queries never become zero.

The observer's four wrappers record device/buffer attempts, not transient
queue/event/enqueue calls. The parser proves zero changes to all counters
actually observed and the accepted operations' exact dispatch totals. Guard
placement and absence of unobserved transient calls require the separate host
fault/control tests and source review; this implementation invents no broader
native observability claim.

## Separate compiler validation

`validate_records(runtime, backend, application, *, driver, fmt, source, build,
jobs)` returns original independent role records: runtime, optional Verilator,
backend C++, kernel, and host. Each role retains its original line SHA-256,
macro flags, include paths and checked configuration. The trusted P02 per-record
validator runs first; additional strict checks bind release/profile selection,
compiler options, include ordering and permitted simulation macros. Runtime,
backend, kernel and host configuration is never pooled. The nonselecting RTL
C++ shim remains distinct from the selecting Verilator record. Counters,
functional/multithreaded SimX switches, tracing and alternate execution modes
are rejected.

The linker is checked separately and accepts only, in exact Makefile order:

1. `-Wl,--wrap=vx_buffer_create`
2. `-Wl,--wrap=vx_buffer_release`
3. `-Wl,--wrap=vx_device_open`
4. `-Wl,--wrap=vx_device_release`
5. The original `-L<absolute build>/sw/runtime -lvortex` binding.

No existing validator or native/cold-benchmark contract was modified. The runner
agent was notified of both new modules and their transitive source-retention
requirements; the runner already inventories imported local validation helpers.
