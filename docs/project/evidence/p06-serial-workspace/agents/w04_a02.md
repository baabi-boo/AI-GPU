## Actual integration boundary

The test compiles the unchanged application translation units
`tests/regression/ai_workspace/main.cpp` and `observer.cpp`, the real
`sw/runtime/ai/runtime.cpp` and `contract.cpp`, and the new test backend. The
backend reuses the existing P03 deferred queue/event fixture through renamed
definitions. It supplies the C API only; it does not replace `ManagedMatmul`,
the caller, the observer or either production reader.

Each format gets a fresh, source-external RV64 `p02-tfr` configured tree.
Actual Make stamp targets generate the runtime, SimX backend and application
compiler records. All eight original role records, four per format, pass the
workspace compiler validator. Compiler sentinel programs remain uninvoked while
generating these stamps. No kernel or simulator target is built.

The host compile consumes the original generated host flags, then appends the
host-test `-O1 -g0`, UBSan/no-recovery and pthread options. It links the same four
observer wrappers in their original order. The fake C APIs deliberately replace
`-lvortex` for these host-only executables. This distinction prevents a generated
native-looking configuration record from being mistaken for native execution.

Before compilation, the trusted independent P02 producers reproduce the complete
88-case fixture header byte-for-byte. During each deferred fake launch, the
backend checks every argument byte, both complete input payloads, the output
poison and the prescribed sequence. It copies the selected fixture's existing
expected words into the output buffer; it performs **no matmul arithmetic**.
The actual application then emits its real records, and the unmocked production
`verify_output` checks those records against the independent fixture inputs.

The fake backend writes a separate process-exit audit, allowing the tests to
check native-API call counts and absence of remaining fake devices, modules,
kernels, queues, events and buffers. Those are host instrumentation observations,
not physical reclamation or native concurrency qualification.

## Concrete finding and resolution

**F1, high confidence, static proof plus executed reproduction:** the application's
final `if (!passed || std::fflush(stdout) != 0 || std::ferror(stdout))` skipped
the flush on an already failed run. Its subsequent stderr failure diagnostic,
merged into stdout by the bounded runner, could appear inside a partially
buffered summary JSON record. Default-policy stale-output and undercharged-
allocation cases reproduced a malformed JSON boundary near character 4,074 in
both formats. The native result remained failed; the defect corrupted retained
failure diagnostics rather than permitting an incorrect pass.

The finding was sent to the parent, who changed the production caller to flush
stdout unconditionally and then inspect its saved result. This agent did not
edit production. The final integration run verifies parseable failure records
and an ordered final diagnostic for all injected faults, including both direct
reproductions. The tested caller hash is recorded below.

The first test-development run also exposed two test assumptions, not production
defects: the C API's `VX_ERR_INVALID_VALUE` is numeric 3, and the bounded runner
does not accept an empty argv element. Those test assumptions were corrected.
The pre-fix compiled run reported ten methods, four assertion failures and six
errors in 28.913 seconds: four errors reproduced the JSON flush defect, two
errors came from the empty-argument harness and four assertions expected the
wrong numeric error. An earlier setup-only attempt used a mistyped fixture-helper
filename and ran no test or compiler. None is represented as a passing result.
