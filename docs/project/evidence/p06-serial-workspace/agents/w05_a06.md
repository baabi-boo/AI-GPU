## Recommended API and trust boundary

1. **Retain `load_contract` / `validate_contract` as execution-source
   validators.** They must continue to validate exact manifest structure,
   all original source hashes, independent fixture reproduction, and counter
   definitions. Do not introduce an environment bypass, default permissive
   parameter, source-hash rewrite, exception suppression or special case for
   the three current runtime files.
2. **Add explicitly named historical-analysis APIs.** The root selected
   `load_analysis_contract` / `validate_analysis_contract`. These validate the
   exact unchanged original manifest and an explicit allowlist of current
   trusted analysis inputs. The allowlist must cover the independently
   executed P02/P04 oracle code and the fixtures, graph/profile/ABI/counter
   definitions those producers validate. It is an inclusion list derived
   from actual analysis dependencies, not the old list with three runtime
   paths removed. This mode makes no claim that current runtime bytes match
   historical execution.
3. **Keep complete original execution validation inside replay.** The current
   reader already verifies all retained-source descriptors, all 46 original
   source pins, the retained manifest, manifest raw hash, contract snapshot,
   workloads, loaded-helper identities, and original source revision. Keep
   these checks mandatory. Never import archived Python or run archived
   binaries; the current reviewed reader and independent oracles interpret
   retained data. Preserve trusted-module origin checks and reader-source
   identities in the replay result.
4. **Use authentic original data for strict positive tests.** A shared,
   bounded, data-only helper can materialize exact original source files in
   a temporary test tree after validating archive identity and per-file
   hashes. Stage transitive P04 artifacts and the leaf P02 JSON too. The
   synthetic runner may include current additional helper files, but its
   pinned runtime inputs must come from the frozen reference. No retained
   code may be executed by this helper. Strict native runner rejection of a
   modified runtime must remain an explicit regression.

`RunnerHarness` uses its module-global `ROOT` for paths, source hashing,
generated configuration, compiler-record paths and copied build inputs;
staging only `paths['source']` is insufficient. `PacketHarness` separately
copies a broader source set and patches that global. These two fixtures need
one coherent shared staging interface. This dependency was sent directly to
the assigned test implementer.

## Selected workflow migration

The root selected an explicit historical replay workflow for automatic and
manual runs. It must use current trusted readers, literal independently
accepted archive digests and original source revision, and report
`native_execution=not_run` / no candidate-performance acceptance. Keep source
and data paths in the trigger inventory, permissions read-only, bounded
execution, failure propagation and always-retained logs/results. Add
independent tests for this new route rather than silently rewriting the old
native-workflow expectations to accept arbitrary structure.

The original frozen native experiment remains reproducible by checking out
its exact accepted source and invoking its strict native runner with the
documented resource/tool requirements. Preserve its archived original
workflow bytes as data for historical workflow-contract tests. The new
candidate native workspace, P04 model and P05 Python/framework workflows
continue to exercise current source; none is a new cold-baseline performance
measurement or a proof of P06-A02/A03.

A tempting alternative was a manual job that checks out the old source ref.
A ref change alone would be incorrect: `GITHUB_SHA` would still name the
current controlling workflow, and copying `workflow.yml` from the old source
would misidentify the workflow actually controlling the job. The selected
replay-only route avoids that provenance ambiguity and unnecessary historical
native rebuilding. No historical native workflow result may be relabeled as
a candidate result.

## Required closure evidence

- Prove strict current-source execution rejection before any build/launch,
  and strict positive source validation against the preserved original data.
- Mutate each trusted analysis input and each retained original source pin;
  verify the corresponding analysis or replay check rejects it without
  repairing the input. Cover manifest drift, missing/nonregular/oversized
  files, symlinks, helper origin and modified oracle code.
- Replay both unchanged accepted ZIPs with the current trusted implementation
  and re-run analysis, retaining the reader identities and exact input
  digests. Compare measurement results without changing accepted values.
- Keep all existing runner, source-integrity, records, timing and archive
  rejection coverage; run the full host suite on a clean committed revision.
- Independently review changes to enforcement/routing under the inherited
  review policy, rerun the base classifier and document the actual CI scope.
  The reviewer must not be an author of the corresponding changes.

No F3 is closed by this design receipt. No test was skipped or waived, no
golden value was changed, and no original artifact was modified. Subsequent
implementation and independent validation must establish closure.
