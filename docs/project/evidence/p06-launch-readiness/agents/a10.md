## Implemented cancellation boundary

The dependency CLI now installs a source-local standard-library SIGTERM
handler before parsing arguments. It raises `KeyboardInterrupt` and restores
the preceding handler in `finally`, including parser help/error exits. The
existing bounded command monitor retains its own SIGTERM/SIGINT ownership
while a child is running and restores the enclosing CLI handler afterward.
Only the standard-library `signal` import was added; no project helper,
dynamic project import or explicit historical helper inventory was added.

The boundary is at `main`, the hosted entry point. Direct `Builder.execute`
callers keep their previous signal/threading contract; the new test confirms
that a worker-thread call can still finish a blocked report. A direct library
caller remains responsible for its enclosing SIGTERM policy. A07's direct
`Builder.execute` reproduction bypasses this CLI boundary; the new regressions
exercise the actual CLI factory, parser and execution method.

Final stability, record inventory and retained-file inventory now handle a
first `KeyboardInterrupt` through the existing failure mechanism, preserving
the first failure reason and continuing report closeout. Inert receipt
verification also handles interruption, revokes a provisional fresh-build
pass and writes the failed report. No command start, cleanup or exit field is
inferred from cancellation. A04's explicit prelaunch classification and A07's
conservative unknown-launch classification remain intact.

## Persistence and interruption limits

The final report write itself remains a persistence boundary. A separate
10-second subprocess probe sent the first SIGTERM from the final checkpoint's
`fsync` boundary, after the shared atomic writer had created and flushed its
exclusive temporary file. The CLI exited `-2`; the retained `report.json`
remained `state=running`, `outcome=blocked`, with no commands and the fresh
flag false. `report.json.tmp` contained `state=finished`, `outcome=blocked` and
the original `source observation stopped` failure. A finished report was not
claimed. The existing writer guard rejects a running dependency report.

No retry loop, removal of a possibly pre-existing temporary, persistence
fallback or success promotion was added. An interruption or I/O error during
the final write can prevent durable closeout; this change does not promise
otherwise. SIGKILL, process loss, and a second interruption during error
handling, report persistence or handler restoration can likewise prevent
closeout. In particular, interruption while rewriting a provisional success
cannot guarantee that the failed replacement reaches storage. The enclosing
process still fails; retained evidence must be judged by its actual state.
