## F2 — a known unstarted dependency command blocks partial retention

**Confidence: high. Evidence: static-proof plus bounded fault reproduction.**

`ci/project/p06_dependency_build.py:287–299` (`Builder.command`) appends a
command with `process_started=None`, then calls `self.save()` before entering
`run_bounded`. If this checkpoint raises `OSError` or `KeyboardInterrupt`, the
command cannot have launched, but its unknown disposition is never repaired.
`Builder.execute` catches these exceptions at lines 502–503 and finishes the
report at lines 515–517, retaining the unknown command.

The production integration consequence is in
`ci/project/p06_qualified_warm_hosted.py:474–479`: `writers_finished` rejects
that child command even after the dependency process and supervisor have
finished with complete outer cleanup. Its result blocks both partial packaging
(line 633) and encryption (line 650). The already retained preparation,
dependency and command originals therefore receive no encrypted delivery.
The native population need not have started for this failure to occur.

This is outside the two prelaunch-checkpoint corrections already made in
`p06_qualified_warm_run.py` and `p06_qualified_warm_inputs.py`.

### Minimal reproduction

From the source root, use
`PYTHONDONTWRITEBYTECODE=1 TMPDIR=/tmp/ai-gpu-c36968d78f0b python3`:

```python
import sys
from pathlib import Path
from unittest import mock
sys.path.insert(0, "ci/project")
import p06_dependency_build as build

b = build.Builder.__new__(build.Builder)
b.report = {"commands": [], "failures": [], "reason": None,
            "outcome": "blocked", "fresh_dependency_build_passed": False}
b.environment = {}
b.output = Path("/unused/output")
b.source = Path("/unused/source")
b.workspace = Path("/unused/workspace")
with mock.patch.object(b, "stable"), \
     mock.patch.object(b, "save", side_effect=OSError("checkpoint")), \
     mock.patch.object(build, "run_bounded") as launch:
    try:
        b.command("softfloat", ["never-executed"], Path("/unused"))
    except OSError as error:
        b.fail(error, "execution")
    assert launch.call_count == 0
    assert b.report["commands"][0]["process_started"] is None
```

Executed this boundary with both `OSError` and `KeyboardInterrupt`: zero
monitor calls, unknown command start, outcome `blocked` in both cases.
A temporary finished supervisor/child receipt fixture passed that exact command
to production `hosted.writers_finished`: **false**. Changing only the known
unstarted row to `process_started=False, cleanup_complete=True` made it
**true**, for both exception types. No subprocess, compiler or native process
was launched by these probes.

### Boundary required of a correction

Repair only the checkpoint before entering `run_bounded`, preserving the
original exception. An additional control injected the same two exceptions
from an entered monitor: one monitor call, `process_started=None`, and
`writers_finished=False`. That unresolved disposition must remain unknown;
monitor entry does not prove a child never launched. `Builder.fail:241` also
currently classifies that unknown case as `blocked` because it uses truthiness
of `process_started`; distinguish it from a known unstarted command when
reviewing outcome semantics. Arbitrary `BaseException` is not in the
`Builder.execute` catch tuple; `KeyboardInterrupt` is.
