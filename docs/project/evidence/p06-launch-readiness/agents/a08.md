# A08 — Managed failure classification and independent checkpoint review

## Scope and result

Base: `e3ad6bd1e2b002aa234d57cd8a02519cec915830`; checks exercised the
uncommitted shared worktree with the checked CPython 3.12.14 / Linux environment.
Only the report-level failure predicate in
`ci/project/p06_managed_preflight_execute.py`, the new
`ci/project/test_p06_managed_failure_state.py`, and this report were changed by
A08. A05's checkpoint change and test file were reviewed independently and
preserved.

**F2, high confidence, reproduced and fixed:** `failure()` used truthiness for
`process_started`. If the first command's monitor raised before returning its
receipt, the command retained `process_started=None` but the overall report
became `blocked`. An omitted start observation had the same result. There was
no reliable nonstart receipt to support that disposition.

The predicate now uses `row.get("process_started") is not False`, matching the
outer qualified-warm supervisor. No commands, or only explicit `False`
observations, remain `blocked`; a confirmed or unresolved start produces `fail`.
The new regression suite exercises three lost-receipt exception types, a
missing start observation, and empty/nonstart/confirmed-start controls. The
`native_execution_state()` function and the command/native accounting are
unchanged. A failed ordinary tool command can correctly have report outcome
`fail` while native execution remains `not_run`.

## Separate cancellation findings; no signal change here

**F2, high confidence, static proof plus host reproduction:** the standalone
managed CLI `main()` has no outer SIGTERM translation. Only
`baseline_process.run_bounded()` installs SIGINT/SIGTERM handlers, and restores
them before returning. A SIGTERM during managed work outside that monitor
therefore terminates the interpreter without the managed final report.

Two fork-isolated Python probes used `ManagedHarness`, reset the child SIGTERM
handler to `SIG_DFL`, patched `base.resolve_paths` to fixture paths, and invoked
the actual managed `main()`. A `_write_json` hook sent the child a real SIGTERM
(1) immediately after retaining the initial report, or (2) before writing the
first native command's confirmed receipt. Both children exited with signal 15:

| Signal point | Last saved state | Native disposition | Commands | Last start | Failures |
|---|---|---|---:|---|---:|
| Initial checkpoint, executor line 440 | `running` | `not_run` | 0 | no command | 0 |
| Receipt checkpoint, executor line 422 | `running` | `unknown` | 20 | `None` | 0 |

The exact separate boundary is the undecorated managed `main()` at line 866,
with the initial checkpoint also outside the main `execute()` try. This is not
a defect introduced by A05 or A08. A09 is reviewing the qualified-warm CLI
wrapper separately; that does not itself change standalone managed CLI entry.

**F2, high confidence, reproduced:** a first `KeyboardInterrupt` during managed
finalization can also escape before the final checkpoint. The final resource
observation at lines 810–815 catches only `OSError`, `ValueError`, and
`RuntimeError`. A fixture `mutate_resources(count, value)` callback that raises
`KeyboardInterrupt()` when `count == 2` reproduces this after the four synthetic
processes complete. The exception escapes `execute()`, leaving the saved report
`state=running`, `native_execution=run`, four process rows marked `pass`, and
zero failure entries. Other finalization boundaries similarly omit
`KeyboardInterrupt`. Extending cancellation coverage requires its own review;
this patch does not change that contract or claim complete cancellation safety.
