## Change and boundary

`ci/project/p06_dependency_build.py` now catches the existing execution-handled
exception classes around only the checkpoint immediately before `run_bounded`.
It records the proven disposition `process_started=False`,
`cleanup_complete=True`, `outcome=blocked`, and the original error reason, then
re-raises the same exception. An empty interrupt reason becomes `interrupted`.

The compiler cannot start before that checkpoint returns. The previous unknown
row prevented the hosted writer guard from authorizing partial retention even
after all outer processes had finished. This correction repairs that producer
record; it does not relax the hosted guard. An exception from inside the
launcher still leaves start and cleanup unresolved. A checkpoint failure after
a returned monitor result preserves that result without reinterpretation.
The adjacent `Builder.fail` outcome classification is unchanged and is reserved
for separate review.

Added `ci/project/test_p06_dependency_launch_failures.py`: three tests with six
`OSError`/`KeyboardInterrupt` subtests. They verify the original exception,
zero launches before a failed checkpoint, actual local Python child completion,
unchanged raw log bytes, and production `hosted.writers_finished` decisions.
The launcher-exception control throws after a real local child finishes but
before its monitor result reaches the builder; retained log bytes cannot prove
cleanup to the caller. No compiler or GPU process is used by these new tests.
