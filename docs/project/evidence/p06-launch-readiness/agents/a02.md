## F2 — the native stage reuses capacity observed before provisioning and acquisition

**Location:** `ci/project/p06_qualified_warm_hosted.py:584–605`.

The only `capacity_gate` call runs before host provisioning, control intake and input acquisition. After acquisition succeeds, execution directly starts `native-supervisor`. The gate's observation can therefore be stale by the time that stage is admitted. The later supervisor (`p06_qualified_warm_run.py:439–443`) rechecks host `MemAvailable`, while `baseline_process.py:158–165,250–261` checks disk and process-group RSS. Neither repeats the finite ancestor headroom observation.

**Reachable scenario:** a visible cgroup parent has `memory.max=8 GiB` and `memory.current=1 GiB` at initial admission. While provisioning/acquisition runs, another descendant retains 4 GiB, leaving that parent's current usage at 5 GiB. Host `MemAvailable` still exceeds 4 GiB, and disk remains above 15 GiB. Membership, mount mapping, hard limits and identities do not change. A fresh bounded observation now reports a complete, stable 3 GiB visible margin and `known_memory_shortfall=true`; the current hosted composition nevertheless starts the native supervisor.

This scenario follows the [Linux 6.8 cgroup-v2 memory interface](https://docs.kernel.org/6.8/admin-guide/cgroup-v2.html#memory-interface-files): a parent's `memory.current` includes descendant memory. The reproduction injects those two snapshots and replaces every child with the existing inert hosted fixture; it does not claim a live hosted failure.

**Distinction from documented limitations:** the defect is omission of a new admission observation at an explicit later stage boundary. Fixing it does not promise atomic snapshots, resource reservation, continuous monitoring, complete ancestry or immunity to changes after the new observation.

```python
import contextlib
import json
from pathlib import Path
import sys
import tempfile
from unittest import mock

sys.dont_write_bytecode = True
sys.path.insert(0, '/workspace/scratch/c36968d78f0b/AI-GPU/ci/project')
import p06_qualified_warm_hosted as hosted
from test_p06_qualified_warm_hosted import HostedCompositionTests
from test_p06_qualified_warm_capacity import Fixture, GIB

tempfile.tempdir = '/tmp/ai-gpu-c36968d78f0b/a02'
real_gate = hosted.capacity_gate
real_observe = hosted.capacity.observe_capacity
f = Fixture().root_layout()
f.scalar(1, 'memory.max', 8 * GIB)
f.scalar(1, 'memory.current', GIB)
case = HostedCompositionTests()
case.setUp()
check = {}

def command(argv, *args, **kwargs):
    module = Path(argv[2]).stem if len(argv) > 2 and argv[1] == '-B' else ''
    if module == 'p06_qualified_warm_run':
        current = real_observe(f.read, clock=lambda: 0)
        check['at_native_supervisor'] = {k: current[k] for k in ('observation_complete', 'known_memory_shortfall', 'visible_headroom_bytes', 'host_available_bytes')}
    result = case.command(argv, *args, **kwargs)
    if module == 'p06_qualified_warm_inputs':
        # A sibling's retained 4 GiB allocation changes an already-observed finite parent.
        # All kernel paths, hard limits, identities and host MemAvailable remain stable.
        f.scalar(1, 'memory.current', 5 * GIB)
    return result

try:
    with mock.patch.object(hosted, 'capacity_gate', wraps=real_gate) as gate, \
            mock.patch.object(hosted.capacity, 'observe_capacity', side_effect=lambda: real_observe(f.read, clock=lambda: 0)), \
            mock.patch.object(hosted.shutil, 'disk_usage', return_value=mock.Mock(free=20 * GIB)), \
            mock.patch.object(hosted, 'run_bounded', side_effect=command):
        result = case.execute()
    retained = json.loads((case.attempt/'hosted/capacity.json').read_text())
    check.update(initial_gate_satisfied=retained['gate_satisfied'], capacity_gate_calls=gate.call_count,
                 native_supervisor_started=any(r['module']=='p06_qualified_warm_run' for r in case.calls),
                 synthetic_hosted_outcome=result['outcome'])
    print(json.dumps(check, sort_keys=True))
finally:
    case.doCleanups()
```

### Narrow implementation direction

Immediately after validating acquisition and before `stage("native-supervisor", ...)`, call the unchanged `capacity_gate` again, retain its full result in a distinct private hosted receipt, and require its `gate_satisfied`. Preserve the initial receipt and permit the existing partial encrypted closeout after a final prelaunch rejection. Do not change the observer's unknown/effective-capacity semantics or add a bypass.

Regression coverage should exercise good initial capacity followed by: a known parent shortfall; an incomplete final observation; a disk shortfall; and a still-valid final observation. Check that failure prevents the supervisor invocation while retaining both observations and partial closeout. Check threshold equality at 4 GiB/15 GiB remains accepted by the same existing predicate. This task does not propose continuous monitoring or broader stage/resource policy changes.
