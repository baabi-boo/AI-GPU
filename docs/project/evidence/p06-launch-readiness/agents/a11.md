## Change

The first checkpoint now runs inside the existing protected execution body.
Its interruption follows the existing execution failure path, performs the
remaining final checks, and persists a finished blocked report with no commands
and zero completed counts when final persistence succeeds.

Eight existing per-operation finalization exception boundaries now also handle
`KeyboardInterrupt`: active-build retention; final source, tool and dependency
observations; frozen build identities; dependency admission; counter
qualification admission; original-log verification; retained evidence; and
resources. Each interrupted operation records its existing stage through
`failure()` and advances to the next final check. There is no operation retry,
replacement native process, new import, or weakened success predicate.

Completed process observations and native execution disposition remain intact.
After completed synthetic native work, an interrupted final check produces
`state=finished`, `outcome=fail`, `native_execution=run`, and unchanged complete
counts. `native_preflight_passed` and all historical qualification, readiness,
performance and acceptance claims are false. The existing dependent success
fields still derive from the false native result. An interrupted retained-file
hash does not set `retained_files_stable=true`.

Final report persistence remains outside these recovery catches. If that write
raises, `execute()` propagates the error instead of returning success or
claiming a finished report was retained. The control interrupts a failed
report's final write before persistence, verifies exactly one attempted final
write, and observes the previous running checkpoint. `SystemExit` also remains
uncaught. This is bounded interruption coverage for the identified execution
and observation operations, not a guarantee against arbitrary interruption
during setup, failure recording, bookkeeping, or final persistence.

The standalone managed CLI's default SIGTERM behavior is unchanged. These
tests inject `KeyboardInterrupt` directly; they do not claim real signal
handling. A09 owns the separate qualified-warm CLI SIGTERM translation.

execution, real file hashing and report persistence, with synthetic external
tools and native outputs. Eight methods execute nine fixture scenarios:

1. Initial checkpoint interruption before and after its write; no command runs.
2. Initial resource interruption; final resource observation remains possible.
3. Final resources interrupted after all four synthetic native observations.
4. Final source snapshot write interrupted; later observations still finish.
5. First final original-log hash interrupted; its receipt remains intact and
   the other logs are verified.
6. Final retained-file hash interrupted; stability is not claimed and the
   retained identity list remains available.
7. Final report persistence interrupted; the exception propagates with no
   retry or returned finished-report claim.
8. Finalization receives `SystemExit`; cancellation still propagates.
