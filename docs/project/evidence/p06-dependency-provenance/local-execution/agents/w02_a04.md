# W02 A04 — explicit local execution orchestrator

## Implementation

Owned and added only `ci/project/p06_dependency_local_execute.py` and
`ci/project/test_p06_dependency_local_execute.py` in `/workspace/ai-gpu-next`.

The runner executes five existing producers in separate Python subprocesses:
local preparation, the fresh dependency build, the four-process native lifetime
population, the pending-read probe, and the alternate-dependency control. It
does not import child producer modules, preserving each child's helper inventory.

The separately versioned `p06-local-dependency-execution-v1` envelope is written
to `evidence/local-execution.json`. It identifies an explicitly local origin,
requires a fresh workspace and clean exact source revision, records the pinned
CPython identity, and retains bounded child command/log observations, copied
orchestrator source, five original report identities, and the native source
snapshot identity. The actual completed dependency report digest is passed to
each downstream stage. The same selected host-tool directory is passed where
the child APIs accept it.

The runner checks each child's reported scope and successful terminal JSON,
preserves failures and stops at the first unexpected failure. A monitor exception
after native launch selection retains an unknown execution state. Final source,
interpreter and original-report checks prevent a later mutation being labelled
successful. All seven qualification, warm and acceptance claims remain false.

The public pure helpers `stage_specs`, `clean_environment`, and `report_terminal`
give the separate local reader an exact command/environment/terminal grammar.
The original child configure/build/process timeouts remain 120/1800/180 seconds,
with two build jobs, one simulation worker, 15 GiB disk reserve, 4 GiB process
RSS and 16 MiB logs. A shared 5400-second deadline bounds the complete route.
