## Static archive and semantic-boundary checks

The local public entry validates all external pins and freezes current reader
identities before intake. It owns one `ArchiveReader` for all four subpackets,
checks the local envelope before the native graph, and returns only after the
context's final original-ZIP rehash and current-reader-source stability check.

The reviewed immutable archive helper bounds the input ZIP at 256 MiB, central
directory at 32 MiB, member count at 20,000, individual members at 256 MiB,
declared expanded data at 1 GiB, cumulative reads at 2 GiB and read attempts at
100,000. It rejects noncanonical paths, symlink/special members, duplicate or
shadowing names, encrypted or unsupported compression, unsupported ZIP64 and
multidisk structures. Read costs are charged before decompression, including
failed reads. Each read checks stability; close rehashes the original.

The dependency layer additionally requires its externally pinned receipt,
exact retained inventory, 16 MiB JSON bound, 64 MiB file bound, 1 GiB packet
bound and bounded cached reads. Its real semantic validator receives a packet
read callback, and uses producer paths only as syntactic identities and graph
keys. The local preparation and toolchain metadata validators use
`PurePosixPath`/string relationships rather than producer filesystem access.
The separate-control readers similarly receive archive views and compare
retained source against the trusted native source inventory.

The existing independent wave-three tests already exercised closing archive
mutation and terminal/extra-member rejection. This review inspected those
boundaries and did not rerun them as an additional claimed result.
