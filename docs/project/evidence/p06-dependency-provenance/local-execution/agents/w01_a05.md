## Evidence and reason

Its Clang 20.1.8 alternative failed `format.h:4168` with `-Wdeprecated-literal-operator` under `-Werror`. GCC `12.2.0-14+deb12u1` passed separate direct/alias compatibility probes without removing warnings. The compiler-recovery-v2 evidence bundle preserves those distinct outcomes and explicitly does not retain the actual extracted compiler binaries/packages.
- The current host reports `g++ (Debian 14.2.0-19) 14.2.0`.
- The retained `b4127b19` original ZIP, `native-lifetime/snapshots/tools-before.json` and `logs/version-gpp.log`, used `/usr/bin/g++` resolving to GCC **11.4.0**, not GCC14. Therefore its native success does not establish compatibility with this host compiler.
- `sim/simx/Makefile:19–26` uses `-std=c++17 -Wall -Wextra -Wfatal-errors -Werror`, and includes Ramulator/spdlog through `-I`. `sim/common/dram_sim.cpp` includes Ramulator headers; its local warning guards do not suppress dangling-reference or literal-operator warnings.
- In contrast, `ci/project/p06_dependency_build.py:157–159` compiles the GDDR6 extension with `-std=c++20 -O3 -DNDEBUG -fPIC` and `-isystem` dependency includes. The 413-operation fresh host diagnostic therefore does not exercise the strict model compilation condition.

## Exact grammar and shared tool selection

The native graph is intentionally constrained. `p06_managed_preflight_build.py:209–297` requires 43 model translation units and two links, including the exact observed model stamp, object paths, libraries and optional dependency map. `p06_managed_preflight_application_build.py:113–216` reconstructs exactly 30 commands and the 14-source runtime-stub compile/link. Host compiler replacement is admissible because the compiler is a selected tool identity; warning/ABI/configuration changes are not a substitute for compatibility.

**Select the same compiler before both dependency and managed builds.** `p06_dependency_admission.Admission.verify_stable()` compares shared selected tools by their complete identities, including invoked paths. Building dependencies with default GCC14 and switching only the native runner to a GCC12 `--host-bin` will be rejected. Even alternate aliases to the same executable must have consistent invoked paths. The local preparation/build interface must propagate one reviewed host tool selection through all stages. Existing `p02_matrix.clean_environment()` admits an explicit `host_bin`; the dependency producer currently does not.

CMake also must be available in the dependency producer's sanitized PATH. Existing `/workspace/p06-build-tools/cmake/data/bin/cmake` is outside it. Do not solve this with an unrecorded environment override that replay cannot reproduce.
