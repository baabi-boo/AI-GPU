The new local replay bridge added in this continuation used the same broad
guard and had the same reachable failure, although it was absent from the

### Narrow test correction

The three bridges share `inert_path_guards`. Its allowed source files come from
the **current trusted reader inventory**, the reader's fixed independent
fixture corpus, and the pinned archive-helper path. Packet-controlled paths
cannot extend the set. The guard also permits the one caller-selected input
ZIP; this is necessary when `TMPDIR` itself lies under `/home/runner`.

All these exceptions permit reading or path resolution only. Every other
producer-prefixed path remains rejected, including source siblings, tools,
build products, unknown runner paths, and synthetic producer paths. Every
write mode remains rejected, including writes to allowed source files and the
input ZIP. The existing subprocess, extraction and live-producer-reader
guards remain, as do the complete native/control/local semantic checks.

Four permanent guard regressions cover the exact trusted source exception,
nonallowlisted producer paths, all write modes, and the exact caller-selected
ZIP exception with sibling rejection. This corrects the test's trust-boundary
model; it does not remove a failing test or relax any production admission.

The helper's documentation explicitly states the unavoidable collision limit:
when a historical producer source pathname equals a current trusted reader
pathname, a pathname guard alone cannot establish which origin was intended.
The independent pinned-source checks, complete semantic replay and execution
guards remain necessary. No stronger path-origin claim is made.

## Finding 2: restored tools precede the hosted clean-source check

**F2 / high confidence / static proof, original partial observation and an
executed real-Git reproduction.**

The original Fresh Dependency Provenance run
[45162083701](https://github.com/baabi-boo/AI-GPU/actions/runs/45162083701),
job `137675967270`, used source
`19333193192ba5a2d3667c0111235ec9e21a5898`. Its failed artifact is
`14816484128`, SHA-256
`6c130c17cc944f633f04835dbad6fd512880e6d987f477b01c48d32d4dd68472`,
**9,225 bytes**. I downloaded it, verified the exact provider digest, checked
ZIP CRCs and read all six member identities. The artifact remains unchanged.

The workflow log records restoration of a **1,329,572,912-byte** cache into
`source/tools`. The original preparation receipt is blocked before any
acquisition command. Its `source_before` has a revision and tree, but
`dirty=null`, empty pins and submodule fields, and the generic source-identity
blocker. This locates the observed failure at the Git-status stage, before its
status rows were parsed. The dependency, native and control steps did not run.

The source `.gitignore` does not ignore `/tools`. The preparation producer
calls `collect_source(source)` before relocating the restored tools outside
the checkout. The collector runs `git status --untracked-files=all`; its
bounded probe rejects output beyond **65,536 bytes**. A small restored tree
therefore makes the source dirty; a sufficiently large tree exhausts that
status-output bound before the dirty flag is set. Either case prevents the
hosted preparation path from reaching its later relocation.

A real isolated Git repository, with the current ignore rules and source
inputs, reproduced both branches without downloading or executing any tool:

| Isolated state | Observation |
| --- | --- |
| Clean initial checkout | Source collection passes |
| One untracked file in `tools` | Dirty-source blocker |
| 5,001 files in `tools` | 190,018 status bytes; same generic blocker and `dirty=null` |
| Same tools tree relocated outside source | Source collection passes and equals the initial clean observation |

The original hosted receipt does **not** retain complete Git-status stdout or
stderr. Therefore, the exact provider subprocess exception is not directly
observed; attribution to the large untracked cache is a high-confidence
inference supported by the observed failure stage, the source ordering defect
and the real-Git reproduction. This distinction is retained in the JSON.

The fix must preserve the strict collector and validate/relocate only the
selected untracked toolchain before the clean-source snapshot. It must still
reject tracked tools, symlinks, dirty non-tool sources, wrong cache identities
and resource failures. Those implementation and regression obligations were
handed to `w09_a01` rather than modified in this agent's test-only patch.
