## Independent fixture and numerical checks

The caller selects exactly `fp16-single-dense_boundaries` and
`bf16-single-dense_boundaries` from the frozen P02 fixture header. Both have
8×4×8 geometry, 32 packed A words, 16 packed B words and 32 FP32 result words.
The host requires the matching format and these exact sizes before execution.

The independent script decoded each packed FP16/BF16 input using explicit sign,
exponent and fraction arithmetic. All selected input values are exact integers.
It computed each dot product directly from row-major A and column-major B and
constructed each exact FP32 result encoding without calling a production
arithmetic model or repository fixture producer. All 32 results per format
agree with the committed layout fixture and the C++ `kA6`/`kB6`/`kExpected6`
and `kA16`/`kB16`/`kExpected16` arrays.

The real host path compares every returned raw word with `fixture->expected`,
rejects a different result length or any mismatch, and records every actual
word. The warm transcript reader independently requires exactly 32 lowercase
FP32 words for every operation and compares the full list with the independently
selected fixture. No numerical tolerance or favorable prefix is admitted.

The kernel statically requires an 8×4×8 tensor tile and 64-bit pointers. It
validates the encoded arguments and launch geometry, initializes the accumulator
to zero, invokes the native tensor `mma_sync` path and stores the complete tile.
This selected workload is an exact-integer dense layout fixture; its result
does not replace the broader floating-point edge-case evidence from P02.

## Ownership, lifecycle and reset checks

The unchanged caller requires successful submit, wait and explicit operation
close before the next submission. It alternates the complete output poison
between `0xdeadbeef` and `0x7fc0dead`, verifies three writes, one launch, one
read, one wait and zero timed-out waits, and rejects overlapping or unaligned
buffer regions. The selected payload is 128 + 64 + 128 = 320 bytes.

`per_operation` requires three creates and releases per operation, or 99 of
each by final close. `reusable_single_tile` requires three allocations in total,
unchanged device addresses across all 33 operations and release of all three
at owner close. Both require one device release and restored memory observations.

The lifetime wrapper observes the real owned processor before and after each
`run_checked()` call. It checks zero pending reads and quiescence before the
reset-bearing call, so a reset cannot erase a bad pending balance and make that
call pass. The real call returns void; its recorded completion/exception fields,
not a fabricated integer return value or architectural `gp` value, establish
successful return.

The reader requires exactly 33 ordered run pairs. For run j it requires reset
generations R+j−1 and R+j, exact preceding-state and flush-state joins, unchanged
host-read/flush counts across the call, and matching prime/final snapshot states.
The four snapshot reset offsets are exactly `[0, 1, 33, 33]`. R+33 must fit in
64 bits. Every MPM and flush supplement is sequence-bound and has zero pending
reads on both sides. The final snapshot, pre-destructor state and completed
destruction observations must agree; teardown may clear the platform clock but
must not manufacture another reset or inspect destroyed processor storage.
