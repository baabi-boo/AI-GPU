# W01 A06 — independent design audit of a truthful local execution route

## Scope and finding

Read-only design audit against `/workspace/ai-gpu-next`, initially `849469e1111870fbcfe0346afd33b284a5a1edd8`. Read the repository agent rules and inspected preparation, dependency receipt, native/control replay and their fixtures. No production files changed, builds or GPU tests ran, acceptance advanced, commit made or push attempted.

The proposed local route is reasonable **only as a separately identified execution origin**. Reuse the existing semantic validators; preserve the hosted entry points and their genuine GitHub metadata requirements. A local receipt establishes consistency of a named local original, not authenticated origin or a GitHub CI result.

## Minimal architecture

1. **Separate local preparation contract and producer.** Prefer a new `p06-local-dependency-preparation-v1` producer rather than adding an optional bypass to hosted preparation. Its explicit inputs are a source revision, exact immutable prebuilt lock, archive root and a fresh owned workspace. Verify archive part sizes, SHA-256 and the reviewed Git identities before extraction; record the exact selected bundle set and extraction results. Join extracted tool identities to native tool inventory. Never manufacture a cache-key field or infer restored-cache provenance from matching binary bytes. Use the existing 15 GiB/4 GiB/two-job constraints.
2. **Strict explicit admission.** `p06_dependency_receipt.py:722–728` currently accepts only preparation contract `p06-dependency-preparation-v1`; `p06_dependency_build.py:425–430` accepts a smaller property subset. Add an explicit independently reviewed local-contract validator at both boundaries. Reject unknown contracts, missing/extra claim fields, wrong source or lock, malformed acquisition inventories and nonfresh products. A passing flag alone is insufficient. Keep old hosted validation behavior unchanged.
3. **Child-process orchestration.** Run preparation, build, managed lifetime, pending-read probe and substitution producers in separate Python processes, preserving their exact helper inventories. Record sanitized argv/cwd/environment identities, actual starts/exits, bounded logs, start/finish times and failures. Stop on the first unexpected failure and retain it. Never re-label a repaired second attempt as the first original. The expected intentionally failing zero/provenance controls stay separately scoped.
4. **Separate local outer envelope.** Use an exact-schema `local-execution.json` containing a versioned contract, local origin, source revision, execution identifier, interpreter identity, observed resources, stage descriptors and terminal result descriptors. Reject GitHub-origin fields and all qualification/warm/performance/phase claims. A random execution identifier prevents accidental collision; it is not authentication. Require caller-pinned envelope/report/archive/source hashes, not pins supplied only by that same envelope.
5. **Thin inert local replay.** Open one externally pinned bounded `ArchiveReader`; make all subviews from that reader. Call native `verify_view()` and both control-view functions, then validate the local envelope and retained terminal records. Retain the closing archive integrity check and reader-source stability check. Do not extract archives, execute retained code, resolve producer paths or import helper code from the packet.

## Exact reusable surfaces

- `p06_dependency_native_replay.py:719–753`: `verify_view()` independently reconstructs dependency semantics, then joins native records. It requires external source/report/receipt pins and returns an inert reconstruction context.
- `p06_dependency_control_replay.py:201`: `verify_probe_view()` checks the separately counted pending/zero control.
- `p06_dependency_control_replay.py:360`: `verify_substitution_view()` checks the fresh alternate-library control.
- `p06_dependency_control_replay.py:448–510`: existing hosted archive wrapper demonstrates ordering, terminal-output joins and one-reader composition. Copy only orchestration concepts; do not invoke or loosen `_hosted_identity()` for local origin.
- `p06_dependency_native_replay.py:653–716`: hosted job, workflow, provision and terminal joins remain mandatory for the hosted API.

The local wrapper must join source revision, preparation descriptor, interpreter, budgets, stage order, report digests and terminal stdout to actual subpackets. Merely accepting `origin=local` and `outcome=pass` would introduce an evidence bypass.

## Required focused tests

| Boundary | Meaningful positive/negative checks |
| --- | --- |
| Immutable tool acquisition | Exact reviewed parts pass; changed bytes/size/blob, missing or duplicate part, wrong commit, mutable-tag-only selection and unsupported component set reject. |
| Extraction and source freshness | Fresh bounded target passes; pre-existing binaries/CMake cache, path escape, unsafe link, extra product, changed source tree or post-freeze input reject. Preserve originals on failures. |
| Preparation admission | Actual local-contract schema passes; old hosted receipt stays accepted under its existing rule; unknown contract, fake hosted-cache field, missing lock and forged success flags reject. |
| Local identity | Valid explicit local envelope passes; missing/extra fields, GitHub fields, wrong source/interpreter, altered preparation or terminal result, duplicate/reordered stages and bad timestamps reject. |
| External intake pins | Every archive/report/source/control/envelope pin is required before semantic work; rehashing internal descriptors cannot defeat an unchanged external expectation. |
| Native/control obligations | Retain all four processes/132 launches/4,224 words, separate control populations, complete model/application graph and actual loaded-library checks. Missing controls or changed counts reject. |
| Inert replay | Patch subprocess, shell, runpy, extraction and producer-path open/resolve to fail; replay still passes the synthetic envelope fixture after producer paths are removed. |
| Hosted isolation | Existing hosted positive/negative tests remain passing; a local packet must fail the hosted public API and a hosted packet must not silently become local. |
| Real original | Independently replay the actual fresh build/native/control original with no semantic mocks; reconcile its raw receipts and provenance before reporting the result. |

## Fixture limitation and review requirement

`test_p06_dependency_native_replay.py` and `test_p06_dependency_control_replay.py` deliberately create synthetic native/control observations. Their public ZIP tests stub `dependency_replay.verify_view()` while running real native/control semantics. They are suitable for local-envelope regression tests with that limitation declared; they do **not** establish a complete fresh source/build/native chain. Keep a separate focused test for the real local preparation validator and retain an actual unmocked original for evidence.

This is an R3 trust/admission contract change requiring an independent review of changed hunks and negative cases. It does not change the project roadmap statuses, numerical tolerances, counter qualification obligations, physical hardware requirements or any golden baseline.
