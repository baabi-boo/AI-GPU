# W02 A01 — local immutable prebuilt provisioning

## Implemented scope

Owned only `ci/project/p06_local_toolchain.py` and
`ci/project/test_p06_local_toolchain.py` in `/workspace/ai-gpu-next`.

The new `p06-local-toolchain-provision-v1` contract provides
`provision(archive_root, tools_root)` and an inert
`validate_receipt(document)` API. It selects the four SimX components from the
existing reviewed full `p01_toolchain.lock.json` and verifies the full manifest
semantic identity before selecting the 15 native archive parts. The production
selection is 606,992,434 compressed bytes at historical immutable commit
`e3db4bcdf819a17f618ad9fc2472f8f7dea3192b`; it does not claim current-tag resolution,
GitHub cache restoration, native execution, or acceptance.

The producer verifies every selected part's size, SHA-256 and Git blob SHA-1
before creating its fresh output directory. It verifies those bytes again while
streaming the split archives into Python's tar reader. It applies the standard
tar data filter plus exact component/path/type checks, defers links until regular
files are written, rejects replacement outputs, escaping/cyclic links, devices,
duplicates and excessive input. Eleven selected native compiler/library
identities are joined to the archive member inventory and the actual installed
file bytes. Compiler executability is checked without running a compiler.

Bounds remain explicit: a 15 GiB free-disk reserve, 4 GiB initial available RAM,
4 GiB expanded regular bytes, 1 GiB per regular member, 50,000 archive members,
1 MiB data chunks and 1,800 seconds. Failures leave the owned partial output for
the caller to retain; no user data or original archives are deleted.

The metadata validator validates exact schemas, the immutable selection,
inventory totals/order, member hierarchy/link resolution and all eleven
native identities. It reads only the current trusted lock; it does not open or
resolve producer paths. Its result explicitly records
`archive_bytes_rehashed=false`, `installed_bytes_rehashed=false`,
`native_execution="not_run"`, and `retained_code_executed=false`. A retained
consistent receipt is not an authenticated original or a repeat extraction.

## Validation

Command from source root:

```sh
python3 -m unittest discover -s ci/project -p 'test_p06_local_toolchain.py' -v
```

**20 tests passed in 0.132 seconds**, with no skips. Tests use explicitly
synthetic locked tiny archives for extraction behavior, and one test verifies
the actual reviewed production lock and exact native part/byte counts. They
cover streamed byte joins, symlink/hardlink behavior, archive hash/blob/size
changes, fresh output admission, disk/RAM/member/byte bounds, path traversal,
escaping links, FIFO rejection, cycles, duplicate members, missing and
nonexecutable native tools, hierarchy inconsistencies, receipt mutations and
metadata validation after both producer directories are deleted.

No full production extraction, compiler/native execution, commit or push was
performed by this assignment. Actual archive compatibility and independent
review remain necessary before the local route is used for a formal original.

## Integration notes

`provision()` returns its embedded receipt directly; `tools_root` names the
fresh installation directory, and `tools` uses the existing native identity
shape `{path, resolved_path, sha256, size_bytes}` for the eleven non-host inputs.
The local preparation producer can embed this receipt as `toolchain_receipt`.
The native envelope must compare these identities to the actual native tool
inventory. Include `ci/project/p01_toolchain.lock.json` in the frozen source
inventory, as the parent intends. Existing hosted preparation/replay semantics
were not edited by this assignment.
