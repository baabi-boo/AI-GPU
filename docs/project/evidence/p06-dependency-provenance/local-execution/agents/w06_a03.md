## Source path from memory traffic to the public accessor

The processor owns `perf_mem_pending_reads_`, initialized to zero. In
`sim/simx/processor.cpp`, each memory-request transmit callback increments it
only for a read; each memory-response transmit callback decrements it.
`sim/simx/mem/memory.cpp` completes writes without emitting a `MemRsp`, while
read completions emit the response that reaches the decrement callback. The
processor reset clears this pending balance.

`Processor::pending_mem_reads() const` delegates to the const implementation
getter in `processor_impl.h`, which returns that owned counter. The read does
not tick, reset, flush, route work or modify the balance. Under the required
checked-counter build, `sim/common/perf_counter.h` checks addition and
subtraction before mutation and throws on overflow or underflow. That checked
arithmetic does not itself prove an absolute lifetime or no-wrap bound.
