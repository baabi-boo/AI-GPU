The orchestrator does not import and invoke those producer stages in its own process, preserving their loaded-helper inventory boundaries.

Parsing was stopped immediately after the real parser accepted the arguments, before any producer code ran. - Dependency receipt digests are derived from retained bytes and supplied to all three later stages. The pending probe and substitution control select the managed FP16 build and report. Native completion must retain the exact four-process, 132-launch, 4,224-word population and the accompanying fixed counts.
- The route requires a fresh owned workspace, safe canonical roots, nonoverlapping source/input/output roots, Linux CPython 3.12.14, a matching clean checkout, available resources, and consistent interpreter identity before each child. Source and interpreter identity are checked again at closeout.
- The environment is rebuilt from an allowlist. It omits inherited GitHub job fields, `PYTHONPATH`, compiler overrides, caches, and arbitrary loader variables. Local origin and all seven false acceptance claims remain explicit.
- Successful child exit alone cannot promote a stage. Cleanup must complete; the report must match stage/revision/pin/claims; its bounded retained bytes must match the descriptor; and the last log line must match the report's actual terminal schema. Child failure prevents later stages.
- The dependency report, preparation, native report/source snapshot, and both control reports are rechecked at closeout. Retained descriptors reject symlink traversal, hardlinks, nonregular files, empty files, and oversized bytes.
- The wall deadline is shared across all stages, with each child receiving only its remaining time. Budgets remain two build jobs, one simulation worker, 15 GiB disk reserve, 4 GiB selected process-group RSS, 16 MiB logs, and the unchanged inner configure/build/run limits. The preparation child has its separate 1,800-second ceiling.
- A failed native-stage launch restores `native_execution=not_run`; a monitoring exception that cannot establish whether launch happened preserves `unknown`; completed native observation remains `run` even if a later control fails. No failure path promotes the acceptance booleans.
