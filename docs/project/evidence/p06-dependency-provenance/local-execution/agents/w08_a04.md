## Root cause and capacity choice

The immutable native report from attempt 03 has SHA-256
`bba2af32da50326b43c0225f63478a3003865a6fc34eaef2e79b9228697a56d0` and
3,679,258 bytes. Independent scanning confirmed **265,793 lexical structural
tokens and maximum depth 10**. The baseline parser's 250,000-token default
therefore rejects this otherwise parseable completed report.

The change exposes an explicit, validated per-call token allowance with a hard
500,000 ceiling. The local native-lifetime child and the two explicitly pinned
dependency-managed control inputs select this allowance. The original
250,000-token default remains effective for every call that omits the keyword.
This is a capacity correction for a known report shape. It does not change a
numerical tolerance, execution population, runtime resource limit, performance
criterion or successful-report acceptance condition.
