## Implementation and failure preservation

The correction moves the existing four-line source snapshot/admission block
immediately after the cache rename and receipt checkpoint. All original checks
before that relocation remain in their original order: exact revision syntax,
version/cache identity, disk and memory reserves, selected superproject
gitlinks, initialized dependency status, absent selected products/fetched
inputs, canonical cache path, fresh relocation/acquisition/log directories,
absence of tracked files under `tools`, and same-filesystem relocation.

The unchanged source collector then checks the complete remaining checkout.
Any tracked edit, nonignored untracked file outside the relocated cache, wrong
source revision or other provenance blocker prevents acquisition. The same
source inventory is collected again after acquisition and must match exactly.
The success receipt's schema and data meanings are unchanged.

A source rejection now occurs after moving the validated cache. Its failed
receipt records the canonical `workspace/tools` location; every cache byte is
preserved there, and no acquisition command starts. The two existing tests were
updated to assert that exact behavior. Adding rollback machinery would have
obscured the required ordering and introduced unnecessary state transitions.
The cache is not deleted, overwritten, executed, treated as dependency output
or used to conceal dirty source outside its original directory.
