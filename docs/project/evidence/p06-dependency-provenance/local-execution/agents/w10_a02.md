## F2 finding: complete control inventory omitted real runtime output

Confidence is **high**, with actual failed-reader evidence and source proof.
The original pending packet contains **43 files**, while the old reader consumes
42. The sole omitted file is the **2,103-byte** `ramulator.stats.log`, SHA-256
`acee45a861d905597670c2b2d72fc4bd3056dc3f406fefaa8d5a9a70b5480d89`.
There are no missing expected files. The complete public local reader therefore
correctly failed its exact membership check rather than silently ignoring the
extra data. The parent's original failed replay log is preserved separately.

The bound native source `sim/common/dram_sim.cpp` unconditionally opens that
literal filename in `~RamulatorDram()` and writes channel finalization output.
The pending binaries run in the packet root. Each finalization can overwrite
prior diagnostic output; it is not a per-process transcript. The actual file
includes `.nan` for an idle channel's latency. That value is legitimate opaque
diagnostic data and is not admitted as a performance measurement.

The same native destructor also creates `work/ramulator.stats.log` during the
substitution run. Its original final retained-file inventory includes that
file, whereas both frozen compilation-product inventories correctly exclude it.
Reading the diagnostic before constructing those frozen inventories would
incorrectly change their phase meaning.
