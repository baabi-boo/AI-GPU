1. **No native cross-toolchain found.** Searches under `/workspace`, `/tmp`, `/opt`, and `/usr/local` found no Vortex clang, RISC-V GCC, associated toolchain archive, or populated `tools` directory. `p02_matrix.py:188–206` requires Vortex clang/clang++, llvm-objcopy/objdump, RISC-V GCC/gcc-ar/objdump/objcopy, libc/libm and libclang_rt archives. Host GCC cannot substitute for that set. Verilator is also absent, although the selected SimX path does not itself require RTL execution.
2. **No real restored cache.** `p06_dependency_prepare.py:63–67` requires a `v3.0.2-<40-hex>` identity and the corresponding `Linux-toolchain-...-lite/full` cache key. Lines 92–101 require and relocate an actual fresh `source/tools` directory. Neither that restoration nor its actual cache key was observed locally. Passing an invented GitHub cache label would misstate provenance.
3. **Uninitialized submodules.** `git submodule status` shows all five superproject submodules uninitialized in the new worktree. Formal source collection requires initialized selected source; preparation additionally checks clean SoftFloat/Ramulator worktrees and absence of pre-existing products (`p06_dependency_prepare.py:76–91`). Existing object repositories can supply pinned objects without replacing historical evidence, but initialization has not been performed.
4. **CMake selection.** `p06_dependency_build.py:87–102` fixes PATH to the executing Python directory plus `/usr/bin:/bin`; it does not offer the diagnostic driver's explicit CMake-path argument. The existing custom CMake cannot be selected merely by changing the caller's PATH. A reviewed explicit host-tool selection mechanism or actual provision into the expected environment is needed for unchanged local execution.
5. **GCC 14 native compatibility requires a real probe.** `docs/project/developer-guide.md:129–140` records a previous `dram_sim.cpp` failure with GCC 14.2.0 (`-Werror=dangling-reference` in fmt) and successful GCC 12.2.0 probes. I found no GCC 12 binary in the selected locations. The host dependency build passing with GCC 14 does not prove the model/backend warning policy will pass. No compatibility compile was run in this audit.
