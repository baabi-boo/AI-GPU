# Wave 2, assignment 2 — explicit local dependency preparation

## Implemented scope

Owned and added only `ci/project/p06_dependency_local_prepare.py` and
`ci/project/test_p06_dependency_local_prepare.py` in `/workspace/ai-gpu-next`.
No existing production files, project status, acceptance flags, source pins,
numerical thresholds, golden data or hosted preparation implementation were
changed by this assignment. No commit, push, dependency build, full toolchain
extraction or native execution was performed.

The new contract is `p06-local-dependency-preparation-v1`, with explicit
`execution_origin="local"`. It rejects hosted-job/cache fields and keeps all
seven qualification, warm and acceptance flags false. The producer accepts a
named source revision, owned workspace, immutable archive root, local dependency
object repositories and an optional host-tool directory. It calls the separate
`p06_local_toolchain.provision()` implementation into a fresh workspace `tools`
directory and retains its complete receipt.

The producer requires the same exact clean source and initialized gitlinks as
the existing formal route. It checks both selected submodule worktrees, rejects
pre-existing dependency products and fetched headers, and verifies all five
complete pinned source trees using the existing bounded Git-object reader.
Source snapshots, dependency object inventories and seven selected host-tool
identities are checked before and after provisioning. The 15 GiB disk reserve,
4 GiB memory prerequisite and existing dependency budget are unchanged.
Blocked and failed attempts retain their reason; an existing preparation receipt
or output directory is never overwritten or removed.

## Integration APIs

- `CONTRACT_ID` and `LOCAL_FIELDS` describe the closed local success schema.
- `validate_local_preparation(document, expected_revision)` validates inert
  data and returns the document. It never opens, resolves or executes producer
  paths. The toolchain validator reads only the trusted fixed archive lock.
- `prepare(args)` writes `evidence/dependency-preparation.json` and returns the
  actual preparation outcome. CLI dependency input is `--dependency-repositories`.
- The receipt includes `host_bin` and exact `host_tools` identities for gcc,
  g++, ar, ranlib, CMake, make and Python. Wave 2 assignment 3 integrated these
  with the shared builder/receipt checks, including source/workspace and source
  manifest joins.
- Test helpers `synthetic_preparation()` and `synthetic_toolchain()` expose
  realistic schema fixtures for admission/envelope controls. They use real
  reviewed immutable lock/source metadata but **invent installed observations**;
  they are never execution evidence.
