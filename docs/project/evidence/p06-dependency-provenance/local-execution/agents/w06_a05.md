# Wave 6 agent 5 — dependency retention ordering

## Finding and correction

**F2, high confidence, static proof and actual failed execution:** the dependency
producer ordered retained paths as `pathlib.Path` objects, while the existing
receipt contract requires lexicographic order of the relative POSIX path
strings. These orders differ when a directory component is a prefix of another
name. The real attempt 02 reached completed compilation, both admitted maps,
three products, 144 generated build inputs and 628 staged files, then correctly
failed its final inert reader with `retained inventory ordering differs`.

The frozen producer is from commit
`ac2f2ae761c3644103278f7a41cc6ae7db734a86`. The original dependency report is
1,784,914 bytes with SHA-256
`344c43fe145a76f11938c45abcdb940ddda5a47da52c9ced6249713b9d62123b`.
Its 3,679 retained descriptors contain exactly three descending boundaries:

| Earlier producer entry | Later producer entry that should sort earlier |
| --- | --- |
| `sources/ramulator/src/dram/lambdas/rowopen.h` | `sources/ramulator/src/dram/lambdas.h` |
| `sources/softfloat/source/8086/specialize.h` | `sources/softfloat/source/8086-SSE/extF80M_isSignalingNaN.c` |
| `sources/softfloat/source/ARM-VFPv2/specialize.h` | `sources/softfloat/source/ARM-VFPv2-defaultNaN/extF80M_isSignalingNaN.c` |

Root changed only the final return in `Builder.retained_inventory` to sort the
completed descriptors by `row["path"]`. I independently compared the complete
old and new producer files and confirmed that this is the sole difference.
The reader's ordering requirement is unchanged. File hashing, type and symlink
checks, omission of the report itself and the total byte bound are unchanged.
