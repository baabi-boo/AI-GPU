## Configuration, tools and provenance

Runtime, backend, kernel and host retain independent original compiler records.
The common selectors are the frozen `p02-tfr` RV64 configuration, input format
`fp16` or `bf16`, output `fp32`, `KUNROLL=1`, and exactly one direct
`SIMX_CHECKED_COUNTERS=1` definition. The backend's enabled counters and generated
configuration are checked separately from the expanded runtime/kernel/host
macros. Fast math, alternative arithmetic/timing modes, conflicting macro
definitions, changed ABI/optimization options and extra compiler options are
rejected by the inherited validators.

The native producer passes the selected host C++ compiler to host/model work.
It intentionally does not pass a host `CC` override to the application Make
invocation, because that would propagate into the RISC-V kernel-library build.
The recorded application graph instead requires the exact RISC-V GCC and
Vortex Clang paths, target, sysroot, Vortex features, static kernel libraries,
startup address, object order and conversion tools.

identities shared with the native inventory must agree. All eleven selected
native compiler/library identities from fresh local preparation are mandatory
and must match the native inventory. The executing Python identity is checked
against pinned Linux CPython 3.12.14 and the selected PATH entry.

The model map must load all 43 exact model objects once and join the fresh

rejected. Source, helpers, tools, dependency bytes, model/map/object identities,
raw logs and retained data are checked at execution boundaries and again during
finalization. Both allocation policies use the same frozen artifacts per format.
