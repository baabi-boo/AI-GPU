## Reviewed behavior

- The outer runner requires a previously absent workspace beneath an existing
  canonical parent. Existing attempts, including failed attempts, are rejected
  before any receipt or log is replaced. Source/output overlap is rejected;
  archive and repository roots are checked against the full independent-root
  set before a child starts.
- Standalone preparation requires an absent preparation receipt and an absent
  tool destination. Existing staged products, fetched source directories and
  ignored submodule products are rejected before provisioning. An existing
  preparation report cannot be changed into a successful retry in place.
- A partial extraction remains available after failure. Preparation retains
  `outcome=fail`, its failure reason and `native_execution=not_run`. A subsequent
  call rejects the original receipt and preserves both its exact bytes and the
  partial output. No cleanup or repair path deletes that failed original.
- Required host tools are selected from the explicit bounded PATH and checked
  for executable availability and identity before provisioning. Missing host
  tools produce a retained blocked preparation; extraction does not start.
- Archive parts are checked before extraction and hashed again by the bounded
  extraction stream. Selected installed tools are joined to retained archive
  members. Preparation rechecks host tools and source objects after extraction;
  native admission rechecks the retained preparation and all eleven selected
  native tools at its stability boundaries. These mechanisms preserve the
  declared observation scope rather than authenticating an adversarial host.
- Symlinked output roots and evidence directories cannot redirect writes.
  Existing symlinked receipts are rejected by `lexists`, preserving the target.
  Retained child reports require bounded regular files with one link and no
  symlink traversal. Explicit archive-internal hardlinks remain supported and
  have separate validated target relationships.
- The outer runner records `unknown` before invoking the native child. A
  reliable process-not-started result preserves `not_run`; a native timeout
  without a child report preserves `unknown`. The actual native producer also
  checkpoints `unknown` before each monitored native command, so a killed or
  interrupted inner monitor does not leave a previous `not_run` checkpoint as
  an apparent observation of successful non-execution. Earlier `run` observations
  remain `run` through later failures. Failed stages stop the sequence.
- Success flags are raised only after all five stages and the final source,
  interpreter and original-report stability checks. All seven qualification,
  warm and acceptance fields remain false throughout.

## Limits

Retention depends on a functioning filesystem and an opportunity to checkpoint;
the code cannot promise a final receipt after disk failure, process termination
before the first checkpoint or malicious concurrent filesystem changes. Atomic
receipt replacement prevents partially written JSON from replacing the last
checkpoint. The outer process-group monitor's lack of hard containment or
aggregate accounting across child-created process groups is explicitly recorded
in the existing contract. Neither limitation was newly introduced or hidden by
this local route.
