### Admission and stability

`p06_dependency_admission.Admission` calls the independently implemented
`p06_dependency_receipt.load_receipt(path, digest, revision)` before the managed
runner starts any command. It requires the receipt's source root to be the
selected measurement checkout and retains the exact caller-pinned receipt bytes.
The new modules are imported before the active helper and source freeze.

The live boundary independently checks the complete staged-file population
against the three fetched source trees and the three canonical product paths.
It hashes every file from all five pinned dependency trees at its measurement
path, the staged products, dependency builder helpers and all selected dependency
tools. Common managed/dependency tools must have identical selected identities.
Explicit compiler support archive descriptors are rehashed as well. These
checks run at admission, before and after each bounded command, after each
process/variant and at finalization. Symlinks, hardlinks, changed bytes and
different product paths reject.

### Model and application joins

The new `tests/regression/ai_counter_preflight/dependency_model.mk` includes the
existing generated model Makefile and appends only
`-Wl,-Map,<runtime>/dependency-model.map`. No historical Makefile was changed.
The model is built separately before the existing wrapped backend command. The
two exact command logs feed the existing 43-translation-unit build validator;
its new optional `dependency_map` argument admits only that exact path and flag
position. The default grammar continues to reject the added flag. A changed,
duplicated, missing or additional linker option rejects.

Admission checks the staged SoftFloat archive against the receipt's fresh
compiler-output members. The linker map must select members from that archive,
load each of the 43 model objects exactly once, and load both canonical staged
shared products. Explicitly recorded compiler support archives have no path
prefix exemption. The model library, all object identities and map identities
remain stable through application building and every native process. The new
route retains all 43 object payloads and the map, within the runner's existing
bounded payload inventory.

After `compiler_records` and before building identities, the live runner calls
the existing complete `validate_application_build` reader. Its recipe reader
requires bytes from the frozen measurement source inventory. The full result
is stored as `application_build_records`, alongside `dependency_model_link` and
`dependency_receipt_sha256`, in each variant and build binding. Every process
binding embeds that build binding and the receipt digest before the native
qualification ID is computed.

The new top-level `dependency_source_to_loaded_binary_verified` becomes true
only after both formats, both policies, all four verified lifetime observations,
the complete counts and final stability checks succeed. A later failure keeps
it false and preserves the first original failure reason.
