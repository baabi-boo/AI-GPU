## Verdict

**The two map size checks should use the existing file-payload category.**
The contract already assigns retained files 64 MiB, JSON receipts 16 MiB and
command logs 16 MiB. The recorder instead selected the JSON cap for a map file;
the parser independently selected the command-log cap. Both fail on the
18,084,083-byte actual GNU linker map even though it meets the file, line-count
and line-length limits. The reviewed two-line correction selects
`contract.MAX_FILE_BYTES` at both boundaries. It changes no numerical constant.
The accompanying design paragraph records that category distinction.

The receipt descriptor/payload readers, build collector, archive view and live
admission already use the file cap. No additional 16 MiB **map byte-size** gate
was found in that inspected path. That statement does not establish complete
link admission. A separate review has identified that the actual map selects
25 yaml-cpp members and zero spdlog members while the current Ramulator callsite
requires a member from both archives. That semantic boundary is outside this
assignment and is not cleared by the size correction.

The dependency contract and process supervisor were compared byte-for-byte
with published `146253db8407e21aaef70e05f3f0dd3c7f5f6d33` and are unchanged.
The 16 MiB receipt/log bounds, 64 MiB file bound, 1 GiB packet bound, map line
bounds, process budgets, source pins, warning policy and acceptance gates remain.
