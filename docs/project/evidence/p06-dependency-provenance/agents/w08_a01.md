# W08-A01 — first failure retention across an error-checkpoint failure

## Scope and reproduced defect

This independent review covers the pending-read probe and dependency-substitution
producer when a supervisor exception is immediately followed by one failed error
checkpoint write. The producers' supervised commands are synthetic. The fixtures
create real temporary inputs, partial logs and report JSON files; the final
report write is real and successful. Fixture setup uses configure, stamp-only
Make invocations and host C++ preprocessing. No GPU/SimX native workload or fresh
dependency build runs in the checkpoint regressions.

The starting checkout is `5527cb062e10dfff3266022d138dd7cdf63f5e5c` plus the
parent's reviewed local changes. The production identities reproduced were:

| File | SHA-256 before correction |
|---|---|
| `ci/project/p06_pending_probe.py` | `f5cb5e2c7e87a79575df8078c1c8703b6fc091977348976859045b0e1d46410e` |
| `ci/project/p06_dependency_substitution.py` | `360df816190984c9db5b5d5e25d49a03187d7a8ddd01be2466cc23168297343c` |

Both command handlers record the original supervisor reason on their command
row, then save the error checkpoint before the outer handler records the
report's primary failure. A one-time `OSError` from that checkpoint replaces the
original exception observed by the outer handler. The final persisted report
therefore incorrectly names the checkpoint error as its primary reason and
contains only that secondary reason in its failure list. The original cause
remains on the command row, but the report's first-reason contract is lost.

The independently owned regression module is
`ci/project/test_p06_dependency_checkpoint_review.py`. It injects
`RuntimeError("synthetic original supervisor failure")`, or the same message
in a `KeyboardInterrupt`, followed by exactly one
`OSError("synthetic one-time error-checkpoint write failure")`. It lets all
other report writes use the real writer and verifies the returned report equals
the final JSON read back from disk.

## Correction review

The parent owns the production correction. Independent inspection confirms that
the pending probe now records its primary reason and failure before attempting
partial-log retention and checkpoint persistence. Its outer handler preserves
the first reason and avoids appending the same adjacent reason when the original
exception is rethrown. The substitution producer similarly calls its existing
failure recorder before checkpoint persistence; that recorder preserves the
first reason and deduplicates only an identical adjacent stage/reason pair.

A distinct checkpoint-write failure therefore reaches the outer handler without
discarding the original cause. It is added to the failure list after that cause.
The correction does not alter the success path, command population, process
start interpretation, resource bounds or original outcome semantics.
