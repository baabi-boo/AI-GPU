# W02-A01 — locked dependency source materialization

## Implemented scope

Added `ci/project/p06_dependency_sources.py` and
`ci/project/test_p06_dependency_sources.py`. No other implementation files,
contracts, historical evidence or acceptance states were changed. This is source
locking/materialization and stability verification, not dependency compilation
or native execution.

The public interfaces are:

```python
materialize_sources(repositories, destination) -> manifest
validate_manifest(manifest) -> independent_copy
verify_sources(manifest, root, *, generated_files=()) -> verification_summary
```

The production API always uses the five fixed pins from
`p06_dependency_contract.PINS`; there is no caller-supplied pin override.
Materialization reads bounded immutable Git objects with the existing
`GitObjects` implementation, including complete root-tree reconstruction and
blob verification. It never copies acquisition worktree bytes or executes
checkout filters/hooks. All inputs are validated before the fresh destination
is created. Partial failed destinations are retained and cannot be silently
reused.

Each component is materialized at `<destination>/<name>`. Its relocatable
manifest retains sorted relative paths, Git modes/OIDs, SHA-256 hashes, byte
sizes, URL, exact commit and exact root tree. `validate_manifest()` is inert:
it checks exact schemas, typed bounded values, the current dependency contract
digest, fixed identities and complete tree reconstruction without opening files
or running commands.

Filesystem verification requires the exact complete regular-file and directory
inventory. It rejects source substitutions, missing inputs, additional ignored
files/directories, changed executable modes, symlinks, hard links and special
files. Component-by-component no-follow opens keep reads and exclusive writes
from traversing a substituted symlink. File identities are checked before and
after hashing. Source bytes must match both their SHA-256 and Git blob identity;
a coherently changed SHA-256/size pair cannot preserve the pinned tree.

`generated_files` is an exact list of `{path, sha256, size_bytes}` descriptors,
not an ignored-directory exemption. Its additional filename grammar admits only
SoftFloat `.o` and `.d` files under `softfloat/build/Linux-x86_64-GCC`, the
`softfloat.a` archive there, and `ramulator/libramulator.so`. The dependency-file
grammar includes recorder names such as `add.o.p06-before.d`. Injected source,
header, CMake-cache or arbitrary-component files remain rejected even if a caller
enumerates and hashes them. CMake binary trees and link maps belong outside the
immutable source roots.
