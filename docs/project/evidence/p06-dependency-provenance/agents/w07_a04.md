## Confirmed pending-probe defect and correction

Before correction, `command()` called `run_bounded()` before appending a command
receipt. A raised supervisor error therefore supplied neither an attempt row
nor a reliable process-start observation. On the first native attempt the
report could still say `not_run`, despite lacking evidence that no process had
started. A first compiler-version supervisor failure could produce a blocked
report with no attempted command. A later failure after a prior positive
native observation retained `run`, but still lost the later attempted row.
The outer handler did not catch `KeyboardInterrupt`.

The new tests use `DependencyProbeHarness`: actual retained files, hashes,
configuration stamps, and raw transcript bytes, with a substituted supervisor
and synthetic executable products. No probe or native model is launched. The
fixture generator uses host configuration, Make dry runs with compiler guards,
and host preprocessing; it does not compile the simulated model. An observed
`run` inside these fixtures is a simulated receipt state, not this assignment's
claim of a native execution.

| Focused control | Required result after correction |
| --- | --- |
| First native supervision error | The checkpoint already contains the attempt and `unknown`; the finished report retains both and identifies the actual partial bytes. |
| Supervision error followed by input change | The supervision reason stays primary; the final input-stability failure remains separately recorded. |
| Known `process_started=false` | The report stays `not_run`, with the failed attempt retained. |
| Prior positive start followed by unknown attempt | The earlier known `run` survives, and the later failed attempt and partial log are retained. |
| `KeyboardInterrupt`, with and without a message | Both return a finalized unsuccessful report; an empty message becomes `interrupted`. |
| Oversized partial log | The first supervision reason survives; a separate log-identity error is recorded without claiming a digest for the oversized file. The read is bounded to the cap plus one byte. |
| Compiler-version supervision error | The failed attempt and partial bytes are retained while native execution remains `not_run`. |

The parent correction checkpoints an attempt before calling supervision and
uses the native state from before that attempt when a receipt returns. This
distinction is necessary: reconciling a known false non-start against the
temporary `unknown` state would incorrectly keep uncertainty forever. A prior
known start correctly dominates a subsequent unknown attempt.

Ordinary supervisor errors and interruptions retain an unsuccessful row before
rethrowing into the report's finalization boundary. The bounded partial-log
read is independent of the normal successful-log digest helper. Failures in
that identity step are secondary. The main report now also uses a nonempty
interruption reason. Positive commands require exact true cleanup and a null
reason. Historical successful command fields, existing admission rules,
resource values, and the seven false claims retain their meaning.
