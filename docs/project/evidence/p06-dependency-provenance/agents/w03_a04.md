## Selected control

The route first requires the completed fresh-dependency managed contract at the
caller-selected revision and dependency-receipt digest. It matches the selected
FP16 build binding, application and model admission, source snapshot, exact
frozen build inventory, selected tools and canonical loaded-library paths. The
new dependency `Admission` also rechecks every pinned source and staged product.

The control constructs its own reviewed compiler commands. It compiles the
admitted GDDR6 source and headers with the original extension options plus a
separately retained `-include` header containing an emitted, externally visible
constant. The two actual recorder operations are one fresh compilation and one
fresh shared link. The reader checks the marker in the compiler dependency
closure, pinned source/header bytes, fresh object consumed by the link, admitted
Ramulator bytes, selected linker-map inputs and the resulting extension bytes.
The alternate extension must contain the marker and differ from the admitted
original's SHA-256.

The existing FP16 application and kernel run in one extra reusable-policy
process with only the isolated extension directory prepended to the original
runtime search path. The exact lifetime reader must accept the raw transcript
with the alternate extension path and reproduce one process, 33 launches and
1,056 exact checked words. The **same** transcript must then fail against the
original expected paths with exactly:

```text
loaded library libramulator-vortex.so: differs from the fixed contract
```

Any other failure reason, changed numerical output, incomplete lifetime trace,
different model path or missing actual extension selection fails the control.
The original source/build/products are checked unchanged before, between and
after commands. Control products and recorder payloads are frozen before the
native process. The first real failure remains primary if final stability also
fails. Retained files reject symlinks, hard links and excess bounds.

The unchanged inner contract fixes its sample/process labels. This extra
process therefore uses those labels with a distinct control binding in a
separate packet. It is explicitly marked `managed_population_included=false`
and is never appended to the original four-process report or its 132 launches.
All seven qualification, warm and acceptance fields remain false.
