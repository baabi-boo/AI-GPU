## Trusted import and inert-data boundary

All three readers use the existing hardened managed archive-helper loader.
That loader reads the fixed current helper path, verifies its reviewed
SHA-256, and compiles those exact bytes into its module. It does not select
an executable helper from the archive or consult a matching timestamp/size
bytecode cache for that helper.

The reader-source inventories require their loaded modules to resolve to the
trusted checkout and compare their source identities before and after review.
These are current-reader stability checks, not authentication of an arbitrary
local checkout or hostile producer. The archive, retained source, binary,
command and producer-path fields remain data. Selected payloads are read
through bounded archive views and exact retained inventories; the archive's
closing digest check remains required. Other outer prefixes retain their
explicitly separate semantic scope.

This assignment reviewed these paths statically and inspected the existing
execution/extraction/producer-path sentinels. It did not repeat a complete ZIP
semantic test or claim that a synthetic packet was an actual original.
