The four downstream implementations read the workspace from the already
admitted dependency document. They reconcile project-owned map loads against
their exact expected inputs: production objects and the three selected
products for the model; the fresh derived object and admitted Ramulator
product for the alternate-library control. Unexpected names, omissions and
repetitions within that selected population are not silently converted into
external inputs.

The control compiler closure applies the same root union to both the literal
`path` and recorded `resolved_path`. The derived source must retain its exact
canonical path and reviewed derivation. Known third-party source/header inputs
retain their pinned-byte and canonical-path checks. The root addition therefore
covers both directly named workspace headers and external-spelled aliases
resolving into the workspace.

The map exception remains limited to individually admitted compiler-support
archive paths in `external_archives`. The formal receipt independently limits
these to the selected `libgcc.a`/`libgcc_eh.a` names, verifies the retained
compiler `-print-file-name` observation, rehashes archive bytes and checks the
member inventory. Live model admission rechecks the selected archive bytes;
retained readers consume the prior admitted archive identities and member
inventories. Their location inside the workspace alone does not turn an
already admitted compiler-support archive into an unreviewed project input.

No rule assumes that every path outside `/usr` is project-owned, or that every
input outside the named project roots has been independently rebuilt. External
and system inputs retain the existing selected scope and limitations. The
reviewed change does not alter any historical packet schema or assert complete
compiler/toolchain reproducibility.
