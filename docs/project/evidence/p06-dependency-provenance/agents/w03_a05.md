# W03-A05 — inert dependency ZIP replay

## Implementation and scope

Added `ci/project/p06_dependency_replay.py` and
`ci/project/test_p06_dependency_replay.py`. The parent owns publication and
whole-packet integration. This assignment did not run a dependency build,
compiler, native process, hosted workflow, commit or push.

The CLI requires independently supplied archive SHA-256, source revision and
dependency-receipt SHA-256. Its explicit ZIP prefix defaults to
`dependency-build`; an empty prefix can select an archive containing only that
packet. It rejects missing, extra, duplicate or self-inventoried packet members,
checks every retained descriptor, and delegates complete dependency semantics
to the trusted current `p06_dependency_receipt.verify_document()` reader.

Each selected member is decompressed once and cached as immutable bytes. The
cache is bounded by the existing 1 GiB packet limit and file-count bound; file
reads retain the existing 64 MiB bound and the report retains its 16 MiB bound.
No archive, decompression, aggregate read or historical reader limit was raised.
The archive reader verifies its original ZIP identity again on close before a
successful result can return. Current trusted reader identities are checked
before and after review.

Public Python interfaces:

```python
replay_archive(path, sha256, *, expected_revision,
               expected_receipt_sha256, prefix="dependency-build")
verify_view(view, *, expected_revision, expected_receipt_sha256)
```

The second interface permits a later complete-original reviewer to reuse the
dependency check on an already bounded archive view. Its owner must retain the
archive identity and closure checks. CLI `--output` uses exclusive creation and
does not overwrite an existing result.

The result labels its scope `selected-dependency-retained-consistency`, records
`native_execution="not_run"` and `retained_code_executed=false`, and keeps all
seven qualification, warm and acceptance fields false. Other packet prefixes
and the managed lifetime population are expressly outside this wrapper's scope.

## Archive-helper choice

Inspection found that the older `p06_replay._archive_api()` checks the helper's
source hash but then uses a Python file loader, which can consult matching
timestamp/size bytecode. The existing managed-preflight replay already contains
a hardened loader and a regression control for this case.

With the parent's authorization, this new wrapper calls the existing
`p06_managed_preflight_replay._archive_api()`. It compiles only the already
hash-verified current helper bytes and preserves the same pinned archive
reader. Neither historical helper was changed. A new route-level control
constructs a real accepted stale-bytecode cache, demonstrates ordinary loading
accepts it, then checks that this route bypasses the file loader and executes
only the pinned source implementation.
