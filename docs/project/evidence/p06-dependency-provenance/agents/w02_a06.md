## Implemented behavior

The new hosted workflow uses one Ubuntu 22.04 job with a 90-minute limit. It
checks out recursive submodules without persisted credentials and restores only
the pinned prebuilt toolchain. It neither restores dependency products nor
writes caches. Workflow authority remains `contents: read`.

Before the cache step, initialization retains the original workflow bytes,
workflow SHA256, source revision, repository/event/ref and run/attempt/job
identities. It records and enforces the 15 GiB disk reserve and 4 GiB available
memory requirement. CPython remains pinned to 3.12.14 and independently checked
against the executable selected by PATH. Build concurrency remains two jobs;
simulation concurrency remains one worker.

The ordered path is baseline host packages, fresh source/toolchain preparation,
fresh selected dependency build, actual receipt-byte SHA256 pinning, managed
dependency lifetime execution, then the separate positive-pending probe and
always-zero control. Receipt pinning requires a bounded complete passing build
record for the requested revision and all seven false claims. The managed
runner performs the full receipt admission. Shell pipelines preserve producer
failure status and original stdout/stderr. The final artifact upload runs under
`always()` and retains the complete evidence directory, including failed or
partial originals.

The pending probe defaults to its unchanged historical managed contract. Only
an explicit `--dependency-receipt-sha256` admits the new contract. That path
requires a canonical 64-digit lowercase SHA256, matching report receipt,
complete four-process population and counts, completed native flags, the narrow
dependency source-to-loaded-binary flag and all seven false claims.

For the selected format, admission rehashes the retained build binding and
checks its semantic identity, contract, receipt digest, format, backend,
application build records, dependency model link records and artifact list.
The new model recipe and linker map are included in the live artifact inventory.
The retained binding is added to the before/after managed snapshot inventory.
Default imports remain independent of the new dependency modules; expanded
artifacts and report metadata are used only after explicit admission.

The probe still runs its separate positive and always-zero controls. It does
not add its processes to the four-process/132-launch/4,224-word managed
population, claim fresh native lifetime execution, or promote any qualification,
warm, phase or performance flag.
