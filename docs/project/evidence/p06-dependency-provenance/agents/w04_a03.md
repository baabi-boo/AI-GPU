## Concrete failures found and fixed

### The original marker recipe was rejected by the recorder

The initial combined run executed **33 tests: 31 passed and two failed**. Both
actual substitution-build fixtures failed with:

```text
dependency recorder: unsupported tool input expansion
```

The recorder intentionally rejects `-include`; the control had attempted to add
its emitted marker through that option. The fix preserves the recorder's
existing grammar and makes the alternate input explicit:

1. Verify and retain the original admitted `GDDR6.cpp` bytes.
2. Create a separate source file under the owned control directory, consisting
   of those exact bytes, one newline and the fixed emitted declaration.
3. Compile that derived file with the reviewed original extension options and
   pinned include roots, then link its fresh object against admitted Ramulator.
4. Reconstruct the exact source derivation from retained bytes and verify that
   the actual compiler's included-input closure contains it. Included dependency
   headers must still match the admitted input inventory; unreviewed generated
   inputs are rejected.
5. Bind the derivation identity to the separate control identity and freeze its
   original/derived inputs, receipts, object, map and product before execution.

No admitted dependency source, product or managed build is modified. There are
still exactly two selected recorder operations: one compile and one shared link.
The emitted constant must be present in the actual output, whose SHA-256 must
be different from the original extension. A newly compiled source with extra,
unreviewed bytes is rejected even though compilation itself succeeds.

### An unreturned native start receipt was incorrectly described as not run

Read-only failure-path review found that an exception escaping the supervisor
could leave `native_execution="not_run"` even after a native invocation had been
attempted. The control now uses the existing managed runner's uncertainty model:
set the state to `unknown` before invoking the native supervisor, then refine it
only when an explicit process-start receipt returns. A raised exception preserves
the command failure and any partial log identity; it cannot report control
success or replace the original failure during finalization.

A targeted control raises after writing a synthetic native log but before
returning its start receipt. The result remains `unknown`, retains the partial
log and original reason, and leaves all pass/acceptance claims false.

## What the tests establish

### Actual small host execution

The real compiler/archive/loader fixture builds a small Ramulator-like shared
library and two extensions. The original and derived-marker extensions both
return **42** when loaded and called in separate actual Python/ctypes processes.
Their bytes differ, the marker is emitted, and the original input/product hashes
remain unchanged. Actual compiler dependency prepass, compile and shared-link
receipts are checked by the trusted record reader. The resulting map joins the
fresh object and selected Ramulator library.

These are intentionally small host fixtures. They do not compile the complete
pinned GDDR6 implementation or execute the managed GPU application.

### Exact synthetic managed observations

The unchanged trusted lifetime reader checks one complete synthetic FP16,
reusable-policy transcript against the alternate extension path: **one process,
33 launches and 1,056 exact words**. Rechecking the same transcript against the
original library paths must fail for exactly:

```text
loaded library libramulator-vortex.so: differs from the fixed contract
```

Bad numerical output, another changed library, missing lifetime observations,
wrong rejection reason, incomplete execution, resource failure and earlier
failure followed by final drift all reject. The control's report and binding
explicitly set `managed_population_included=false`; it never adds these launches
to the original four-process / 132-launch population.

### Inert ZIP replay

The replay tests use actual bounded ZIP bytes and external archive, receipt and
revision pins. They cover exact selected-prefix inventory, descriptors, bounded
read caching, archive identity before/after review, malformed paths, duplicate
members, links/special members, CRC or trailing-payload changes, wrong pins,
trusted-reader drift, exclusive output and a matching stale-bytecode sentinel.
Retained Python, command strings, ELF-like payloads and producer paths remain
inert. The existing hardened managed archive loader compiles its verified helper
source directly; historical loaders are unchanged.

The positive transport fixture explicitly replaces full build semantics to
isolate the ZIP boundary. A separate test requires the real receipt reader to
reject that incomplete synthetic packet. No transport-only pass is presented as
a successful 406-unit dependency original. The complete native population and
other artifact prefixes remain outside this reader's declared scope.
