## Acquisition, freshness and staging

Preparation checks the requested source revision and clean source observation,
both selected superproject gitlinks and initialized dependency HEADs. Its
submodule status check includes ignored and all untracked inputs. Existing
selected products, fetched source roots, acquisition roots and acquisition logs
reject before the cached tools are relocated. A matching prebuilt-toolchain
cache remains an explicit prerequisite; no source build or invented cache
identity substitutes for it.

The three transitive acquisitions use fixed URLs and exact revisions, with
bounded commands and controlled Git configuration. Acquisition precedes the
source freeze. The later object materializer independently checks the selected
commit/tree, so a successful fetch command alone cannot establish source
identity. Proxy environment values are not included in the preparation report.

Fresh source and build directories are distinct from the measurement checkout.
Materialization uses exclusive, no-follow file creation and directory-relative
operations. Subsequent verification rejects missing or additional files,
unexpected directories, symlinks, hard links, special files, altered source
bytes and changed source modes. Generated source-root files have an explicit
restricted grammar and cannot replace immutable source entries; the producer
derives that population from tool records, and the receipt reader reconstructs
the stability boundary sequence.

The live build constructors select the fixed SoftFloat specialization/options,
local disconnected CMake inputs and reviewed compiler/archive/link wrappers.
Fresh output checks and the selected graph are independent of CMake's plan.
The source freeze, helper/tool identities and source inventories are rechecked
at command boundaries. Disconnected FetchContent selection remains distinct
from operating-system network isolation.

Staging requires canonical source and destination paths, a regular single-link
input, an absent destination and exclusive creation. It copies the source's
permission mode, verifies the destination bytes and rechecks the source
identity before returning a staged identity. Required fetched source trees and
the three product paths are selected explicitly. A failed copy is not silently
removed or replaced on a retry. The builder retains its initial failure reason
when later stability or retention checks also fail.

These checks retain the documented limitation concerning concurrent filesystem
writers; this review does not turn before/after observations into a complete
concurrency or producer-authentication guarantee.

## Focused verification

Added
[`test_p06_dependency_source_review.py`](../../../../../ci/project/test_p06_dependency_source_review.py).
Each test first stages real bytes successfully and verifies the preserved
executable mode. The two failure cases then use actual temporary files:

1. The copy callback writes a prefix and raises a specific I/O error. That
   error reaches the caller, the source remains unchanged, the partial
   destination remains observable, and a subsequent attempt rejects the
   non-fresh destination without changing its bytes.
2. The copy callback completes the copy and then changes the source bytes.
   The real post-copy source check rejects it. The destination retains the
   prior bytes, and a retry again rejects rather than replacing them.

Only the copy callback's failure/change timing is injected. Path admission,
actual file I/O, identity checks, mode preservation and exclusive retry behavior
are real. No compiler, native process or full receipt is represented by these
tests.
