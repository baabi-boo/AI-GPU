## Concrete conclusions

- The current managed APIs are internal C++ classes, and the operator manifest
  explicitly says `installed_api: false`. The handoff proposes opaque Python
  owners through a versioned C++ extension; it does not represent STL objects or
  the device argument block as an existing host C ABI.
- `ManagedMatmul::create` copies module bytes and `submit` copies A/B bytes;
  operations retain their shared runtime context. A first copying Python surface
  can preserve these semantics with explicit representation and lifetime checks.
- `ManagedMlp` copies `MlpCase`, including expected H/bridge/Y, and compares actual
  results internally. The first model entry must select trusted frozen cases;
  arbitrary model loading or a reference-free inference API is separate work.
- Exact input representations, supported shapes/strides, output ownership,
  single-caller access, partial failures, timeout retention, explicit draining,
  interruption and interpreter-finalization policy are named before implementation.
- The handoff specifies a first native matmul vertical slice, then six-signature
  and fixed-model coverage, clean installation and separately qualified framework
  registration. It preserves no-fallback and unsupported-autograd boundaries.
- P06 counter/benchmark work, the P01-A03 vendor integration blocker and the
  inherited 267-to-283 DSP area-gate failure remain distinct obligations.
