## Source-supported cause

The main `third_party/Makefile` builds cocogfx during shared-cache preparation.
The setup action then caches the complete `third_party` directory. The pinned
[cocogfx tree](https://github.com/gtcasl/cocogfx/tree/b1befdb36df8af7ac9e2c96acaf81957aab5d107)
has 22 tracked files and **no `.gitignore`**. Its
[Makefile](https://github.com/gtcasl/cocogfx/blob/b1befdb36df8af7ac9e2c96acaf81957aab5d107/Makefile)
creates these ten unignored products:

| Product kind | Exact paths |
|---|---|
| Dependency list / archive | `.depend`, `libcocogfx.a` |
| Objects corresponding to its eight top-level sources | `src/blitter.o`, `src/bmp.o`, `src/cgltrace.o`, `src/imageutil.o`, `src/main.o`, `src/math.o`, `src/png.o`, `src/tga.o` |

The Makefile selects only top-level `src/*.cpp`, not recursive sources. Git
reports these untracked products as a dirty submodule in the parent checkout.
The retained failed packet does not include the cache's nested file-status list;
this diagnosis is a pinned-source causal reproduction, not a claim to have read
the actual cached object bytes.

The three named P04 dependency libraries are SoftFloat, Ramulator and its Vortex
extension. Neither native backend's linker inputs nor the model application
requires `libcocogfx.a`. Cocogfx tracked headers remain in source and must stay
unchanged.

## Bounded reproduction

A separate scratch clone was checked out at the exact pinned cocogfx commit:

```text
git clone --no-checkout https://github.com/gtcasl/cocogfx.git <scratch>/cocogfx
git -C <scratch>/cocogfx checkout --detach b1befdb36df8af7ac9e2c96acaf81957aab5d107
```

Commands ran through `tensor_host_tools.run_host_command`, with 60 seconds for
clone and 20–30 seconds for subsequent Git operations. The probe created
explicitly synthetic files at the ten product paths; it invoked no compiler,
simulator, model application or dependency build.

The real Git/file probe passed these checks:

- Clean pinned checkout before inserting products; all ten inserted products
  appear as nonignored untracked inputs.
- No tracked/index difference while those products exist.
- Moving the ten regular files into an outside-source quarantine restores clean
  Git status and preserves every moved-file SHA-256.
- All 22 tracked file hashes remain unchanged.
- An unknown untracked header is outside the recognized inventory, a symlink at
  a recognized path fails a non-following regular-file check, and a tracked
  Makefile modification is visible separately.

Temporary helper logs were moved outside the main source checkout. The probe
does not test the forthcoming production correction; its durable regression and
independent review are separate obligations.

## Recommended correction and acceptance boundary

Preparation should verify the cocogfx gitlink/HEAD and reject tracked or staged
differences, enumerate actual untracked inputs, and accept relocation only when
every candidate is an exact known build product. Derive object names from tracked
top-level C++ sources, plus the two fixed products. Validate the complete candidate
set before moving anything; reject unknown names, nonregular files, symlink
traversal, and an occupied quarantine destination. Preserve path, size, digest and
before/after status in the preparation record. Relocate into fresh outside-source
storage, then require the existing full source and dependency identity checks.

Do not run the upstream broad cleanup target, edit ignore rules, suppress dirty
submodule reporting, discard unknown files, or waive the source gate. A strict
relocation will remain blocked if actual cached contents differ from the supported
product inventory. Successful hosted preparation and native execution still need
to be observed after the fix.
