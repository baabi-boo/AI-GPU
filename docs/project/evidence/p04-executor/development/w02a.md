## Changes

Added only `sw/runtime/ai/mlp_runtime.h`, `sw/runtime/ai/mlp_runtime.cpp` and this
receipt. The internal `ManagedMlp` owner composes the fixed graph through the
existing `ManagedMatmul` API. Native input arrays and comparison arrays have
separate types and are copied before dispatch. Inputs are serialized explicitly
little endian. Each output projection consumes the corresponding slice of the
actual host bridge, which itself consumes actual, exactly compared hidden words.

The owner retains its active operation across bounded waits and partial
submission failures. An incomplete operation is never destroyed on a bounded
return. Terminal failures cannot restart the graph; explicit close prohibits
further dependent submissions. A successful drain preserves previous numerical
and runtime failures. Normal stages close and release their operation before
starting the next stage. Device-memory counters are compared after operations
release and before the managed owner closes.

The trace retains actual input bytes, hidden and output words, bridge bytes,
comparison counts, separate submission/completion/cleanup results, copied native
dispatch/profile observations, host durations and memory-query outcomes.
Observed-data flags are distinct from correctness: only `MlpResult::ok()` means
successful complete inference. Successful asynchronous submission normally has
`complete=false`; successful wait, cleanup and terminal model results require
completion. Native sequence IDs are 0, 1 and 2, matching the agreed record schema.

`timeout_ns` bounds each native wait/drain separately. It is not a whole-call
deadline, and host work is not interruptible. Destruction drains indefinitely;
callers must retain the owner after incomplete close. CPU matmul fallback is
absent. The fixed fixture, producer, manifest, kernel and numerical contract
were not modified by this task.
