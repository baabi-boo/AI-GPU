## Findings and required data flow

The frozen domain is internally consistent: X and weights are integers in
[-2,2]; first-layer prefix sums stay within ±64; the bridge encodes integers
in [0,64] exactly into FP16/BF16; second-layer prefix sums stay within ±1024.
The independent producer computes integer sums and serializes exact bits. No
new arithmetic tolerance or float-based recomputation is needed by the adapter.

The executor must observe this sequence:

1. Submit X/W1; wait for successful **and complete** native execution.
2. Copy the actual 128 hidden words while their operation still owns them.
3. Compare all raw hidden words against the frozen reference before ReLU.
4. Call `prepare_mlp_hidden` with those actual words and compare all 256 actual
   bridge bytes against the frozen bridge reference.
5. Submit actual bridge bytes [0,128) and [128,256) with W2 in two separate
   `(8,4,8)` operations. Each consumes exactly eight rows of eight 16-bit values.
6. Compare each actual 32-word result against its own final-reference row range.
   Copy those actual results to offsets 0 and 128 bytes of the final output;
   compare all 64 assembled words again.

Frozen H/R/Y arrays are comparison-only inputs. Their names, types and access
sites should make that restriction reviewable. Runtime input capture should
show that second-layer A bytes equal the recorded actual bridge slices. Traces
should identify case, iteration, native operation ID, row range, dependency and
input/output byte digest. Hashes document observed lineage; they are not a
substitute for source review or actual native execution.

## Precise failure tests

| Test | Fault | Required result |
|---|---|---|
| Negative hidden corruption | In either `seeded_dense` format, replace actual hidden[0] `bf800000` (-1) with `c0000000` (-2) | Hidden comparison fails after one native launch; neither output launch occurs. Both values activate to zero, so final-only checking would miss this bug. |
| Signed-zero corruption | In the zero case, replace one actual hidden `00000000` with `80000000` | Raw hidden comparison fails before the bridge/output stages, although the helper alone permits and normalizes signed zero. |
| Bridge comparison | Alter one expected bridge halfword in a test-local copy, or inject a bad bridge result in the host harness | Exact bridge comparison fails; no output submission and no successful model result. Frozen repository data is unchanged. |
| Actual bridge capture | Capture the A buffers of both output submissions in the mock runtime | They equal actual bridge bytes [0,128) and [128,256), respectively, with no reordered elements or reference substitution. |
| Output block swap | Exchange the two returned blocks for `split_boundary` | Row comparison fails. All 32 corresponding words in the two halves differ in both formats. The zero case cannot detect this swap. |
| Assembly offset | Copy the second block to offset 0, reverse blocks, or leave the last word poisoned | Final 64-word comparison fails, even if each individual block had passed. |
| Failed/incomplete dependency | Hidden or first output operation fails/times out | No dependent submission, no use of old output, and retained ownership until drained. |
| Format packing | Swap 16-bit halves or use host-endian memory reinterpretation | Adapter round-trip or exact bridge-input capture fails in both FP16/BF16. |
| Hidden invalid-domain values | ±65, ±0.5, smallest ±subnormal, ±infinity, NaN | Existing bridge rejects invalid values; executor also rejects mismatching H before native dependent work. |
| Failed bridge prefix | Place a bad value late in an otherwise valid 128-word input | Bridge failure returns a fully zeroed byte array and the executor never submits it. |

The bridge already performs domain validation before zeroing negative values
and returns no usable prefix on failure. Preserve its bytes and its manifest
pin. Mutation tests should change local observations/copies only.

## Adapter recommendation

Add a new deterministic adapter; do not modify the accepted fixture, producer,
manifest or specification. The trusted runner first invokes
`p04_model_contract.validate(source_root)`, then reads the validated fixture and
uses the adapter. A generated C++ header is a simple representation requiring
no runtime JSON parser; alternatively use a fixed-length binary packet with
equally explicit bounds.

For a header, keep separate immutable structures:

- Case identity: fixed model/fixture IDs, case ID, dtype and fixture SHA-256.
- Native inputs: 128 packed X words; 64 packed W1 words; 16 packed W2 words.
- Expected results: 128 H words; 64 packed bridge words; 64 Y words.

Weights are selected by format and may be shared by its five cases. Use exact
`uint32_t` constants. Materialize transfer bytes explicitly little endian;
the earlier 16-bit element occupies each word's low half. Avoid floating-point
conversion in the adapter. Pin the new adapter and generated header in the
execution binding/source inventory rather than repinning the old source-only
manifest. Require deterministic regeneration and a parser/compile round-trip
that compares every emitted array to its original validated JSON words.

Reject unknown/duplicate case IDs, unsupported formats, missing or extra arrays,
wrong counts and noncanonical words before any native allocation/launch. A
direct executable accepting supplied arrays is not itself a qualified fixture
runner; the external trusted runner must bind and validate them.
