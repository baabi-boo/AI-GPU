## Semantics checked against actual source

| Clarification | Independent check |
|---|---|
| Asynchronous submission | The consumer calls `_execution(..., complete=False)` only for native submission. It still requires successful status fields and a real boolean. Native completion, operation cleanup, model execution and owner cleanup require `complete=true`. The documentation now states this distinction instead of broadly rejecting every incomplete result. |
| Cumulative model duration | `ManagedMlp::advance()` creates a scope-wide `Duration` that adds to `advance_ns`. Submission, waiting, comparisons, bridge, assembly and operation-close work occur within that scope. It is not exclusive orchestration overhead. |
| Overlapping measurements | Host waits contain time during which the queue worker executes events. Nested host durations and event intervals do not form disjoint costs; the revised warning against adding them is accurate. |
| Clock domains | The model and runtime use host `steady_clock` nanoseconds. The consumer checks stage/repetition chronology within one application invocation. Absolute values from distinct hosted machines cannot establish a shared timeline. |
| Polled resource budgets | `run_bounded()` samples disk reserve and child-process-group RSS at intervals. P04 supplies 4 GiB RSS, 15 GiB disk reserve and 16 MiB retained log limits. The README correctly avoids a cgroup or whole-job quota claim. |
| Case deadlines | The actual dedicated workflow and catalog wrapper pass `--run-timeout-seconds 180`. The inherited `_timeout` parser accepts integers from 1 through 1,800; 180 is the frozen hosted invocation, not the CLI's absolute maximum. |
| Native evidence boundary | The complete matrix remains a requirement. The initial four packets are blocked preparation with `native_execution=not_run`; no passing subset, numerical failure or native execution is inferred. |
