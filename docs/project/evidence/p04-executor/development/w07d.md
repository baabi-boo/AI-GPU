## Concrete packaging defect

`ci/project/p04_execute.py` copies generated configuration bodies, including
the dotfile stamp, into the evidence directory. At the audited source,
`.github/workflows/p04-model.yml` and the model evidence upload in
`.github/workflows/ci.yml` use `actions/upload-artifact@v4` without enabling
hidden-file inclusion. The archive therefore lost a body required by the
runner's own inventory. The parent is correcting those two narrow evidence
uploads and obtaining independent workflow review before fresh qualification.

The inventory check covered 89 referenced source, generated configuration,
raw log, snapshot, fixture snapshot, and binding files. It rehashed all 88
existing files successfully. The configuration dotfile is the **only** missing
file in this set. The packet report and sibling preparation/job receipts are
additional metadata; the count is not a ZIP member count. A successful fresh
run must retain the actual stamp and pass the complete audit; execution success
alone does not resolve this packaging failure.

## Independent audit program

[`audit_provenance.py`](../reviews/audit_provenance.py) uses the Python standard
library and Git object reads. It imports no production verifier, fixture
oracle, or runtime implementation. Its input is a retained packet directory
or `report.json`, with an explicit source repository for exact Git comparisons:

```sh
python3 docs/project/evidence/p04-executor/reviews/audit_provenance.py \
  --packet /path/to/model \
  --source-dir /path/to/AI-GPU \
  --selected-scope \
  --output /new/path/provenance.json
```

Repeat `--packet` for a matrix. Without `--selected-scope`, four unique
SimX/processor-RTL × FP16/BF16 variants are required. `--output` creates a new
file exclusively. A passing audit still reports `acceptance_claimed: false`.

Checks cover bounded reads, safe relative paths, duplicate JSON fields,
nonfinite JSON numbers, file byte identities, clean and stable source
snapshots, committed trees and root gitlinks, source inventory coverage for
the runtime/processor source directories, exact committed source bodies,
retained helper/runtime/model bodies, the frozen profile and fixture, exact
tool and dependency inventories, stable artifact bindings, canonical binding
digests, raw compiler records, generated header observations, and preparation
identity consistency. It checks the fixed Makefile argument grammar rather
than acting as a general compiler-command parser.

Before reaching the missing-file gate, the actual packet supplied 966 source
inventory entries: 773 main-repository bodies match their exact Git blobs;
193 external-submodule file identities are recorded without rehydrating those
bodies. All 57 retained source bodies match Git and their snapshot identities.
The source-before and source-after snapshots agree. Eight initialized
recursive submodule entries were recorded; top-level gitlinks are compared
with the committed root tree. External nested-tree body authentication remains
outside this offline audit.

## Arithmetic and compiler roles

The native tensor configuration is the frozen RV64 `p02-tfr` profile:
TCU `TFR`, scalar FPU `STD`, one cluster/core, four warps/threads, issue width
one, FP16 tensor bank enabled, local memory enabled, and the excluded tensor
banks/features disabled. BF16 uses its declared input type through the same
profile. Compiler records carry `ITYPE=fp16` or `ITYPE=bf16`, `OTYPE=fp32`,
`KUNROLL=1`, and release assertions disabled through `NDEBUG`.

| Compiler role | Required arithmetic observation |
| --- | --- |
| Runtime driver | Raw TFR/STD enums and matching companion selectors |
| SimX backend C++ | Raw enums and matching selectors |
| Processor RTL Verilator | Raw enums and matching selectors, native package inputs, `rtlsim_shim` top, bounded job count |
| Processor RTL C++ support | Raw enums; selectors need not be repeated because Verilator selects the arithmetic |
| Kernel and host application | Raw enums, matching selectors, declared data types and unroll value |
| Application linker | Exact selected build's runtime directory and `-lvortex` |

`sim/rtlsim/Makefile` retains `SV_DPI` and support plumbing; its presence does
not mean the selected tensor/FPU arithmetic is DPI. Arithmetic selection is
established by the enum companions and native source selection, including
the `VX_tcu_core.sv` TFR branch. The audit rejects alternative arithmetic
selectors, opaque macro forwarding, response files, undefines, conflicting
macros, tracing/debug overrides, and fast/finite-only math. This is processor
RTL provenance; it says nothing about AFU, vendor emulation, FPGA, PPA, or silicon.

The initial component checks on actual retained SimX stamps passed all four
roles. Thirty-two mutations, eight per role, failed. Mutations recompute their
record hashes and macro summaries, so rejection does not merely observe a
stale hash. The legitimate frozen spellings `-I../common` in the runtime and
SimX `-MMD -MP -MF <build>/sw/runtime/simx_config.stamp` were explicitly checked
against their Makefiles and accepted narrowly. Syntax compilation also passes.
Earlier configuration-only probes generated all four variants and checked
18 roles without building native executables. The follow-up below checks the
repaired grammar against all 18 actual SimX/RTL compiler roles.

## Independent review follow-up: include search roots

W08B found a concrete coverage gap in the original offline auditor: its broad
absolute `-I` grammar accepted a prepended foreign include directory or an
absolute path containing `..`, even after the mutation's record hash was
recomputed. Actual native records used the expected Makefile paths; no native
foreign-input incident was observed. The finding concerns the audit program's
ability to reject substituted evidence.

Before editing, the original 25,998-byte script was preserved in
[`audit_provenance-542f2e3e.py.gz`](../reviews/history/audit_provenance-542f2e3e.py.gz).
Its decompressed SHA-256 remains
`542f2e3e56b6eb0b0ed88df4e7de1c7c80a55b00634c6f30cd6e3d733c610f13`,
so the original saved failure can be reproduced. The gzip SHA-256 is
`fe1da3d6d2acbd6673ac8c293d01e12e832caf707683832d5211f179c5b5e185`.

The repaired auditor requires the exact ordered include roots for each
runtime, SimX backend, processor-RTL Verilator, processor-RTL C++, kernel, and
host record, derived from the frozen Makefiles. It rejects additional,
missing, duplicated, reordered, substituted, or differently spelled roots.
Only the literal `-I../common` at its expected SimX runtime position is
permitted; arbitrary traversal is rejected. Source/build roots must be
canonical, nonoverlapping absolute paths. Backend and build are explicit
compiler-check arguments, and the selector requirement must match the role.
The command-line interface is unchanged.

The repaired script SHA-256 is
`32f18937591df8e91dd86d6693550748a4d3ed8f1cfd766733d20f0617fa4ab9`.
[`probe_provenance_includes.py`](../reviews/probe_provenance_includes.py)
checks independently rehashed retained stamps and recomputes each mutation's
record hash and macro summary. Its retained
[`provenance-includes-f4c6a3-probes.json`](../reviews/provenance-includes-f4c6a3-probes.json)
records **18 accepted actual roles and 468 rejected mutations**, covering all
four backend/format variants. These include both original reproducers,
reordering/duplicate/missing roots, normalized/traversal aliases, split include
arguments, alternate include transports, and the existing DPI/type/fast-math
guards. No native executable was run by the probe.

W08B independently reviewed the repaired hash, restored the original gzip,
accepted all 18 actual roles, and reproduced rejection of the two original
mutations and an RTL include-order mutation. The old four archives remain
incomplete because their generated configuration dotfiles were not uploaded.
These component checks preserve the original whole-packet failure and do not
claim phase acceptance. Fresh qualification after the separate upload repair
remains required.

## Cache preparation and limits

The actual preparation receipt reports relocation of exactly ten unused
`cocogfx` build products: `.depend`, `libcocogfx.a`, and eight `src/*.o` files.
All recorded before/after byte counts and hashes agree, moved flags are true,
the pinned revision is unchanged, and the final submodule status is clean.
Its source, tool, and dependency identities match the execution packet. The
quarantined bytes were not downloaded, so this is an audit of preserved
identities and the reviewed preparation implementation, not an independent
rehash of those cache products.

The packet records three reused dependency binaries and twenty SimX tool or
runtime-archive identities. Native binaries, tool executables, and dependency
bodies are intentionally not a replay archive. The audit cannot rehash absent
binaries or inventory every system header, compiler support file, and dynamic
library. Cache keys, source pins, flags, and content bindings identify trusted
execution inputs; they do not physically authenticate arbitrary hardware or
protect against a malicious concurrent writer. Numerical and dispatch reviews
have independent owners. This reviewer neither reran native execution nor
changed production code, committed, or pushed.
