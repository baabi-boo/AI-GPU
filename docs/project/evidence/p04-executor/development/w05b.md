## Reviewed data flow

1. The adapter validates the frozen contract and rechecks the reopened fixture
   hash. It copies the existing encoded inputs and format-specific weights into
   distinct `NativeInputs`; expected H/R/Y are separate `ExpectedOutputs`.
   The native app assigns these fields to corresponding members of `MlpCase`.
2. `ManagedMlp` copies the case at creation. Its first native submission
   explicitly serializes copied X and W1 words into little-endian bytes.
   X is row-major; W1 is column-major. The unchanged kernel loads A row-major
   and B column-major with the declared K stride and stores row-major FP32 D.
3. Completed operation output is copied into the stage and hidden arrays while
   its operation still exists. Exact H comparison runs before ReLU. A mismatch
   sets a terminal result, prevents the bridge and prevents dependent launches;
   a different negative value therefore cannot disappear through ReLU.
4. The bridge consumes `trace_.hidden_words`, never the expected H array. The
   unchanged helper first checks all signed values are integral and within
   [-64,64], then applies ReLU and exact FP16/BF16 encoding. Both signed zeros
   normalize to positive zero in the helper; a native negative-zero result still
   fails the executor's earlier exact comparison against canonical positive zero.
5. Output submissions copy actual bridge byte ranges `[0,128)` and `[128,256)`.
   Each range contains eight complete rows of eight two-byte elements. W2 is
   copied from its encoded input field; expected bridge words only participate
   in comparison and cannot become native input through this code path.
6. Both output blocks are copied from completed operation results, independently
   checked against expected ranges `[0,32)` and `[32,64)`, then copied into the
   final array in that order. The final comparison reads the assembled actual
   array. No expected-array assignment or host matrix multiplication exists in
   this production composition.

The three native requests remain `(M,N,K) = (16,8,16), (8,4,8), (8,4,8)`.
The second layer does not introduce an unsupported `(16,4,8)` signature. Byte
extents and row splits agree with the unchanged fixture graph and P03 kernel.

## Independent calculation

One bounded-size Python 3 stdin probe completed with exit 0 in 0.174 seconds.
It imported only `pathlib`, `fractions`, `hashlib`, `json`, `re`, and `struct`;
it did not import the fixture producer, production arithmetic, adapter or model
contract checker. It read the existing JSON/header without modifying either.

The probe decoded each low-half-first packed FP16/BF16 element using explicit
IEEE sign/exponent/fraction fields and exact `Fraction` arithmetic. It required
every decoded input/weight to be an integer in [-2,2], reconstructed both
column-major weight arrays and matched their frozen logical matrices. It then
computed ordinary integer matrix products from those decoded bytes:

```python
def multiply(a, b, m, n, k):
    out, peak = [], 0
    for row in range(m):
        for column in range(n):
            total = 0
            for inner in range(k):
                total += a[row*k+inner] * b[column*k+inner]
                peak = max(peak, abs(total))
            out.append(total)
    return out, peak
```

FP32 results were encoded with standard-library IEEE `struct.pack('<f', ...)`;
FP16 bridge values used `struct.pack('<e', ...)`; BF16 bridge values used the
upper 16 bits of their exact FP32 representation. Every integer in the frozen
bridge domain is exactly representable by both formats. The probe compared:

| Source-only check | Observed successful comparisons |
|---|---:|
| Hidden FP32 words | 1,280 |
| Packed bridge words | 640 |
| Final FP32 words | 640 |
| Independently recomputed split output versus whole output | 640 values |
| Header word literals versus all ten original case/weight/reference sequences | 4,640 |

All ten cases passed. The split calculation independently multiplied bridge
elements `[0,64)` and `[64,128)` and concatenated their 32-element outputs.
The dense case changed when ReLU was omitted; the split-boundary case had
different output halves and different rows 7 and 8. Zero-case intermediate
and output words were all canonical positive zero.

The observed integer accumulation-prefix maxima were identical across formats:

| Family | Hidden prefix absolute maximum | Output prefix absolute maximum |
|---|---:|---:|
| `seeded_dense` | 26 | 86 |
| `negated_dense` | 26 | 80 |
| `zero` | 0 | 0 |
| `signed_basis` | 4 | 34 |
| `split_boundary` | 24 | 50 |

These observations fit the unchanged proof bounds 64 and 1,024; they do not
replace those bounds or demonstrate native tensor arithmetic. The accepted
P02 reduction contract remains the prerequisite for native arithmetic claims.

The probe hashed all 13 inputs before and after its calculation and required
the inventories to match. Existing W02F source/host fault-injection coverage
already exercises negative H corruption before ReLU, signed-zero corruption,
bridge mismatch, swapped rows and output corruption. Its reviewed executor,
bridge and generated-header hashes match this review, so the broad suites
were not redundantly rerun.
