# Wave 1A — managed model runtime audit

Reviewer: `/root/w01a_runtime_audit` (independent architecture audit).
Source inspected: `041f0981b2648dd5ec1494f4c1ca0300da8b9ca6` on `master`.
Scope: static source inspection only. No host test, native launch, or GPU

## Conclusion

P04-T02 can reuse the accepted managed matmul API without extending its
supported shapes, device argument ABI, native arithmetic or kernel. Add a
small fixed-model owner and its native regression harness. Do not introduce a
generic graph engine or a fallback arithmetic path for this bounded milestone.

The three calls already fit `ManagedMatmul::submit`: `(16,8,16)` followed by two
`(8,4,8)` calls. `submit` copies A/B inputs into operation-owned storage before
enqueueing. `prepare_mlp_hidden` supplies the exact host bridge. The missing
parts are model composition, retained model-level ownership/state, ordered
comparison and lineage records, regression integration, and independently
verified execution receipts.

## Concrete API and lifetime findings

1. **Completion and success are separate.** `ExecutionResult::ok()` checks
   validation, primary and cleanup statuses; it does not check `complete`.
   Successful submission is normally incomplete. Only a successful complete
   wait permits consuming `output_words()` or starting the dependent stage.

2. **Submission failure may still own live work.** `ManagedMatmul::submit`
   deliberately returns a `MatmulOperation` after partial enqueue. Store that
   object before branching on the result. Preserve the original submission
   outcome, then drain explicitly and preserve the independent close outcome.
   Do not let a later drain success erase the failed submission.

3. **A timeout is not bounded cancellation.** `MatmulOperation` destruction
   repeatedly calls infinite close until the operation completes. Returning
   from a helper with an in-flight local `unique_ptr` invokes that destructor
   and can block indefinitely. A model object must retain its active operation
   across an incomplete return and allow a later explicit drain. A command
   runner may impose a process-level deadline, but that is not successful
   runtime cancellation.

4. **References cannot outlive an operation.** Copy both the actual output
   vector and trace before resetting the operation. Closing it preserves its
   output and trace while the object remains alive, but resetting it does not.
   Trace snapshots should include the final close status and final wait counters.

5. **The runtime owner can outlive or precede operations.** Operations hold
   shared context ownership. `ManagedMatmul::close()` returns an incomplete
   timeout while any operation retains that context. Close operations first,
   inspect cleanup results, then close the owner and require completion.

6. **Failure and evidence validity need explicit state.** Uncreated entries in
   `MatmulTrace::event_results` default to success values. Enqueue counts and
   observation state must distinguish unobserved/skipped events from completed
   successful commands. A failed model must never expose a stale final result
   as valid.

7. **Resource counters are available while the owner is live.** Capture
   `memory_info` after owner creation, before a case, and after releasing all
   of that case's operations. Compare both used and free bytes. The owner is
   already closed when its device handle becomes unavailable, so an after-close
   query cannot supply the comparison. Report owner close separately.

## Fixed model data flow

Keep invocation inputs and comparator data separate. A fixed invocation can
own 512 X bytes, 256 W1 bytes and 64 W2 bytes, while its comparator owns 128
expected hidden words, 256 expected bridge bytes and 64 expected output words.
Explicit ownership makes timeout retention safe if caller storage disappears.

The execution sequence must be:

1. Submit the hidden projection and retain its operation even on error.
2. Complete it, copy its 128 actual words and trace, and close it.
3. Compare actual H exactly before ReLU. A negative mismatch must stop here.
4. Pass those actual H words to `prepare_mlp_hidden`; require bridge success.
5. Compare the produced bridge bytes exactly. Submit byte slices `[0,128)`
   and `[128,256)` as the two real output-stage inputs.
6. Complete, copy, compare and close each 32-word output block sequentially.
7. Copy the actual blocks into offsets 0 and 32 words of the 64-word result,
   then perform the complete final comparison.

`copy_row_blocks` is a label in the execution plan, not an existing function in
the inspected source. Two fixed array copies implement this operation without
adding generic tensor-stride semantics. Expected H, bridge and Y arrays must
never supply native input bytes.

## Recommended interface

Use a noncopyable `ManagedMlp` or equivalent fixed-model operation owner with:

- Owned input/comparison storage and a single retained active matmul operation.
- A small explicit state enum for hidden, bridge, output block 0, output block 1,
  assembly, failed/draining and complete.
- A bounded advance/wait operation and explicit bounded close/drain operation.
- Separate model/comparison/bridge status, original runtime results, close
  results, resource observations, and a final-output-valid flag.
- Stable operation IDs, row ranges and predecessor IDs accompanying copied
  native traces; actual host bridge and assembly records.

Failure is terminal for graph execution: drain may finish ownership cleanup,
but must never resume dependent graph work after a failed comparison or native
error. A new attempt needs a new result record. A transient timeout may permit
later completion of the same stage, but its observed timeout remains recorded.

The runner, not an arbitrary string accepted by the model object, must verify
the fixture/source/backend/kernel/compiler identities before it constructs the
existing `ExecutionBinding`. The profile booleans and a 64-digit qualification
ID alone do not authenticate artifacts.

## Timing and traffic gap

`MatmulTrace` currently exposes counts and device spans but no per-command
timing. Host duration around `submit` or `wait` cannot isolate native work from
transfers because both occur in the same asynchronous queue.

The installed `vortex2.h` API already defines `VX_QUEUE_PROFILING_ENABLE`,
`vx_profile_info_t` and `vx_event_get_profiling`. The current managed wrapper
calls `vx_queue_create(..., nullptr, ...)`, so profiling is not enabled.
An internal opt-in binding flag and copied per-event profiling records can
supply the required five-event observations without changing the installed ABI.
The order is A write, B write, output-poison write, launch, read. Record query
success separately from event completion, and describe timestamps as runtime
host-clock observations, not physical-device timing. Independent review should
check profiling semantics in the queue/backend implementations before treating
their intervals as separate durations.

Model wall timing, explicit host bridge/comparison/assembly timing and event
intervals overlap or nest; do not add them to claim physical throughput.
Successful tensor traffic is 1,920 H2D bytes and 768 D2H bytes per case.
For partial failures, derive submitted/observed traffic from actual enqueue
counts rather than unconditionally recording these planned totals. Argument,
control, module and setup traffic remain outside tensor-buffer accounting.

## Targeted verification obligations

Host mocks should exercise complete composition and input lineage, a corrupted
negative hidden value, each output-block mismatch, bridge rejection, partial
submission, a timeout followed by completion/drain, late-stage errors, cleanup
errors, repeated use and restoration of memory counters. They establish host
control-flow behavior only. Qualification still requires the declared frozen
case inventory on actual SimX and the selected native processor RTL path,
with independent raw-bit and trace reconciliation.
