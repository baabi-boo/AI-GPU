## Reviewed properties

- The adapter validates the existing frozen source contract before reading
  cases. The inherited checker verifies canonical fixture reproduction and
  matches the target checker/reference/encoding-helper bodies to the invoking
  implementations.
- Reopened fixture bytes must match the hash returned by validation. The
  focused replacement test confirms that a change between validation and the
  second read is rejected.
- Every case is copied independently. Weight arrays are selected by that
  case's format without transposition, arithmetic or floating conversion.
  Header `NativeInputs` and `ExpectedOutputs` are distinct types within an
  immutable `inline constexpr` fixture array.
- The C++ round-trip checks all 4,640 emitted words against the original JSON,
  including both weight matrices, all intermediate/final references, case
  order, IDs, formats and fixture identity. The generated word values preserve
  the existing low-half/earlier-element packing convention. Explicit
  little-endian transfer serialization remains the consumer's responsibility.
- Generated-header reads reject symlinks and oversized files; rendering is
  bounded to 256 KiB. `--check` does not repair or mutate inputs. Explicit
  regeneration changes only the derived header in the tested copied checkout.
- Source/reference checks and CLI messages make no native-execution claim.

The adapter and header are new execution inputs outside the historical P04-A01
manifest. The P04 runner must retain their identities and check the generated
header against the validated fixture before building. This is an integration
obligation, not a defect in the unchanged historical manifest.
