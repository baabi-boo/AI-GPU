- **F0, high confidence, static proof — source handoff is deliberate.**
  `configure` does not copy `ci/project`. The catalog's shared Python bootstrap
  reads one bounded literal source path from the generated configuration and
  executes the source wrapper. The wrapper verifies RV64, its selected source
  bytes, outside-source tools and fresh outside-source work/evidence paths.
  It explicitly selects both formats and two repetitions for its backend.
  The native runner rebuilds fresh variants instead of executing the downloaded
  general-CI app artifacts.
- **F0, high confidence, static proof — exact source identity is checked after
  restoration.** Recursive submodule initialization precedes dependency-cache
  restoration. Preparation checks the requested workflow SHA before moving
  tools and checks it again through `collect_source`, which rejects dirty
  tracked/nonignored source and invalid recursive submodule provenance.
  Restored tools are not hidden with a new ignore rule. They are atomically
  renamed to a fresh outside-checkout destination only when no tracked files
  would move and source/destination use the same filesystem.
- **F0, high confidence, static proof — cache labels are not substituted for
  actual input identities.** Preparation accepts the resolved pinned toolchain
  with an exact lite/full key and the exact dependency key. It then inventories
  actual tool and library hashes. A dedicated-workflow cache miss blocks with
  a concrete cache-warming remedy; it does not silently build an unpinned
  toolchain or claim success. General CI checks the shared action's exact hit
  outputs and repeats toolchain resolution before preparation.
- **F0, high confidence, static proof — failure evidence remains separate from
  execution evidence.** Both routes initialize an explicit `not_run` job
  receipt before preparation and unconditionally upload available packet
  files. The helper's success still says `native_execution: not_run` and
  `acceptance_claimed: false`. No new step uses allowed failure. The native
  command has two build jobs, finite per-command limits and the runner's
  process-group memory/disk/log guards; the hosted jobs add outer time bounds.
- **F0, high confidence, independently checked — existing general CI behavior
  is preserved.** Removing the five steps conditional on `p04_mlp` and the
  added output identifier reconstructs the base workflow's parsed structure
  exactly. Existing test selections, gates, aggregates and shared setup action
  are unchanged. This is additional model coverage, not a coverage reduction.
