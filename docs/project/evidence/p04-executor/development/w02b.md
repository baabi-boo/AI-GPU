## Implemented change

The internal `ExecutionBinding::enable_profiling` flag defaults to false.
Unprofiled managed submissions continue to pass a null queue-info pointer.
Enabled submissions request `VX_QUEUE_PROFILING_ENABLE` with the existing
versioned queue-info structure and normal priority. No installed API changed.

`MatmulTrace` now retains `profiling_enabled`, five raw `event_profiles`, five
`event_profile_results` and five `event_profile_queried` flags. Profiles are
queried exactly once after completion and before event release. Failed queries
retain their error and no timestamp payload. Disabled or uncreated slots retain
`queried=false`, `VX_ERR_NOT_SUPPORTED` and zero-initialized timestamps. A timeout
does not query incomplete work. Closed traces retain their captured records.

Profiling is diagnostic: query failure does not alter the arithmetic result,
primary execution error or cleanup error. Qualification consumers must require
actual queried slots, successful query and event outcomes, and ordered timestamps.
Successful profile retrieval for a failed/skipped command does not make that
command successful. Zero-duration intervals are permitted.

The values originate from the existing host steady-clock queue instrumentation.
For launch commands, argument staging and control programming precede `start_ns`;
`start_ns - submit_ns` and `end_ns - start_ns` have distinct meanings. No native
cycle, physical DMA duration or board-speed interpretation is added here.
