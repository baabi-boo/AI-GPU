## Observed failure and bounded correction

The first hosted model attempt at published source
`7167ce17d335ec1f50e26da9b4832c1c27013ada` stopped before native execution.
The retained [preparation receipt](../failed-attempts/7167ce1-simx-fp16/preparation.json)
identifies the correct source/gitlink identities and reports only
`third_party/cocogfx` as a changed submodule. W06C independently inspected its
pinned Makefile and reproduced the cause: the submodule has no `.gitignore`,
and the shared cache contains its untracked `.depend`, `libcocogfx.a` and
top-level `src/*.o` build products. These products are not model dependencies.

The preparation helper now preserves only those recognized products outside
the source checkout. Before moving any product, it checks:

- The parent HEAD records a submodule gitlink, the index still records that
  same gitlink, and the initialized submodule HEAD matches it.
- Porcelain status contains only untracked entries. Staged changes, working
  changes, and a staged change hidden by a restored original worktree all block.
- Every reported untracked name is `.depend`, `libcocogfx.a`, or an object whose
  corresponding C++ file is tracked directly under `src`. Nested and unmatched
  object names block the entire batch.
- Existing recognized product paths are regular files without symlink traversal,
  including special file kinds that Git itself omits from status. Candidates
  must share the workspace filesystem for atomic rename.
- The quarantine destination is fresh, and cocogfx has not become a named model
  dependency.

All candidate identities are collected before any rename. Files are then moved
to `workspace/cache-quarantine/cocogfx`, preserving their bytes and inodes.
The preparation receipt records original path, destination, size, SHA-256,
per-file moved state, after-move identity and submodule status/revision before
and after. A partial filesystem failure remains blocked and records which files
were moved; each original byte sequence remains at its original or quarantine
path. There is no broad cleanup, source reset, ignore rule or dirty-source waiver.

The existing complete `collect_source` check still runs afterward and must pass.
The named softfloat/Ramulator dependencies are neither moved nor changed. The
dedicated workflow and general catalog already use this helper, so no workflow
edit was necessary.
