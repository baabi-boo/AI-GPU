## Scope and implementation

Added `ci/project/test_p04_app_contract.py` and
`ci/project/fixtures/p04_app_contract_test.cpp`. The harness includes the real
native app source under a renamed entry point, so its parser, module reader,
profiling predicate, format guard, and serializer are tested directly.

The harness has explicit fail-closed native-create and status-string stubs.
Accepted app arguments reach the create stub with the actual frozen inputs,
expected outputs, compiled format, profiling flag, qualification identity, and
module extent; the stub then returns `VX_ERR_NOT_SUPPORTED`. Any unexpected
attempt to advance, close, or inspect a stub model aborts. No native runtime or
device operation is implemented by this harness, and it does not validate the
production status-string mapping.

The eight test groups cover:

- All required option values, permutations, missing/duplicate/empty options,
  unknown/unpaired options, malformed iteration counts, noncanonical identities,
  absent drivers, and backend/driver mismatches.
- The real app's early case/compiled-format, backend, and module guards in both
  FP16 and BF16 builds; rejection occurs before native create.
- Missing, zero-byte, 15-byte, 16-byte, 64-byte, exactly 16 MiB, and 16 MiB + 1
  module inputs, including full successful reads and untouched invalid outputs.
- Every native observation flag, event count, event success/query result, and
  each monotonic timestamp relation in the app's profiling predicate. Observed
  zero-duration profiles remain valid.
- Every stage's invalid array extent, including immediate overflows and maximum
  `size_t`; zero, one-element, and full-capacity prefixes; unsigned 32/64-bit
  values; null operation IDs; enum formatting; quote, slash, control, NUL, and
  UTF-8 string encoding; JSON output despite stream hex/boolalpha state.
- Actual C++ serializer output consumed by the strict Python verifier for all
  ten frozen cases, both backend labels, and both poison values: 40 explicitly
  synthetic records. Exact duration/resource/profile observations supplement
  the verifier's complete field/type and numerical lineage checks.
- Corrupted launch wire bytes, actual bridge-slice input bytes, profile-query
  flags, and profile ordering in the second poison record, for both formats.

The Python driver compiles both binaries with C++17, `-Wall -Wextra -Werror`,
UBSan, and fail-fast sanitizer behavior. It resolves the accepted P02 compiler
profile through the real configuration generator. Every compile and execution
uses `tensor_host_tools.run_host_command` with a finite deadline and existing
RSS/log/disk bounds. Scratch output stays below 64 MiB. SHA-256 identities of
17 source/fixture/configuration inputs are taken before compilation and checked
after every test.
