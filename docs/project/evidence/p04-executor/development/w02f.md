## Changes and test boundary

Added `ci/project/fixtures/p04_mlp_runtime_test.cpp` and
`ci/project/test_p04_mlp_runtime.py`. The harness links the real
`mlp_runtime.cpp` and unchanged `mlp_host.cpp` against test-only replacements
of `ManagedMatmul` and `MatmulOperation`. It does not link `runtime.cpp`,
execute GPU arithmetic, or replace the existing P03 tests of the real managed
operator wrapper.

The mock returns predetermined response words from the frozen fixture and
records every submitted shape, poison and actual A/B byte span. Assertions
compare the executor's submissions directly with independently serialized
fixture inputs and actual bridge slices. Mock outputs and synthetic profiling
timestamps are never represented as native observations.

Fourteen discovered groups cover:

- All ten frozen cases and both poisons, three ordered native-stage requests,
  exact observed H/bridge/row blocks/logits and restored resources.
- Caller mutation of inputs, weights, references, identity, dtype and poison
  after creation; the owned case remains unchanged.
- Two consecutive timeouts at each stage, retained ownership, no premature
  destructor drain, and resumed completion without duplicate submission.
- Every-stage immediate and partial submission errors; partial draining retains
  the original allocation error while `complete=false`, even though that error
  is not `VX_ERR_TIMEOUT`.
- Every-stage asynchronous failure and cleanup failure, including simultaneous
  primary and cleanup errors with their distinct results preserved.
- A negative hidden-word error that ReLU would hide, signed-zero corruption,
  a bridge-reference mismatch, swapped output row blocks and first/last output
  corruption. Dependent work stops at the failing boundary.
- Nine invalid hidden-domain values that match a test-local hidden reference
  but must still fail the real bridge before a dependent submission.
- Close before execution, during every pending stage, after completion and
  repeated calls; explicit close and destruction drain without finishing the graph.
- Invalid creation, setup failures, memory-query errors, changed resource counts,
  owner cleanup failure and incomplete owner-close observations.
- Oversized and undersized output spans at every stage, rejected before copying.
- Host allocation failure before creation and trace-copy allocation failure
  after each submission, preserving the pending operation for explicit drain.
- Thirty-two successive model creations and releases with zero owned handles
  and zero tracked active bytes afterward.

The native sequence contract was reconciled with the parent and implementation
owner to use `0,1,2`; the successful-graph test checks it.

Final result: **14 tests passed in 11.485 seconds**, no failures, errors or
skips. Compilation used C++17, `-O1 -Wall -Wextra -Werror`, UBSan with recovery
disabled and a bounded 45-second compile. Each group has a 10-second bound;
the shared host-command helper limits RSS to 1 GiB and retained output to 1 MiB.
Source identities were checked after each group and temporary outputs stayed
below 64 MiB. A separate Python check confirmed final newlines, no trailing
whitespace and no tabs in both added files.

Two earlier harness failures remain explicit:

1. The first compile ran zero tests because GCC 14 diagnosed an inlined
   replacement allocation/deallocation boundary as mismatched new/delete.
   Replacement functions now use explicit non-inlined boundaries. Warning
   enforcement and UBSan remain enabled.
2. The next run passed 13 groups and failed `invalid_create` because the mock
   incorrectly asserted that a previously closed owner could not be queried.
   The real wrapper returns `VX_ERR_INVALID_HANDLE`; correcting the mock to
   that contract produced the final 14-group pass. No production fix was made.
