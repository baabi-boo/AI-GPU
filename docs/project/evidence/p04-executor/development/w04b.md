## Scope and result

Independently inspected `ci/project/p04_ci_prepare.py` and added the durable
host-only suite `ci/project/test_p04_ci_prepare.py`. The production preparation
helper and workflow were not changed. No blocking production defect was found
in the reviewed preparation paths.

The suite exercises actual disposable Git checkouts, actual source-status and
submodule observations, actual SHA-256 artifact hashing, atomic directory
relocation and receipt writes. Each fixture contains visibly synthetic
dependency bytes and a cache marker; it contains no executable GPU tools.
Available RAM, free disk and native tool inventory are controlled observations.
The tests do not establish that hosted caches exist or that their binaries run.

The 13 test groups establish the following development properties:

- Exact 4 GiB available RAM and 15 GiB disk boundaries permit preparation, for
  both accepted toolchain cache profiles and both backend selectors. The
  original cache marker inode is preserved by relocation. Actual clean-source,
  dependency and preparation-source identities are retained in the receipt.
- Invalid VERSION pins, malformed or different source revisions, absent or
  mismatched cache keys and unknown or insufficient resources block before
  cached tools move or the tool inventory runs.
- Existing destination files, directories and dangling symlinks are preserved.
  Symlinked cached tools, workspace traversal and symlinked evidence directories
  are rejected. The cross-filesystem case blocks before a rename or copy.
- A real tracked file under `tools` prevents relocation. A real tracked change,
  nonignored untracked input or uninitialized Git submodule blocks preparation
  after preserving the relocated cache for inspection.
- A real new Git commit inserted between the preliminary HEAD check and final
  inventory is rejected by the second source-revision check.
- A tool-inventory failure or missing dependency retains a blocked receipt.
  CLI cache failure returns nonzero, and a second call cannot overwrite either
  the receipt bytes or its modification time.

Every emitted test receipt explicitly retains `native_execution: not_run`
and `acceptance_claimed: false`. The positive test also checks the environment
passed to the inventory: no inherited HOME and an explicit two-job make limit.

## Validation

Executed from the source checkout:

```sh
python3 -m unittest discover -s ci/project -p test_p04_ci_prepare.py -v
```

Final result: **13 tests passed in 5.179 seconds**, without skips. A separate
owned-file whitespace check passed. Preparation-source identities were checked
after each test and remained unchanged.

Test fixture Git mutations use the existing bounded host-command helper with
a 20-second command timeout, 1 GiB process-group RSS limit, 1 GiB disk reserve
and 1 MiB output cap. The helper's own source observations retain their existing
timeouts. All Git operations are local, and no submodule is downloaded.

The first development run had one harness error: automatic Git maintenance
removed a transient lock file while a disposable checkout was being copied.
The test helper now disables automatic maintenance and garbage collection for
its local fixture commands. The corrected complete run passed. This was a test
fixture race; no production guard was relaxed.

These are shared-development-checkout results, not a clean-revision native
qualification packet. No native compile, simulator execution, hosted workflow,
phase acceptance, commit or push was performed by this agent.
