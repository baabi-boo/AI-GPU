not a native rebuild, execution result, physical performance claim or phase
acceptance.

## Compatibility proof

- `ExecutionBinding::enable_profiling` is an appended member initialized to
  `false`. The existing P03 application uses ordinary default construction and
  assigns the original fields individually. It does not enable profiling.
  A separate bounded compiled probe also confirmed that the original five-field
  aggregate initialization remains accepted and ordinary, aggregate and copied
  bindings all leave profiling disabled.
- The context copies that flag, and an unprofiled submission still passes
  exactly `nullptr` to `vx_queue_create`. No event profiling API is called on
  that path. Existing primary-error, wait, timeout, cleanup and shared-owner
  rules are otherwise unchanged in the diff.
- `MatmulTrace` gains fixed storage with explicit defaults. The existing P03
  serializer selects its original fields explicitly; it neither serializes
  object memory nor enumerates the added members. Its record producer and
  strict Python consumer remain byte-identical to the base revision.
- The new completion call uses the already declared/exported
  `vx_event_get_profiling`. `sw/runtime/stub/Makefile` already links
  `sw/runtime/common/event.cpp`, which supplies that C symbol. The installed
  `vortex2.h`, queue/event implementation and backend C API are unchanged.
- The AI wrapper remains an internal source component. The P03 Makefile builds
  its current `runtime.cpp` with the current application and includes `runtime.h`
  in its header dependencies. The new model does the same. This review makes
  no binary-layout compatibility claim for mixing independently compiled old
  and new internal C++ structs; no such installed ABI is introduced.
- Query failures stay diagnostic and cannot overwrite arithmetic or cleanup
  outcomes. The model qualification consumer separately requires successful
  event/profile observations. Default P03 execution does not acquire that new
  qualification requirement.

The existing runtime lifecycle tests exercise the installed C API directly and
do not depend on the enlarged internal C++ trace layout. The source-wide client
search found the P03 application, new model composition and host mock harnesses;
no additional production `ManagedMatmul` client was missed in this review.
