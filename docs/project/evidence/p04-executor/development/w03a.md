## Implementation

- Added `tests/regression/ai_mlp/Makefile`, reusing the unchanged native matmul
  kernel, internal managed runtime, accepted arithmetic-profile guard and
  `vortex2` kernel library. Header prerequisites include the model executor,
  bridge, generated fixture and record serializer.
- Added `main.cpp` with strict required arguments, duplicate/unknown rejection,
  lowercase source/binding identities, compiled-format validation and an exact
  match between the requested backend and `VORTEX_DRIVER`.
- The application supplies copied fixture inputs and separately stored expected
  arrays to `ManagedMlp`. Profiling is enabled. Two repetitions use distinct
  output poisons. Finite one-second waits preserve model ownership on timeout;
  the trusted runner supplies the hard process deadline.
- Runtime or numerical failures retain a `P04_FAILURE` trace and explicitly
  drain the owner. Cleanup and profiling validity are checked before a
  `P04_RESULT` record. No failing invocation prints the final `PASSED!` marker.
- Added `records.h`. `p04::write_result` writes a JSON object from the live trace,
  preserving every public model, native-stage and managed-dispatch field. It
  uses explicit lowercase word/byte encodings, real boolean types, raw result
  values and all four event timestamps. Invalid fixed-array extents throw;
  unused suffixes are never serialized. Frozen expected arrays do not supply
  observed output records.

The serializer follows
[`mlp_execution_records_v1.md`](../../../../designs/mlp_execution_records_v1.md).
Successful submission's `complete=false` is preserved independently from later
successful completion and cleanup. Profiling query validity is distinct from
timestamp values; zero-duration intervals are permitted.
