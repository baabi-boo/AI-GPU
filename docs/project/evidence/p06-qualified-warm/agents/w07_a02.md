## Findings and corrections

### W07-A02-F1-01 — Optimization could disable operator-helper assertions

**Severity F1; confidence high; evidence type static-proof.** The dependency-pin
and archive-packaging heredocs originally invoked Python with `-B` and inherited
`PYTHONOPTIMIZE`. They contain four and seventeen assertions respectively. In an
operator environment with optimization enabled, those assertions disappear even
though the packaging helper can emit affirmative verification flags. This is a
guard in the operator recipe; the production reader's explicit checks are not
weakened by this issue.

With coordinator authorization, both standard-library-only helper invocations
now use `-I -B`. Isolated mode ignores the Python optimization environment
setting. Native producer and reader invocation flags were not changed. A small
in-memory compilation/disassembly control records assertion removal at
optimization level one; it executes neither runbook heredoc nor retained code.

### W07-A02-F1-02 — Nonzero replay exit was described too narrowly

**Severity F1; confidence high; evidence type static-proof.** Section 6 originally
equated every nonzero exit with consistency/qualification failure. The actual
CLI catches `OSError`, including output creation or writing errors after a valid
replay. The paragraph now requires inspecting the reason and distinguishes
qualification rejection from output I/O failure. Neither an unsuccessful
command nor incomplete output is treated as an experimental result.

Both findings are closed in the reviewed runbook. Its original SHA-256 was
`a475b3f5083e411b0b82b484a1cb3759df765e5851c3bfa55923fc24496f6ac1`;
the corrected identity and complete per-input identities are in the receipt.
