## Bounds, cleanup and outcomes

The suite command receives 3,600 seconds; the command schedule has a 5,400-second
overall allowance. Each child receives at most the remaining allowance and its
own selected maximum. Logs are opened exclusively, monitored against a 64 MiB
polled budget, hashed and retained. The record acknowledges that polling can
observe an overrun after it occurs.

Each command starts a new session. On a deadline, excess log, interruption or
remaining live process-group member, the supervisor attempts bounded TERM then
KILL and observes the remaining group. Nonzero exits, unstarted commands,
exceptions, incomplete cleanup and remaining commands prevent a passing final
record. Ordinary failed commands may be followed by other checks only after
cleanup; every failed result remains in the final failure list. Interrupted or
unstarted commands are distinguished from passes.

Before/after inventories record all index entries and actual regular-file
hashes, symlink text and Gitlink identities. A pass additionally requires exact
inventory equality, clean final status, unchanged revision/tree, all commands
attempted and no failure. Atomic replacement of the status receipt preserves
the preceding status if a later update cannot complete; an interrupted update
does not create a newly successful execution.
