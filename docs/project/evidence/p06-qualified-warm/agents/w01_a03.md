## Critical implementation finding: native pair-zero restriction

`tests/regression/ai_counter_preflight/main.cpp:2-4` includes the unchanged warm
caller and renames its entry point. `run_preflight` then explicitly requires
`opts.pair_index == 0 && opts.phase == "warmup"` at lines 522-523 before invoking
the caller. Merely extending the Python process plan to pairs 1-5 will fail at
the first measured process.

That main file is one of the proof's 69 `measurement_sources`. The trusted
contract enforces both raw and canonical proof identities
(`ci/project/p06_counter_qualification_contract.py:122-149`) and checks every
measurement source descriptor (`:201-215`). The original control replay also
compares every one of those source descriptors against the retained original
(`ci/project/p06_counter_qualification_prerequisites.py:249-252`). Consequently,
replacing a digest in the old proof or supplying a revised proof to its old
control reader would misstate the original relationship and must not be the
implementation strategy.

The current harness also emits a fixed inner
`preflight-simx-<format>-<policy>` process ID, plus the fully bound `sample_id`
(`main.cpp:389-397,447-454`). Across six pairs, the fixed inner ID alone is not a
unique process identity. The new route must validate the exact pair/phase/sample
identity and its prelaunch binding; a matching format/policy or shared binary
is insufficient.

## Recommended explicit projection extension

1. Keep the original proof bytes, proof contract, diagnostic archive, control
   archive and historical reader semantics unchanged. Verify those originals
   through their original trusted paths, including all 69 historical source
   joins. The historical diagnostic source population stays excluded from the
   actual measurement build.
2. Define a separate warm qualification envelope with its own fixed identity.
   Bind the original proof digest, original prerequisite results and the frozen
   warm sampling digest. Record the exact old and new descriptors for every
   reviewed native/build input change and any added entry-point source. Require
   the actual warm projection to equal the unchanged base projection plus
   precisely that reviewed extension. Reject omitted, extra or independently
   rehashed substitutions; do not add a generic source-check bypass.
3. Make native full-warm selection explicit. Preserve the old pair-zero entry's
   rejection semantics. The new entry must admit only the frozen six pairs,
   pair-zero warm-up versus pairs-one-through-five measured phase relation, both
   exact policies and their canonical sample IDs. Keep the per-process workload
   at one prime and 32 serial closed operations. Bind and retain the actual
   compiled entry point and wrapper flags, not merely an unused historical file.
4. Independently review the narrow source diff for the projection extension.
   The allowed change should affect admission/identity only: no counter updater,
   reset, destructor, callback, workload, timer boundary, output check or resource
   guard change. If any such behavior changes, its premise needs new evidence.
5. The new reader reconstructs the warm extension and its per-process bindings
   explicitly. It must not strip fields, relabel a preflight archive, infer mode
   from packet metadata or turn a synthetic summary into qualification.

The coordinator may choose a separate native entry point or an explicit mode in
the existing harness. Both require an exact, reviewed actual-build projection;
neither permits treating the old four-process report as evidence about the new
24 native lifetimes.

## What transfers, and what must be proved again

The source theorem has **33 available selectors, 40 backing cumulative
components and 12 unavailable selectors**. Six D-cache two-bank sums and one
two-buffer TCU sum account for the seven additional components. The proof is
per lifetime, not per aggregate campaign: each warm process still has exactly
33 launches. Increasing the process population from four to 24 does not itself
increase any one lifetime's operation count or require a larger numeric bound.

The terminal-vector argument remains conditional:
`S_j(t) <= S_j(T) <= 2^64 - 1`. It requires checked monotone components,
checked aggregate sums, and a no-update suffix through destruction. Endpoint
subtraction and small observed values alone do not prove it
(`docs/designs/complete_counter_qualification_v1.md:17-45`).

| Premises | Fresh obligation for every actual warm process |
| --- | --- |
| P01: exact route/inventory | Actual RV64, serial timing, checked counters, fixed p02-tfr topology, generated/effective flags, exact available/unqueried inventories and loaded-library identities. |
| P02-P03: origin/update/reset | Zero unseeded opening vector; all 33 run/reset boundary pairs; no checked failure; drained, idle, zero-pending state before every permitted reset. |
| P04: terminal aggregate | All 33 successfully checked terminal aggregates and all 66 full-width terminal half replies. Per-component checks alone are insufficient. |
| P05-P06: completion/ownership | All operations explicitly closed, real queue joins, final device reference, zero live buffers, collected execution, completed flushes and terminal zero pending reads. |
| P07: coherence | Exclusive public core-zero replies, no GPU tick/reset during each full vector, correct low/high reconstruction, successful enabled/error-free CP and restored class. |
| P08: terminal suffix | Terminal state equals destructor-entry state; actual complete final destruction; no post-terminal selected-counter update. |
| P09: dependency behavior | The unchanged 21-source dependency projection joined to fresh compilation, link inputs, loaded products and their stability. A cached hash is insufficient. |
| P10: failure containment | Exact old diagnostic/control prerequisites remain verified; any new guard, query, prime, operation or cleanup failure invalidates the whole attempt. No same-context recovery or replacement sample. |

Pending reads remain a transient balance, not a 41st cumulative component.
The new qualified warm result is restricted to the exact reviewed route and
fresh recorded population; it cannot qualify RTL, other configurations or
future native processes.

## Frozen performance decision

The exact order is FP16 then BF16, ascending pair index 0-5, reference first for
even pairs and candidate first for odd pairs
(`ci/project/p06_warm_contract.py:339-350`). Every process's prime and both
formats' entire warm-up pair remain in the evidence but outside the criteria.
No replacements, outlier removal or optional stopping are permitted.

Keep all existing conditions without rounding substitutions:

- Batch statistic: arithmetic mean of the 32 timed intervals.
- Candidate median at most 95% of reference median, evaluated by exact integer
  cross-products.
- Every measured candidate pair no slower in host time.
- Every measured candidate pair no larger in qualified modeled cycles.
- Both FP16 and BF16 satisfy all conditions.

The arithmetic is already isolated in
`ci/project/p06_warm_analyze.py:203-234`; the historical analysis route itself
must retain its unconditional high-half block (`:71-84,237-259`). A new trusted
route can reuse the fixed arithmetic only after complete new qualification and
provenance. It must not use the old conditional result as proof of qualification.
The metric remains instrumented host time, including comparison and explicit
close; do not subtract observer overhead, supervisor delay or primes from an
already defined batch statistic. Report the guarded/lifetime-instrumented build
scope and keep identical binaries for both arms within each format.

## Independent validation required before execution

Require separate review of native admission and the frozen projection extension,
the full source/build/load join, each lifetime's P01-P10 obligations, new reader
inertness/input stability, and exact sample/analysis identity. Focus rejection
tests on omitted/duplicate/reordered pairs, measured data labeled warm-up,
cross-process or stale bindings, a proof change outside the reviewed extension,
source changes after admission, missing halves or terminal rows, failed prime,
unjoined ownership and destruction failure. Historical pair-zero and warm-v1
rejection must remain covered.

A passing complete archive should derive a separately named/scoped warm
qualification result. Preserve the seven false fields in historical nested
records. Replay still reports `native_execution="not_run"`,
`retained_code_executed=false` and no origin authentication. A valid experiment
whose fixed performance predicates fail is a useful negative result, not a
reason to weaken thresholds or rerun selectively. Phase and performance
acceptance remain distinct reviewed decisions.
