## Concrete findings

1. **The reusable complete reader is `_QualifiedReplay`, not the old warm reader.**
   `p06_counter_qualification_replay.py:89–160` subclasses
   `p06_dependency_native_replay._NativeReplay`, adds the proof/prerequisite
   reconstruction, and already exposes route/build/process/stability/result hooks.
   `_NativeReplay` reconstructs source, five loaded libraries, fresh dependency
   products, all model objects/link maps, complete application invocations,
   generated configuration, raw numerical records and destruction. The old warm
   reader has the 24-process plan and arithmetic but lacks this later evidence.

2. **Simply changing counts cannot produce a real warm run.**
   `tests/regression/ai_counter_preflight/main.cpp:522–523` requires pair zero and
   phase `warmup`; lines 392 and 450 hardcode the preflight process identity.
   This file is one of the 69 immutable measurement sources in the existing
   `d12718e9…` proof. Python mirrors those restrictions in
   `p06_managed_preflight_records.py:262–281` and
   `p06_native_lifetime_records.py:138–147`. An explicit new native argument and
   identity route must be reviewed and source-bound before using measured pairs.

3. **The original proof/control relationship must remain historical.**
   `p06_counter_qualification_contract.py:122–150` checks both exact proof bytes
   and canonical semantic digest; `verify_source_projection` at 201–215 checks
   every measurement descriptor. `p06_counter_qualification_prerequisites.py:226–252`
   replays the original control archive and compares its measurement projection
   to those exact old descriptors. Updating the old proof or relaxing that
   comparison would erase the boundary it establishes. The new route needs its
   own frozen projection extension, explicitly naming original source identities,
   new source identities, the exact changed paths and why their changes preserve
   each affected premise. Reconstruct the original prerequisites unchanged, then
   verify the extension against the actual new build source. Do not feed rewritten
   current-source descriptors to the old verifier as if they were historical bytes.

4. **Four-process assumptions have identifiable extension points.**
   `p06_managed_preflight_replay._Replay.__init__` at 142–159 selects the four-cell
   plan. In `p06_dependency_native_replay.py`, `processes` at 546–595 fixes the
   process argv to pair zero/warmup, while `run` at 616–692 requires 37 commands,
   four processes and `COUNTS`. Use reviewed class properties/methods for the
   selected plan/counts/command total/process argv/record verifier. Old defaults
   must remain exact. The new route's command total would be 57 if the existing
   build graph is unchanged: 33 non-native commands plus 24 native processes.
   Do not infer these switches from a packet's contract ID or reported counts.

5. **The actual 24-process report will exceed the generic JSON structure bound.**
   The frozen `docs/project/evidence/p05-torch/reviews/archive_reader.py:92–106`
   accepts at most 16 MiB and 300,000 structural nodes; the managed constructor
   uses `view.json("report.json")`. I read the retained actual four-process report
   at `/workspace/p06-counter-qualified-run-01/evidence/native-qualification/report.json`:
   it is 3,770,129 bytes and contains 92,649 JSON value nodes; its process records
   alone account for 60,325 nodes. Scaling only that section to 24 processes
   produces roughly 394,000 nodes. Define a bounded decoder selected exclusively
   by the new route, with a justified finite byte/node limit, before the next
   native attempt. Keep the frozen archive-helper identity and historical limits
   unchanged. Test exact acceptance/rejection boundaries, duplicate keys,
   nonfinite values, excessive depth and oversized reports.

## Proposed reader contract and decomposition

- Add a new public module/CLI with independent caller expectations for the ZIP,
  source revision, dependency receipt, native report, source-before manifest,
  original proof and reviewed warm projection. Require both diagnostic/control
  prerequisite archive paths and exact pins. Exact new archive roots should be
  `dependency-build/` and one explicitly named qualified warm native root;
  reject every unaccounted root/member.
- Define a new outer report and result contract with exact fields. Preserve the
  original seven false claim fields wherever original nested contracts require
  them. Use new result names/scopes for the complete recorded warm population;
  keep phase/performance acceptance distinct from validity and the hypothesis
  decision. Replay must retain `native_execution="not_run"`,
  `retained_code_executed=false` and `origin_authenticated=false`.
- Derive the plan from the unchanged warm manifest: FP16 then BF16, pairs 0–5,
  alternating policy order beginning reference-first; pair 0 is warmup and
  pairs 1–5 are measured. Bind this exact sampling contract to both format build
  bindings, and bind each exact planned identity plus qualification admission
  into its process hash before the native `--qualification-id` echo.
- Reuse the dependency reader without trusting producer-supplied verification
  summaries. Reconstruct admission from the old originals plus the new source
  extension. Share `_NativeReplay.provenance`, `generated`, `compiler_commands`,
  `model_link`, `build_binding`, `stability` and membership accounting through
  narrow route hooks. Avoid a separate copy of the entire reader implementation.
- Introduce a new explicitly called record validator for warm identities. It
  should validate the new native identity mode, then share the existing raw
  observation, snapshot, half-read, cache-flush, pending balance, 33 run/reset
  and destruction checks. Parse the unchanged warm prefix for its actual pair
  and phase; never rewrite log bytes, synthesize missing witnesses or translate
  a measured pair into pair zero for admission.
- Require 24 processes, 792 launches, 25,344 checked FP32 words, 96 snapshots,
  3,168 available queries, 6,336 half replies, 792 cache flush reads, 7,128 DCR
  reads and 1,152 unavailable rows. Keep unavailable counters null/unavailable.
  Independently reconstruct the measured subset: 20 processes, 640 operations,
  20,480 checked words. The 24 primes and four warmup processes are excluded
  only from the performance calculation, never from validation.
- Derive analysis from the already reconstructed observations and bindings.
  Share the exact arithmetic in `p06_warm_analyze._statistics` and
  `_format_result` (95% cross-product check and all ten no-regression pairs),
  or extract a pure private helper preserving old output. The existing
  `analyze_processes` entry point at 237–263 must keep its historical high-half
  block and strict build schemas. Do not call it with stripped/new bindings and
  override `hypothesis_evaluation` afterward.
- Include every new trusted reader/helper, source proof/projection and existing
  frozen reference input in a before/after reader inventory. The current
  qualification reader explicitly adds reference pins at 64–86; retain that
  coverage when extending it. Archive provenance is consistency, not proof of
  an arbitrary producer's honesty or source Git membership.
