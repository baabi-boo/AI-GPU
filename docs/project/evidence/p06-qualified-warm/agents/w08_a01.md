## Separate CMake finding

**F2; high confidence; static proof; local invocation environment.**

`p06_dependency_build.clean_environment()` constructs PATH from the selected
interpreter's directory followed by `/usr/bin` and `/bin`. The corrected
`DependencyBuildTests.setUp()` discovers tools through exactly that PATH; it
intentionally ignores the ambient PATH. With the current canonical interpreter:

```text
/opt/codex/runtimes/codex-primary-runtime/dependencies/python/bin:/usr/bin:/bin
```

`shutil.which("cmake", path=that_path)` returns **null**. The ambient executable
is `/home/agent/.local/bin/cmake`, which is outside this sanitized path. Merely
prepending a directory to the coordinator's ambient PATH does not fix these
fixtures.

The source supplies a concrete consequence:

- `DependencyBuildTests.test_actual_cmake_records_static_archive_index_and_shared_link_only`
  calls `skipTest` when `cmake` is absent.
- `ActualCMakeReviewTests.setUpClass()` and
  `ActualGeneratedOptionControls.setUpClass()` call that integration fixture.
- A further recipe metadata fixture has its own explicit missing-CMake skip.

These methods/classes therefore cannot supply zero-skip exhaustive coverage in
the current environment. This reviewer did **not** run those CMake test bodies;
the finding combines current tool-path observation with the unchanged source
branches. It does not claim that the still-running coordinator suite has already
reached or reported those skips.

The prior proper venv's sanitized path does find
`host-venv/bin/cmake`, resolving to
`/workspace/p06-build-tools/cmake/data/bin/cmake`. Its SHA-256 remains
`a5560a96289c53778c9ba0112ce054f693d7d1a6975af3be69316fba31726f83`.
The prior venv configuration remains
`284d39aaef3431bfe81e674f6b29a96d18794ff86c2ff37c756fa33827d24eb4`.
A separately selected proper venv can expose that existing binary without
altering the shared Python installation or system directories.
