## Behavior prepared

The supervisor is manually invoked only after the selected native attempt is
finished and its cleanup has been reviewed. It requires an independently
selected SHA-256 for the native supervision receipt. A successful three-stage
receipt must identify the exact implementation revision and completed cleanup
for every stage. A failed or incompletely reported attempt additionally needs
an explicit coordinator cleanup-review file identifying the same receipt,
revision, verified cleanup and reason. That is scheduling bookkeeping and does
not change the native result or authorize any qualification claim. There is no
background poller or automatic launch.

The selected locations are:

| Purpose | Absolute path |
| --- | --- |
| Clean source | `/workspace/p06-qualified-warm-governance-source-01` |
| Evidence output | `/workspace/scratch/dc8be1693f91/full-governance-c0b44ce6` |
| Temporary test files | `/workspace/p06-qualified-warm-governance-tmp-01` |
| Native supervision | `/workspace/scratch/dc8be1693f91/native-qualified-warm-attempt-01/supervision.json` |

It requires Python 3.12 using the selected runtime interpreter, a clean exact
revision and tree, canonical paths, and absent output/temp directories. It
inventories every staged regular file by SHA-256 before and after execution,
records tracked symlink text without following the link, and preserves gitlink
object IDs without claiming recursive native checkout qualification.

The five source-root commands are preflight, project structure validation,
published baseline packet consistency, canonical full unittest discovery, and
`git diff --check`. Full discovery uses exactly:

```text
/opt/codex/runtimes/codex-primary-runtime/dependencies/python/bin/python3 -B -m unittest discover -s ci/project -p test_*.py -v
```

The suite is bounded to 60 minutes, matching the workflow's overall timeout
value; the supervisor's total budget is 90 minutes. The distinction is explicit:
this local supervisor does not claim identical hosted scheduling or job timing.
Other commands have narrower bounds. Combined output is retained with a polled
64 MiB log budget; the final log size is also checked after command exit.
There is no additional RAM or free-disk gate imposed on governance tests.

Each child starts in its own process group. Timeout, log-budget failure,
interruption and exceptions trigger bounded termination and a live-group
cleanup observation. SIGINT and SIGTERM handlers route through failure
preservation. Descendants that leave their group remain outside containment;
the receipt states this limitation. Logs are created exclusively. The initial
status is created exclusively and later updated atomically within the newly
owned output directory. Source snapshots are exclusive files.

Every started command records actual argv, source directory, timestamps,
duration, exit code, cleanup, reason, log size and SHA-256. An interrupted or
unstarted command is never inferred to have passed. Unrun command names are
explicitly retained. The final result also requires unchanged source bytes,
revision, tree and clean Git state. A failed test command remains failed even
if later inexpensive checks pass.
