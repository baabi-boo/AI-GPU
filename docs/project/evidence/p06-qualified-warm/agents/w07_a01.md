## Statistical and phase edge cases inspected

The reducer checks every planned identity against the immutable process plan.
It derives inclusion from that validated phase, so a packet cannot supply a
separate inclusion flag to drop a slow measured process. Pair zero is excluded
as warm-up and all prime intervals remain diagnostic. The raw record validator
computes batch counters between the post-prime and post-batch snapshots
(`p06_warm_records.py:148–180`), consistent with the 32 timed operations.

The frozen `_format_result` function compares integer batch totals. Every batch
has the same denominator of 32, so comparing totals preserves the corresponding
mean comparisons. The median threshold is an exact integer cross-product with
the frozen 95 percent constant. Both five-pair host-time and five-pair cycle
predicates use `all`, and the new reducer also uses `all` across FP16 and BF16.
The reduction has no outlier removal, early stopping, weighting by operation
count, or fallback to the better format.

The rational and floating values produced by `_ratio` and `_statistics` are
presentation/statistical summaries. Their rounded values are not fed back into
the three predicates. A dictionary overwrite in `_format_result` would require
duplicate `(pair_index, policy)` inputs, which are excluded by the complete
validated plan before this internal helper is reached. Calling the reducer
directly with invented dictionaries is explicitly outside archive admission and
does not create qualification evidence.
