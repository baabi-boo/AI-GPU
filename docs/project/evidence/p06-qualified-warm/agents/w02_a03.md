# W02 A03 — Explicit qualified warm producer

## Implemented scope

Owned changes are `ci/project/p06_managed_preflight_execute.py`, the new
`ci/project/p06_qualified_warm_execute.py` public entry point, and
`ci/project/test_p06_qualified_warm_runner.py`. Other contributors own the
native caller, contract/admission, raw records and reader. No commit or push
was performed by this assignment.

The shared producer accepts a new exact Boolean `qualified_warm` that requires
all three earlier lifetime, dependency and counter-qualification selections.
It dynamically loads the explicit warm admission and record-validator modules
from the trusted checkout. Historical defaults and public entry points retain
their original route and four-process behavior.

The warm route obtains its exact ordered plan and complete counts from the new
contract. Every build and process binding includes `warm_sampling`, comprising
the original warm-contract digest, complete frozen sampling descriptor and all
24 planned process rows. These fields and the selected source-extension proof
enter both hashes before native execution. Each process receives its actual
pair/phase/sample and binding, with the native prefix
`--lifetime --qualified-warm`.

The existing source, helper, dependency, compiler, product, loaded-library,
resource and finalization checks remain active. Failed or interrupted processes
retain the original attempt and stop without replacement samples. The additional
outer `qualified_warm_passed` field requires the complete successful qualified
population. All seven inherited claim fields remain false. The producer makes
no performance-hypothesis or phase-acceptance decision.

## Reader interface

- The only additional report field is `qualified_warm_passed`.
- The source-extension proof retains the existing member path
  `artifacts/counter-qualification/proof.json` but has its independently selected
  new identity and explicit outer contract.
- Both build and process bindings add exactly
  `warm_sampling = {contract_sha256, sampling, processes}`.
- The native command carries the lifetime flag, then qualified-warm flag, then
  existing key/value arguments with the planned pair and phase.
- New raw verification receives `pair_index` and `phase` explicitly. It receives
  the unchanged managed-preflight descriptor for shared semantic obligations.
- A clean import diagnostic captured **81 producer helpers**: exactly the old
  qualified producer inventory plus the new qualified-warm execute, admission,
  contract and records modules. The comparison captured the producer inventory
  before importing the historical reader and did not derive it from a packet.
