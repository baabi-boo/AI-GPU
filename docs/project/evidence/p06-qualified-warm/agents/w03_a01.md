# Wave 03, agent 01: independent native caller and source-proof review

## Scope and decision

Reviewed the root-authored native caller delta against published base
`f80b58b06e7bcf734f3190f6db478fd11f0bab01`, the repository instructions, the
qualified-warm design, the wave-one source-proof findings, the new frozen source
projection, and the retained diagnostic receipts. This reviewer did not author
the native change. No concrete blocker was found within this review's scope.
No production files were edited and no diagnostics were rerun.

This decision concerns the bounded source extension and its diagnostic evidence.
It does not establish a fresh qualified warm execution, numerical correctness
of a new execution, a performance benefit, or P06 phase acceptance.

## Every native diff hunk

1. The caller-private state gains `qualified_warm`, initially false. Neither
   runtime state nor the observation-hook ABI changes.
2. Counter-witness serialization selects the new
   `p06-qualified-warm-counter-witness-v1` contract and canonical sample ID only
   when that flag is true. Otherwise it emits the original
   `p06-managed-counter-preflight-v1` contract and
   `preflight-simx-<format>-<policy>` process ID. All other witness fields and
   false claims remain unchanged. The successful historical witness's serialized
   identity and schema therefore remain unchanged.
3. Lifetime-witness serialization follows the same selection, using
   `p06-qualified-warm-lifetime-witness-v1` for the new route and retaining
   `p06-managed-counter-lifetime-v1` and the historical process ID otherwise.
   Both new witnesses identify the same canonical sample.
4. Argument handling accepts the new mode only after the existing `--lifetime`
   prefix. `--qualified-warm` without that prefix, including reversed flags,
   fails before delegation to the unchanged workload. The historical route
   still requires pair zero and `warmup`. The new route delegates validity to
   the unchanged options parser, which enforces pairs 0–5, pair-zero warmup,
   measured phase for other pairs, the fixed format, supported policy, a
   64-character lowercase hexadecimal binding, and the exact pair/policy sample
   ID. Duplicate flags or unknown options fail its exact argument count and
   unique-key checks. The failure diagnostic now describes both accepted routes;
   this is an intentional diagnostic wording change, not a claim that every
   historical error byte is identical.

The unchanged warm caller still owns all operations, priming, timing and
correctness checks. New argument selection occurs before that call; new witness
formatting occurs afterward. The rest of the preflight's query counts, run and
reset observations, construction/destruction checks, quiescence, loaded-library
stability and lifetime checks is unchanged. A scoped diff over `sim`, `hw`,
`sw`, the warm caller and the preflight found only this caller source changed.

The temporary `std::string` used as the historical `%s` argument survives until
the end of the `printf` full expression. Argument types and format arity remain
correct. Shifting `argv` retains the guaranteed null sentinel, and duplicate
mode tokens remain rejectable. The lifetime-enablement function only checks and
sets observation state under its mutex; it does not construct a processor or
launch the workload. No compiler or pointer-lifetime defect was found. This is
source-level invariance of the measured workload, not a binary-identity or
equal-performance assertion about the changed caller executable.

## Ten-premise transfer implications

The source change does not discharge any dynamic premise by itself. Each of the
24 fresh processes still has to satisfy the original premises and the new
route's complete admission and lifetime requirements.

| Premise | Transfer obligation |
| --- | --- |
| P01 | Establish the actual RV64 serial checked route, effective frozen-profile headers, selector discipline and loaded-library identities for the new executable. |
| P02 | Preserve zero, unseeded counter origin and the observed run/reset relationship. |
| P03 | Prove drained, idle, zero-pending state before every permitted reset and absence of checked failures. |
| P04 | Retain 33 terminal aggregates and 66 full-width half replies per process. |
| P05 | Retain complete resource closure and ownership observations through final device-reference release. |
| P06 | Retain worker joins, collected execution, zero buffers, required flushes and terminal zero pending work. |
| P07 | Retain exclusive public core-zero observation, successful low/high reads, restored class selection and no tick/reset movement during a vector. |
| P08 | Retain terminal/destructor-entry equality, completed final destruction and no post-terminal counter update. |
| P09 | Join the unchanged 21-source Ramulator projection to fresh compilation, linking, actual loading and library-stability evidence. |
| P10 | Preserve diagnostic prerequisites and whole-attempt failure for guard, query, prime, operation or cleanup failure; do not recover or replace a failed sample in the same attempt. |

The increased process count does not increase the 33-operation bound of any
single lifetime. Mandatory lifetime mode supplements, rather than removes, the
existing observation requirements. The overlay is a distinct reviewed source
extension; it cannot relabel historical evidence as a new qualified run.

## Retained diagnostic receipts

Inspected `/workspace/scratch/dc8be1693f91/validation/caller-syntax-results.json`
and `/workspace/scratch/dc8be1693f91/validation/native-argument-probe.json`, and
checked their expected rows, return codes and source binding using read-only
assertions.

- Both FP16 and BF16 syntax checks exited zero with `-fsyntax-only`, `-Werror`
  and checked-counter selection. They used previously generated frozen-profile
  headers. They establish syntax compatibility, not native execution.
- Both current callers linked successfully for the rejection probes. Each
  format has ten actual rejected invocations: historical measured mode,
  lifetime measured mode, missing lifetime, reversed flags, duplicate mode,
  pair six, wrong phase, cross-pair sample ID, invalid binding digest and
  unknown option. All 20 exited one with the expected preflight failure output.
  Their rejection points precede the unchanged workload call.
- The receipt explicitly identifies previously built dependency binaries.
  These probes intentionally launch no kernels and do not count as a fresh
  source-qualified experiment. The two positive syntax checks and 20 negative
  argument checks must retain that limited scope.

## Remaining boundary

No native/source-extension blocker was found. Successful execution of all 24
processes, fresh build/load qualification, complete witness admission and replay,
and the immutable performance decision remain separate obligations. This review
does not independently approve every Python reader or admission implementation,
does not assert physical-device results, and does not earn any formerly false
phase or acceptance claim.
