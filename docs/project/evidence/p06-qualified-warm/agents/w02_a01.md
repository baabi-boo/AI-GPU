# W02 A01 — Explicit qualified warm raw-record validator

## Implementation

Added `ci/project/p06_qualified_warm_records.py` and
`ci/project/test_p06_qualified_warm_records.py`. No existing production validator,
native source, workload, proof, golden, tolerance or acceptance record was changed
by this assignment.

The new entry point accepts the existing managed-preflight contract plus an
explicit pair index and phase. `process_identity` strictly validates format,
allocation policy, lowercase execution digest, integer pair 0–5 and the required
warm-up/measured phase. Each managed and lifetime witness must carry its own new
fixed contract ID and the exact unique warm sample ID as its process ID.

The validator splits the original transcript without rewriting its contents.
It independently validates both new witness schemas and identities, then passes
the unchanged warm prefix to the original warm verifier with the actual selected
pair and phase. It reuses only the managed and lifetime semantic helpers: all
33 exact numerical operations, loaded-library paths, 33 available selectors and
their raw half replies, unavailable rows, flushes, every run/reset boundary,
pending balances, terminal consistency and complete destruction remain checked.
The seven historical claim fields remain false. The returned `warm`, `witness`
and `lifetime` data preserve the validated original records.
