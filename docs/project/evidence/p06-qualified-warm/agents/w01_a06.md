`f80b58b06e7bcf734f3190f6db478fd11f0bab01`. Read the root agent contract and
W01 A01–A03 reports, then inspected the native argument/witness boundary and

## Required tests, ordered by concrete risk

### 1. Trusted route selection and native argument validation

`ai_counter_preflight/main.cpp:509–523` strips the leading lifetime flag and then
hard-rejects every nonzero pair/measured phase. The included unchanged warm
`options()` parser already validates pair 0–5, phase, exact sample/format/policy
relationship and binding syntax (`ai_warm_workspace/main.cpp:69–109`). Test the
explicit new warm flag with lifetime required, repeated/misordered flags rejected,
and default/old lifetime routes still restricted to pair-zero warm-up. Test pair
5 as well as pair 1; test incorrect phase, sample ID, format and policy. Invalid
arguments should fail before native device open. Check both witness printers,
not just the warm prefix, for distinct new route contract/process identities.

### 2. Exact population and direct raw identity binding

The positive synthetic packet must contain all 24 unique process identities in
the frozen order: FP16 then BF16; pairs 0–5; reference first on even pairs,
candidate first on odd pairs. Assert four warm-up and twenty measured processes,
792 launches, 25,344 checked words and 640 measured operations. Negative cases:
omit, duplicate, reorder or swap a phase/pair/policy; splice one process from
another format or binding; reuse a valid pair-zero transcript under a repaired
pair-one envelope. Repair enclosing digests in these attacks so rejection proves
semantic checking rather than an incidental checksum mismatch.

Every operation, summary, parent witness and lifetime witness must agree with
the externally planned sample and process binding. Mutate each layer separately,
including prime records. A valid terminal witness must never rescue an invalid
prime or failed explicit close. Require each allocation arm to retain the same
guarded binary/build identity within its format.

### 3. New source projection and fail-closed prelaunch admission

The original proof and old control source projection must remain byte-identical.
The new extension should reject: changed base proof; wrong old/new caller hash;
missing or extra changed path; any drift in the other 68 original measurement
sources; changed dependency projection; mismatched source revision; wrong
diagnostic/control originals; stale receipt; changed helper or reference input.
Assert the original proof rejects the new caller bytes. Historical fixtures that
currently copy current `main.cpp` must use clearly labelled exact historical
bytes pinned against the original descriptor, not silently update old proof pins.

For each admission failure, assert zero recorded build/native launches and a
retained blocked/failure disposition. Inject drift before the first native
process, between pairs, between formats and during finalization. A final-only
change must invalidate a completed population. Preserve the first failure and
all original logs; do not retry or replace failed samples.

### 4. Lifetime theorem remains per process

Reuse the actual lifetime semantic helpers for every warm process. Preserve
existing tests for zero pending balance at each run/read/flush boundary, exact
reset progression, monotonic cumulative counters, complete selector vectors,
required flush accounting, no post-terminal tick and completed destruction.
Add cross-process witness substitution and high-half/terminal corruption with
repaired summaries. Counts alone cannot establish a correct lifetime. No growth
of the 33-run hook capacity is needed because processes remain fresh.

### 5. Full-reader bounds, immutability and inertness

W01 A02 established the scaled report exceeds the old 300,000-node parser cap.
The new bounded report decoder must be selected by trusted new-route code only.
Test the exact new node/byte/depth limits, one unit beyond each, duplicate JSON
keys, nonfinite values, integer/Boolean substitutions and unknown fields. Keep
the frozen archive helper and old reader bounds untouched.

Exercise the actual ZIP entry point with complete roots, original member bytes,
explicit source/report/proof/receipt/archive pins and final input-stability
checks. Reject extra roots, unexpected members, missing artifacts and changed
trusted inputs during replay. Retain existing no-execution/no-extraction/network
guards and exact producer-path denial. Test that historical public readers reject
new packets even when an attacker repairs hashes and labels.

### 6. Frozen decision arithmetic after qualified reconstruction

Preserve exact integer cross-products for the 95% median boundary and pairwise
host/cycle comparisons. Test a one-unit threshold miss, one slower host pair with
an otherwise passing median, one added cycle, and one failing format. Alter
prime/warm-up timings dramatically: they must remain validated but excluded from
the measured result. Validate complete same-build inputs before computing a
decision. Historical analysis must continue returning its unconditional
high-half qualification block; no new caller claim may upgrade it. A new valid
experiment may fail the performance hypothesis without invalidating its recorded
execution. Phase/performance acceptance remains a separate review decision.

## Execution evidence still needed

Synthetic tests establish implementation behavior at their declared seams.
After independent source/enforcement review, freeze a published revision and run
the actual fresh dependency build and all 24 native processes. Independently
reconstruct the unchanged original archive and inspect numerical, lifetime and
source/build/load evidence before interpreting the measured predicates. No
test plan or synthetic positive packet satisfies that obligation.
