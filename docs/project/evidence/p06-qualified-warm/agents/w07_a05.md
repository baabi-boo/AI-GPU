# W07 A05 — Replay inertness and capability review

## Decision and scope

No concrete F2/F3 packet-driven execution or filesystem capability defect was
found in the selected qualified-warm replay path. This is a static call-path and
AST review of published implementation `c0b44ce64665fe11895f869eea8c38c9b820d6f7`.
It does not execute a project reader, import project modules, open a candidate
archive, run native code, or establish a full-governance result.

The accompanying [static receipt](../validation/w07_a05-inertness-static.json)
records SHA-256 identities for 16 selected front-end, archive, and trusted-loader
files, all exactly equal to the published Git blobs and stable after inspection.
Its bounded AST census found no direct subprocess, shell, network, retained-script
or extraction call in those selected files. It enumerated 11 dynamic-code-load
call sites and 41 filesystem read/open sites for the manual classification below.
The census completed in 0.887439181 seconds. A finite AST census alone does not
prove all transitive behavior; the review therefore followed the actual selected
entry points and distinguished pure helpers from producer-only functions.

## Selected call path

`p06_qualified_warm_replay.main` selects `replay_archive` directly. It supplies
explicit caller-selected archive, source revision, dependency receipt, native
report, source-manifest, qualification-proof, diagnostic and control identities.
The main candidate supplies no module name, Python path, callable or reader mode.

The entry point constructs exactly the `dependency-build` and `qualified-warm`
views under the optional validated literal prefix. The union must equal the
complete archive file population. The proof digest must equal the fixed warm
extension pin. `_QualifiedWarmReplay` is selected by trusted code, with its fixed
24-process/57-command schema and retained old claim fields; packet metadata cannot
fall back to the four-process reader or select the blocked historical warm route.

`verify_view` first invokes `p06_dependency_replay.verify_view`. That constructs a
`CachedPacket`, checks the externally pinned raw report, selects a bounded exact
member inventory, and passes a byte-reading callback into
`p06_dependency_receipt.verify_document`. The callback reads archive members;
it never converts a retained descriptor into a local producer file. Complete
dependency membership is checked after reconstruction.

The native reader reconstructs source, compile/link, command, load, raw counter,
lifetime and chronology relationships from retained data. Its inherited
`paths_and_tools` uses `recorded_absolute`, which returns `PurePosixPath` values
for lexical comparisons. Recorded compiler paths, binary paths, build roots and
command argument arrays are not executed or resolved against the reviewer's
filesystem. No original producer source checkout, installed libraries or toolchain
is required at those recorded paths.

The dependency receipt module also contains a live `PacketReader`/local verification
entry point, and its imported recorder contains process-launching producer code.
Those capabilities are not selected by this public archive route. The selected
receipt verifier calls the recorder's argument/depfile parsers
(`without_dependency_flags`, `_prepass`, `dependency_paths`) and constants.
The inspected `dependency_paths` parses bounded supplied bytes and performs
lexical path normalization; it does not open the resulting paths. Source-manifest
handling uses `validate_manifest`, not live `verify_sources`.

## What may be read or executed

| Capability | Selected origin and boundary |
| --- | --- |
| Main archive reads | The explicit caller path and SHA-256 passed to `ArchiveReader`; no packet path selects another host file. |
| Diagnostic original reads | The explicitly selected diagnostic archive, checked against the immutable original proof; both model and public diagnostic populations are reconstructed. |
| Control original reads | The explicitly selected prior control archive, with all original report/source/receipt/control pins supplied by the immutable original proof. |
| Current trusted-source reads | Fixed `ROOT` paths for reader/helper source inventories, frozen contracts, proof inputs, configuration inputs and independent fixtures. Their expected identities and repeated stability checks are separate from archive metadata. |
| Public diagnostic source inventory | The fixed trusted checkout inventory path selected by the original proof, with its independent digest. It is data and does not resolve its source descriptors against the producer filesystem. |
| Retained member reads | Bounded ZIP member streams, with path, type, inventory, size, CRC/decompression, aggregate-read and before/after archive identity checks; no extraction. |
| Result output | Standard output, or only the caller's explicit `--output` opened with mode `x`; an existing file is not overwritten. Output I/O can fail after a valid replay and is therefore distinct from a qualification rejection. |

The trusted code must execute to interpret evidence. That is distinct from
executing code supplied in the evidence archive:

1. `p06_dependency_replay._archive_api` delegates to
   `p06_managed_preflight_replay._archive_api`. This reads the fixed current
   archive helper, checks its frozen SHA-256, and directly compiles those verified
   bytes. Its `spec_from_file_location` is module metadata; it does not select a
   path from a candidate member.
2. `p06_managed_preflight_generated._load_renderer` directly compiles the frozen
   current `ci/gen_config.py` bytes. The configuration renderer is bound to fixed
   checked inputs and receives a restricted in-memory `open_input`, environment,
   path interface and argument list. Rendering retained header expectations is
   not compiler or retained-source execution.
3. The inherited diagnostic prerequisite path calls
   `p06_replay._archive_api`. This hashes the same fixed current helper and uses
   `SourceFileLoader.exec_module`. Unlike the managed loader, this historical
   loader can consult the local bytecode cache. That cache is within the trusted
   reviewer environment; no archive member can select it or write it through the
   inert route. This review does **not** claim that all transitive Python loading
   bypasses local caches, or that an already compromised reviewer installation is
   authenticated by source-file hashes. This is an F0 trust-boundary observation,
   not evidence of retained-code execution or a packet-driven blocking defect.

Standard Python imports likewise belong to the trusted execution environment.
The import/closure checks establish selected module paths and source identities;
they are not an operating-system sandbox or producer attestation.

## Prerequisites and result boundaries

`p06_counter_qualification_prerequisites` passes the unchanged original proof to
the original diagnostic and control readers. It does not run their producer
counterparts. The public-source inventory is a trusted explicit input, and the
control reader's recorded pending/substitution subprocesses are reconstructed
from logs rather than relaunched.

Complete native reconstruction precedes the analysis call. Trusted reader inputs
are checked before reconstruction, after reconstruction, after analysis and after
the archive context closes. The archive owner rechecks its original bytes and
file identity. These checks reject observed persistent drift; they do not prove
the honesty of an arbitrary producer or defend against every malicious transient
change to an already compromised host.

Results retain `native_execution="not_run"`, `retained_code_executed=false` and
`origin_authenticated=false`. A consistent retained history remains consistent
data. It does not independently prove that an untrusted producer executed a GPU,
establish Git membership, or accept a performance/phase gate.
