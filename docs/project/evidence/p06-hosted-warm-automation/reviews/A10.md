# A10 — encrypted private retention

## Scope and API

Implemented only `ci/project/p06_qualified_warm_encrypt.py` and
`ci/project/test_p06_qualified_warm_encrypt.py`. No native GPU work, upload,
branch/ref update, commit, or push was performed by A10.

API: `encrypt_private_directory(*, input_dir, output_dir, recipient, age_binary="age", expected_revision=None)`.
CLI: `python3 -B ci/project/p06_qualified_warm_encrypt.py --input-dir ABSOLUTE_PRIVATE_PACK_DIR --output-dir ABSOLUTE_FRESH_PUBLIC_DIR --recipient AGE_PUBLIC_RECIPIENT --age-binary ABSOLUTE_TRUSTED_AGE --expected-revision EXACT_40_HEX_REVISION`.
The revision flag is optional. `validate_recipient(recipient)` performs offline
canonical lowercase X25519 Bech32 address, 32-byte encoding/padding and BIP-173
checksum validation. All encryption/key agreement is delegated to age.

## Boundary and implementation

The fresh public directory receives only `qualified-warm-retention.tar.age`
and `encryption-summary.json` after success. Public JSON contains schema/contract,
selected revision, encryption outcome, bounded counts and ciphertext size/SHA256;
no input names, machine paths, recipient, raw logs or content. A fresh 0700
sibling `<output-dir>.PRIVATE` retains bounded 0600 stderr, incomplete output and
failure receipt. Failures never authorize substituting plaintext.

Streaming uncompressed tar uses a selector-driven subprocess pump with fixed
arguments/environment, bounded stdin/stdout/stderr, 180-second deadline and
process-group cleanup observations. No plaintext intermediate tar is written.
The encrypted payload contains `manifest.json` and the entire input tree under
`private/`, including hidden files and empty directories. Manifest files record
relative path, exact size and SHA256; its directory list includes the empty root
name. Input identities and hashes are checked before, during and after streaming;
ciphertext is independently reread before publication. Symlinks, hard links,
special files, noncanonical/case aliases, overlaps and reused outputs fail closed.

The root-approved retention-only admission requires exact padded tar size +
16 bytes per ceil(tar-size / 65536) payload chunks + 4096 bytes conservative age
overhead + 64 MiB disk margin, with checks during writes. It changes no native or
acquisition 15 GiB admission gate. Limits include 1 GiB selected bytes, 256 MiB
per file, 40,000 entries, 16 MiB manifest and 16 MiB stderr.

## Limitations and persistence

The caller must stop writers. Identity checks are observations, not exclusion of
malicious concurrent writers. Process-group cleanup cannot prove containment of
escaped descendants. The operator must authenticate/pin the trusted age executable;
syntax/framing checks do not prove an arbitrary executable performed encryption.
Offline public-address validation is not recipient ownership or curve key-agreement
proof; a trusted age empty-input probe can provide the latter pre-acquisition check.
