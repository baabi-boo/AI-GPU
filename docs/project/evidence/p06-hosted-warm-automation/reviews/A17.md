## Findings and resolution

**Medium, resolved: ambient TLS key logging.** `ssl.create_default_context()` honored `SSLKEYLOGFILE` during ordinary direct CLI/API use. This created an output outside the exclusive private directory and enabled TLS traffic-secret disclosure; a configured stdout/stderr descriptor could receive it. The intake now constructs `SSLContext(PROTOCOL_TLS_CLIENT)`, loads the system trust store, and retains TLS 1.2 minimum, certificate verification and hostname checking. It does not mutate the parent's environment. Hosted environment filtering and recommended isolated invocation already limit this exposure, but the callable/direct command needed its own protection.

**Medium, resolved: inherited HTTP debug logging.** Setting the standard library's `HTTPConnection.debuglevel` before calling the intake caused the complete signed request URL to be printed. The individual connection now explicitly disables debug logging. A real HTTP request/response parser over an in-memory fake socket reproduced the disclosure before the fix and remains silent afterward.

Both regressions failed against the original implementation and pass with the changes. No real signed URL, original archive, network handshake, extraction or native execution was used.
