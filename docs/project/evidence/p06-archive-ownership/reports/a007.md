## Findings

### F2 — a failing raw descriptor close skips parent cleanup

**Confidence:** high. **Evidence type:** static-proof, corroborated by the bounded host fault injection above.

At production lines 113–116, `os.close(descriptor)` and `os.close(parent)` execute sequentially in one finally block. Any exception from the first prevents the second. When a preceding open validation/fstat/fdopen failure leaves the raw descriptor owned, a consuming close failure leaks the independently owned parent directory. The harness directly observed the parent still open after unwinding.

Action: make parent cleanup independent of raw-descriptor cleanup, and record a raw close attempt as consumed before invoking it. Do not retry a failed close against a potentially recycled descriptor number. Add a regression for the demonstrated consuming-close case.

### F1 — cleanup errors replace the primary failure

**Confidence:** high. **Evidence type:** static-proof, corroborated by host fault injection.

The stream context manager at line 101, fresh-parent finally at lines 111–112, and outer raw cleanup can replace an already-active construction/body/validation exception. The original remains chained in `__context__`; it is not the propagated primary exception. This is a narrow simultaneous-failure trigger and does not turn invalid input into accepted input.

Action: if first-failure preservation is required for this reader, preserve the original exception identity while independently attempting remaining owned cleanup, and add targeted construction/body/validation plus close-error regressions. A cleanup failure on an otherwise successful path should still surface.
