## Finding and design review

**Known baseline defect: F2 / high confidence / static-proof, corroborated by executed host reproduction.** The baseline opens the raw file descriptor and then constructs an owning stream without a cleanup path covering construction failure. An audit hook can reject the real CPython integer-open event, leaving the descriptor live. Both negative controls reproduced this precisely. This is the coordinator's existing finding, independently confirmed, not an additional newly discovered defect.

**Changed source: scoped no finding.** `closefd=False` leaves one explicit raw descriptor owner. `_close_owned` attempts stream close first (allowing buffered output flush), then raw fd close, then parent close. Each resource is attempted once; a cleanup failure does not prevent attempting later closes. On an existing primary exception, secondary cleanup failures are suppressed; after otherwise successful work the first cleanup failure is raised. This behavior is established here by source review; injected cleanup-error combinations were not independently executed by this worker.

`_read_file` covers hashing allocation, fdopen construction, stat/identity checks, read/copy work and return preparation with the ownership finally. `_exclusive` is a context manager, so raw fd ownership remains live through its body and cleanup. Both in-repository call sites already use `with`, and rejected entry is cleaned inside the generator before yield. The real audit rejection and post-open cancellation probes support these paths. The created partial output is retained, consistent with existing packaging retention behavior.

Action: retain the explicit raw-fd ownership/contextmanager repair and its source-bound regression tests. No additional patch is requested by this bounded review.
