   diagnostic checkout, observe all trace allocations, completed constructions,
   destructors and deallocations. Identify each allocation generation; copied
   traces share UUIDs and pooled addresses recur. Count trace-owned vector
   buffers separately from pool chunks, free slots, remote-return slots and heap
   fallbacks. After joined full-context destruction, require zero outstanding
   constructed traces and matched allocation/deallocation. Check constructor

   an RSS plateau or “reachable” leak-detector classification is insufficient
   (`sw/common/mempool.h:48–74,139–175`; `sim/simx/instr_trace.h:82–139`).

2. **Fix the population in advance.** Preserve the original native completion
   unit, including checked/legacy results and x3 `7`/`-1`. Add an independently
   identified diagnostic sequence of **eight** serial pairs: bounded-RAM fault
   at address/capacity 4096, consume `OutOfRange` through `future.get()`, join and
   destroy, then run a fresh successful context. Compare with **16 healthy
   contexts** in a separate process using identical build/instrumentation.
   Record balances after every lifetime. Never reset/reuse a failed context or
   overlap contexts. The built parent must fail the ownership assertion while
   reaching the intended fault; compile errors/timeouts are not sensitivity.
   One pair diagnoses missing destruction; repetition checks accumulation and
   reuse. Do not extend the population merely to obtain visible RSS growth.

3. **Review one owner, then implement separately.** Candidate design: one
   live-trace owner per Core; queues/tables/LSU/retirement retain observer
   pointers. Central creation/copy and release operations must cover scheduler
   allocation, sequencer micro-ops, dispatcher splits, LSU response beats and
   store copies. A `pending_instrs_` sweep misses allocations; independently
   deleting aliases from every queue risks double destruction. Prove exactly
   one registration/removal, exception-safe construction/registration, copy
   bookkeeping, cross-thread allocator return and nonthrowing cleanup. Establish
   worker-join and callback/event/late-owner destruction ordering before freeing
   objects. Cleanup must neither tick nor update counters, allocate a new
   tracking container, rehabilitate failure, or destroy immortal allocator pools.

4. **Verify the complete affected lifecycle.** Repeat the same parent/candidate
   diagnostic with identical tools, profile and assertions. Add bounded directed

5. **Resolve frozen-source scope before adoption.** Obtain coordinated maintainer
