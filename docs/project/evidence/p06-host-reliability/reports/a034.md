# A034 — encryption stream and publication audit

Read-only review at `4c9c612ba17e8b69b29083ad9743fe0e1710f0bc`. Examined `ci/project/p06_qualified_warm_encrypt.py`, its primary fake-age fixture, and descriptor, operational-failure, publication, directory-drift and SIGTERM tests; consulted project and retention guidance.

## Confirmed finding

**F2 — raw source descriptor leaks on stream-construction failure.** In `_VerifiedReader.__init__` (approximately lines 275–280), `os.open` succeeds before `os.fdopen` transfers ownership. If `fdopen` raises, `self.stream` is still `None`; the exception handler calls `self.close()`, which closes only the parent directory. The source descriptor remains open indefinitely in a long-lived caller.

The retained `a034-probe.py` patched `os.fdopen` to raise `OSError` or `KeyboardInterrupt`, recorded successful source `os.open`, and verified with `os.fstat` that the descriptor still referenced the same synthetic source inode. Both cases reproduced; the probe closed its leaked descriptors. Replay from the repository root: `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=ci/project python3 ../reports/a034-probe.py`.

Recommended repair: retain explicit raw-descriptor ownership until stream construction succeeds, close it once on failed transfer, and preserve the original exception. Add a focused failure-injection regression covering ordinary failure and cancellation, including consuming-close behavior.
