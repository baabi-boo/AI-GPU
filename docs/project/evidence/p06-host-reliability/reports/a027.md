# A027 — managed MLP ordering and lifetime audit

**Outcome:** No demonstrated supported-case defect. This is a read-only source review at observed HEAD `4c9c612ba17e8b69b29083ad9743fe0e1710f0bc`, not new execution or acceptance evidence.

**Scope and checks.** Examined `sw/runtime/ai/mlp_runtime.cpp`, `mlp_host.cpp`, their headers, and the underlying `runtime.cpp` submission/wait/close behavior. Compared them with `docs/designs/tiny_mlp_fixture_v1.md`, `mlp_execution_records_v1.md`, the P04 executor plan and existing numerical/dispatch acceptance scope. Read both P04 runtime/bridge Python test drivers and their complete C++ harnesses. `git diff` reported no local changes to these reviewed source/test files; no builds or tests were run and no frozen source was edited.

**Ordering and ownership.** `submit_stage` selects `(16,8,16)`, then two `(8,4,8)` calls. `advance` requires successful completed waits, copies and compares actual outputs, and completes operation cleanup before advancing. Hidden comparison precedes the host bridge. The two output inputs use actual bridge bytes `[0,128)` and `[128,256)`; assembly preserves the corresponding 32-word row blocks. The constructor copies the case, including inputs/references, while operation-owned outputs and traces are copied before release. Thus caller mutation and temporary operation destruction cannot replace the model's retained data.

**Errors and close.** Partial submissions retain returned operations; incomplete waits/closes retain ownership. Resume does not resubmit the pending stage. Primary, validation and cleanup failures remain separate, stop dependent work and survive later drains. Explicit close sets terminal state and drains existing work without finishing the graph. Destruction may drain indefinitely, consistent with the documented absence of bounded cancellation. Resource restoration and owner cleanup are checked separately.

**Conversion and existing coverage.** The bridge rejects nonintegral/nonfinite/out-of-range signed values before ReLU, accepts both zero signs, and encodes exact integers into little-endian FP16/BF16; failures return zero bytes throughout. Existing harnesses cover every legal integer/position/format, boundary encodings, frozen cases, caller mutation, each-stage timeout/error/cleanup, cancellation, allocation failure, output extents and resource/owner failures. These reviewed tests remain host fault coverage, not fresh native qualification or general-model support.
