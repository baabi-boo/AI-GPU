# A007 — bundle descriptor construction-failure regressions

Added only `ci/project/test_p05_bundle_descriptor_ownership.py` in the checkout.
Read the project guidance, A002 report/reproducer, both production readers and
existing bundle/producer tests. A006 owns the production repair.

## Behavioral coverage

Four test methods run ten isolated CPython child probes. The audit hook rejects
the real integer-descriptor `open` event for the fixture inode; neither
`os.open`, `os.fdopen`, nor the reader implementation is replaced.

- Both `_bundle._read_regular` and producer `_consume` must close the descriptor
  when construction raises `RuntimeError`, `MemoryError`, `KeyboardInterrupt`
  or `OSError`. Observed descriptors must produce `EBADF` from `os.fstat`.
- Runtime/allocation/interruption errors retain their original object identity.
  Installed `OSError` retains the existing `BundleError` translation with the
  exact original cause; producer `OSError` retains its original identity.
- Each reader handles 128 consecutive rejected constructions with the child's
  `RLIMIT_NOFILE` set to 64, without descriptor exhaustion.
- Every child then performs a successful exact-bound read, independently checks
  bytes, SHA-256 and size, rejects a one-byte-smaller limit, and verifies closure
  on both paths.

Audit hooks, reduced limits and producer imports remain child-scoped. Cleanup
closes only still-open descriptors for the observed fixture inode, preserving
failure diagnostics when testing leaking revisions. No broad `sys.modules`
patching is used.
