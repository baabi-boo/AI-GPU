# A071 — SimX exceptional completion and teardown

**Scope and method.** Read-only source review at clean revision
`81d7a35c641f3a969c23c8e604f7468a4d88644a`. Read the assignment, `AGENTS.md`,
current project guidance and `docs/designs/simulator_completion_v1.md`.
Used `git rev-parse HEAD`, `git status --short`, `rg` and bounded source reads.
No compilation, test execution, tool acquisition, native-source edits or
acceptance change occurred.

**One lifecycle traced.** The native unit's bounded-RAM `check_exception()`
launches an instruction fetch at capacity, consumes `OutOfRange` through an
asynchronous future, destroys the processor and RAM, then runs a fresh normal
context. Inspected `sim/simx/{processor.cpp,processor_impl.h,core.cpp,
scheduler.cpp,instr_trace.h,mem/memory.cpp}`, `sim/common/mem.cpp`, both
SimObject headers, `sw/common/mempool.h`, `sw/runtime/common/async_run.h`,
`sw/runtime/simx/vortex.cpp`, and the direct completion/platform fixtures plus
native unit/public-success sources.

**Completion ordering is consistent on inspection.** Core running state includes
pending instructions and undrained LSU work; normal processor completion also
requires platform idle. `run_checked()` propagates the first model exception;
the legacy integer/x3 result remains separate. `AsyncRun` consumes the future
and latches failure before busy can report successful completion. Backend
destruction joins before freeing host regions. Platform cleanup stops workers,
disposes registered ownership/events/domains, then clears abandoned accounting.
Neither reset route clears terminal backend failure.

**Concrete static ownership concern.** The same fault leaves an allocated
`instr_trace_t`: scheduler allocation precedes fetch; memory reads RAM before
popping its request; the exception prevents response and retirement. Normal
retirement explicitly destroys/deallocates traces, but `Core::~Core()` only
deletes `Impl`, whose pending containers hold raw pointers and whose implicit
destructor has no trace-drain step. `PoolAllocator` uses process-lifetime pools;
destroying the allocator does not reclaim this live trace or its vector storage.
Resetting global packet counts therefore does not establish complete resource
release. Independently review exceptional trace ownership before strengthening
teardown claims; preserve frozen sources pending coordinated disposition.

**Limits.** This is a static resource-ownership finding, not a measured leak size,
reproduced failure, or demonstrated violation of fresh-context idle. Fixtures
assert transport/accounting, not trace reclamation. Native execution,
multiworker faults and performance remain unqualified by this review.
