## Confirmed issue: file descriptor leaks if stream wrapping fails

**Suggested priority: P2, host error-path resource ownership.**

Affected locations:

- `python/vortex_ai/_bundle.py`, `_read_regular`, lines 101–102: `os.open` succeeds,
  then `os.fdopen(descriptor, "rb")` can raise before the context manager owns it.
  The error path never closes that raw descriptor.
- `ci/project/p05_bundle.py`, `_consume`, line 91: the same gap occurs in
  `with os.fdopen(os.open(path, flags), "rb") as stream`.

This is not just a hypothetical mock response. CPython's real `open` audit event
for wrapping an integer descriptor can raise before `io.open` assumes ownership.
A rejecting audit hook reproduces the leak against both unchanged production
functions. Other exceptions at that ownership boundary need the same cleanup.
Each failed call retains one descriptor until process exit; repeated failed
verification/production can exhaust a long-lived host process's descriptor limit.

### Reproduction and observed result

Host: Linux, CPython 3.12.14. The retained probe uses a nonempty inert temporary
file, an actual `sys.addaudithook`, and `os.fstat` to verify that leaked descriptors
still name that exact inode. It closes its own leaked descriptors after observation.
It does not replace `os.open`, `os.fdopen`, or production reader code.

### Reachable consumers

The installed helper backs `read_file`, `file_record`, `source_inventory`,
`read_manifest`, `validate_files`, and `build_binding`. Consequently the gap
affects launcher preverification (`launch.py:34,38`), package input staging and
wheel checks (`setup.py:76,308,311`), and bundle production. The producer's
separate `_consume` backs `_Inputs.observe`, `.read`, `.records`, and `.stable`,
so both initial reads/copies and publication-time stability checks are affected.
The C++ native loader has its own RAII descriptor owner and is not implicated by
this reproducer.

### Bounded repair and verification recommendation

Give the raw descriptor explicit ownership from the successful `os.open` until
stream wrapping either succeeds or fails. Cover `BaseException` so interrupted
and allocation-failure paths also release it. Preserve the original failure and
existing file-integrity/size checks; avoid a second close after ownership passes
to a stream. A helper may serve both production readers, but preserve the
producer's distinct zero-size allowance, inode/mode stamps, and `sink` behavior.
Do not broaden this into path-policy or manifest-format changes.

Add independent regressions for both readers: pre-wrapper failure must leave no
live descriptor; ordinary success and read/sink failure must close exactly once;
the original exception must remain primary. The real audit-hook probe can run
in a child because audit hooks cannot be removed. Existing focused bundle and
producer suites provide the integrity compatibility checks.
