**Outcome:** No confirmed runtime defect. FileDescriptor ownership covers exceptions and early returns; failed `fdopendir` explicitly closes its descriptor, while successful ownership transfers to `closedir`. VerifiedBundle receives only fully checked owned bytes/metadata. Build preparation binds source identity to exact manifest bytes; runtime checks the compiled artifact table, manifest hash, all six artifacts, ordered paths and backend. Handles/table intentionally survive teardown. Partial loading never publishes the API; the attempted state requires a fresh process. Canonical paths, relevant SONAMEs, symbol origins and pre/post-load checks reject incompatible selections within the documented non-hostile-writer model.

**Concrete coverage gap (nonblocking):** Existing compiled binding scenarios bootstrap a valid bundle through `FaultControls.activate`; packaging tests do not execute the native loader. I found no direct executable case for a receipt-pinned DSO missing a required symbol or a failure after an earlier DSO loaded. A future bounded host fixture should assert failed open, unpublished API, retained earlier handles and persistent rejection on retry. This is a coverage finding, not evidence that those safeguards fail.
