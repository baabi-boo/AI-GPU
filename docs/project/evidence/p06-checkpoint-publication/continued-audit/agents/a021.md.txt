## Finding: failing descriptor-release assertions leave descriptors open

**Severity: low; test failure isolation.** At `test_checkpoint_ownership.py:159–174`, `record_open` retains the two descriptor numbers, but neither a `finally` block nor a registered cleanup releases a descriptor if `assert_closed` fails. `setUp` only registers `TemporaryDirectory.cleanup` (lines 25–27), which removes directory entries without releasing those open descriptors. A regression in the writer's close loop therefore makes this test both fail and leak its owned descriptors into the remaining tests. The first failed assertion also prevents checking the second descriptor for that subcase.

A focused, in-memory probe wrapped the existing writer and suppressed its `os.close` calls only while it ran. It executed only `test_fdopen_failure_releases_owned_descriptors`, then inspected descriptors after unittest had run the test's registered cleanup. Result:

```text
subtest_failures: 2
errors: 0
owned_descriptors_still_open_after_test_cleanup: 4
temporary_root_removed: True
```

The probe explicitly closed all four descriptors afterward. This demonstrates failure-path leakage in the test; it does not claim the repaired writer currently leaks. Add a local resource guard around these assertions, retaining each descriptor's identity and using the saved real close function to release any still-owned live descriptor without accidentally closing a reused number.
