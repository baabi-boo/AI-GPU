## Reconstruction, publication and errors

The stable wire contract uses two unsigned 32-bit replies on both XLENs. The
public API accepts low CSR addresses `0xB00..0xB1F`, reads low before high, and
publishes the reconstructed uint64 only after both reads succeed. The all-core
route uses unsigned 64-bit accumulation and publishes only after every core
succeeds. Null handles/output, invalid addresses, capability failure, and the
first failing low/high read retain their explicit error results; failed or
partially completed reads do not replace the caller's output sentinel.
Sources: `sw/runtime/common/perf.cpp:265–303`;
`ci/project/fixtures/p06_mpm_transport_host.cpp:230–291`.

The separate host adapter copies the actual production definitions into a
controlled-responder fixture, compiles C++17 with UBSan for RV32/RV64 semantics,
and checks exact vectors, class restoration, architectural aliases, sum carry,
publication and error ordering. It explicitly describes itself as an extracted
host adapter, not a full SimX or native public-runtime execution. Those tests
belong to governance discovery; the transport workflow does not independently
run this host unittest module. A green transport workflow alone must not be
credited with these separate controlled-responder tests.
Sources: `ci/project/test_p06_mpm_transport.py:1–3,35–149`;
`docs/designs/host_mpm_transport_v1.md:138–141`.

RTL counters remain 44 bits; SimX retains uint64 bits above bit 43. The contract
also keeps the backend-specific PERF/class and invalid-core behavior rather
than inventing cross-backend equality or new validation. Stable serialized
sampling remains a prerequisite. Sources:
`docs/designs/host_mpm_transport_v1.md:42–87`.
