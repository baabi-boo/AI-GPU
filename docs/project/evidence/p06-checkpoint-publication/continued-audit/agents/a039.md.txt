## Evidence

- `python/native/module.cpp:450–487`: model success requires all three native stages to have submitted, waited, retained valid trace/output, compared successfully, closed, and passed cleanup. The profile loop checks event status, queried flags, profile status and monotonic queued/submit/start/end times. The corresponding arrays in `sw/runtime/ai/runtime.h:60–66` all have the same fixed extent of five, so the index does not cross a shorter parallel array.
- `sw/runtime/ai/runtime.cpp:642–656`: collection records query status independently and copies a profile only after `VX_SUCCESS`. Default traces have zero-initialized profile values, explicit unsupported query results, and false queried flags. Consequently an unqueried or failed profile cannot establish model output readiness merely through zero timestamps. Diagnostic snapshots may retain incomplete/failing observations by contract.
- `tests/regression/ai_mlp/records.h:143–189`: timestamps, addresses and counters are serialized through unsigned 64-bit decimal output without a float conversion. The Python wrapper parses JSON integers as integers. The shared serializer checks variable stage array extents before reading their content (`:193–197`), and fixed arrays use their declared sizes. Supported runtime status codes are nonnegative and within the converted integer range.
- `python/native/module.cpp:272–302, 433–447`: text checks `PY_SSIZE_T_MAX` before converting its length; word output checks `PY_SSIZE_T_MAX / 4` before multiplication. Temporary Python objects use `PyOwned`; `set_item` releases its local reference on both success and error while the dictionary owns its inserted reference. No borrowed-reference escape was found in this scope.
- `python/native/module.cpp:789–807, 968–1018`: trace and record calls hold a `BusyGuard`, serialize into a local stream with failure exceptions enabled, and return a new Python string. They do not transfer or release the native owner. C++ serialization/allocation exceptions are translated by `boundary`; a post-call Python signal drops only the unpublished Python result. The caller's existing capsule/operation continues to retain native state.
- `python/vortex_ai/_api.py:324–333, 659–662, 753–766`: the public wrapper requires a JSON string containing an object, creates a detached parsed snapshot and preserves record poison/iteration checks. No parsing failure closes or removes the operation owner.

## Existing coverage inspected, not rerun

`test_p05_native_binding.py` contains one host-fault profile-query case for each of the five events, checking the failed status and zero profile, plus publication `MemoryError` cases after real compiled host-only progress. Those publication cases inject Python status conversion failures; they do not claim allocation-fault coverage inside the C++ serializer. `test_p05_python_api.py::test_diagnostic_json_is_detached_and_requires_an_object` checks independent snapshots and invalid diagnostic payload rejection.

The lack of a newly executed C++ stream-allocation fault is a limit of this read-only review, not a demonstrated defect. No new test or production change is recommended solely to expand the audit.
