## Cryptographic and trust boundaries

The archive API is loaded only from the trusted local reader file after checking
its reviewed SHA-256 pin. Current replay helpers must resolve to the expected
repository paths and retain their recorded identities throughout replay. The
archive owner checks canonical non-symlink regular files, original SHA-256,
unique safe member names, ordinary members, reviewed compression methods and
bounded encoded/expanded populations. It rechecks file identity while reading
and closing. Recorded absolute historical paths are interpreted as data, not
opened on the current machine; retained binaries and Python are not executed.

Sources: `ci/project/p06_replay.py:28–31,87–96,139–163,639–652`;
`docs/project/evidence/p05-torch/reviews/archive_reader.py:130–191,203–239,255–299`.

Digest matching and internal hosted-envelope consistency do **not** authenticate
GitHub origin or prove that an arbitrary self-consistent producer executed a
GPU. The original acceptance relies on its separate provider/source/measurement
review; this workflow preserves that already scoped evidence. Current trusted
reader evolution never authorizes replacing original execution-source bytes
with today's runtime implementation.

## Required rejection cases and coverage limits

The inspected reader/analyzer tests specify rejection of:

- Wrong or absent external ZIP digest, historical revision or format identity;
  missing, swapped or duplicated format archives.
- Traversal/absolute names, duplicate members, symlinks/special files, trailing
  ZIP bytes, changed archive files and pinned trusted-reader/source drift.
- Missing or altered retained helpers, rehashed frozen runtime/source
  substitutions, broken compiler/build bindings and before/after instability.
- Corrupted raw warm-up or measured numerics, unsigned-counter violations,
  incomplete or reordered samples/commands, and fabricated matching summary
  copies that disagree with the observations.
- Cross-format source/tool/dependency/configuration or hosted-run mismatches,
  inadequate recorded resources, invalid process/cleanup receipts and widened
  execution or acceptance claims.
