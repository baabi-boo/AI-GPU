# A085 — reconstruction of the original local commits

## Result and scope

**All 49 preservation assertions passed.** This was an actual
reconstruction in a new isolated bare Git object database, not merely a hash
comparison against the original checkout. No project test bodies, GPU/native
workloads, builds, replay commands, network requests or remote writes ran.

The published head is `30b2e8ca69fba47646392c0cf6650cbb75155843`. The reconstructed original
local head is `9f369a579ca764800b22eedd15e09795f09615da`. Their complete tracked trees
are identical at `548b85370e3d13119730b5a30d1ec388d3e141a9`, and `git diff --exit-code` returned 0 with no output.

## Controlled starting object set

The source checkout's published API head supplied exactly **8,896
reachable objects**: 7,969 blobs, eight commits and 919 trees, totaling
**522,558,228 raw bytes**. None of the five original local
commit IDs was in that set. The source's shallow boundary at
`e3ad6bd1e2b002aa234d57cd8a02519cec915830` was retained explicitly.

The objects were packed from that explicit ID list using one thread, zero delta
search window/depth and no delta reuse, then indexed with one thread into
`/tmp/ai-gpu-2bfab0261c05/a085-restoration-work/objects.git`. The resulting pack is **231,264,075
bytes**. Packing and indexing took **6.619761 seconds**.
The isolated database has **no object alternates**, no checkout and no refs.

A complete `cat-file --batch-all-objects` inventory exactly matched the selected
published-reachability set. Before restoration, all five original commit lookups
failed as expected. This proves the verification did not obtain the originals
through an alternate object store or an accidentally copied original branch.

Each exact retained raw body was supplied to
`git hash-object -t commit -w --stdin` in the isolated database, in original
parent order. The output ID, stored raw body, original parent, root tree and
complete recursive tree entries were checked against the record and mapped
published commit.
