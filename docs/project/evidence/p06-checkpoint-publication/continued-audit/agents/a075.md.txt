then requires the compiled exact size/digest pair. There is no CLI override for
the URL, expected identity, proof or resource budget. The URL is consumed from
`P06_CONTROL_ARCHIVE_URL`, removed from the environment and omitted from receipts.

Only bounded ASCII canonical HTTPS signed object URLs on explicitly recognized
Azure Blob and virtual-hosted S3 names are accepted. User information, custom
ports, arbitrary aliases, fragments, path traversal, malformed escapes,
duplicate query keys and nonconforming signature shapes are rejected. Azure
requires blob/read-only fields; S3 requires its declared HMAC/host-signed shape
and a bounded expiry field. These are input-shape checks, not independent
validation of a provider signature or proof that the link remains unexpired.
The provider must accept the request.

The transport performs one direct HTTPS GET with a certificate/hostname-checked
TLS client context and TLS 1.2 minimum. It does not select a redirect target or
proxy override; HTTP debug output is disabled and the context does not enable
ambient TLS key logging. Only status 200 with exact decimal Content-Length,
accepted binary content type and unambiguous unencoded framing can reach the
stream reader. Redirects, range responses, chunked/encoded responses and other
statuses are rejected without reading response text.

The connection timeout is 20 seconds; an unused main-thread POSIX alarm bounds
the transfer at 120 seconds. Reads use at most 64 KiB, request only a bounded
extra byte at the end, and retain no more than the exact expected archive size.

**plus 47,632,218 bytes plus one 64 KiB chunk**. This intake disk test does not
replace the hosted capacity checks, memory checks or later native admission.

messages, never raw URL/response/exception details. Actual partial bytes remain
