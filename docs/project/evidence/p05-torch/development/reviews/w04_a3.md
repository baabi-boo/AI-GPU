The successful matmul scenario covers `(M,N,K)` `(8,4,8)`, `(8,4,16)` and
`(16,8,16)`. It checks copied original operand bits, native arguments/grid,
returned CPU FP32 bits, no pending owner after return, and retained output after
native shutdown. The successful model scenario covers all five FP16 families,
with three captured native-host launches per model, actual transferred fixture
input checks and actual assembled C++ output bytes reaching the returned tensor.
These are scripted host calls, not numerical qualification launch counts.

The error scenarios establish:

- A transient native timeout is retried successfully without losing ownership.
- Matmul and model aggregate deadlines raise with the actual native owner still
  reachable; detach rejects pending work. Clearing the controlled timeout and
  explicitly waiting/advancing/closing restores the owner and permits later work.
- Partial enqueue and asynchronous execution errors do not return successful
  tensors. Explicit close preserves primary code `6`, releases resources, and
  permits a subsequent operation when cleanup succeeds.
- Native cleanup code `10` prevents output and further work. A state-rejected
  follow-up submission can still publish an empty recovery owner; the test
  explicitly closes it. After session close, process-wide cleanup poison still
  blocks opening a replacement session.
- A corrupted hidden model response produces `hidden_mismatch`, retains its
  owner for close and cannot publish output.

Every successful child finishes with zero devices/modules/kernels/queues/
buffers/events/bytes, zero premature frees, zero contract errors and zero input
copy mismatches. Maximum live native devices never exceeds one. All nine child
stderr logs are empty; UBSan reports no issue in these runs.

## Initial probe failures retained

The first run executed all nine scenarios: seven passed and two failed because
of test-harness assumptions. Its original script snapshot and raw logs remain
unaltered under `w04_a3-native-initial/`.

1. `transient_timeout` required a positive final `last_timeout_ns`. Successful
   native cleanup can finish with a zero-time event poll. The corrected assertion
   accepts a nonnegative bounded final poll; the deadline scenarios separately
   verify a positive bounded wait before retained ownership is recovered.
2. `cleanup_failure` attempted to detach after deliberately trying another
   rejected submission. The binding correctly retained that attempt's empty
   owner. The corrected probe explicitly closes `BindingError.operation` before
   detaching, matching the established recovery contract.

These corrections changed only the new probe, not production behavior. The
corrected script was run against the **same single compiled immutable runtime**
using `w04_a3_recheck.py`; no second native build was needed. The recheck verifies
all retained native/Python source hashes and copied adapter files before use.
The complete corrected nine-scenario result is
`w04_a3-native-recheck/report.json`.
