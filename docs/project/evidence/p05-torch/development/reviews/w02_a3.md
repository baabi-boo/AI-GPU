Coverage includes:

- All six supported shape/dtype signatures through the raw registered operator,
  with both poison values, exact packed A and physical column-major B bytes,
  and exact returned FP32 words including signed zero, subnormals, infinities,
  signaling/quiet NaN patterns and poison words.
- Every one of the 65,536 input encodings through the actual adapter for each
  dtype and operand layout. This uses 512 bounded mock submissions per dtype;
  B visits each encoding once and A twice, totaling 393,216 compared input words.
  These are transport checks with synthetic responses, not matrix calculations.
- All ten fixed case names and both poisons through the fixed-model op, with
  owned FP32 results. The native mock outputs synthetic patterns and does not
  evaluate the frozen model or use its expected results as computed evidence.
- Input mutation after copying, output survival after native/session close,
  result mutation independence, and matmul→model→matmul repeated ownership.
- Direct raw-op rejection of gradients including `no_grad`, direct forward AD,
  autocast, fake/meta tensors, tensor subclasses, lazy negative views, malformed
  dtype/rank/shape/strides/offset/storage, sparse/overlapping/expanded operands,
  unknown/stale tokens, invalid model cases and out-of-range poisons.
- Raw-op rejection before scripted execution for vmap (including the no-input
  model), functionalization, JVP, fullgraph compile and TorchScript tracing.
- Partial submission failure, interrupted submission, allocation failure,
  deadline expiry and explicit recovery, cleanup failure, fixed-model creation
  failure and numerical-mismatch status. No output is returned from those errors.
- A native mock that raises if matmul output is requested before explicit close;
  this directly guards the native lease requirement rather than only counting
  wait calls.
- Reentrant and concurrent submission rejection; borrowed-session detach leaves
  the native session open. A simulated PID change checks the process guard;
  this is not a real post-fork execution test.

The mock-based checks exercise the existing real Python `Session`, `Operation`
and `ModelOperation` classes. They intentionally do not substitute a fake Torch
module for dispatcher or tensor behavior. NumPy absence produced Torch's normal
warning; the tests did not use NumPy. TorchScript deprecation warnings were also
retained, with no warning suppression.
