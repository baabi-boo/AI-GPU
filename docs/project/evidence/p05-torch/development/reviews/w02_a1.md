## Implemented boundary

- Explicit optional import with actionable missing-Torch errors. Import requires
  the selected `torch==2.15.0+cpu`, little-endian Linux x86_64 CPython 3.12 with
  the GIL; it does not request the native extension or bundle itself. Base
  `vortex_ai` imports are unchanged.
- Exported `TORCH_OPS_API = 1`, `SUPPORTED_TORCH_VERSION`, and `TorchSession`.
- Versioned raw schemas are exactly the two in the shared interface document:
  `matmul_v1(Tensor a, Tensor b, int session_token, int poison) -> Tensor` and
  `fixed_mlp_v1(str case_id, int session_token, int poison) -> Tensor`.
- Low-level `torch.library.Library` registrations preserve the original tensor
  before guards. CPU/Autograd matmul and CompositeExplicitAutograd no-tensor
  model entries share strict eager guards. Explicit rejecting dispatch handlers
  cover Meta, FuncTorchBatched, FuncTorchVmapMode, Functionalize, Tracer,
  AutocastCPU, Negative, Conjugate and FuncTorchDynamicLayerFrontMode.
- Exact ordinary CPU tensors, FP16/BF16, matching bundle dtype, the three frozen
  shapes, A `(K,1)` and B `(1,K)` element strides, storage offset zero and exact
  dense backing extent. Original tensor gradients, forward tangents and lazy
  negative/conjugate flags are checked before integer reinterpretation.
- A and physical-order `B.t()` are reinterpreted as signed int16 values and
  packed explicitly little-endian. No NumPy, floating conversion, implicit
  layout repair or raw pointer access. Actual native FP32 output bytes become
  a cloned independent CPU tensor.
- `TorchSession` borrows an exact existing native `Session`. A strong registry
  retains the adapter/native session until explicit detach. Tokens increase
  monotonically from `2**32` and stay in signed int64 range. Registry and
  per-adapter mutations use the existing nonblocking, process-aware `_Gate`.
- The adapter exposes token, borrowed session, actual last operation and pending
  native owners. `.close()` detaches only after pending owners have completed
  explicit close; it does not close the borrowed native session.
- Matmul waits and model advances retry only nonterminal timeout/success states.
  Both paths require completed explicit close before output. Models recheck
  their successful terminal status after close. The configured retry deadline
  ranges from one nanosecond through 300 seconds, with each wait capped at
  100 ms; it is not a cancellation or strict whole-call deadline.
- Exceptions preserve existing native owners. The Session registry is the
  durable recovery path even if an interrupt prevents assignment or exception
  attribute attachment. No catch selects a reference output or CPU matmul.

## Integration and independent-review notes

Packaging and installed qualification are owned by separate agents. The adapter
must enter both strict package source inventories before a fresh bound build;
historical accepted bundles/wheels must not be rebound to this source.

PyTorch converts scalar schema arguments before a Python kernel receives them.
The public facade enforces exact Python types; raw operators follow pinned
PyTorch `int` schema conversion. Starting tokens above `2**32` prevents raw
boolean arguments from selecting a valid token, but this is not a claim that
the kernel can recover an argument's pre-dispatch Python type. Tokens are
process-local owner selectors, not credentials or provenance assertions.

The root requested later independent review of interruption immediately after
registry insertion and before constructor publication. The constructor attaches
its adapter/session best effort, and the caller already owns the native Session,
so native work is not lost; an inaccessible retained registration is still a
possible Python adapter-lifetime edge to probe. No extra recovery API was added
without a reviewed interface decision.

Unknown user dispatch modes, monkeypatches, module reload, alternate framework
versions, concurrent tensor mutation while packing, arbitrary models, autograd,
training, compile/export compatibility and a full device backend remain outside
the supported boundary. Explicit dispatch rejection covers the documented,
actually tested transforms; it is not a universal claim about arbitrary caller
interception of PyTorch.
