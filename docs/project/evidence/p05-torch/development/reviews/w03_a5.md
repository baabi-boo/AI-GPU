## Confirmed findings and correction

1. **Vendored entry points treated as installed commands.** F3, high confidence,
   static proof and reproduced behavior. The locked setuptools 84.2.1 wheel
   contains `setuptools/_vendor/wheel-0.46.3.dist-info/entry_points.txt`.
   The original suffix-only interpretation required `bin/wheel`, which pip does
   not install for this vendored distribution. The original runner would reject
   the intended supported dependency installation. The corrected predicate
   interprets active entry points only in a top-level distribution directory.
   Nested metadata remains an ordinary immutable wheel member.

2. **Vendored RECORD and generated-file allowances bypassed payload identity.**
   F2, high confidence, static proof and reproduced behavior. The same suffix-only
   classification exempted a nested vendored `RECORD` from immutable matching and
   allowed unexplained `INSTALLER`, `REQUESTED`, or `direct_url.json` files beside
   it. My probe confirmed that the original accepted changed nested RECORD bytes.
   The correction restricts rewritten RECORD and generated-file allowances to
   actual top-level installed distributions. Tests independently show that valid
   top-level installer rewriting remains accepted.

Neither fix weakens the existing P05 validators, package-source inventory, file
hashes, log failure scanner, native arithmetic checks, or live canonical paths.
