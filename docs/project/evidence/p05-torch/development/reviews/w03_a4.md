## F3 — distinct storage starts do not establish independent output

Evidence type: static proof plus reproducible host execution using actual pinned
PyTorch. Original `run_matrix.retain_output` compared storage base addresses for
equality. Two ordinary CPU tensors can have different storage starts while their
exact packed backing extents overlap. Each can have storage offset zero, the
required shape/strides, and the exact declared extent.

The actual PyTorch 2.15.0+cpu probe constructed two `(8,4)` FP32 tensors, both with
128-byte storage extents and offset zero. Their starts differed by four bytes;
writing through the second changed the first. Thus all representation checks
can succeed while the result aliases another live tensor.

The first host control-flow reproduction caused the original checker to return
`outcome=pass` for three cases: overlapping matmul outputs, a model result
partially overlapping an earlier result, and a matmul result partially
overlapping an input. An adjacent, nonoverlapping control also passed.

A stronger probe retained the frozen matmul/model values and the unchanged
native numerical/dispatch/lineage validators. It used actual Torch tensors but
scripted native owners. The two poison iterations of the fixed `zero` model
returned overlapping 256-byte tensors at offsets zero and four into one buffer.
All their bits remain zero, so final byte stability cannot detect this alias.
For **both FP16 and BF16**, the original checker and pure record verifier accepted
the complete observations with 16 recorded calls. The corrected checker rejected
the second overlapping zero result. These are host fixture-validation results;
there were zero real native launches.

The present adapter's `clone()` implementation does provide separate output
storage. This finding concerns the qualification oracle's ability to reject a
subsequent ownership regression, not observed corruption in the current adapter.

## Correction

The new checker computes half-open byte ranges from actual storage addresses and
extents and rejects every overlap with an earlier live result or matrix input.
It retains all input tensors until completion so allocator reuse cannot cause
false overlap reports and a later model result is checked against earlier inputs.
Adjacent ranges remain valid. The correction does not change native validators,
fixtures, package identities, execution counts or numeric tolerances.

Four dependency-free tests exercise:

- partial overlap with an earlier result at both matmul and model boundaries;
- partial overlap with the current matmul input;
- a model result overlapping an earlier matrix input;
- valid adjacent result ranges at both boundaries.

The default discovery module imports neither Torch nor `vortex_ai`, requires no
network, and has no skips. The actual Torch probes are separate explicit scripts.

## Other reviewed boundaries

The checker observes the returned tensor with an integer reinterpretation of its
physical bytes; it never constructs the reported framework result from reference
values. It compares those bytes to the actual retained owner's output, checks
input bytes before/after invocation, retains result objects, and checks them again
after native session closure. Pending owners are rejected immediately after an
operator returns, before diagnostic repeated close can hide an early return.

The pure verifier keeps exact outer/nested field inventories, distinguishes
booleans from integers through canonical JSON, rejects duplicate keys and
noninteger/nonfinite JSON numbers, binds schemas/version/adapter bytes to the
request and live installed package, and checks actual input/result bytes against
frozen inputs and the corresponding native record. Native model bridge lineage,
explicit close, resource restoration and independent comparison still pass
through unchanged validators. Raw observations must have complete interleaved
chronology and exact equality with saved observations. No relocated-path exception
or relaxed failure scanner was added.
