## Concrete runner defects and correction

**CI-01 — F2, high confidence, static proof plus actual locked-wheel probe.** `_wheel_payload` treated any nested `.dist-info/entry_points.txt` as an active wheel entrypoint. The locked setuptools 84.2.1 wheel contains `setuptools/_vendor/wheel-0.46.3.dist-info/entry_points.txt`, which declares `wheel`. The original runner consequently requires `bin/wheel`, although pip does not generate that command for vendored metadata. The actual pinned venv has no such script. This would make the first complete framework installation fail its inventory check.

**CI-02 — F2, high confidence, adversarial host probe.** `_installed_inventory` exempted every nested `.dist-info/RECORD` from immutable-byte comparison and allowed generated installer metadata underneath each such directory. The original runner accepted a modified vendored RECORD and an injected vendored INSTALLER. Those files are ordinary locked wheel payload and should not get top-level distribution rewrite exceptions.

The proposed patch recognizes active distribution metadata only when it is directly beneath the wheel root, or directly beneath installed site-packages. It leaves nested metadata in the immutable payload inventory. Actual setuptools produces `['bin/wheel']` under the original code and `[]` under the correction; both versions retain all 348 payload files. The corrected inventory rejects both nested tamper cases and still permits normal top-level pip RECORD/INSTALLER rewriting. No existing native or Python validator, numerical scanner, hash lock or qualification scope was relaxed.

Proof and patch: `w03_a6_wheel_probe.py`, `w03_a6-wheel-probe.log`, `w03_a6-vendored-metadata-probe.json`, `w03_a6_vendored_metadata.patch`, and `drafts/w03_a6_p05_torch_execute.py`.
