## Decision

Proceed with a separate, optional, explicitly imported PyTorch module above the
accepted `Session`, `Operation`, and `ModelOperation` objects. Preserve the native
extension, managed runtime, frozen fixtures and arithmetic unchanged. The first
supported framework surface should be eager, synchronous, inference-only,
copying CPU tensors whose mathematical work is dispatched to the qualified SimX
bundle. A CPU tensor at this boundary describes host storage, not CPU matmul.

The justified milestone is P05-A02 plus its P05-A03 compatibility evidence.
`docs/project/p05-entry-handoff.md:163` starts the remaining framework slice;
`docs/project/phases/p05-framework.md:47` defines its acceptance obligations.
Existing A01 acceptance cannot establish a new framework caller, modified source
inventory, or newly built package. Preserve its historical exact revision.

## Native invariants the adapter must preserve

| Invariant | Source | Consequence for custom operators |
|---|---|---|
| One live native context in the process | `python/native/module.cpp:36-54` | Opening another session per operator is unsafe if an older call timed out; never hide the active owner in a temporary local. |
| Cleanup failure permanently blocks new native work | `python/native/module.cpp:39-60` | Propagate cleanup status and instruct fresh-process recovery; an adapter must not clear or work around the poisoned state. |
| Only one outstanding matmul until explicit close | `python/native/module.cpp:683-703` | Successful `wait` is insufficient. Successful framework return must follow successful completed `close`. |
| Session registers owners before submission/creation | `python/vortex_ai/_api.py:478-489`, `505-519` | An interrupt can occur before normal return. Recover from `Session.pending_operations()` rather than relying only on a local assignment or exception attributes. |
| Exception attribute attachment is best effort | `python/vortex_ai/_api.py:175-183` | A caller-held session must remain independently reachable through MemoryError and exception-publication failures. |
| Native destructors drain without a deadline | `python/native/module.cpp:63-72`, `112-115`, `130-133` | Dropping a failed local owner can block. Timeout is not cancellation; never advertise bounded teardown. |
| Session close does not drain arbitrary pending work | `python/vortex_ai/_api.py:541-561`; contract `python_binding_v1.md:61` | Close/drain individual retained operations first; then close the session. |
| Model switches away from the idle matmul context | `python/native/module.cpp:870-903` | Matmul must be explicitly closed before model execution; model must close before lazy matmul resume. |
| Model cleanup success is not model success | `python/vortex_ai/_api.py:689-751` | Require successful terminal model status, completed successful close, then re-read model status before copying output. |
| Model output additionally requires valid dispatch/profiling/resources | `python/native/module.cpp:450-478`, `1022-1038` | Use `model.output_bytes()`; do not bypass its checks by taking a diagnostic `trace['output_words']`. |
| GIL/main interpreter/no inherited fork state | `python/native/module.cpp:160-175`; `_api.py:186-201`, `297-321` | Do not release the GIL or invent concurrent queue support; preserve process/reentrancy errors. |

## Recommended public shape

Keep `import vortex_ai` usable without Torch. Explicitly import an optional
module such as `vortex_ai.torch_ops`; expose one adapter owner wrapping an already
qualified `Session`, plus two versioned custom operator schemas. Suggested
logical schemas (the final exact spellings and registration mechanism require
the selected Torch version's actual tests):

```text
vortex_ai::matmul_v1(Tensor a, Tensor b, int session_token, int poison) -> Tensor
vortex_ai::fixed_mlp_v1(str case_id, int session_token, int poison) -> Tensor
```

The token is an opaque process-local reference to a live registered owner,
never provenance or an address. Use a monotonically allocated token rather than
bare `id(session)` reuse. Unknown, removed, stale and cross-process tokens must
fail. A caller-held adapter/session must retain all pending work. Release its
registration only when closure is complete, while allowing retry after
incomplete closure. The adapter can expose `.matmul(a,b)` and
`.fixed_mlp(case_id)` convenience methods which call the registered operators,
plus `.pending_operations()`, explicit `.close()`, and detached completed
execution observations.

This is a recommendation, not a requirement to add a large registry framework.
A reviewed single-live-session binding is also compatible with the inherited
one-context restriction, provided its lifecycle, recovery, raw `torch.ops` entry
and process boundaries are explicit. Avoid opening and discarding an implicit
session per operator; this loses the robust pending-owner recovery path.

The fixed-model schema should take the named fixture case, not a decorative
tensor that is ignored by execution. Its result is honestly the frozen
qualification model. It does not accept user model inputs or arbitrary weights.
If the chosen registration API cannot support a no-tensor operation safely,
choose another documented registration form rather than inventing an unused
tensor input. Do not claim general network inference from this route.

Eager-only is the smallest coherent initial contract. Fake/meta tracing,
`torch.compile`, export, vmap, symbolic shapes, tensor subclasses, forward-mode
AD, distributed tensors and autocast require separately selected policy and
tests. Do not register a fake implementation merely to make a check pass and
then imply those systems execute native work. If the contract promises explicit
rejection, prove rejection through the raw registered op as well as its facade.

## Tensor representation contract to freeze

Accept exact ordinary CPU `torch.Tensor` inputs only, rank two, identical dtype
`torch.float16` or `torch.bfloat16` matching the bundle. Only these `(M,N,K)`
triples are supported: `(8,4,8)`, `(8,4,16)`, `(16,8,16)`.

Use physical packed layout matching the accepted API: A shape `(M,K)` and element
strides `(K,1)`, B shape `(K,N)` and element strides `(1,K)`. The corresponding
binding byte strides are `(2*K,2)` and `(2,2*K)`. `Tensor.is_contiguous()` alone
is wrong for accepted column-major B and does not define storage-offset policy.
Freeze a simple storage-offset-zero policy or explicitly test nonzero offsets;
reject overlapping, expanded, padded, sparse, quantized and unsupported views.
Reject unresolved negative/conjugate views before reading raw storage.

Packing should reinterpret 16-bit bits and copy them in their actual physical
layout. Avoid conversion through Python floats, `.float()`, dtype conversion or
ordinary BF16 NumPy conversion. One implementation route is an integer view of
A and of the contiguous physical-order transpose view of B, followed by explicit
little-endian word packing. Another may use safely bounded tensor buffer access;
do not bypass extent checks with a raw pointer. Preserve signed zeros and all
16-bit input words, including NaNs and subnormals. All layout/dtype conversions
belong in an explicit caller preparation example, not implicit op behavior.

Return a new, independently owned, row-major contiguous CPU FP32 tensor of shape
`(M,N)` or model shape `(16,4)`. Copy `operation.output_bytes()` after successful
closure. A mutable temporary byte buffer plus `torch.frombuffer(...).clone()`
is a plausible bit-preserving route; test raw output words including signed zero
and NaN payloads instead of assuming a floating conversion preserves them.
Output storage must survive owner/session close, and caller mutation must not
change recorded native observations. Do not return a tensor sharing native
memory or cached result storage.

Reject gradients explicitly, including `requires_grad=True` inputs inside
`torch.no_grad()` and direct `torch.ops` invocation. A check only in a convenience
method is insufficient. Verify the selected Torch registration layer does not
strip gradient state before the rejection callback. A non-differentiable output
created silently by detach is not an explicit rejection. Forward-mode duals and
autocast need their own policy/probes because `requires_grad` alone cannot
describe those modes.

## Synchronous execution and error behavior

The framework call must either return a complete independent result or raise
while retaining recoverable ownership. It must never return a placeholder,
reference result, partially computed tensor or CPU fallback on error.

1. Validate framework representation and gradient restrictions before native
   submission. Bind the active process/session before inspecting foreign handles.
2. Copy inputs into accepted `vortex_ai.Tensor` storage and submit through the
   existing API. The held framework inputs must remain alive through packing.
3. Distinguish initial successful submission (`complete` may be false) from
   terminal success. Retry only transient primary timeout code 7 with no
   validation or cleanup failure; all other codes remain errors.
4. For matmul, wait to completion, then complete explicit close and validate the
   final status before materializing FP32 output. For a model, advance to
   successful terminal inference, complete close, re-read model status and then
   request output. Capture the raw trace/record without replacing observations.
5. On any exception, preserve the original failure and separately retain cleanup
   outcomes. Query pending owners because submission may have completed before
   a Python assignment failed. Do not mask an original native error with a later
   successful close or lose it behind a second cleanup exception.

Existing bounded waiting examples are in
`ci/project/p05_installed_check.py:289-344`. An aggregate monotonic deadline may
stop retries, but cannot promise strict whole-call latency: a model `advance`
applies the timeout per native wait and can perform several waits. Native
destruction remains unbounded. Document a timeout as resumable pending work, and
do not retry the op as a new submission while the previous owner remains live.

## Packaging and provenance traps

The package is CPython 3.12/Linux-specific (`pyproject.toml:11-20`) and base
runtime dependencies are empty. Preserve optionality. Select one obtainable
exact Torch distribution/version, platform, CPU-versus-CUDA flavor and transitive
dependency lock before claiming qualification; do not infer a supported version
from API familiarity or a contemporary documentation version.

The source inventory is strict: `python/vortex_ai/_bundle.py:17-28` lists every
bound Python/native source and `setup.py:56-72` rejects added `.py` files outside
it. `MANIFEST.in` explicitly lists package files. New adapter files must be in
both inventories, build/install validation and the archived source snapshots.
The package source digest includes `pyproject.toml`, `setup.py`, `MANIFEST.in` and
the inventory itself. Therefore adding a Torch module or optional dependency
changes the pin; old accepted bound wheel/bundle pairs cannot simply be combined
with an untracked adapter and reported as a freshly qualified package.

Run the fresh native-to-bundle-to-sdist-to-wheel-to-clean-venv path at a fixed
revision, with the framework installed outside the source checkout. Retain
distribution metadata and hashes, wheel identity, loaded adapter file identity,
actual `torch.__version__` and native/session identity. Keep existing core-only
installation and import checks; framework absence should yield an actionable
error only when the optional module is requested. Do not monkeypatch the
existing bundle manifest or source hashes to make earlier archives usable.

## Acceptance tests with real failure scenarios

- All six dtype/shape signatures, each with two output poisons, exact input bytes
  and output words; the raw `torch.ops` route must actually reach native submit.
- All ten frozen model cases, two poisons, exact hidden/bridge/final outputs,
  three native launches, actual bridge-input lineage and successful cleanup;
  compare independently with the native executable and unchanged fixtures.
- Wrong dtype/device/rank/shape/stride/offset, mixed formats, empty/expanded/
  overlapping views, wrong token/closed session, unsupported gradients in normal
  and no-grad modes, raw op bypass attempts, and selected mode restrictions.
- Timeout during wait and close, native submission failure, model mismatch,
  cleanup failure, MemoryError/interrupt during publication, output construction
  failure, resubmission rejection while pending, explicit recovery and later
  success. Label injected-runtime checks as host-only, not SimX observations.
- Input mutation/release after copy; returned output survives explicit operation
  and session close; repeated calls do not grow native allocation counts;
  matmul→model→matmul correctly suspends and reacquires its sole context.
- Fresh process execution for each format, post-fork rejection, second live
  session rejection, and concurrent/reentrant adapter invocation rejection.
- Base import without Torch, explicit optional import with wrong/missing Torch,
  clean staged sdist rebuild and installed package outside checkout with complete
  source inventory. No optional adapter can execute from ambient checkout files.

## Review disposition

No concrete pre-existing native ownership defect was established in this
read-only audit. The items above are reachable implementation hazards at the new
framework boundary, with explicit source evidence and test obligations. The
external schemas, packaging inventory and execution evidence need independent
review before P05-A02/A03 acceptance. P01 vendor XRT and physical hardware claims
remain separate from this software milestone.
