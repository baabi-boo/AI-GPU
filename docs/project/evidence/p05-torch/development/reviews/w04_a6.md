## Optional compiled host runner findings

### F2 — captured failure bytes were lost or reformatted

Confidence: high. Evidence: static proof and executed scripted-subprocess
regressions.

The original runner parsed a child's stdout before writing its captured logs.
Malformed or noisy JSON therefore raised before stdout/stderr were retained.
It also captured ordinary output as text through the existing helper and used
`str(bytes)` for timeout output. This changed CRLF bytes and rendered timeout
bytes as a Python representation rather than preserving the captured stream.

The proposed correction invokes the identical bounded child command,
directory and runtime environment with binary capture, writes stdout and stderr
before parsing, retains timeout bytes unchanged, and marks invalid JSON as a
failed scenario. Old shared helpers remain unchanged. An invalid output does
not become a successful result or stop later independent scenario attempts.

### F3 — valid JSON from the wrong child context could pass the host gate

Confidence: high. Evidence: executed scripted-subprocess regressions.

Exit zero, empty stderr and any JSON value previously sufficed for a passing
scenario, including an empty object or the wrong scope, format or scenario.
The correction requires the observed scope, scenario, format and explicit
`outcome: pass` to match the expected child. The child emits that marker only
after its native ownership, resource and output assertions finish. These are
host fault tests, and a `simx` scope cannot substitute for their expected scope.

The final five dependency-free regression tests exercise malformed and
non-UTF8 JSON, six wrong-identity variants, nonzero exits, exact timeout bytes,
and a valid identity control with CRLF output. Against the original script
they produce eight subtest failures and three errors; against the corrected
draft all **five tests pass in 0.077 seconds**. The tests import neither Torch
nor a native extension and perform no compilation. Original failures remain
retained. Earlier four-test exploratory logs are also retained separately;
the final five-test original/corrected comparison is the definitive receipt.
