## Installed execution behavior

The CLI requires `--request`, `--output`, and `--contract`, each with an absolute
canonical path. Its two helper imports use explicit sibling locations, so
`python -I` needs neither the source checkout nor a source path insertion.

The checker verifies the copied contract digest, pinned environment and operator
schemas. It checks CPython 3.12.14, Linux x86_64, little endian, GIL enabled,
PyTorch 2.15.0+cpu, the distribution identity, the installed compiled Torch
extension, installed adapter location/hash, and actual dispatcher schema text.
The existing P05 installation, bundle, runtime-library, immutable-fixture, trace,
status, and model lineage checks are reused unchanged.

For each format it invokes the raw registered `torch.ops.vortex_ai` entries for
six matmuls and ten fixed models. A and B are constructed from frozen physical
bytes with the exact required row/column strides. Returned tensor bytes are read
independently through integer views and explicit little-endian packing; no CPU
matrix arithmetic or NumPy conversion is used.

Each call's actual `TorchSession.last_operation` supplies the native status,
trace, output, and model record. The checker verifies that native pending owners
are already empty **before** its diagnostic repeat-close call. This prevents a
broken adapter from returning early and then being repaired by the checker.
It retains all output tensors, rejects storage aliases, closes the adapter and
native session, then checks that every returned output's bytes remain unchanged.
Failure handling uses the existing bounded owner cleanup, preserves incomplete
owners, emits a nonzero result, and terminates the standalone failed checker if
cleanup is incomplete.

inventories, bool/int distinctions, bounded strict JSON with duplicate-key
rejection, canonical live paths, installed source hashes, ordered case/iteration
membership, and full raw-log chronology. Native observations reach the existing
`p05_execution_records.verify_observations` without rewriting. Its existing live
path checks and failure scanner remain unchanged. Framework input bytes match
the frozen fixture; actual returned framework output bytes match the observed
native owner bytes validated against fresh native references.
