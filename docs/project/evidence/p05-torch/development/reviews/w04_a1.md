## Findings resolved

### Original forward tangent hidden by inference mode — resolved

The integrated `_operand` temporarily disables inference mode only while reading
`unpack_dual(value).tangent`, then restores the original context before any
copying or native work. It still examines the original tensor and does not
replace, detach, reinterpret, or normalize that tensor before the gradient
checks. The reverse-gradient rejection remains present.

The new regression supplies a pre-existing dual independently as A and B inside
inference mode and requires rejection with no native submission. Companion
tests demonstrate that fresh inference primal tensors still execute inside and
outside inference mode, including an otherwise empty forward-AD level. The
context manager restores state on normal return and exceptions. The correction
does not broaden autograd support or modify integer packing/output publication.

### OWN-01: partially initialized native Session accepted — resolved

The native binding initializes `Session._info` to an empty immutable mapping.
It publishes a nonempty snapshot only after successful complete native opening
and full identity validation. The added readiness check runs under the existing
Session gate and tests this established invariant; it does not accept an
external caller's qualification flag.

All four injected opening failures are rejected during adapter attachment,
before registration or native work. The error retains the actual Session, and
the tests close that owner successfully. This avoids the previous delayed
`KeyError('format')` without changing native creation or cleanup semantics.

### OWN-02: interrupted constructor exposed the wrong adapter — resolved

When a duplicate attachment is found, `retained_adapter` now identifies the
already registered adapter. The exception handler runs after the registry gate
has exited and attaches that existing owner to the duplicate error. This fixes
recovery after registration succeeded but interruption prevented assignment of
the constructor return value.

The regression injects an actual CPython return-trace interruption, retries
attachment, obtains `BindingError.adapter`, detaches it, creates a different
token, and successfully invokes a new host-mock matmul. The change preserves
strong registry retention, token monotonicity, nonblocking gate behavior, and
the Session's authoritative pending-owner inventory.

The documented ordering remains material: recover the adapter while the native
Session is open. If a caller closes that Session first, the existing readiness
check precedes duplicate lookup and a closed registry entry can remain until
process exit. This is the already reported narrow F1 memory-retention limit;
successful Session close releases active native resources. This approval does
not claim recovery after native Session close or grant a waiver for a broader
lifetime contract.

### Distinct storage starts accepted overlapping buffers — resolved

The checker now compares half-open byte intervals derived from actual storage
start addresses and extents. Its nonoverlap predicate accepts adjacent buffers
but rejects partial overlap in either direction. This addresses the demonstrated
zero-model case in which all compared values remained correct despite aliasing.

All prior outputs remain strongly referenced. All matrix inputs are now retained
as well, so every result is checked against still-live input allocations and
allocator reuse cannot create a false overlap. A model output is checked against
earlier matmul inputs. Exact tensor type, dense layout, offset, extent, and byte
validation still precede acceptance. The native validators, numerical tolerance,
raw-record checks, launch counts, and explicit-close checks are unchanged.

The four dependency-free regression tests exercise overlapping matmul/model
results, current-input overlap, earlier-input overlap at the model boundary,
and adjacent valid buffers. They test checker policy with scripted objects;
their synthetic counts are not accelerator execution evidence.
