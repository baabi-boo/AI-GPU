## Existing numerical contract

The public copying boundary is `python/vortex_ai/_api.py:Tensor`, `Session.submit`, `Operation.output_bytes`, `ModelOperation.output_bytes`, and `ModelOperation.record`. Its documented contract is `docs/designs/python_binding_v1.md`.

| Shape `(M,N,K)` | A tensor shape / PyTorch element strides | B tensor shape / PyTorch element strides | FP32 result |
|---|---|---|---|
| `(8,4,8)` | `(8,8)` / `(8,1)` | `(8,4)` / `(1,8)` | `(8,4)` / `(4,1)` |
| `(8,4,16)` | `(8,16)` / `(16,1)` | `(16,4)` / `(1,16)` | `(8,4)` / `(4,1)` |
| `(16,8,16)` | `(16,16)` / `(16,1)` | `(16,8)` / `(1,16)` | `(16,8)` / `(8,1)` |

Each row is supported for both `torch.float16` and `torch.bfloat16`, with the dtype matching the bound session. Native/Python `Tensor.strides` are **byte strides**, twice the element strides above. The result byte strides are four times its element strides. Initial C is positive zero; the native TFR arithmetic is not interchangeable with arbitrary PyTorch CPU matmul rounding.

Input storage is exact little-endian 16-bit elements. Packed fixture `uint32` words place the earlier element in the low 16 bits. Output storage is exact little-endian FP32 bits, not a Python-float serialization. A PyTorch numerical cast or Python float list is therefore the wrong bridge, particularly for BF16, subnormals, signed zero, and NaN payload/quieting cases.

A minimal explicit input policy should accept plain CPU, strided, rank-two tensors with the exact shapes/strides above, matching dtypes, no conjugate/negative lazy bit, and no requested gradient. For the initial contract, requiring storage offset zero is the simplest reviewable boundary. Whether larger underlying storage is allowed must be deliberate and tested; it must not accidentally authorize reading unrelated elements. Unsupported padding, broadcasting, negative/zero strides, expanded views, sparse layouts, devices, and dtypes must fail before a native context/launch when practical.

### Critical B-layout footgun

B is mathematically `(K,N)` but physically column-major. Calling `b.contiguous()` or ordinary row-major flatten/reshape before extracting its bytes changes the native operand ordering. Merely checking `numel`, shape or dtype will not catch this. Validate B stride `(1,K)` and serialize physical column-major order explicitly. One possible metadata-only route is the validated transpose, whose `(N,K)` view is row-major, followed by a bitwise byte view; this is not a numerical transpose operation passed to the kernel. The exact implementation must be tested using non-symmetric fixtures and retained input bytes.

NumPy is not needed for these bounded tensors. In particular, do not rely on ordinary BF16 `.numpy()` or on `.float()` as an intermediate. A byte reinterpretation/copy preserves encodings and avoids adding an unqualified conversion.

## Native model lineage is already correct and reusable

`sw/runtime/ai/mlp_runtime.cpp` contains the relevant concrete sequence:

- `submit_stage()` serializes actual frozen X/W1 for the first call. For output stages, it copies the corresponding 128-byte slice from `trace_.bridge_bytes`, and serializes W2.
- `compare_stage()` copies the actual `operation_->output_words()` into the stage record. For the hidden stage, it copies those same actual words into `trace_.hidden_words` before comparing with the independent expected hidden words.
- `bridge()` passes actual `trace_.hidden_words` to `prepare_mlp_hidden`, stores its actual bytes, and separately compares the actual bridge words to the frozen reference.
- `assemble()` copies the two actual output blocks into the final output and separately compares the final words.
- `advance()` will not bridge past a failed hidden comparison, nor publish successful inference after a runtime, comparison, bridge, cleanup, or accounting failure.

The `prepare_mlp_hidden` helper is deliberately narrower than a generic `torch.relu(...).to(...)`: it accepts exactly 128 finite, integral FP32 words in `[-64,64]`, applies ReLU and an exact integer-bit encoding, and rejects malformed values. Both signed-zero inputs encode positive zero, while the preceding hidden raw-bit comparison still rejects unexpected negative zero. Replacing this helper with an ordinary framework conversion loses the reviewed domain checks even when current fixture values happen to agree.

Each model run is precisely:

1. `(16,8,16)` hidden matmul, 128 FP32 words;
2. host ReLU/exact format conversion, 256 bytes / 64 packed words;
3. `(8,4,8)` output rows 0–7, 32 FP32 words;
4. `(8,4,8)` output rows 8–15, 32 FP32 words;
5. host assembly of those actual blocks into 64 FP32 words.

A model custom operator should be explicitly named a fixed/frozen qualification case operator, not arbitrary inference. The existing native owner accepts a named case with internally owned expected arrays. Arbitrary model inputs, arbitrary weights, a reference-free executor, and an apparent generic `linear` operator are separate work.

## Recommended operator surface and evidence access

Freeze an operator namespace and version, e.g. `vortex_ai::matmul_v1` and `vortex_ai::fixed_mlp_v1`, before implementation. At the mathematical boundary:

- `matmul_v1(Tensor a, Tensor b, <qualified owner selector>) -> Tensor`: returns a new owned CPU FP32 row-major tensor only after native success and completed explicit close.
- `fixed_mlp_v1(str case_id, <qualified owner selector>) -> Tensor`: returns the actual fixed case's new owned CPU FP32 `(16,4)` result, after successful model status and completed explicit close.

The owner-selector representation belongs to the lifecycle/registration design; this audit does not prescribe passing arbitrary Python objects through a schema or granting caller-supplied provenance. The zero-tensor-input model schema needs an actual registration/dispatch test rather than assuming a CPU dispatch key will be inferred.

Keep a framework-visible receipt or explicit capture API tied to **that exact invocation**, so qualification can obtain the existing native `trace()`/`record()`, the input byte digests, and the actual returned torch tensor bytes. A global stale `last_trace` is not sufficient without strict invocation identity and serialization. Preserve separate primary, cleanup and completion outcomes; do not turn cleanup success into numerical success. Owner retention after failure must continue to work through the framework wrapper.

Explicitly reject `requires_grad=True` at the public entry and direct registered-op entry. Do not silently call `detach()` to accept it. Reject or clearly declare unavailable autograd, autocast, fake/meta execution, compile/export, tensor subclasses, and vmap unless individually implemented and tested. An opaque custom operator registration is not proof that these subsystems behave correctly.

## Reusable comparison and observation infrastructure

### Selection and independent raw records

`ci/project/p05_execution_records.py:select_matmul_cases` already freezes three cases per format:

- `single-dense_boundaries`: `(8,4,8)`;
- `numerical-cross_tile_rounding_positive`: `(8,4,16)`;
- `multi-dense_boundaries`: `(16,8,16)`.

The middle case specifically exercises native rounding across tiles; its observed fixture output is positive zero for all 32 words. It is a useful guard against replacing TFR reduction with host arithmetic. The dense cases have non-symmetric operand patterns that can expose B-order errors.

`select_model_cases` freezes the five families, in order, for each format: `seeded_dense`, `negated_dense`, `zero`, `signed_basis`, `split_boundary`. The last family distinguishes the two output row blocks. Keep all existing immutable inputs and independent reference producers unchanged.

`ci/project/p05_execute.py` already orchestrates an independent native matmul executable, an unchanged native P04 model executable, bound sdist/wheel construction, a clean installed venv, and exact source/bundle identities. Reuse the underlying helpers; do not copy accepted historical output into a fresh-run success packet or count a copied native packet as an additional execution.

### Existing validators

`ci/project/p05_execution_records.py:verify_observations` checks raw JSON/log agreement, canonical membership/order, per-operation status and cleanup, resource restoration, actual raw output words, five native event/profile observations, dispatch ABI, and exact agreement with independently executed native matmuls/models. Model validation delegates to `p04_execution_records.verify_output`, which checks all intermediate words and input lineage. These routines can underpin a **new framework observation schema** while keeping the old plain-Python schema unchanged. The missing proof is the framework-to-binding boundary: actual torch input metadata and bytes, direct registered-op invocation, actual returned torch tensor bytes, exact framework/version identity, and binding those observations to their corresponding native record. Do not satisfy this by recording only the owner bytes while never reading the returned framework tensor.

`p05_installed_check.py:check_model` provides extensive native trace assertions and ties final bytes to immutable model output SHA-256 pins. It must be supplemented, not relabelled as a PyTorch test. `run_matrix` currently calls `api.Session.submit/model` directly and does not execute a torch custom operator.

Derive all published totals from the actual retained observations rather than these planned counts.

For each framework result retain/check:

- Exact input dtype, shape, element stride, storage offset, device, grad flags, and extracted raw bytes/digests.
- Exact returned FP32 tensor shape, strides, device, no-grad flag, owned storage/nonaliasing, and raw uint32 output words. Compare these to the completed native owner's bytes, independent native executable, and unchanged fixture.
- For each model, 128 hidden words, 64 bridge packed words, 32+32 stage output words and 64 assembled words; negative hidden mismatches must fail before ReLU can mask them.
- Exact live bridge byte slices on dependent launches and correct output-row assembly; fake expected arrays must never feed launches.
- Actual native launch/event completion, explicit close, separate cleanup results and restored memory baseline.
- Explicit host copies: framework serialization/result creation are additional host copying work. The native model's existing 1,920 H2D tensor bytes, 768 D2H bytes and 256 assembly bytes per model run remain their own counts, excluding setup/argument traffic. Do not mislabel framework copies as DMA.

## Targeted adversarial tests

These new tests resolve concrete new risks rather than repeating unrelated native tests:

1. Serialize non-symmetric B column-major and reject row-major B; check retained submitted bytes.
2. Preserve representative fp16/bf16 raw encodings through the packing function, including both zeros, subnormals, infinities and NaNs, without claiming those packing-only checks are native arithmetic qualification.
3. Return an FP32 result containing chosen raw words via a host stub to prove bit-preserving output construction, nonaliasing and lifetime after owner closure.
4. Reject same-shaped transposes/padded slices/expanded zero-stride views, wrong format, mixed format, rank mismatch, storage-offset policy violations, and `requires_grad` through both helper and `torch.ops` entry points before dispatch.
5. Inject native submission, wait, cleanup, model mismatch and incomplete timeout states; require no successful framework tensor, no CPU matmul call and retained recoverable owner.
6. Corrupt only the returned torch tensor while keeping the native record valid: the framework consumer must reject it.
7. Corrupt only framework operand bytes/metadata while keeping native records valid: the consumer must reject it.
8. Substitute a different case's output/record, swap the two model output blocks, omit an iteration, duplicate an observation or reuse a stale trace: reject all.
9. Confirm successful result storage survives session/owner closure and cannot mutate a later result or original native bytes.

## Blockers and limits

The repository contains no implemented or qualified PyTorch version/operator at this revision. An exact version must be chosen from an actual available installation, its package identities retained, and the fresh tests run. The accepted A01 package is bound to a 22-input source inventory; adding a new module/metadata may require updating that inventory and building fresh bound artifacts, not pretending the old accepted source digest names new adapter code.

The accepted implementation proves SimX, not a full framework device backend, native RTL framework execution, physical performance, training or CUDA compatibility. Vendor XRT and the inherited DSP gate remain separate obligations. This source audit does not close P05-A02/A03.
