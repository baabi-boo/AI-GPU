## Evidence-led design corrections

The original `-fno-access-control` suggestion was rejected by a real syntax check: disabling access checks changes the SimObject access-detection template and triggers its existing `on_tick() must be protected` assertion. The model assertion remains unchanged. A small standard C++17 explicit-instantiation/private-member-pointer probe passed `g++ -std=c++17 -Wall -Wextra -Werror -pedantic -fsyntax-only`. All accessors now use that typed test-only seam, without special compiler flags, access macros, layout arithmetic, or production class changes.

The socket/cache/memory wrappers each include their unchanged nominated production `.cpp`. The TCU implementation has an anonymous-namespace Buffer member, and GCC diagnoses its external containing class only in include context (`-Wsubobject-linkage`). The original implementation passes as a main source file. No warning is suppressed: the diagnostic makefile generates `obj/tests/checked_counters/access_tcu.generated.cpp` from exact production `tcu_tbuf.cpp` bytes + one LF byte + exact accessor-footer bytes. This is compiled as a main source to `access_tcu.o` with the same flags as every other TU. The runner binds and retains both inputs and the exact generated bytes.

Only the diagnostic object list replaces `socket.o`, `mem/cache.o`, `mem/memory.o`, and `tcu/tcu_tbuf.o`; it adds the separate counter-access helper. Production SRCS, OBJS, targets, and compiler flags remain untouched.
