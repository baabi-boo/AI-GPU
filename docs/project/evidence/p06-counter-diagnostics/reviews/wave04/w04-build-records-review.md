## Findings

### F0 — prior model records must come from validated original records

The public pure parser accepts the previously validated model summary. It checks that summary's required shape, exact counts, source/object mappings, includes, and file-identity inventory. It does not itself replay the original 45-translation-unit compiler log. That is consistent with the current native caller, which obtains the summary through `checked.validate_build`.

Any retained-data replay caller must first run `checked.parse_build_records` against the original model compile log and exact retained source/generated bytes, bind and compare the retained model object identities, and then pass that validated result to the public parser. It must not accept an unverified archived `model_records` summary as authoritative. This is an integration precondition rather than a defect in the reviewed API.

## Contract verification

### Source, object, and role inventory

- The prior model inventory is exactly 45 translation units. The boundary-test main is excluded by its exact tuple, leaving 44 reused model objects.
- The public inventory contains exactly 19 newly compiled source/object/role tuples: 14 runtime objects, three backend objects, one hook object, and one public-main object.
- The implementation deliberately distinguishes object paths and build roles. It therefore supports the shared `runtime/common/utils.cpp` source in runtime and backend roles, and the separately compiled `sim/common/cmd_processor.cpp` source in model and backend roles, without silently deduplicating either required object.
- Exact target/source mappings, dependency targets, include ordering, role-specific compiler options, required macro values, and source coverage are checked. Duplicate targets, foreign objects, missing source coverage, unknown compiler flags, and incorrect role flags are rejected by the implementation and negative tests.

Exactly four final link commands are accepted, in order:

1. `libchecked-simx.so`, containing the 44 expected reused model objects and the exact model dependency/SONAME contract.
2. `libvortex-simx.so`, containing the exact 14 runtime objects with its shared-library options and literal `$ORIGIN` rpath.
3. `libvortex.so`, containing the three backend objects and hooks exactly once, the checked-model dependency, and all five processor wrappers at this backend DSO boundary.
4. `checked_public_test`, containing the exact public main and isolated runtime/backend link and rpath contract.

Wrapper names cover processor construction, destruction, `run_checked`, DCR reads, and DCR writes. They are required at the backend link rather than merely somewhere in the build output. Extra commands that compile or link recognized source/object/library types are rejected. Link order, artifact names, expected object inventories, dependency suffixes, and literal shell handling are constrained as implemented by the checked-record grammar.

### Pure parsing and live identities

- Pure parsing uses normalized inert `PurePosixPath` identities. Traversal, dot aliases, unsafe path tokens, malformed identity fields, duplicate identities, incorrect digests, and nonpositive or non-integer sizes are rejected.
- The pure parser performs no producer-path file access or subprocess execution. This was checked both by the existing deleted-producer-tree test and by an independent probe that denied `builtins.open`, `os.open`, `os.stat`, `os.lstat`, `subprocess.run`, and `subprocess.Popen` while parsing actual configured retained records successfully.
- Live validation rehashes all 44 reused objects against prior identities and checks all 19 new objects. A separate probe confirmed it rejects a new object path that resolves through a symlink alias.
- Make dry-run records are evidence about the configured build contract. This parser is not an authentication mechanism for arbitrary producer-controlled records. The trusted runner, source snapshot, actual command results, and subsequent file identities remain necessary parts of the integrated evidence chain.
