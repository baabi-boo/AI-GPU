## Finding and bounded repair

The source exporter previously trusted the recursive `git ls-tree` inventory
after selecting an explicit commit/root identity. It independently rehashed
selected blobs, but a statically inconsistent nested tree in a caller-selected
object store could supply different, individually valid blob identities.
This is the narrow object-store trigger reported in the
[boundary review](w07_a02.md), not evidence of corruption in either historical
archive.

local checkpoint `5d2b2df53a619e9cde11ae9a4c3337a019a40434`, source SHA-256
`4369ee67411c403d321cae35e16823ef37f9c1721dad2a6239672d94452359aa`.
In a disposable repository, the original root ID remained unchanged while the
old reader returned the altered nested source. The repaired constructor rejected
the same fixture with `Git tree reconstruction differs from the selected root
identity; empty trees are unsupported`. This local parent control executes
reviewed exporter code; it does not execute an archived producer payload. The
committed regression has no dependency on unavailable historical Git commits.

The [35-line exporter addition](../../../../../ci/project/p06_managed_preflight_source_export.py)
reconstructs the complete canonical root tree from its bounded flat inventory.
It preserves regular/executable/symlink/gitlink modes, uses Git's directory
sorting rule, permits shared object identities, and rejects file/directory prefix
collisions in either insertion order. Implicit directory entries share the
50,000-entry bound; input depth remains at most 64 components. Recursion is
therefore bounded by the already checked path depth. Committed empty directories
omitted by recursive `ls-tree` fail closed as explicitly unsupported.

The repair adds no Git command, output field, source selection, or serialization
change. It does not authenticate remote origin, establish dependency compilation
provenance, or defend a compromised trusted interpreter/Git executable.
