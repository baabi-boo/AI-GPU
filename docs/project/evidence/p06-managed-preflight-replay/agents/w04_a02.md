## Review evidence

| Boundary | Evidence and assessment |
| --- | --- |
| Closed command inventory | The parser constructs exactly 30 unique commands: 14 RISC-V compiles, two archives, two archive dumps, five Clang invocations, two recursive make invocations, and one each of host dependency generation, kernel conversion, kernel dump, stub link, and host link. Every actual record must match one known command, occur once, and satisfy its prerequisites. The integrated call runs after the independent compiler-record binding. This closes the previous final-host-command-only acceptance gap. |
| Shell quoting and normalization | `_line` folds only ASCII spaces and tabs and retains shell punctuation and quotes. The supported quoted configuration value is a whitespace-separated definition list; its values are independently checked. The literal `'$ORIGIN'` token and the startup command-substitution text remain part of the exact grammar. The parser does not execute any of these strings. Added controls reject operators, comments, assignments, substitutions, and executable prefixes within an otherwise unchanged command record. |
| Path and tool binding | Source, build, selected tools, and tool root pass the canonical absolute path restriction. Compiler, archiver, objdump, objcopy, libc, libm, and builtins selections are bound to the retained tool-root layout. Host compiler and make paths are selected from the independently bound tool inventory. No arbitrary command spelling is admitted by whitespace normalization. |
| Flags and ABI | The two application stamp records must equal the independent kernel and host originals. Projection preserves the checked-counter guard requirement, and both timed-record validation and the exact warm-profile macro inventory run again. This rejects added macros as well as altered known values. RV64 target/ABI, optimization, KMU selection, startup flags, include paths, library order, wrapper flags, and host linkage match the retained recipes. |
| Object and source mapping | All seven source-to-object mappings are explicit for each of the ordinary and KMU kernel libraries; archive member order is exact. Matmul and startup sources, two startup compilation stages, intermediate startup ELF, final kernel ELF, conversion inputs, and stub/host source lists match the pinned recipes. |
| Parallel make dependencies | Independent ordinary/KMU compilation and host/kernel branches can interleave. Each archive follows all its seven compiles, each dump follows its archive, application compilation follows completion of both kernel-library dumps, startup stages are ordered, and conversion/dump follow kernel link. Host link follows stub link. The parser does not impose an unnecessary total order between independent branches. |
| Recipe drift | All eight grammar-dependent recipe bodies must match their pinned SHA-256 identities. A changed recipe requires a reviewed grammar update. The retained startup script and vxbin implementation are hash-checked as data, without execution. |

unchanged. No shell command from a log or mutation is executed by these tests.

## Limits

This review checks an inert replay of recorded commands for the supported
recipes. Matching the recorded command graph does not establish that a
compiler actually executed, nor does it establish dependency compilation
provenance. Silent recipe actions are not asserted to be additional observed
commands. The existing replay qualification limits therefore remain
necessary. This reviewer did not run a native build, execute retained code,
run the full project suite, commit, or modify a remote branch.
