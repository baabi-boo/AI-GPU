entry, the asynchronous future and upstream runtime error/completion handling.

## Documentation change

observations alongside exception and upstream completion/error observations,
and preserves the established legacy-register meaning. Its ambiguous
“nonzero execution result” wording now refers specifically to failed upstream
completion/API status. The proposal does not require a fabricated integer return
or a blanket zero check on legacy `gp`.

One proposed control was added: distinguish a successful run with nonzero
legacy `gp` from an actual asynchronous failure. This complements the existing
parent-failure, trace, reset, pending-balance, ownership and cleanup controls;
none was executed here.

The bounded sequence remains intact: freeze the new witness and nonmutating
accessor; capture all 33 run/reset pairs with exact reset deltas and both flush
boundaries; bind terminal state through actual destruction; apply the source
theorem; independently review the controls before a fresh native attempt.
Fresh dependency provenance and the nested `make -j4` resource issue remain
