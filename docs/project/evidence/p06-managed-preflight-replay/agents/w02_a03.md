# Wave 2 / assignment 3 — Git-object source exporter

## Delivered

Implemented `ci/project/p06_managed_preflight_source_export.py` and its focused
23-method test module. The exporter receives an explicit source commit and local
Git repositories, derives Ramulator/SoftFloat commits from the source Gitlinks,
checks their `.gitmodules` declarations, checks Ramulator's selected CMake
FetchContent declarations and uses explicit full spdlog/yaml-cpp commits.

All source bytes come from read-only Git object operations. Selected bodies are
never imported, executed or checked out, and no archive supplies names or expected
bytes. Every selected blob's SHA-1 object identity is recomputed, alongside its
SHA-256 and length. Shared command and byte budgets, per-command deadlines and
bounded pipe reads constrain discovery. Git replacement objects and inherited Git
configuration/environment injection are disabled. Selected symlink blobs reject.

First-party discovery combines the required 806-name inventory with the reviewed
source-root suffix rules and direct runtime test sources. The 33 source-discovery
and import-bearing helper bodies must match one of the independently reviewed
8756f400/57248e73 fingerprints; changed producer discovery therefore requires
review. Dependency discovery includes SoftFloat's RISCV headers. Output creation
is exclusive, with paired-output cleanup that preserves pre-existing files.

## Receipt API for replay review

`export_inventory` returns `(manifest, receipt)` and accepts explicit keyword
arguments `source_repository`, `source_revision`, `ramulator_repository`,
`softfloat_repository`, `spdlog_repository`, `spdlog_revision`,
`yaml_cpp_repository`, and `yaml_cpp_revision`. The existing inventory-v1 schema
is unchanged. The receipt contract is
`p06-managed-counter-preflight-source-export-v1`, schema version 1.

The receipt's `repositories.source.commit` and `repositories.source.tree` are the
Git-derived producer revision and tree (`cd61992a845ad14cbebd24b930c5801f727d5b41`
for the successful original). `repositories` also includes entries `ramulator`,
`softfloat`, `spdlog`, and `yaml-cpp`, each with `commit`, `tree`, and `selection`,
plus Gitlink `producer_path` or FetchContent `declared_tag` and reviewed `url`.
`manifest_sha256` pins the exact serialized inventory bytes; `source_revision`,
`source_files`, `source_names_sha256`, and `discovery_helper_sha256` bind discovery.
Every `sources` row has `path`, `repository`, `repository_path`, `git_mode`,
`git_blob`, `sha256`, and `size_bytes`. An independently pinned receipt or
explicit expected-tree argument can therefore strengthen replay tree checks
without revising inventory-v1. The exporter does not itself provide a receipt
reader; adding one should validate the expected digest before accepting its tree.
