## Boundary review

| Boundary | Evidence and assessment |
| --- | --- |
| Explicit Git selection | Repository paths must be canonical absolute directories without symlink ancestors. Revisions must be complete lowercase SHA-1 commit names. The exporter requires the SHA-1 object format and exact commit resolution, obtains the selected tree, and reads objects without checking out source. Dirty and untracked checkout contents do not enter the inventory. |
| Command isolation | Git is resolved through the system command path. The child environment is constructed explicitly, excluding inherited Git configuration and object-directory overrides. Replacement objects, hooks, filesystem monitoring, untracked caching, optional locks, prompting, and lazy fetching are disabled; generic protocol access is denied. The actual commands are `rev-parse`, `ls-tree`, and `cat-file`. No retained producer helper or CMake body is imported or executed. |
| Resource bounds | A shared budget across all five repositories limits Git commands to 25,000 and selected blob bodies to 64 MiB. Individual blobs are bounded at 16 MiB before payload reads; each recursive tree listing is bounded at 8 MiB and 50,000 entries. Commands have a 30-second deadline and 64-KiB stderr bound. Source and receipt serialization are bounded independently. These are explicit per-command and aggregate-data bounds, not a separate short total wall-clock guarantee. |
| Complete selected discovery | The existing minimum is exactly 806 sorted, hash-bound first-party names. The exporter extends this through fixed reviewed source roots and suffixes, direct runtime tests, and dependency header roots. Required producer/helper bodies are hashed and checked against the two reviewed discovery identities. A changed helper requires a separately reviewed recipe update. Fresh exports independently found 999 selected files for each revision. |
| Gitlinks and FetchContent | Ramulator and SoftFloat commits are selected by the producer tree's two required Gitlinks, with exact paths and URLs checked in `.gitmodules`. Ramulator's two FetchContent declarations must contain the reviewed URL, tag, and source-directory text. spdlog and yaml-cpp bytes are selected by caller-supplied full commits; the receipt explicitly avoids claiming remote tag or origin authentication. |
| Source integrity | Every selected path must identify a regular Git blob. The exporter checks its advertised length, computes the Git blob SHA-1 from the exact header and body, and records body SHA-256 and size. The replay reader independently recomputes both hashes and length for each retained source body. Modes, repository mapping, selected header roots, paths, names digest, and row ordering are validated. |
| External digest binding | `replay_archive` first loads the source manifest through its independently supplied exact-byte SHA-256, then loads the derivation receipt through its separately supplied exact-byte SHA-256. The receipt must name that manifest digest and source revision, and all receipt descriptors must equal the validated manifest. Receipt digest checking precedes JSON parsing. The lower-level dictionary validators explicitly require a trusted or already validated caller. |
| File input and strict schemas | The receipt loader rejects parent traversal and uses the shared descriptor-relative no-follow reader, including nonblocking opens, regular-file checks, directory identity checks, file-state checks, byte bounds, and a second read. File and directory links, FIFOs, invalid JSON, extra fields, reordered or duplicate rows, boolean counts, and inflated claims are covered by focused rejection tests. |
| Retained checkout binding | The source checkout revision and tree must equal the external receipt. Submodule records have exact fields, valid full revisions, unique sorted paths, initialized status, bounded counts, and no errors. Both selected dependency Gitlinks must equal the receipt's independently exported commits. |
| Honest claims | The receipt and replay retain `native_execution: not_run`, `retained_code_executed: false`, and false compilation-provenance and qualification/acceptance fields. Replay explicitly sets `remote_origin_authenticated` and `git_object_membership_revalidated` false. This separates the producer's Git-object export from later inert archive validation. |

The review used `AGENTS.md` and `docs/review/code-review-policy.md`. No F2
or F3 finding was established, and no waiver is requested. The following
two initially suspected corruption paths were disproved in the tested
environment rather than reported as findings: a loose commit object and a
loose tree object were each rewritten under their original object filename
to reference different valid source bytes in disposable local repositories.
Git 2.56.1 rejected both with hash-mismatch errors before the exporter could
select the altered body. These probes did not touch any supplied repository.

## Limits

The selected source/header inventory is not a complete dependency compilation
closure. Git membership and matching bytes do not authenticate a remote
origin, resolve remote tags, prove source-to-binary compilation, establish
loaded bytes, or qualify counter behavior. Caller-selected repositories and
the trusted local Git executable remain inputs; the documented concurrent
object-store mutation limitation remains. The tested loose-object corruption
cases do not establish all-version Git corruption coverage.

This reviewer ran no native build, hardware test, full project suite, remote
operation, commit, or push. No acceptance state was changed.
