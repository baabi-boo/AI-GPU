## Source-backed checks

- **Every run/reset boundary.** In
  [processor.cpp](../../../../../sim/simx/processor.cpp),
  `ProcessorImpl::run()` calls `launch_reset()`; with no LLC CP port, that
  invokes `reset()` exactly once. The constructor separately invokes
  `reset()`. Requiring 33 run pairs, each with reset delta one, and total
  delta 33 beyond the observed construction baseline is correct for the bound
  route. It must not be generalized to the excluded LLC-client branch.
- **Missing transient observation.** Request callbacks increment
  `perf_mem_pending_reads_`, response callbacks decrement it, and reset
  clears it. Current [ModelState](../../../../../tests/regression/ai_counter_preflight/hooks.h)
  lacks pending balance; the [run wrapper](../../../../../tests/regression/ai_counter_preflight/hooks.cpp)
  retains aggregate entry/completion/error counts, without each run's states.
  A later zero cannot recover the erased pre-reset premise. The proposed const
  accessor and zero checks before reset, after run, on both flush sides,
  through terminal observations, and before destruction address that gap.
- **Clock and cleanup semantics.**
  [SimPlatform::reset](../../../../../sim/common/simobject.h) sets cycles to
  zero and increments the reset generation. Cleanup stops workers, removes
  objects/events and resets cycles; it does not increment that generation.
  Comparing clocks only within a generation is correct. The destructor wrapper
  reads live model state before the real destructor and platform state after
  it; the plan correctly forbids post-destruction processor reads.
- **Ownership and terminal order.**
  [OperationState::release](../../../../../sw/runtime/ai/runtime.cpp) releases
  events and queue before operation buffers.
  [Queue destruction](../../../../../sw/runtime/common/queue.cpp) joins the
  worker before unregistering and releasing its device reference.
  [RefCounted::release](../../../../../sw/runtime/common/vortex2_internal.h)
  destroys only at the final reference. The
  [before-release observer](../../../../../tests/regression/ai_warm_workspace/observer.cpp)
  samples before the real device release; the
  [preflight caller](../../../../../tests/regression/ai_counter_preflight/main.cpp)
  binds terminal CP/ownership state to actual destructor entry. Return success
  alone therefore remains insufficient, as the plan states.
- **33 selectors and 40 components.** Independently parsed the
  [lifetime manifest](../../p06-counter-diagnostics/lifetime-source-manifest.json):
  26 single-component plus seven two-component aggregates give 33 selectors
  and 40 unique components; twelve unavailable rows remain unqueried.
  All **45 production source bodies** still match that manifest's SHA-256 and
  size. The [theorem](../../../../designs/simx_counter_lifetime_v1.md) requires
  audited nonnegative checked updates, preserved resets, successful terminal
