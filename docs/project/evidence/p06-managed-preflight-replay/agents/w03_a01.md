# Wave 3, agent 1 — external source derivation binding

## Scope and finding

The source-inventory v1 contract binds an externally selected revision and every
source descriptor. Its schema does not include the producer's recorded Git tree
or the selected dependency Gitlinks. Before this addition, the complete replay
checked the tree's syntax but did not compare it with an independent expectation.
This is a concrete consistency gap: a valid-looking changed tree could survive
the inventory comparison.

Implemented `ci/project/p06_managed_preflight_derivation.py` and
`ci/project/test_p06_managed_preflight_derivation.py`. The existing inventory-v1
schema and original evidence files remain unchanged. The parent owns CLI/core
integration and subsequent independent review.

## Implemented checks

The loader requires an external receipt SHA-256, source revision and inventory
SHA-256. It checks the receipt digest before strict JSON parsing, uses bounded
no-follow I/O, and rejects symlinks, parent traversal, nonregular files,
duplicate JSON fields, excessive nesting and invalid external expectations.

The receipt validator checks exact schema and claim fields, source count and
names, the reviewed discovery-helper digest, every descriptor and canonical
repository/path mapping, regular Git blob modes, five repository identities,
reviewed URLs and FetchContent tags, and bounded Git exporter resource records.
It imports no exporter module and runs no Git subprocess.

The retained-data check compares the checkout tree and Ramulator/SoftFloat
Gitlinks with the independently pinned receipt. It recomputes SHA-256 and Git
blob identities for all retained source bodies. The successful original binds
999 bodies: 806 project files, 50 Ramulator headers, 7 SoftFloat headers,
99 spdlog headers and 37 yaml-cpp headers.

## Validation

Executed from the source root:

```sh
python3 -m unittest discover -s ci/project -p 'test_p06_managed_preflight_derivation.py' -v
```

Result: **25 tests passed in 1.341 seconds**. Tests load the original independently
pinned manifest and derivation receipt and verify the original ZIP's digest.
Rehashed receipt mutations reject at the intended tree, selected Gitlink,
descriptor, repository mapping or Git-blob check. Further controls cover
inventory ambiguity, reordered/missing rows, schema/claim changes, resource
bounds and unsafe external receipt paths.

A synthetic added Python source body containing a deliberate exception remains
inert while its declared hashes are verified; process execution and dynamic
module-loading entry points are guarded during that test. This synthetic check
does not claim native execution or producer authenticity.

## Limits and handoff

The receipt is an independently supplied expectation, not authenticated remote
origin. The replay does not reopen Git repositories to reconstruct commit/tree
membership. It verifies retained bytes against the pinned export result.
Dependency compilation provenance, counter lifetime qualification, warm
readiness and every acceptance claim remain false.

API: `load_source_derivation(...)` returns a validated receipt;
`validate_retained_derivation(receipt, checkout=..., source_body=...)` returns a
compact verification result. Direct dictionary callers must establish the
receipt's trust separately. No native build, native execution, commit or push
was performed by this assignment.
