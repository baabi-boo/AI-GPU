## Separate application-grammar handoff

The inherited pure `producer.validate_host_build()` checks the final host
compile/link command. Kernel stamps and effective headers are checked, but a
consistently rehashed application log retaining only its final host line can
evade validation of the kernel-library compilation, kernel link/conversion,
and runtime stub build. Root assigned the complete application grammar to a
separate implementation; this recovery restores the original bounded base.

Each original application log contains 30 nonempty lines: host dependency
command; two recursive Make invocations; fourteen RISC-V GCC compilations;
two archives and two archive dumps; five Clang++ compilation/link commands;
VXBIN conversion; kernel dump; runtime stub compile/link; final host compile/link.
One startup recompilation includes a logged GP-size command substitution: parse
it as inert grammar, never evaluate it. The integration point is
`compiler_commands()` after obtaining `application_text` and validating compiler
records, with the original binding shape preserved.

Generated-header reproduction commands are validated as recorded observations;
this base mixin does not rerun a compiler or generator. Matching hashes and
command records do not authenticate the producer or independently prove
dependency compilation. Qualification, warm readiness, performance sampling and
all phase acceptance remain false. The three unresolved obligations remain.
No native builds, full suite, commits, or remote writes were performed.
