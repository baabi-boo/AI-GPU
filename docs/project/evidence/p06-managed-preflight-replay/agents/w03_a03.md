# Wave 3, assignment 3 — dedicated replay CI

Implemented `.github/workflows/p06-managed-preflight-replay.yml` and
`ci/project/test_p06_managed_preflight_replay_ci.py`. The dedicated job runs on
GitHub-hosted Ubuntu 24.04 with system CPython 3.12, read-only permissions,
checkout without credentials/submodules/LFS, and a 20-minute execution budget.
Its identity records the actual interpreter patch version. Historical producer
interpreter requirements remain the replay reader's separate obligation.

The job binds both original archives and their independently generated source
inventories and derivation receipts to six fixed digests. It retains the reader
revision, historical producer revisions, workflow bytes, input identities,
interpreter identity, replay output, and test/failure logs. Successful replay
must pass. The failed-original control requires exit code 1 and exactly
`report.outcome: value differs`, with exact fields and types; unrelated failures,
argument errors, duplicate JSON keys, integer substitutes for booleans, and
forged acceptance claims cannot satisfy it. All five focused test groups are
mandatory, including rejection of a missing/empty group. Shell pipelines retain
both output streams and propagate failures; artifact upload uses `always()`
and a commit/run/attempt-specific name.

The existing native preflight workflow is unchanged. No native execution,
dependency installation, toolchain download, archive extraction, original
payload execution, performance acceptance, or phase acceptance is introduced.
