## Workflow trust and failure handling

The intended exposure is ordinary `pull_request` execution, pushes to master,
and a dispatch without inputs on a GitHub-hosted `ubuntu-24.04` runner. The
workflow grants only `contents: read`, does not persist checkout credentials,
and disables submodules and LFS. No self-hosted runner, `pull_request_target`,
`workflow_run`, secret interpolation, write permission, OIDC permission, cache,
installer, dependency download, or retained native executable invocation is
present. Its only actions are checkout and artifact upload. The 20-minute
replay job deadline and fixed system CPython 3.12 requirement are explicit.

The initializer streams six independently pinned files, retains their actual
hashes, sizes and read errors, copies the actual workflow, and records the
current CI identity separately from both historical producer revisions.
Identity is retained before a pin or interpreter mismatch raises a failure.
The six fixed digests cover both original ZIPs and both independently exported
source inventories and derivations. The successful invocation carries all
seven required external arguments; it does not substitute the current
`GITHUB_SHA` for the historical source revision.

The failed-original control requires exit code 1, empty stderr, a unique-key
JSON object with exactly the 13 expected fields and their exact types and
values, including `report.outcome: value differs`. Missing scripts, usage
errors, unrelated validation failures, duplicate or additional keys, a success
exit, and integer substitutions for false booleans cannot satisfy the
control. Its actual subprocess has a 120-second timeout. Original stdout and
stderr are retained before the response is validated.

All four shell blocks use `set -euo pipefail`; each of the three logged
pipelines merges both streams and preserves nonzero exit status through
`tee`. The test step discovers all five named groups, rejects any empty group,
and returns the aggregate unittest result. The replay glob also covers new
`test_p06_managed_preflight_replay*.py` regression files. Required checks have
no skip condition or failure suppression. Artifact upload is the final step,
uses `always()`, has a revision/run/attempt identity, includes hidden evidence,
retains it for 30 days, and errors on missing files. A failure before evidence
creation can still leave no artifact; `always()` is an upload attempt, not a
promise that an unavailable runner or directory will produce one.

All seven qualification/acceptance booleans, retained-code execution, and
dependency compilation provenance remain false; native execution remains
`not_run`. The workflow does not advance P06 acceptance.
