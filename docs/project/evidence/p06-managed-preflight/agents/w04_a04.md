## Independent source basis and coverage

Read AGENTS, the task contract, and the original independent finding in
`w04_a01.md`. Traced the relevant existing source:

- `Device::cp_ring_append_` marks cache state dirty on launch and emits a full
  cache flush before the following output DMA; it then clears dirty state.
- `CommandProcessor::flush_cores_` issues a flush DCR write and one flush DCR
  read per core.
- `ProcessorImpl::dcr_read` handles that address by flushing caches and
  returning zero. The reviewed frozen workload has one core and 33 launches.

Tests independently assert the expected 264 MPM half replies, 33 flush replies,
and 297 total DCR reads per process. All four format/policy cells pass through
the public output verifier, yielding 132 flushes and 1,188 total DCR reads while
all qualification/acceptance fields remain false.

The expected global MPM groups are 1–66, 68–133, 166–231 and 232–297. Flush
positions are 67 and 134–165, bound to completed-run counts 1–33. Snapshot flush
counts remain 0, 1, 33 and 33. These expectations are stated independently in
the test rather than derived from parser helper output.

Every flush index is tested for address, tag, reply value, global sequence,
completed-run binding, generation, completion/error/overflow status, idle and
running endpoints, reset/class preservation and clock rewind. Direct tests of
the flush sub-contract keep this exhaustive field coverage bounded; separate
public-verifier integration controls show that those checks are applied to the
complete retained output.

Additional rejection cases cover each omitted flush, duplicate/reordered or
surplus records, an unknown DCR route accompanied by forged aggregate totals,
cross-substitution of MPM and flush replies, the old 264-total-read assumption,
incorrect observation/snapshot counts, per-trace rather than global numbering,
prime/final reset boundary mismatch, lifetime/order violations, missing/extra
fields, invalid containers, integer bounds and Boolean/integer confusion.

Positive controls permit either unchanged or advancing ticks during flushes.
Counter sampling still requires unchanged ticks, tested through the public
verifier. No requirement for full counter lifetime bounds or dependency
compilation provenance was introduced or claimed.
