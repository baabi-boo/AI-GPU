## New function boundaries

1. `process_plan()` returns the exact four ordered outer IDs and their format/policy pairs. No backend/format/case/repetition selectors are necessary for formal execution.
2. `source_snapshot(source)` extends the established full native source inventory with the new producer/record/build closure and hook. Its clean revision/tree and relevant source bodies are retained once.
3. `tool_inventory(paths, env)` augments the existing host/kernel inventory with the executing interpreter and any symbol/ELF-inspection tools actually used. All invoked tools have retained versions and file identities.
4. `artifacts(build, fmt)` lists the exact final app, kernel, runtime stub, backend, model, read-only witness library/object if separate, compiler stamps and generated configuration. Do not reuse `warm.artifacts()` unchanged if the app lives under a new directory: it hardcodes `ai_warm_workspace`.
5. `build_variant(fmt)` configures a separate fresh build, builds checked production artifacts and the read-only observer, validates original commands/stamps/effective headers, inventories the final linked production sources/objects, and creates a frozen artifact set.
6. `make_build_binding(variant)` binds contract, source, fixtures, exact tools, guard/configuration, original compile/link records, artifacts and dependency identities before either policy launches. It is an execution identity, not a qualification decision.
7. `run_process(planned, variant)` creates a process binding, checks all source/tool/dependency/artifact bytes, launches the existing complete numerical caller plus witness, verifies the raw log and process receipt, validates output and witness together, repeats stability checks, and only then marks that process passed.
8. `finalize()` rehashes retained originals and all inputs, preserves failed commands/builds, records final resources, derives exact completion counts, and emits a nonaccepting result. Any final hash/log/resource failure changes an otherwise successful run to failure.

## Per-format build sequence

Use separate `work/simx-fp16` and `work/simx-bf16` directories. In each:

- Configure exact RV64 `p02-tfr`, existing pinned tools and explicit supported OS version. Reproduce C++ and Verilog generated headers from the frozen TOML/profile and compare bytes.
- Build using `CONFIGS="-DITYPE=<format> -DOTYPE=fp32 -DKUNROLL=1 -DSIMX_CHECKED_COUNTERS=1"`, `PERF=1`, `THREADS=1`, `-j1` or `-j2`, and the independently identified compiler. Guard selection must agree in every participating ABI-compatible model/backend/witness build. Reject unknown `SIMX_*`, diagnostic access replacements and injected limit macros.
- Use the ordinary production model source list and `runtime-simx` path, not `checked_counters.mk` or `checked-public` objects. Those diagnostic paths deliberately replace production translation units and carry seed accessors.
- A new application directory may include the unchanged warm `main.cpp` under a renamed entry point and compile the original warm observer, managed runtime and frozen kernel. The extra measurement object must be read-only and have its own exact source/link contract. It cannot reuse `public_hooks.cpp`, which exports `seed_component` and `clear_components`.
- Record the *actual* final compile/link commands, output identities and model source mapping. A compiler stamp proves configuration, not the absence of extra objects. A seed-symbol scan alone is insufficient because symbols can be local or stripped; use the complete known build-input inventory.
- Build everything before freezing. If a dedicated backend link adds Processor wrappers, retain that final link separately and bind it to the ordinary checked model; do not rebuild after the first policy or between policies.
- Validate four independent runtime/model/kernel/host stamps and the added hook’s own stamp/link arguments. An explicit guard projection may reuse old option validators only after independently checking the exact original guard token count/value and preserving the original stamp hash. Never delete arbitrary `SIMX_*` tokens to make old validation pass.

## Preserve the old inner record identity

`p06_warm_records.verify_output` requires `sample_id = warm-simx-<fmt>-pair0-<policy>`, `pair_index=0`, `phase="warmup"`, and the historical inner contract ID. The caller itself expects the same identity.

Give the new envelope an outer ID such as `managed-preflight-simx-fp16-per_operation`; its prelaunch binding contains the outer contract and process ID plus that unchanged inner identity. Pass the new process-binding digest through the caller’s existing `--qualification-id` argument, explicitly describing it as an execution binding in the outer contract. The same digest must appear in the witness. Do not label the old four warm-up process records as a shortened complete warm-v1 experiment.

An exact inner plan can be derived from the old frozen `process_plan(contract)` entries with `pair_index == 0`, then checked against the new four-entry plan. The old 24-process producer remains untouched.

A wrapper can emit a single bounded witness trailer after the warm caller returns. The new parser must require one exact framed warm section followed by one exact witness section, reject extra/duplicate/trailing records, and pass only the warm section to the old parser. If native code throws, teardown fails, or the witness is absent, the entire process fails even if an earlier warm `PASSED!` line exists.

## Launch and per-format identity

Invoke the final app directly with exact module, policy, execution-binding ID and inner sample arguments. The old `make run-simx` recipe rebuilds the backend and appends inherited `LD_LIBRARY_PATH`; it must not be used after artifact freezing.

Use only the clean environment plus `VORTEX_DRIVER=simx` and exact `LD_LIBRARY_PATH=<build>/sw/runtime` (or the separately frozen isolated runtime directory). Runtime `dlopen` selects `libvortex-simx.so`; library hashes are not proof of what it loaded. Collect actual loaded-object paths/bytes from the native observer where available, after backend initialization, and compare them to expected final artifacts. System dynamic libraries remain a separately declared inventory scope.

Both policies within a format reuse one source/build/artifact binding, and the same complete artifact set is rehashed before and after each process. No rebuilding, per-policy binary options, implicit retry, sample substitution, or interleaved format ordering is admitted.

## Failure, resources and evidence scope

Retain the exact predeclared budget: two build jobs maximum, one simulator worker, 4 GiB polled RSS, 15 GiB reserve, 16 MiB per log, 1,800-second builds, 180-second processes and a 90-minute hosted job. Resource checks cover source, tools, work and output volumes before and after commands. No downloads or cache writes belong in this producer.

Create output exclusively and checkpoint before launching each command. A missing prerequisite is `blocked` only when no relevant process started; actual failed commands, incomplete cleanup and invalid completed logs are `fail`. Preserve the failed attempted process and raw command receipt, skip remaining work, and require a new fresh attempt directory for any later retry. Never count a partially parsed process toward success.

The read-only witness is required for this preflight’s declared counter/lifetime observation scope; treating it as optional while still declaring preflight completion would hide the missing obligation. If only numerical execution is present, expose that narrower result and keep managed counter preflight incomplete.

Cached Ramulator library hashes, the existing `p04_ci_prepare` receipt, or a source manifest do not establish source-to-object-to-linked-to-loaded provenance. Record this explicitly as a remaining qualification blocker. It is valid to deliver a rigorously checked executable preflight while keeping qualification/readiness false; it is invalid to turn that blocker into a claimed qualification by copying a diagnostic success boolean.
