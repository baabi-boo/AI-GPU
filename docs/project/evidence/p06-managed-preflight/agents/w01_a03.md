## Decision

Add a **separately versioned managed counter preflight**. Do not modify warm-v1's frozen numerical/sampling contract, old report shape, replay semantics or unconditional qualification rejection. Preflight is four ordered processes: FP16 per-operation/reusable, then BF16 per-operation/reusable; each uses the complete real managed caller, one prime plus 32 operations. Totals are 132 launches and 4,224 exact output words. No timing acceptance follows from this prerequisite.

## Concrete existing boundaries

1. `p06_warm_compiler_records._configuration` requires exact frozen macro equality for four roles. A correct checked build adding `SIMX_CHECKED_COUNTERS=1` will be rejected. `validate_effective_header` likewise requires exact old effective macro maps. Add a dedicated preflight compiler validator; do not weaken the historical one or allow arbitrary extra defines.
2. `p06_warm_execute.execute` creates a 24-process experiment and concludes only with `COMPLETE_COUNTS={24,792,25344}`. Its `build_binding`/per-process bindings are identity digests, not counter qualification. `p06_warm_replay` reconstructs exactly this old contract, command plan, expected artifacts and report. New four-process report must not masquerade as a shortened warm-v1 run.
3. `p06_warm_records.verify_output` is valuable unchanged: exact independent fixture, all 33 operations/1,056 words per process, poison policy, explicit operation/owner results, resident-buffer reuse, four chronological snapshots, allocation/free identities, device release, timing containment. It proves only monotonic **sampled values**, not the complete lifetime theorem. Reuse this parser for the unchanged warm record section, then validate a separately prefixed witness record and cross-bind the two.
4. `p06_counter_public_records` cannot be directly reused as a complete new witness validator. It hardcodes the scalar success program (`exitcode=7`), two model lifetimes, reset generation `2*generation`, fixed command/check counts, and optionally seeds. Its `SELECTORS` inventory and bounded strict JSON/type checks are useful references. A new validator must derive actual managed caller resets/33 launches, compare real reads to aggregate backing sources, and require seed-free behavior.
5. `p02_matrix.tool_inventory` records PATH Python, not `sys.executable`; warm runner inherits it. `p06_mpm_execute.tools_snapshot` and `p06_counter_diagnostics_replay` already model `executing_python` separately and compare exact bytes/resolved identity. Use that pattern with the kernel/tool inventory needed by warm builds.
6. Warm `dependencies` is `hash_artifacts(source, base.DEPENDENCIES)`: identities of reused `.a/.so` files, without the source-to-object-to-link provenance or proof that these files were the actually loaded Ramulator graph. A library digest or source manifest alone cannot close this obligation.
7. `p06_counter_source_inventory` admits only the two historical diagnostic producer contract IDs and preserves their pinned required source sets. Do not weaken those allowlists to let a new producer through. A new preflight inventory can reuse low-level strict descriptor/path/hash logic under a new contract and independently supplied digest.
8. Existing public reader's `DiagnosticPacket` expects diagnostic report/tool/build semantics. Its bounded inert archive opening and trusted JSON facilities can be reused, but inheritance must not carry scalar/seeded assumptions into a managed packet.

## Recommended file ownership split

- `p06_managed_preflight_contract.py` + versioned JSON: exact process order, format/policy pairs, inventories, counts, allowed configuration and nonacceptance semantics.
- `p06_managed_preflight_records.py`: pure record validator for new witness plus cross-validation with unchanged `p06_warm_records.verify_output`.
- `p06_managed_preflight_build.py`: exact checked/no-seed compiler, link and loaded-dependency binding validation. Keep all roles independent and track actual compile commands rather than expanded synthetic stamps.
- `p06_managed_preflight_execute.py`: fresh bounded build/run with four-process plan, before/after source/tool/artifact inventories, prelaunch binding IDs and retained failure records.
- `p06_managed_preflight_replay.py`: inert packet replay with caller-pinned archive SHA, source revision and source/proof inventory hashes. Derive results again from raw records, never trust producer booleans.

Names are suggestions; separation of historical and new contracts is the substantive requirement. A safe minimal milestone may deliver build/record preflight first and keep qualification/readiness false until dependency/lifetime bindings are independently reviewed and actually executed.

## Proposed binding/record schema

### Immutable pre-execution attempt binding

Use `schema_version:1`, `contract_id:p06-managed-counter-preflight-v1`, and `execution_binding_sha256` (do not name an ordinary digest `qualified`). Exact fields:

- Frozen warm contract, fixture corpus, kernel and profile SHA-256 values; expected source revision/tree and complete source inventory digest, plus separate submodule/dependency graph identities.
- Exact backend `simx`, XLEN 64, profile `p02-tfr`, checked counter width 64, timing mode, PERF=1, one simulation worker, VM off and CP direct RAM. WGMMA/L2/L3 remain disabled as reviewed. Exact generated/effective macro inventories for every compiler role.
- Source-proved lifetime/inventory contract digests, reviewed proof source closure and independently pinned diagnostic original locators (all-33 model, public failure/completion/transport), with their narrower scopes retained.
- Per-format host/runtime/backend/kernel artifact identities and original compiler/link/object records. Both policies use one identical artifact set. Explicit absence of diagnostic access/seed objects and nonproduction substitutions is checked from complete compile/link inventory, not a reported `seed_free:true` alone.
- Actual executing interpreter and PATH Python identities and versions; compilers/linkers/support tools; cleaned launch environment. Loaded-library inventory must bind the actual runtime-selected files to audited build receipts and source graph.
- Exact four-process plan, fixed resource budget and fresh output namespace. Bind before launch; no final archive hash in this structure (avoid circular identity).

### One process witness, separate from unchanged warm records

Fixed fields should include binding ID, process ID, format/policy, backend/configuration identity, `seeded:false`, successful/failed guard count, constructor/final destructor count, zero-origin observations, 33 successful complete run entries and no failed entries, and four named snapshots (opened/after-prime/after-batch/before-release).

For each snapshot bind 33 known selectors in fixed order and 12 unavailable rows with no queries. Retain 66 actual half-read observations: class/selector/tag, sequence, return status, low/high 32-bit values, stable model tick/reset/generation before and after the pair, and reconstructed uint64 value. Cross-check these values against the existing warm summary; reject extras/duplicates/missing rows.

For terminal proof retain the actual 40 component values and checked sums, expected exact CP retirement plus enabled-idle status, joined queues, no live operations/buffers, final device reference, no surviving submitter, and equal model/component state from terminal readout through actual destruction. A successful release result cannot stand in for actual destruction. Match modeled aggregate semantics and retain any unavailable evidence explicitly.

One process contributes exactly 33 launches, 1,056 words, four snapshots, 132 enabled queries/264 half replies and 48 unavailable rows. Four processes contribute 16 snapshots, 528 queries/1,056 half replies, and 192 unavailable rows.

### Result semantics

`preflight_complete` is derived only from all four valid original processes. Preserve `qualified:false`, `ready_for_warm:false`, `warm_execution:false`, `performance_acceptance:false`, `phase_acceptance:false` in a source/diagnostic prerequisite result unless a separately enforced, complete qualification decision is in scope. Replay emits `native_execution:not_run`, `retained_code_executed:false` and consistency-only scope. No free-form producer assertion may upgrade old archives, qualify binaries absent from a source-to-loaded-artifact chain, or close P06.

## Required negative tests

1. Missing/extra/duplicate JSON keys; bool accepted as int; NaN/infinity; overlarge/deep records; unknown schema/contract; repeated result marker/trailing success/failed preceding process.
2. Three/five processes; duplicate format/policy; reordered plan; fewer operations, missing prime, changed fixture/poison, incorrect output word; foreign old sample attached to a new binding.
3. Guard absent/zero/other width; seeds/diagnostic wrappers/access objects; multiple workers or unsupported topology/features; stamps that conflict with effective preprocessed headers; different policy binaries.
4. Same hash-shaped string with wrong size/body; mutated executable/library after binding; incomplete compile inventory or missing linker receipt; claimed dependency source not bound to loaded binary; foreign system-path substitution.
5. PATH Python differs from executing Python; executable path same but bytes/resolved inode content differ; incomplete trusted helper closure; source changes after import/before/after execution.
6. Any missing/duplicate/wrong-class selector; available row reported null; unavailable queried; failed high read; low/high from different tick/reset/generation; wrong 64-bit reconstruction; forged backing sum or >UINT64_MAX aggregate.
7. Nonzero origins; pending work, live queue/operation/extra reference; CP disabled before drain witness; wrong retirement or tail accounting; no real destructor; counter mutation/reset during final cleanup.
8. Guard fault, close/release failure, timeout, bounded runner cleanup failure, missing log, budget exceed, truncated process; no partial-success admission or replacement samples.
9. Tampered and rehashed witness/proof/source manifest remains inconsistent with independent expectations; malformed explicit inventory never falls back.
10. Archive traversal, absolute paths, symlinks, duplicate entries, decompression/size bounds; archived Python is never imported/executed; recorded producer paths are never opened, even when they coincide with current reader paths.
11. Favorable or unfavorable timing values cannot bypass any qualification failure. Historical warm-v1 remains rejected with its original finding and unestablished bound.
