## Interface and behavior

The simulator-independent POD header exports three `extern "C"` read functions:
`p06_preflight_get_observation`, `p06_preflight_get_model_state`, and
`p06_preflight_get_read(index)`. All return zero on success and negative on an
invalid output/index or failed observation. No reset, seed or mutator API exists.

The backend wraps the actual Processor constructor, destructor, `run_checked`,
`dcr_read` and `dcr_write`. It records one actual Processor lifetime, constructor
state, completed/error counters, 512 bounded raw DCR read slots, and destructor
state before/after. Each raw read retains exact route/tag, value/status, selected
class, generation, tick/reset boundaries, idle and running observations. Both
typed counter errors and unexpected exceptions invalidate observable success.
The raw-read capacity exceeds the prescribed 264 replies per process but never
resizes. The complete preflight reader must require the exact prescribed count.

Only existing public Processor/Core/SimPlatform getters are used. There is no
private access wrapper, replacement model translation unit, diagnostic object,
counter storage assignment, injected seed or tiny counter limit. The hook
translation unit requires checked counters, RV64, timing mode and one worker
at compile time. Guard checks for the actual model and all original objects
remain the separate build validator's obligation.

The header's ModelState deliberately has no pending-read balance or all-40
component fields. These hooks do not establish those missing observations or
full qualification. Read-only endpoint observations are not a lifetime proof.

## Exact build entry

After configuring a fresh build, invoke the copied makefile from the generated
`sw/runtime/simx` directory:

```sh
make --no-print-directory -j2 THREADS=1 \
  DESTDIR="$P06_BUILD/sw/runtime" \
  -f "$P06_BUILD/tests/regression/ai_counter_preflight/backend.mk" all
```

Use the same reviewed `CONFIGS` as the model and application, including
`-DSIMX_CHECKED_COUNTERS=1`, with `PERF=1`. The new makefile includes the
production backend `Makefile`. It appends only `hooks.cpp` after the existing
three backend sources and the five Processor wrap flags after the inherited
link flags. It adds no CXXFLAGS, include path or PERF macro.

The original runtime compiler stamp stays `sw/runtime/simx_rt_config.stamp`.
The additional `sw/runtime/preflight_backend_link.stamp` preserves the original
linker spelling, including the literal single-quoted `$ORIGIN`. A phony relink
prerequisite prevents an intervening ordinary backend build from being mistaken
for an already-built preflight backend. Direct executable invocation after
artifact freezing remains required.
