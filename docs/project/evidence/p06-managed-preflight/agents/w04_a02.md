# Wave 4 / assignment 2 — cache-flush observation correction

## Finding and implemented correction

Independent reviewer `w04_a01_hooks_review` identified a concrete F2 integration
failure: the original observer classified every Processor DCR read as an MPM
half reply. The unchanged managed workload lazily flushes its dirty cache once
per operation, yielding 33 additional DCR replies. The first post-prime snapshot
would therefore fail before native measurement could complete.

Changed only the new application files `hooks.h`, `hooks.cpp`, and `main.cpp`
under `tests/regression/ai_counter_preflight/`. No production model/runtime,
original warm caller, kernel, fixture, build file, or historical contract changed.

The backend now retains separate bounded MPM and cache-flush traces. MPM
`read_count` remains 264; new `cache_flush_count` is 33; DCR entry/completion totals
are 297. Each `DcrRead` retains the global DCR sequence and new `completed_runs`
observation. The new read-only accessor is
`p06_preflight_get_cache_flush_read(index, DcrRead*)`. Unknown DCR addresses
increase the violation count and throw; none are silently ignored.

The managed app checks flush counts 0, 1, 33, 33 at the four snapshots and keeps
them unchanged across all queries. MPM global sequence groups are 1–66, 68–133,
166–231 and 232–297, with completed-run counts 0, 1, 33 and 33. The 33 flushes
occupy global positions 67 and 134–165 and correspond exactly to completed runs
1–33. Every flush must use address 0, tag 0, result 0 and success status, preserve
class/reset generation, remain idle and not running on both sides, and have
nondecreasing ticks. Cache flushing may advance simulation time; MPM snapshot
coherence retains its stricter no-advance requirement.

The JSON witness adds `cache_flush_reads`, `observation.cache_flush_count`,
`snapshots[].cache_flush_count`, and `completed_runs` to both raw reply kinds.
All qualification/readiness/acceptance flags and unresolved obligations remain
unchanged. Root owns the coordinated Python contract/parser/fixture updates.
