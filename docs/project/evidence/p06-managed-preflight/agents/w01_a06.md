## Decision and admission boundary

The bounded seed-free managed preflight is useful and feasible. Its pass can mean that four original managed processes produced 132 successful launches, 4,224 exact words, 16 complete snapshots, 528 enabled queries and 1,056 coherent half replies under the checked configuration and observed lifecycle conditions.

It cannot yet mean that the complete lifetime theorem or dependency compilation origin is qualified. The proposed public getters do not expose pending-read balance or all 40 backing components. Existing reused-library hashes do not establish Ramulator source-to-object-to-link-to-loaded-library provenance. Preserve `qualified=false`, `ready_for_warm=false`, `full_warm_coverage=false`, `warm_execution=false`, `phase_acceptance=false` and `performance_acceptance=false`. Use an explicit `native_managed_preflight_passed` result for the producer; an offline replay establishes retained-data consistency with `native_execution=not_run` and `retained_code_executed=false`.

## Concrete hazards and required controls

### 1. Self-certified success and consistently rehashed forgery

**F3 if admitted; high confidence; reasoned-risk.** A report can claim `seed_free`, `guard_enabled` or `lifetime_proven` and recompute every internal digest without establishing any of those facts. An execution binding is an identity, not qualification. Recompute numerical, counter, command and build summaries from retained originals; compare against an independently selected versioned contract and source expectation. Exact false acceptance fields must be enforced, not copied through. External archive/source digests identify selected evidence; they do not authenticate its producer.

Required rejection tests: true/string/integer replacements of false fields; copied old diagnostic success; changed contract/source plus consistent rehashing; favorable and unfavorable timings accompanying invalid witnesses. None may produce readiness.

### 2. Seed exclusion and loaded-library substitution

**F3 if called seed-free without proof; high confidence; static-proof of existing diagnostic content.** `public_hooks.cpp` exports seeding/clearing and its model uses private-access replacement translation units. Never reuse those objects. Validate a complete production compile/link inventory and exact macro roles; reject diagnostic access objects, extra injected objects, alternative guard widths and missing guards in the actual model. A host-only checked define proves nothing about model storage.

Clean launch environment must exclude inherited `LD_PRELOAD`, `LD_AUDIT`, `PYTHONPATH`, arbitrary compiler flags and make overrides. Bind actually loaded model/backend/dependency files to their selected identities; hashing expected paths does not prove the loader selected them. Keep source-to-binary dependency provenance explicitly unresolved if only loaded bytes are identified.

Tests: seed/access object insertion, guard only on host, unknown `-D` or `-U`, stale object reuse, same soname at another path, changed library after binding, inherited loader injection, missing or conflicting build records.

### 3. New witness splitting must not sanitize a failed original

**F3 if malformed records are discarded; high confidence; reasoned-risk.** The unchanged warm parser intentionally requires one final success marker and rejects wrong-route `P0[3456]` records. A bridge that removes arbitrary extra lines before invoking it can accidentally erase malformed, duplicate or failed witness output. Define one exact new record location/marker, parse that record strictly, preserve every other original byte, and require complete agreement with the old warm identity/binding.

Tests: duplicate/truncated/misplaced witness, unknown marker, second success marker, error text before/after success, extra trailing data, malformed UTF-8, duplicate JSON keys, booleans in integer fields, out-of-range integers, NaN/infinity, nesting/size limits. A substring search for success is insufficient.

### 4. Counts do not identify snapshots or coherent halves

**F3 if counts stand in for routing; high confidence; static-proof of route-dependent semantics.** Grouping each 33 queries alone cannot prove that they are the required selectors. Require exact ordered `(class, CSR, core_id)` tuples, known availability, consecutive low/high sequence, statuses, 32-bit widths and reconstruction against the unchanged warm summary. Both halves and the full snapshot must bind the same live Processor generation and stable tick/reset state. No unavailable selector may be queried.

Tests: duplicate selector replacing another, wrong class/tag/core, missing high half, successful low plus failed high, swapped halves, nonconsecutive reply, reset/tick/generation change, available null, queried unavailable row, extra read or snapshot. Zero opening aggregate values may be reported as observed aggregate origins, not as direct observations of all 40 individual components.

### 5. Cleanup success is not lifetime closure

**F3 if promoted to a no-wrap theorem; high confidence; static-proof.** Release returns can only drop references. Counter monotonicity at four samples does not prove uninterrupted monotonic storage or safe pending-balance reset. Require actual constructed/destroyed Processor balance, 33 successful checked entries, no errors, no surviving live object, final Device ownership and complete queue/buffer closure. Describe which premises are observed and which remain source-conditional.

`terminal_cp()` correctly uses enabled CP controls, exact retirement and tail accounting. Raw host head storage is unsupported, and the tail pair has staged/committed semantics. Do not simplify it into head-equals-tail or not-busy-after-disable. Platform destruction resets its clock to zero; require the documented cleanup state, not impossible monotonic equality across disposal.

Tests: extra retained reference, surviving queue/buffer, missed destructor, disabled CP, wrong retirement/tail, failed run hidden by later success, second Processor generation, partial cleanup. Pending balance/all-component values absent from public getters must remain unavailable rather than fabricated zero observations.

### 6. Worker, configuration and interpreter drift

**F2; high confidence; static-proof.** The old warm runner uses `THREADS=str(args.jobs)`; copying it with two build jobs violates the selected one-worker proof. The new route must independently enforce `make -j2` and `THREADS=1`. Pin the effective generated headers and original compiler records for each role, not just the profile name. Bind PATH Python and the actual executing interpreter with matching resolved bytes/version.

Tests: two workers, unsupported VM/LLC/topology, differing FP16/BF16 guards, host/backend/header disagreement, altered executable between policies, alternate interpreter or helper imported from outside the trusted checkout.

### 7. Failure retention and replay trust

**F2/F3 depending on resulting claim; high confidence; reasoned-risk.** Allocate a fresh attempt namespace, write intent and command receipts before launch, retain failing logs and final cleanup status, and derive totals only from fully validated processes. A later successful process cannot replace a failed prime or clear a prior failure. Distinguish tools/build commands starting from actual managed native execution starting.

Replay must use only current trusted parser/helper code. Never import retained Python, execute artifact commands, extract untrusted archive paths or reopen recorded producer absolute paths. Require exact bounded archive inventories and caller-pinned source manifest selection; malformed explicit input must not fall back to a live glob or old inventory. Existing readers already implement this separation and should be reused at their low-level boundaries without importing scalar/seeded assumptions.

Tests: early resource block, launch exception, timeout/kill, log truncation/hash change, cleanup failure, rerun into an existing directory, missing process, duplicated format/policy, replaced failed sample, archive traversal/symlink/duplicate members, forged retained helper, and producer-root pathname equal to the trusted reader root.
