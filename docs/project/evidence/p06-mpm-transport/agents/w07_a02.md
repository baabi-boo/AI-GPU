## Register attribution

The wrapper registers independent 44-bit cycles and instret inputs, plus four
44-bit CORE counters under `PERF_ENABLE`. Old RV64 makes only bits 31:0
observable through the 32-bit host response; high aliases return zero.
Restoring high aliases exposes bits 43:32, predicting **2 × 12 = 24 additional
observable wrapper FF bits with PERF off**, and **6 × 12 = 72 with PERF on**.
These are structural predictions, not measured counts. RV32 already exposes
both halves and is the unchanged semantic control.

The production patch adds no sequential block or pipeline stage. Its `reg`
declarations describe combinational decoder variables. `VX_dcr_data.sv`, which
owns the response registers, is byte-identical to the reference. Retaining
formerly dead wrapper bits therefore must not be described as newly declared
production registers. This does not prove zero full-GPU area impact: existing
producer bits can become retained too. Highword decoding/multiplexing may change
LUTs and depth; the 24/72 explanation cannot justify arbitrary logic growth.
