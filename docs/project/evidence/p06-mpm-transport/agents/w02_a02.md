## Exact scope and rationale

Changed only `hw/rtl/core/VX_csr_mpm.sv` plus this receipt:

- Removed the XLEN-dependent branch from its host-only `CSR_READ_64` macro. Every existing invocation now emits the existing low-address and `+0x80` high-address cases for both RV32 and RV64, including all enabled performance classes.
- Sized `dcr_data` and `dcr_data_w` to `VX_DCR_DATA_WIDTH`, matching the fixed 32-bit DCR response instead of architectural XLEN.
- Retained the low `[31:0]` slice and explicit `32'(...)` cast of the high part-select. A part-select is unsigned, so a 44-bit source contributes twelve high bits with twenty leading zeros. For `0xABC_89ABCDEF`, the derived low/high words are `0x89ABCDEF` / `0x00000ABC`; this is a source-level argument, not a simulated result.

The combinational decode structure, constant-ready assignment, valid handling, response assignment, counter widths, addresses, tags, and all class/extension selection remain unchanged. No edits to `VX_csr_data`, device CSR semantics, interfaces, configuration, runtime, or SimX. No registers or handshake stages were added.
