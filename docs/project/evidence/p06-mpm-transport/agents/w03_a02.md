native wrapper and production files are untouched by this assignment.

FPU headers and the TLB package to support its broad source-directory scan;
these are not instantiated datapaths.

for all four combinations, using generated RV32/RV64 headers and command
prefix `slang --top=VX_mpm_transport_synth_top -DSYNTHESIS -DVIVADO -DNDEBUG`
plus matching XLEN defines and PERF_ENABLE only for on. Two preliminary probes
failed from an omitted driver argv[0] and an unsupported CIRCT-only option;
the corrected invocation passed without suppressing unknown modules.

The actual `synth_gate.load_catalog`/`select` functions selected exactly the
four combinations and excluded them by default. Parsed previous tests,
defaults and preexisting builds compare equal. Scoped `git diff --check`
passed. No simulation, Beacon, Yosys or vendor builds ran here.

Expected RV64 restoration keeps twelve additional input-register bits per
counter observable: 24 bits with PERF off, 72 with the four CORE fields on,
plus high-half selection logic. These are structural expectations, not measured
FF/LUT/depth deltas. Root owns matched parent/head Beacon then Yosys runs;
the baseline must receive this identical wrapper/catalog without the repair.
Depth scope is register-to-register request decode, class/selector decode and
counter selection into the production response register; no placement, routing
or physical timing claim is supported.
