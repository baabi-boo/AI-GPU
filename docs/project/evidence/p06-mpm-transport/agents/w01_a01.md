## Findings

**F3 / high / static-proof: RV64 high-half loss.** `vx_device_mpm_query` (`sw/runtime/common/perf.cpp:265–304`) sends low and high 32-bit DCR queries, then joins them. `Device::cp_submit_dcr_read` (`device.cpp:1007–1025`) submits through the CP and reads its response slot. `sim/common/cmd_processor.cpp:504–513` calls the SimX hook (`sw/runtime/simx/vortex.cpp:208–214`), which waits for background execution. Processor (`sim/simx/processor.cpp:495–532`), cluster (`cluster.cpp:609–617`) and socket (`socket.cpp:489–500`) route the tag to `Core::dcr_read` (`core.cpp:1252–1273`).

Core maps a high selector to `BASE_H+idx`. However, `sim/simx/csr_unit.cpp:39–46` emits only low-address cases under RV64; high reads fall through to zero. Core counters are `uint64_t` (`core.h:42–73`). A stable `0x00000001_00000005` therefore returns `5`—a symbolic source proof, not an execution result.

**Recommendation:** in the Core DCR adapter, RV64 reads `BASE+idx`, retains the 64-bit result, selects its requested 32-bit half, then narrows. RV32 retains its existing low/high CSR mapping. Preserve class restoration. Do not expose new architectural RV64 high CSR aliases.

**F3 / high / static-proof: matching RTL defect.** `hw/rtl/core/VX_dcr_data.sv:38–44` selects high addresses, while host-only `VX_csr_mpm.sv:16–23,47` defines only low cases in RV64 and truncates the response. Repair this host decoder's fixed-width halves separately. Preserve architectural `VX_csr_data.sv:157–162,221–229` semantics. Root notified; no native RTL result claimed.

**Separate hazards:** low-then-high assembly has no snapshot/retry and can tear during rollover. Ordinary serial SimX reads wait for execution completion, so that moving-counter scenario is not established there. Concurrent raw runtime DCR callers also risk response misassociation: `device.cpp:719–766` releases the ring lock before completion, and `cp_submit_dcr_read` subsequently reads shared `CP_Q_LAST_DCR_RSP` outside it. Neither issue is solved by the width repair.
