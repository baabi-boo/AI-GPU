## Exact change and rationale

Inside `Core::Impl::dcr_read`, the `VX_DCR_BASE_MPM_VALUE` case now separates
RV64 from RV32 using the existing `VX_CFG_XLEN_64` configuration macro:

- RV64 obtains `get_csr(VX_CSR_MPM_BASE + idx, 0, 0)` for either host tag.
  Its inferred `csr_value` type is `Word`, which is `uint64_t` for RV64.
  The adapter right-shifts by `0` or `32`, selected by `is_hi`, before the
  existing 32-bit response conversion.
- RV32 retains the original selection between `VX_CSR_MPM_BASE + idx` and
  `VX_CSR_MPM_BASE_H + idx`, followed by the original conversion.

This addresses the audited root cause: the architectural RV64 CSR reader
provides the full counter at its low address and does not provide a high
alias. Narrowing only after selection retains the high word; the RV32 path
never performs a 32-bit shift on a 32-bit `Word`.

The patch has six added lines and one removed line. Existing tag/index
decoding, class save/select/restore, response width, return behavior and
cache-flush handling are preserved. No CSR-unit or device CSR semantics,
public API, counter definition, simulation timing, class definition, include,
build file or other production file was changed by this assignment.
