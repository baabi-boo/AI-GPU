## Delivered scope

Implemented `ci/project/p06_counter_qualification_admission.py` and its focused
host tests. Only these files, this report and the assigned validation log were
written. No native build, native execution, commit or publication occurred.

The constructor requires a complete live dependency `Admission`, its matching
source/revision and successful fresh-build verification. It loads the exact
frozen proof, checks the 69 measurement source identities, joins the 21 selected
dependency source identities, replays both diagnostic originals and the complete
earlier control original, and derives a deterministic admission summary.
Copied `pass` metadata is not an input route to the constructor.

Proof, diagnostic archive, control archive, measurement sources, trusted reader
closure, fixed public source inventory and existing dependency admission are
checked again by `verify_stable()`. File reads require canonical absolute paths,
no symlink traversal, single-link bounded regular files, and matching descriptor
and timestamp observations across each read. These checks preserve the existing
limitation concerning malicious concurrent filesystem writers.

The trusted reader closure includes the independently pinned archive utility,
the pending-read probe source and other non-Python reader inputs. The new runner
must retain `.helper_sources` and `.prerequisite_inputs` paths in its source
snapshot; the runner implementer was notified.

## Shared interfaces

`Admission(path, expected_sha256, *, source, expected_revision,
dependency_admission, diagnostic_archive, diagnostic_sha256, control_archive,
control_sha256)` exposes `.proof`, `.identity`, `.summary`, `.helper_sources`,
`.prerequisite_inputs` and `.verify_stable()`.

The pure `admission_summary(proof, source_projection, dependency_projection,
diagnostics, controls)` composes internally verified results; it does not itself
validate original archives. The pure `stability_summary(proof, helper_sources,
prerequisite_inputs)` returns six path-independent digests. Replay reconstructs
producer helper values from retained source descriptors using the fixed trusted
helper-name inventory, rather than requiring historical producer bytes to match
later reader bytes.

All seven historical claims and `counter_qualification_passed` remain false in
admission. The native reader must establish any subsequent fresh-process result.
Legitimate control data, including the `gp=-1` context, remain intact.
