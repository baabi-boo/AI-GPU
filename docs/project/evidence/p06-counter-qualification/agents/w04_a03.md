## Independent findings

1. The default `p06_dependency_native_replay.verify_view` constructs
   `_NativeReplay` directly. New report metadata cannot select `_QualifiedReplay`
   or another subclass. The old and qualified readers require their own exact
   report fields and contract identities. Both cross-route directions reject.
2. Shared extension hooks are explicit trusted code. `extend_fields` rejects
   collisions with existing build/result fields, so an extension cannot replace
   a historical false claim or the original source binding. The default hooks
   return no new fields; the default reader still reconstructs a complete
   unqualified synthetic packet.
3. The new qualified result is scoped to four recorded preflight processes.
   Original managed/lifetime observations retain their historical contracts and
   false claims. The proof is carried in the reconstructed common build and
   process bindings, and each process's raw echo must match that new identity.
4. The historical warm analyzer retains its unconditional
   `P06-WARM-RV64-MPM-HIGH-HALF` block. Favorable host/reported-cycle predicates,
   monotonic low words that reverse the true cycle comparison, and caller-authored
   qualification fields do not qualify the historical experiment. Importing the
   new qualification modules in the same test interpreter does not change this.
5. All **76 protected input hashes** matched the coordinator's starting
   inventory before and after testing. A separate Git comparison against the
   baseline found no changed/new paths in goldens, test catalogs, SimX/RTL,
   runtime, native tests, software headers, `VERSION`, both top-level config
   files, the canonical roadmap, acceptance policy, protected SVG, or the five
   historical warm producer/contract/record/analysis/replay modules. The actual
   `docs/designs/warm_workspace_benchmark_v1.md` also has no diff.

## Added regression

`ci/project/test_p06_counter_qualification_compatibility.py` adds one focused
test with four subcases, one for each format/policy process. Each starts with a
complete synthetic qualified envelope, substitutes the **unchanged old-route
raw transcript** and its observation, and repairs the command log hash/length,
raw-log inventory, retained observation descriptor, complete inventory, report
bytes and externally supplied report digest. Every subcase rejects specifically
at `managed witness.execution_binding_sha256`.

This tests a metadata-upgrade attempt beyond simple old/new schema mismatch:
the new proof and bindings are present, but they cannot retroactively change a
recorded process's prelaunch echo. It does not establish producer authentication
or prevent someone from fabricating an entirely new consistent transcript.
Dependency replay and the two historical-prerequisite replay boundaries are
explicitly mocked in this synthetic control; actual native transcript parsing,
common build/process reconstruction and public qualified `verify_view` are used.
