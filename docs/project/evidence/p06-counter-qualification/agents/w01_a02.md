## Minimal explicit shared-runner and replay design

Use new `p06_counter_qualification_contract.py`,
`p06_counter_qualification_admission.py`,
`p06_counter_qualification_execute.py` and
`p06_counter_qualification_replay.py` modules with their own IDs and exact schema.
Keep the frozen warm measurement contract SHA-256
`893d85401b1d5f7757d82cb7c743a89b36264fe19c7d08c239b7f216b7a8cbbd`.

The shared executor currently constructs the common build binding in
`p06_managed_preflight_execute.execute` before `build_id = qualification_id(binding)`;
it next constructs each process binding before `binding_id = qualification_id(process_binding)`
and before `command(... native_process=True)`. These are the necessary insertion
points for the validated qualification digest. A separate explicitly selected
qualification entry point should require lifetime and dependency modes, validate
the qualification input before native build/launch, add its contract/digest and
source-bound admission to both bindings, and check their stability before and
after each process. Preserve the old branch's exact bindings and claim fields.

The old `_NativeReplay` hardcodes dependency admission IDs in four places:

1. `provenance`: `admission.contract_hash()`, `admission.contract()`,
   `RUNNER_HELPERS`, and required `admission.SOURCE_FILES`.
2. `build_binding`: dependency `contract_id`, its exact field inventory and
   the recomputed common digest.
3. `processes`: dependency `contract_id`, exact process binding and command argv.
4. `run`: report/variant field sets, contract/scope/limitations, and all seven
   old false claims.

Minimal safe refactor: trusted class attributes `route_module`, `report_fields`,
`runner_helpers` and explicit hook methods such as `build_binding_extra()`,
`process_binding_extra()` and `validate_route_provenance()`. The base defaults
must exactly preserve the dependency-v1 behavior. A new subclass supplies the
new static contract and exact extra fields. The historical `verify_view`
continues to instantiate only the base class; the new entry point explicitly
instantiates the new subclass after the same dependency reconstruction. Do not
select a subclass from an archive field and do not rewrite retained documents
into an older schema before validation.

An immutable route object or equivalent narrow hooks are an implementation
choice, not a caller-controlled generic validator or bypass. The new wrapper
must preserve strict complete member accounting, source/path inertness and raw
log reconstruction. New replay still reports `native_execution="not_run"` and
`retained_code_executed=false`; a derived counter-proof result has its own
scoped field, not automatic phase/performance acceptance.

**Import closure footgun:** executor `loaded_helpers()` inventories every loaded
Python module under `ci/project`. Import the new admission only inside the
explicit new route, rather than at shared-executor module scope. Otherwise
old commands acquire a new helper inventory. New-route readers must declare
the entire actual new helper closure, including replay helpers imported by
admission. Preserve independent helper-stability checks.

## Immutable intake and two-stage identity

Before any new process runs, externally pin the qualification contract/source
proof, diagnostic originals and inventories, native/dependency prerequisite
original, selected source revision, generated route, and expected tooling.
Validate semantic contents rather than accepting a `pass` JSON summary. Separate
the prerequisite receipt digest from the future fresh-run digest; the final
archive digest cannot be required in its own pre-launch record.

Admission validates the ten source premises and their exact 33/40/12 inventory,
guard width/selection, seed-free production build, exact topology, one worker,
exclusive ownership, source/configuration projection and fixed dependencies.
The fresh process adds its own run/reset, coherent read, terminal aggregate,
pending balance, CP retirement, final-reference, loaded-library and disposal
observations. A prerequisite pass alone cannot discharge these future facts.
Missing or malformed explicit qualification fails closed; there is no fallback
to v1 or an unqualified measurement path.

Any mismatch in checked guard, source/component identity, generated headers,
library/tool hashes, format/policy, process inventory, query halves, pending
balance, terminal read, cleanup, or final stability invalidates the new attempt.
Favorable timing statistics cannot override invalid qualification. All original
warm populations, timings, poison schedule and acceptance thresholds stay fixed.
