These limits have the declared practical boundaries:

- Available-memory checks are admission observations. The process monitor samples RSS; it does not maintain a hard system-wide available-memory reserve.
- The outer monitor observes its producer's group and does not aggregate groups created by the child producers. Its sampled peak is not a whole-build aggregate peak.
- Resource sampling can miss peaks, shared pages can be counted repeatedly, and page cache is excluded.
- Initial supervisor input checks precede the stage-sequence clock. Cleanup, report hashing and receipt writing can finish beyond a polled deadline.
- `cleanup_complete` describes the monitored group. It is not proof that every separately grouped descendant on the machine has exited.

The supervisor explicitly calls itself `local-three-stage-supervision-only` and execution bookkeeping. It claims neither the historical local-v1 envelope nor a hard cgroup/quota boundary. Success is checked from each producer's own original report and the final qualification flag; this bookkeeping is not a substitute for complete independent replay.

## W06-A05-F1 — failed-attempt handoff can start governance before cleanup review

**Severity:** F1. **Confidence:** high. **Evidence type:** static-proof, with a concrete failure path. **Surface:** the separate local governance scheduler, not the native qualification producer.

The inspected `run_governance.py` breaks its waiting loop when `supervision.state == "finished"`. It records the native outcome but does not require a successful outcome or successful stage cleanup observations before starting the full suite. The native supervisor's `finally` block sets `state="finished"` on failures as well as success.

If an outer timeout/resource failure terminates a producer before that producer finishes cleaning up a child in a separate process group, the outer monitor cannot prove that the child has exited. In that reachable case, the governance scheduler can release heavy compiler-backed tests while the earlier build still consumes resources. A producer failure or incomplete cleanup therefore needs a distinct handoff decision; a terminal JSON state alone does not establish it.

**Follow-up:** require successful native completion and successful cleanup observations for automatic release, or leave a failed attempt waiting for the coordinator to inspect surviving processes and resources before explicitly starting governance. This finding was sent to the coordinator before the report was written. No scheduler or live process was changed by this reviewer. The observed attempt was still running, with governance waiting; no actual overlap or timeout failure is claimed.
