## Regression evidence

Two methods were added to the existing reader test module. One asserts the exact
94-path inventory, including an independently listed set of the 12 reference
paths. The other exercises every one of those 12 inputs after the complete
synthetic reader has validated all four process transcripts. Only then does a
test wrapper substitute a bounded-loader read from a temporary copy with one
extra newline. Each case must reject at the final frozen-reference pin check;
the test confirms that four process results had completed and that exactly its
selected changed input was read.

The tests never modify a real protected reference file. Their dependency and
historical-prerequisite readers use the existing synthetic fixture's explicit
mocks. They test the complete native grammar and final reference boundary; the
separate actual-original replay below uses no mocks.

Before the production change, both new methods were run against unchanged
`17e02844` reader code. The [baseline log](../validation/w08_a03-baseline-regression.log)
records the expected **13 failures in two methods**: one missing-inventory
failure and one missing final reference-sampling rejection per input. This
test-only substitution does not alter the configuration renderer's separate
input loader, so those three cases do not imply its existing final checks were
absent. This deliberate regression demonstration took **29.464 seconds**.

After the eight-line change, the entire affected module passed:

```text

Ran 23 tests in 126.614s

```

The [complete focused log](../validation/w08_a03-focused-replay-tests.log) retains
all 23 methods, including the 12 late-reference subcases within one method.
There were zero failures, errors or skips. These are **23 unique methods**, not
23 plus the two repeated baseline methods. Full-suite governance is a separate
coordinator result and is not claimed by this report.
