serial run's bare interpreter alias sets `sys._base_executable` to the alias.
The unchanged P05 test creates a copied nested venv whose configuration records
that alias directory as its Python home. The nested child then searches
`/install/lib/python3.12` and exits one with a fatal missing `encodings` module,
before the installed checker executes. The expected checker rejection is exit
two. The exact child stderr and configuration are retained in the
[review receipt](../validation/w09_a04-governance-setup-review.json).

The unchanged test fails through the bare alias and passes through the canonical
interpreter. A new proper venv was created from that canonical interpreter with
`--without-pip --symlinks`; only a symlink to the already available CMake binary
was added to its `bin`. Its `sys._base_executable` correctly remains the canonical
Python executable. No shared toolchain or running alias directory was changed.

**25 affected tests passed, zero failures/errors/skips**, in 6.279 seconds

## Exhaustive partition proposal

The coordinator's proposed three-worker validation can establish complete test
coverage if each worker performs standard discovery and selects whole modules,
preserving the original order within each module and class. The selected ID
sets must be disjoint and their union must equal all 4,437 canonical IDs exactly
once. Actual started/completed IDs, `testsRun`, failures, errors, skips and exit
status must be reconciled; a discovered ID or an incomplete worker is not a pass.
Separate temporary roots and stable source/tool snapshots are required.

This changes cross-module execution order and process-global state compared with
one monolithic invocation. The final report must state that scope and retain
both serial runs and their failures. This reviewer assessed the strategy; no
partitioned suite was started or declared complete here.
