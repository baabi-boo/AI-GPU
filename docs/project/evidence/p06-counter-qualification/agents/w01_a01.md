## Fixed route

Require generated and compiled evidence for RV64 timing SimX, PERF enabled,
`SIMX_CHECKED_COUNTERS=1`, `p02-tfr` / STD, one cluster/socket/core, four
warps, four threads, issue width one, one LSU block, one TCU block, one I-cache
bank, two D-cache banks, two memory channels and local memory enabled. Require
VM/L2/L3/WGMMA disabled, `CP_ON_L2=CP_ON_L3=0`, one simulation worker and one
exclusive host submitter. Memory is the pinned Ramulator HBM2 graph, with no
`VORTEX_DRAM_MODEL` override, `DRAM_TRACE`, replacement factory or plugin.

Do not infer this route from a profile name or runtime capabilities alone.
Reuse `p06_managed_preflight_generated.validate_generated_headers` and
`validate_generated_flags`, the complete model/application compiler graph
validators, seed/object exclusions and the source-to-loaded dependency verifier.
`memory_lt` keeps its existing run/cycle accumulation meaning; it is not the
integral of pending reads over every possible model tick.

## Suggested versioned record and admission API

Use a separate `p06-counter-qualification-v1` contract with strict fields:

- `schema_version`, `contract_id`, `qualification_contract_sha256` and the
  unchanged `measurement_contract_sha256`:
  `893d85401b1d5f7757d82cb7c743a89b36264fe19c7d08c239b7f216b7a8cbbd`.
- `source_binding`: target revision/tree, complete independently pinned source
  inventory and proof/diagnostic projection identities.
- `prerequisites`: exact diagnostic original/revision/archive identities,
  trusted reader closure, independently reviewed projection, dependency receipt
  and selected products. Evidence kind and scope are fixed per prerequisite.
- `route`, `selectors`, `unavailable_selectors`, `components`, and `premises`:
  exact, ordered fixed inventories, with each premise mapped to verified
  evidence relationships. Presence or a Boolean is not satisfaction.
- `admission`: pre-execution target build/interpreter/library/tool identities,
  explicit new route and digest, before any fresh process starts. Keep the
  final archive digest outside this pre-execution digest to avoid circularity.
- `processes`: exactly the four prescribed fresh preflight processes, each
  bound to admission and original command/log/resource/witness data, plus
  before/after build stability.
- `result`: counter qualification scoped to those freshly validated lifetimes;
  warm execution/full warm coverage/performance acceptance/phase acceptance
  stay false for the preflight.

Recommended pure entry point: `verify_qualification(...)` takes externally
supplied expected revision, contract/projection/prerequisite/archive digests,
retained-data views and the trusted reader APIs. Recommended live entry point:
`Admission(...)` selects this contract explicitly, checks live identities and
produces a prelaunch digest; a final validator replays every original process.
Historic receipts remain inputs with their historic false claims intact.
Never mutate the historical warm-v1 contract, analyzer or rejection path.
