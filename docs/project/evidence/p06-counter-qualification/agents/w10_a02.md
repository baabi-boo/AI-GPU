between selected, started and completed IDs. Discovery alone is never counted

## Accounting finding, correction and controls

**F1, high confidence, static proof — corrected before launch.** The original
outer worker-result predicate checked the worker's outcome marker, exit status,
identities and started/completed IDs, but did not independently verify the
recorded test count or failure-related arrays. A contradictory receipt could
satisfy that expression. The worker itself already derived its pass/exit status
from the real unittest result; no trusted worker emitted a contradictory receipt
and no actual false pass was observed.

The parent now additionally requires a strict integer `tests_run` equal to its
expected population, exact `selected_ids`, and empty lists for failures,
errors, skips, expected failures and unexpected successes. It also verifies the
manifest, source revision/tree, partition, interpreter and worker-program
identities, while retaining the existing exact started/completed ID checks.

The before-hardening source was reconstructed from the reviewed source and
verified byte-for-byte against its independently observed hash. Only the
specific trusted accounting expressions were extracted from their syntax trees
for pure controls; neither whole supervisor was imported or executed by this
reviewer.

The [validation receipt](../validation/w10_a02-supervisor-review.json) records:

- One positive parent control and **34 negative parent controls** covering
  contradictory result arrays, wrong counts/types, omitted/duplicated/reordered
  IDs, wrong identities, failed outcome, nonzero exit and missing completion.
- **Ten worker controls**, including its positive case and failures, errors,
  skips, expected failures, unexpected successes, short counts, missing starts,
  missing completions and class-setup failure.
- One synthetic cleanup control with already-exited process races and a
  simulated wait timeout. Every fake worker receives the appropriate wait,
  the saved result remains `interrupted`/`fail`, and the original interruption
  propagates. No real process was started or signaled by that control.

All controls passed their expected outcomes. They are reviewer accounting
checks, not additional unique project tests. No repository test body, native
workload or public archive replay was executed by this agent.

## Limits and retained evidence

Whole-module partitioning changes cross-module order and process-global state
relative to one monolithic invocation. The report of the completed run must
state that distinction. Standard module/class fixture ordering is preserved
within each group; this review does not establish every possible cross-module
interaction or authenticate an adversarial local test producer.

The 90-minute worker deadline is fail-closed. Process-group termination cannot
contain deliberately escaped descendants. Normal worker exit is not an
independent certification that every descendant exited. A further cleanup or
receipt-processing exception can leave an incomplete `running` record; an
incomplete or missing final record cannot establish a pass.

At the retained observation the partitioned execution was still `running`.
The coordinator and final outcome reviewer must reconcile its completed logs,
reports and source/tool checks before claiming the complete pass.
