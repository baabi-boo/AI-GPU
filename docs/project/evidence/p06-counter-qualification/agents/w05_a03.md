## Why seeded diagnostic objects cannot enter the admitted measurement graph

The conclusion is conditional on the trusted producer and complete validators operating as inspected; it is not authentication of an arbitrary producer or a defense against a malicious concurrent filesystem writer.

1. The live qualified route configures fresh RV64 `p02-tfr` builds. Its explicit dependency model command selects the copied `tests/regression/ai_counter_preflight/dependency_model.mk`, whose only extension to the ordinary model Makefile is the link-map flag. The backend command selects the separate preflight observer companion. It never invokes `sim/simx/checked_counters.mk` or its `test-checked-counters` target.
2. The diagnostic Makefile is the layer that replaces `socket`, cache, memory and TCU-buffer objects with accessor versions, and generates the concatenated TCU diagnostic translation unit. The ordinary `sim/simx/Makefile` does not include that diagnostic Makefile. Retaining its bytes therefore documents the alternative route without selecting it.
3. [`p06_managed_preflight_build.validate_build_commands`](../../../../../ci/project/p06_managed_preflight_build.py) requires exactly **43 production model translation units**, a one-to-one source/object mapping, original checked-counter compiler flags, the exact model object multiset and dependency tail at the model link, and the exact **four backend sources** with fixed observer wrappers. Unexpected compiler targets or unrecognized source/object/library commands reject the packet. The seven diagnostic paths intersect none of those inputs.
4. The host input set is the exact **four application sources**: the managed caller, the warm observer and the two AI runtime implementation files. Full application reconstruction checks pinned recipes, compiler roles, the kernel library, runtime stub graph, final links and conversion steps; retaining a diagnostic source does not add it to any accepted application command.
5. Live dependency admission checks the actual model linker map against those production objects and the three freshly compiled/staged products. Every production object must have exactly one `LOAD` entry; the complete project-root load population must equal the expected objects and products. Selected archive members are tied to the fresh receipt. An added or substituted diagnostic project object fails this join.
6. The inert native reader repeats the same source/object and map reconstruction. Its split model/backend graph requires 44 model commands and two backend commands, exact reviewed recipe bytes and compile-before-link ordering. It also rederives generated headers/configuration from the pinned trusted inputs. The new qualification subclass does not replace these checks.
7. Qualification admission compares the 69 current measurement identities with the proof and joins the 21 selected dependency identities to an already verified receipt. Historical diagnostic model/public results are revalidated separately and their source projections are compared as data. A diagnostic result cannot supply an absent fresh compile, source or loader relationship.

The inspected primary model, backend, application and runtime-stub input lists have **zero intersection** with the seven diagnostic accessor/unit sources. Exact source hashes, complete command inventories, map loads and loaded-library expectations form the relevant enforcement chain; a broad retained source inventory alone would not establish this exclusion.
