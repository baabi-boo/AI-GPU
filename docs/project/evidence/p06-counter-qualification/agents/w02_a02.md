# Wave 02 / agent 02 — qualification prerequisite verification

## Scope and delivered API

Implemented `ci/project/p06_counter_qualification_prerequisites.py` and its
focused test module. The prerequisite API consumes the frozen source proof;
it does not mint a qualification or change historical acceptance fields.

- `verify_prerequisites(proof, *, diagnostic_archive, diagnostic_sha256)`
  invokes both original diagnostic readers against the explicitly selected
  immutable original. The public reader receives the frozen external 683-file
  source manifest. Results are joined to all 321 historical `sim/` and `sw/`
  descriptors, the seven diagnostic sources, the exact three reviewed pending
  getter changes, and the 69 current measurement source descriptors.
- `verify_control_prerequisite(proof, *, archive, sha256)` invokes the complete
  existing local replay with all eight frozen attempt04 identity pins. It
  projects all 69 current measurement sources and the exact actual probe source,
  and derives the two positive-pending contexts, always-zero rejection, and
  alternate-library provenance rejection from verified reader results.
- `verify_dependency_projection(proof, verified_dependency_document)` checks
  the 21 frozen Ramulator source descriptors and Git blobs, revision, and tree.
  Its input must already have passed complete fresh dependency verification.
- `reader_sources()` exposes the complete trusted reader source closure for
  callers to include in their admission and late-stability checks.

The output separates historical control populations from the new managed
measurement population. All seven original qualification, warm, and acceptance
claims remain false. No retained producer path is opened and no code from an
input archive executes. Readers inspect archive member bytes in place.
