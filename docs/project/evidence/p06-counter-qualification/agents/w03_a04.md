# Wave 03, agent 04 — independent qualified-reader review

Scope: the new qualified retained reader, shared native replay extension seams,
and their prerequisite joins. Production files were read only. This review does
not claim native execution, authentication of a producer, historical warm
acceptance, or general qualification beyond the recorded four-process scope.

## Findings

**F0 — no concrete false-qualification bypass found. Confidence: high within
this bounded reader review; evidence: source inspection and executed synthetic
complete-packet controls.**

- The new reader has an explicit entry point and strict report fields. It does
  not infer a mode from archive contents or transform an old report. Tests
  reject a new packet through the old reader and an old report through the new
  reader. The shared extension helper rejects collisions with existing fields.
- External native report, dependency receipt, source manifest, revision, proof,
  diagnostic archive, and control archive pins remain independently checked.
  The proof must match the frozen trusted byte identity and semantic contract;
  its retained bytes must also equal the executing source snapshot.
- Public `verify_view` calls the full dependency reader before decoding the
  dependency document used for the 21-file dependency projection. Qualification
  provenance reconstructs the 69-file measurement projection, invokes both
  diagnostic verification and the complete separate-control verifier, and then
  compares the newly derived admission object to the retained summary. Supplied
  summaries do not choose or replace those verification calls.
- Qualification proof and admission fields participate in build identities;
  the proof identity also participates in each process identity. Retained helper
  coverage is a fixed inventory. The six stability digests are reconstructed,
  checked against both admission endpoints, and required at each inherited
  command/variant/final checkpoint.
- The recorded true qualification flag is only a consistency requirement at
  provenance review. The returned true flag is derived by `result_extra` after
  the inherited reader verifies all 37 commands, four raw process transcripts,
  complete counts, final stability, payload accounting, exact retained
  inventory, and exact member inventory. The public entry rechecks its trusted
  reader source closure before returning. All seven historical claim fields
  remain false.

**F0 — rehashing bad raw observations did not bypass semantic checks.
Confidence: high; evidence: three independent public-entry mutation controls.**
Starting from the synthetic complete qualified packet, independently changed a
raw pending-read count to one, substituted a loaded Ramulator path, and removed
a measured run. Each mutation regenerated its raw transcript, command log
digest/length, raw-log inventory, complete retained inventory, report bytes, and
external report SHA. All three were rejected at their corresponding semantic
check, rather than for an obsolete descriptor digest. Dependency and original
prerequisite readers were explicitly mocked in these synthetic controls; their
real invocation and joins were inspected in production source.
