## Findings

1. **Historical public entry points retain their selection semantics.** All
   nine top-level functions in `p06_dependency_native_replay.py`, including
   `verify_view`, `replay_archive`, the parser and CLI, have identical parsed
   syntax trees at the task baseline and reviewed checkpoint. The public view
   function still constructs `_NativeReplay` directly. Packet fields cannot
   select the qualified subclass. Every changed shared-reader hunk was also
   inspected: the default route constants and empty extension hooks retain the
   former behavior, while `extend_fields` rejects replacements of existing
   fields. The new reader selects its subclass in trusted Python code.

2. **Producer admission is explicit and preserves old calls.** In the shared
   producer, `execute` is the only changed top-level function. Its new keyword
   defaults to `False` and requires explicitly selected lifetime and dependency
   modes before activation. The historical CLI parser and main function are
   unchanged. The new entry point selects all three modes explicitly. The
   qualification result additionally depends on successful complete native and
   dependency outcomes; admission or matching metadata alone cannot produce it.

3. **The seven historical claim fields stay false.** These are `qualified`,
   `ready_for_warm`, `warm_execution`, `full_warm_coverage`,
   `acceptance_claimed`, `phase_acceptance` and `performance_acceptance`.
   The original native report contains 115 occurrences of these fields across
   its nested records; each is the Boolean `false`. The original and updated
   retained replay results also preserve all seven. The new true field is
   separately named `counter_qualification_passed` and scoped to
   `recorded-four-process-preflight-only`.

4. **The qualification population remains fixed.** The unchanged frozen proof

   Its SHA-256 remains
   `d12718e9b182a3c93eab346901b380031516d556dd823017a63831d4a0304b4e`.
   The inspected actual report and both replay results retain four processes,

   `576b77872d6b918e3dbe30cef4107481f39ee73c346a813562e7e916b2afd7c4`.

5. **Historical warm and acceptance gates are unchanged.** All 76 protected
   inputs matched the initial inventory, baseline Git blobs and reviewed Git
   blobs. Every top-level `p06_warm*` file, the warm design, canonical roadmap,
   acceptance policy and managed preflight contract are byte-identical to the

   `893d85401b1d5f7757d82cb7c743a89b36264fe19c7d08c239b7f216b7a8cbbd`.
