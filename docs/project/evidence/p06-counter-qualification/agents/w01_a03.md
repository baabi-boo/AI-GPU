## Replay extension without weakening historical readers

`p06_dependency_native_replay._NativeReplay` already reconstructs source,
tools, dependency compilation, model link map, application build, generated
headers, bindings, every raw process transcript, resources, stability and the
complete archive inventory. Its current methods hard-code the dependency
contract and exact field sets. A new wrapper cannot simply add fields and
reuse this class unchanged.

Factor narrow protected hooks/class constants from that class for:

- exact report field set, contract, scope and limitations;
- exact runner-helper and extra source inventory;
- contract/admission snapshot validation;
- extra reconstructed build and process binding fields;
- extra admission stability fields and final result metadata.

The old public `verify_view()` must continue constructing the default
`_NativeReplay`. A separately named qualified reader can instantiate a strict
subclass that supplies the new contract and independently pinned qualification
data while inheriting all original checks. Selection comes from the reader's
explicit API, never from a packet-authored mode flag. Do not strip new fields,
translate a qualified report into an old report, mutate module globals, or
discard retained members to make old replay accept it.

The local five-stage orchestrator also fixes exact module argv, report fields,
counts and source identity. A new qualified local envelope/entry point must
name its changed child command explicitly; historical local attempt 04 retains
its original envelope and all seven false claims. An initial manual execution
