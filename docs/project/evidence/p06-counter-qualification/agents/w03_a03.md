## Enforcement findings

- Admission is constructed before the first recorded command. It requires a live
  existing dependency `Admission`, matching source/revision and fresh-build
  verification, the frozen proof pin, all measurement source bodies, dependency
  projections, trusted helper/data inventory, and both complete prerequisite
  replays. Failure does not fall back to a prior receipt or launch a native process.
- Proof and archive identities are bounded regular-file reads with symlink,
  hard-link and identity checks. `verify_stable()` rechecks proof, source, helper,
  prerequisite, archive and dependency identities. The shared executor separately
  verifies the clean exact source revision before build/native commands.
- The qualification digest and admission summary enter the build binding before
  `qualification_id()`; each process receives the digest before its own binding
  hash is calculated. Native argv receives that process qualification ID and the
  existing transcript reader requires its exact echo.
- The common command wrapper checks stability before and after every successful
  command. Process/variant checks cover policy boundaries; finalization compares
  the final admission observation with the original one. A late failure sets the
  sticky failed outcome, retaining any earlier primary failure.
- A positive `counter_qualification_passed` requires successful native population,
  successful dependency/model/application checks, a live admission and equal
  before/final observations. The original seven broader claims remain false.
  The legacy dependency route lacks the new report/binding fields and the old
  CLI import paths do not load the new qualification modules.
