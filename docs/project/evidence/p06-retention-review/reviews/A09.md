The stable public function is:

```python
restore_archive(archive, expected_sha256, *, expected_revision, output_dir, summary=None)
```

The CLI supports `inspect --archive PATH --sha256 HEX --expected-revision HEX
[--summary PATH]` and the corresponding `restore` operation with required
`--output-dir ABSENT`. All paths are canonical absolute paths; `--summary` is an
existing encryption-summary input, never an output receipt. A08 agreed and
implemented the additional reader `.manifest_bytes` property so restoration
preserves the original manifest bytes exactly.

## Implemented behavior

Full reader validation, revision/digest matching, optional summary consistency,
and source stability precede output creation. The destination must be absent;
existing objects, symlink ancestors, lexical input/output overlap and observed
ancestor/directory inode aliases are rejected. Output is one owner-only root
containing exact `manifest.json` and the manifest's `private/` tree, including
hidden files, empty files and empty directories.

All directory traversal uses no-follow descriptors, and each file is created
relative to an opened owned parent with `O_CREAT | O_EXCL | O_NOFOLLOW` and
`O_CLOEXEC`. File writes handle short writes. Directories are mode 0700; files
are mode 0600. Member modes, ownership, links and executable behavior are never
applied. Descriptor use is bounded by path depth during tree verification.

An exclusive fixed-name `.restore-incomplete.PRIVATE.json` marker is written
first outside `private/`. On failure, all owned partial bytes remain in place;
there is no recursive cleanup or removal of a replacement tree. Marker
recreation after a late failure is best effort and exclusive. Files and
directories are fsynced; restored type, identity, mode, single-link count, size,
hash and exact inventory are checked. The archive and original named root are
rechecked before a success report, and the reader context's final archive check
completes before the function returns.

There is no persistent pass receipt. The CLI prints fixed-field JSON, with fixed
error codes instead of user arguments, retained paths, member names, payload
bytes or arbitrary exception messages. Success remains retention consistency
only: native execution is `not_run`, and retained-code execution, origin
authentication, native acceptance, performance acceptance and phase acceptance
remain false. Restoring a retained partial attempt does not promote it to a
complete original or a native result.

## Limits and handoff

Repeated checks detect observed changes; they do not exclude a malicious
same-user concurrent writer. Filesystem failure or abrupt death can prevent
marker creation or cleanup. Marker absence and output existence do not prove
success, and this is not an atomic crash transaction. No claim was made about
real age interoperability, full canonical governance, native execution or any
phase gate. Independent filesystem/privacy/error-path review and the actual
packaging/encryption integration checks are handed back to root; A11 received
the stable API and output-layout details directly.
