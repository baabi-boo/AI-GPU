## Replay repair preserves the qualification sequence

The qualified replay diff changes only `_reader_sources`: it binds the records, analysis and replay modules to three explicit trusted checkout paths instead of deriving the direct entry point as `__main__.py`. The existing resolved `module.__file__` equality check, raw file SHA-256/size inventory, prerequisite pins and before/during/after reader-stability checks remain in place.

An AST comparison between base and current, removing only the top-level `_reader_sources` function from each, is identical. This verifies that the replay class, flags, command count, semantic validators, analysis ordering and CLI success/failure code were not otherwise changed.

The unchanged success sequence is:

1. `replay_archive` verifies the independently selected ZIP digest and exact two-root inventory.
2. `verify_view` verifies all external pins and exact revision, hashes the native report, and performs the complete existing dependency replay.
3. `_QualifiedWarmReplay.run` validates the full report, source/build/load relationships, independently pinned diagnostics and controls, qualified source projection, both format builds, all 24 raw process observations, all 57 command receipts, recomputed complete counts, stability, and complete retained-member inventory.
4. Only after those checks does inherited `run` merge `result_extra`, which sets `counter_qualification_passed=true` and `qualified_warm_passed=true` for the recorded complete 24-process attempt.
5. `verify_view` then runs the unchanged qualified arithmetic and rechecks reader stability. The API returns, and the CLI writes a success result, only after this completes. Exceptions return failure flags; a supplied pass-shaped producer report alone cannot satisfy these checks.

The subclass's internal `result_extra` method is not an independent public validator. Its literals acquire meaning only through the complete unchanged replay sequence. Replay success still means inert retained consistency: `native_execution="not_run"`, `retained_code_executed=false`, and `origin_authenticated=false`. All seven historical fields remain false: `qualified`, `ready_for_warm`, `warm_execution`, `full_warm_coverage`, `acceptance_claimed`, `phase_acceptance`, and `performance_acceptance`.
