## Contract conclusions

1. Manifest JSON must be a dictionary with exactly `schema_version`, `contract_id`, `expected_revision`, `directories`, and `files`. Version is an exact integer 1; booleans are rejected. Contract ID must equal the producer contract. Expected revision must match the caller-selected lowercase 40-hex revision. The private `_manifest` parser permits a JSON null revision in its schema, but a real public reader requires a selected string revision, so null cannot pass inspection.
2. JSON decoding is strict UTF-8. Duplicate keys are rejected at every object level. Floating-point and exponent tokens, NaN and other nonstandard constants are rejected before schema use. Manifest bytes must equal sorted compact `ensure_ascii=True` JSON plus one newline, matching the producer serializer. Extra whitespace, absent or extra newline, unnecessary escapes, raw non-ASCII JSON and uppercase Unicode escape digits are rejected. Integer `-0` parses as 0 but fails this canonical byte comparison.
3. Directories and files are exact lists. The root directory is the first empty-name entry; directories are sorted; file paths are strictly ascending. File dictionaries have exactly path, size and digest. Size is an exact nonnegative integer bounded by the producer per-file limit, and total bytes and entry counts are bounded. File SHA-256 values must be lowercase 64-hex strings.
4. Paths use the producer NFC, UTF-8, component-length and depth rules. The entire manifest namespace is checked for exact and Unicode casefold collisions across both files and directories. Every non-root entry must have an exactly named declared directory parent; missing ancestors, a file-as-parent and case-mismatched parents are rejected. Combining the parent condition with relative path syntax excludes a path outside the root.
5. Optional summary JSON has exactly the producer ten-field shape. Version and all counts/sizes are exact integers, encryption_passed is the literal boolean true, and outcome is pass. Revision, file_count, directory_count (including root) and input_bytes must equal the validated archive. Ciphertext size is only checked for a positive value within a conservative global limit; ciphertext_sha256 is only checked for lowercase 64-hex syntax.
6. Summary serialization is intentionally less restrictive than manifest serialization: pretty JSON, no terminal newline and equivalent escaped keys are accepted. Duplicate keys and floating-point count tokens still fail. This does not loosen manifest or archive verification, and the existing advertised optional-summary contract only requires retention consistency. There is no reason to impose canonical summary byte spelling merely for symmetry.
7. A fresh small source tree passed the actual producer inventory helper; its manifest bytes, summary values and tar-size helper matched the independent fixture. No production age executable was run. No new redundant tracked tests were added because no new concrete defect was found.
