## 2. Actual arithmetic and what rejects the treatment hypothesis

Let `T[f,p,i]` be the integer sum of the 32 primary host intervals for format `f`, policy `p`, and measured pair `i` in 1–5. A batch mean is `T/32`. The reference is `per_operation`; the candidate is `reusable_single_tile`.

For each format independently, `p06_warm_analyze._format_result()` implements exactly:

1. `100 × median(T_candidate) <= 95 × median(T_reference)`.
2. For all five matched pair indices, `T_candidate[i] <= T_reference[i]`.
3. For all five matched pair indices, `cycles_candidate[i] <= cycles_reference[i]`.

All three predicates must be true for each of FP16 and BF16; the qualified analyzer then takes the conjunction across both formats (`p06_warm_analyze.py:203–234`; `p06_qualified_warm_analyze.py:69–81`). Equal pair host times and equal pair cycles are permitted. The median must still achieve the frozen at-least-5% reduction. A favorable median cannot compensate for one slower pair, one cycle increase, or a failure in the other format.

The median statistic is the third sorted **batch mean within each policy**, followed by a ratio of those two medians. It is not the median of the five paired ratios. The matching pair predicates are separate. Using batch totals for the integer comparisons is exact because every denominator is 32. `_ratio()` supplies reduced rational numerator/denominator fields plus a floating display value; floating display ratios and `population_stddev` do not determine any predicate (`p06_warm_analyze.py:87–107,203–234`).

Modeled cycles come from the validated cumulative difference **after_batch minus after_prime**, spanning the 32 operations. They are not the process-wide cycle total and are not attributed to individual kernels. `reported_active_cycles_per_useful_flop` divides that batch delta by exactly 16,384 useful FLOPs (`32 × 512`). The reducer selects exactly one available positive 64-bit `cycles` delta; the complete reader and lifetime witness checks supply the qualification preconditions. Other retained counter deltas are diagnostic observations, not additional performance pass/fail criteria.

## 3. Measured quantity and the native caller

The native caller packs inputs and allocates record storage before timing. Each primary interval starts immediately before `runtime->submit`, includes wait, the actual 32-word comparison, explicit operation close, and operation result success checks, and ends immediately afterward. Count snapshots, trace/output retention copies, the remaining dispatch/ownership checks, and closed-operation destruction occur after the end timestamp. Counter and memory observations occur after the prime and after operation 32, outside primary intervals. Owner creation and teardown are separate intervals (`tests/regression/ai_warm_workspace/main.cpp:334–443`; `observer.cpp:53–55`).

This matches the frozen primary metric: **instrumented host nanoseconds per validated operation in the SimX timing configuration**. It measures the intended warm allocation-lifetime treatment using the same build per format and retains fixed observer bookkeeping. It does not include candidate owner-allocation setup in the batch mean, so it cannot establish cold-start improvement, application amortization, or total job elapsed-time improvement. The frozen design intentionally selects the warm metric; this is not a discovered mismatch.

The analyzer preserves `process_duration_seconds` only as a separate observation. The complete reader checks the owner lifetime against that supervised duration; no supervisor delay, observer overhead, or teardown cost is subtracted from primary time (`p06_dependency_native_replay.py:589–595`; `p06_warm_analyze.py:175–199`; manifest `timing`).

## 4. The complete-population gate is before analysis

The producer iterates the fixed plan serially. It appends each process before launch, validates its native output, checks source/artifact stability, and only then marks that process passed. The exception/interruption handler exits the attempt's work and finalizes failure; there is no sample retry or replacement loop. A passed native result requires the exact ordered process inventory, complete derived counts, final stability/resource checks, and dependency/counter admission (`p06_managed_preflight_execute.py:688–742,808–827`).

The independent reader requires a finished passing native report, no failures, the exact expected plan and 24-process count, two format builds, all 57 command receipts, passing process outcomes, canonical process identities, and matching build/execution bindings. It reconstructs observations from raw logs, compares both the report's observation and the separately retained observation, recomputes counts, and completes its source/build/load and other validity checks (`p06_dependency_native_replay.py:563–605,631–709`; `p06_qualified_warm_replay.py:136–165,237–273`). Only after `replay.run()` returns does `verify_view()` call `analysis.analyze_population()`.

The arithmetic helper additionally rejects an incomplete/reordered process list, nonpassing process, wrong common build, malformed execution identity, duplicate raw warm transcript digest, missing prime, missing/nonpositive sample interval, or unavailable/invalid cycle delta. Its docstring and limitations correctly state that calling it with dictionaries alone does not establish packet qualification. This internal trust boundary is intentional, not a standalone admission API.

A missing or failed sample therefore yields invalid/incomplete evidence. It is not converted to a valid negative hypothesis. A complete but unfavorable population remains a valid experiment and must keep every unfavorable observation.

### Outcome interpretation

| Observed state | Correct disposition |
| --- | --- |
| Native incomplete/failed/blocked, or complete-reader validity rejection | No usable qualified hypothesis result. Preserve the attempt and failure reason. Do not label this `not_satisfied`. |
| Complete replay succeeds and `A.hypothesis_evaluation == "not_satisfied"` | Valid unfavorable experiment: reject the frozen compound treatment hypothesis for the recorded scope; state which format/predicate/pair failed. |
| Complete replay succeeds and `A.hypothesis_evaluation == "satisfied"` | The frozen engineering rule is supported for this exact source/build/host/configuration/fixture and instrumented warm workload. Keep performance/phase/hardware acceptance false. |
| Replay exit zero or `qualified_warm_passed == true` without checking `A.hypothesis_evaluation` | Validity alone is insufficient to claim the treatment passed. |
| Hosted success without independently completed replay | Successful orchestration/retention at its stated scope; no independent hypothesis conclusion. |
| Replay nonzero from output I/O after otherwise valid computation | No successfully delivered result; inspect the error. Do not conflate output failure with an unfavorable hypothesis. |

The CLI deliberately returns zero for either valid hypothesis outcome and includes `hypothesis_evaluation` in its success summary when writing a report (`p06_qualified_warm_replay.py:333–359`). Native execution does not run the arithmetic at all; its success flag is derived validity (`p06_qualified_warm_execute.py:33–43`).
