## Source-bound checks

- **Canonical metadata and PAX sequence:** retention `_header` (258–263)
  constructs the same fresh `TarInfo`, type, modes, size, zero mtime, PAX format,
  strict UTF-8 serialization, and default metadata as producer `_tar_info`
  (359–365) and its actual `tarfile.open(..., mode="w|", ...)` writer (591–607).
  Comparing the complete serialized sequence checks local PAX headers, records,
  padding, ordinary fallback names, numeric encoding, and checksum together.
  Non-ASCII names and names across the 100-byte ordinary-header boundary remain
  compatible; directory slashes are generated by the same serializer.
- **Manifest and namespace:** 183–255 rejects duplicate JSON keys, noncanonical
  JSON, wrong schema/types, revision mismatch, invalid relative names, Unicode
  casefold aliases, undeclared parents, and producer resource-limit violations.
  Root `""` is present exactly once. File and directory names share one namespace.
  The explicitly selected revision route intentionally rejects producer-permitted
  null revisions as `revision-mismatch`; this is not a format incompatibility.
- **Exact inventory and order:** 329–356 requires the ordinary manifest header
  first, then reconstructs the exact root/file/directory sequence from sorted
  entries. This matches producer `_tar_members` (368–372), including interleaved
  files and directories. Extra, missing, reordered, substituted or duplicate
  physical records cannot satisfy the byte comparisons and computed size.
- **Bodies, padding and end:** every regular payload is hashed against its
  manifest digest. Manifest/file padding is checked for zeros. The size formula
  at 341–345 matches producer `_tar_size` (375–380), including full PAX sequences,
  two terminal zero blocks, and the 10,240-byte record boundary. Exact descriptor
  size, at least 1,024 final zero bytes, all remaining padding, complete archive
  SHA-256, and physical EOF are required. An additional all-zero record is
  rejected despite a matching caller-selected digest.
- **Bounds and stability:** initial file size is bounded before content reads;
  the first fixed header bounds the manifest allocation to 16 MiB. All descriptor
  reads are capped at `CHUNK_BYTES` (64 KiB); payloads are streamed. Canonical
  serialized member headers are bounded by the validated path and size limits.
  Entry count, per-file bytes and total payload bytes are independently bounded.
  Identity and complete-digest rechecks remain separate from origin
  authentication. No arbitrary tar extraction is used.
- **Remaining public API:** defensive manifest/entry snapshots, summary scope,
  source rechecks, fixed diagnostic codes, bounded copies, and context cleanup
  were read. No additional reachable F2/F3 failure was established. The existing
  documented limitation concerning malicious concurrent writers remains a
  limitation, not a new finding.
