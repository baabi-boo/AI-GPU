## F1 — Missing nested command inventory is accepted as finished (medium robustness)

`ci/project/p06_qualified_warm_hosted.py:389` uses `child.get("commands", [])` for every started native child. A dependency-build or qualified-warm receipt that says `state="finished"` but entirely omits `commands` therefore passes `writers_finished`; a present `commands=null` is correctly rejected. Local preparation legitimately has no command array, so that stage needs a deliberate exception.

Reproduction (small temporary files, actual helper; no child launch): create `workspace/evidence/qualified-warm-run.json` containing a finished native report with one started/cleaned `dependency-build` stage and its normal report path. Give `dependency-build/report.json` only `{"state":"finished"}`. Call `writers_finished(attempt, [{"id":"native-supervisor", "process_started":true, "cleanup_complete":true}])`. Observed `true`; changing the child to `{"state":"finished","commands":null}` produces `false`.

Impact: malformed failure evidence can authorize `--writers-finished` and encryption without an actual nested cleanup inventory. Success packaging has separate population checks; this is chiefly an erroneous closeout observation, not a native/performance false pass. The producer normally emits `commands`, so this is not a demonstrated normal-path blocker. Recommendation: require an explicit list for non-preparation started children, preserve preparation's established schema, and add missing-field cases beside the existing malformed-command tests. Do not expand this into new descendant-containment claims.
