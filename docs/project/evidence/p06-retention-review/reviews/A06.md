# A06 — Offline retention inspection and restore design audit

Reviewed source: `25543e1cf96530264746c0e2d130018dd0dba465`; working tree was clean when inspected. Read-only review; no repository files changed and no tests or builds run. Reviewed `AGENTS.md`, the retention plan, current project/acceptance context, encryption producer, packaging producer, and hosted guide §5.

## Recommendation

Keep the proposed two-module interface: `p06_qualified_warm_retention.py` validates and exposes one descriptor-backed archive inventory; `p06_qualified_warm_restore.py` supplies the small inspect/restore CLI and bounded copy operation. Default to returning a JSON-safe report rather than introducing additional success-receipt publication machinery. Neither mode should decrypt, unpack inner ZIPs, execute payloads, determine native acceptance, or alter originals.

Use the root's finalized API in `retention-plan.md`. In particular, `--sha256` pins the **plaintext tar**, while optional `--summary` is an **input** encryption summary used only to compare exact revision and retention counts. The summary's `ciphertext_sha256` cannot validate the plaintext tar; no supplied summary authenticates the producer or establishes successful hosted invocation. The caller's expected revision must be an exact lowercase 40-character hex string and must equal the manifest value; producer archives with a null revision cannot satisfy that strict review request.

## Producer facts the reader must preserve

Sources: `ci/project/p06_qualified_warm_encrypt.py` (`_relative`, `_inventory`, `_tar_members`, `_tar_size`, `_summary`, `encrypt_private_directory`) and `docs/project/p06-hosted-warm-guide.md` §5.

- The manifest has exactly `schema_version`, `contract_id`, `expected_revision`, `directories`, and `files`. The contract is `p06-qualified-warm-encrypted-retention-v1`; each file row has exactly `path`, `size_bytes`, and `sha256`. Reject duplicate JSON keys, non-finite numbers, wrong primitive types, and unexpected schema fields. Integer checks must exclude Boolean values.
- An empty directory path is the selected input root; it maps to `private/`. It is required, counts toward `directory_count`, and can exist without any regular files. A top-level manifest member is additional to the producer's selected-entry count.
- The producer preserves hidden files and empty directories, normalizes neither payload bytes nor relative names, and rejects case-fold aliases. Require exact manifest/tar membership, declared directory parents, no duplicate or file/directory collision, NFC paths, no control characters, backslash, colon, empty interior components, dot or parent components.
- Producer relative-path limits are **4,096 UTF-8 bytes and 128 components before adding `private/`**. A valid raw tar path can consequently reach 4,104 bytes and 129 components. Do not apply the unprefixed limits to the full tar member name. Directory-header slash handling must match the actual producer representation without allowing arbitrary normalization.
- Existing limits are 40,000 selected entries, 1 GiB combined selected-file bytes, 256 MiB per selected file, and 16 MiB manifest bytes. The manifest is separate from selected input bytes. Use bounded UTF-8 local PAX path handling; reject global/unknown extensions, sparse members, links, devices, FIFOs, malformed headers, nonzero payload padding, missing end markers, concatenated archives, and nonzero trailing bytes. Count physical extension headers and bound their lengths as well as logical entries.
- Stream every regular-file payload and compare size plus SHA-256. Preserve the original manifest bytes on restore; reserializing parsed JSON would change an original. Exact tar digest, structural inventory, and end-of-archive verification all precede a successful inspection report.

## Filesystem lifecycle

1. Validate arguments and acquire the archive through ancestors opened one component at a time with `O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC`. Open the final name with `O_RDONLY | O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC`, then require a bounded regular single-link file. Compare the pre-open named identity with `fstat`; retain that descriptor for the whole operation. Do the same for an optional summary. Do not use `resolve()` to silently accept symlink aliases.
2. Validate the **entire** archive, expected revision, optional summary, digest, and full manifest inventory before creating the restore output. Thus ordinary invalid input leaves no newly created restore tree. Record only bounded file offsets/sizes/hashes and directory paths, not whole file bodies.
3. Require a canonical absolute, absent output path. Reject every preexisting object, including an empty directory or dangling symlink; provide no overwrite/merge option. Open its parent using the same no-follow component walk. Reject lexical archive/output overlap and observable ancestor/inode aliases. Create exactly one new root with `mkdir(..., dir_fd=parent_fd, mode=0o700)`, open it without following links, and force owner-only mode with `fchmod`. Retain its inode identity and open descriptor.
4. Create an owned, fixed-name incomplete marker first, outside `private/`, so a caught interruption or write failure has an unambiguous retained scope. Create directories from validated manifest parents using `mkdir` relative to opened parent descriptors. Create files using `O_CREAT | O_EXCL | O_NOFOLLOW | O_CLOEXEC` and mode `0o600`, then `fchmod`. Any existing name is failure. Never use `extract`, `extractall`, payload-derived absolute paths, `chmod` by a mutable path, chown, or member-supplied metadata.
5. Keep descriptor usage bounded by depth; do not retain 40,000 open directory descriptors. Traverse from the held root with no-follow opens and compare created-directory identities when reopening. Every write is to one validated basename under a held parent descriptor. Loop on short writes. Hash while copying and verify the just-written descriptor's size, type, mode, single-link count, and digest. Preserve hidden names, empty directories, archive files, receipts, and malformed payload reports as bytes.
6. Recheck the archive descriptor identity and original named identity, full archive hash, and copied member hashes before success. Verify the complete output inventory and owned-root pathname identity, including no extra entries or aliases. Flush/fsync completed files and directories if claiming durable local completion. Remove only the owned incomplete marker after final verification; return/print success only after the operation has completed. No output path's existence alone establishes completion.

An open descriptor prevents later symlink substitution from redirecting that descriptor; it does not prevent a same-user adversary from moving the underlying directory or modifying already-written files. Repeated identities/hashes detect observed changes, not hard exclusion. State that boundary explicitly. Filesystem errors or abrupt death can prevent final receipts, marker cleanup, or durable publication; do not claim an atomic crash transaction.

## Failure and claim boundaries

Catch interruption as well as ordinary failures after output creation. Keep every owned partial byte under the new private root; never recursively delete the output or unlink an unrelated replacement. A small fixed-code private failure receipt may be written exclusively through the retained root descriptor on a best-effort basis. Record stage/error class without embedding source paths, raw member names, payload bytes, or arbitrary exception strings. Do not change permissions or contents of the input tar, summary, downloaded ciphertext, or existing directories.

The minimal API avoids a persistent pass receipt: return the report only after final verification and let the CLI emit it only after success. If a persistent pass receipt is added, its publication needs an explicit commit boundary and ownership-aware withdrawal; copying the producer's complex multi-file publication behavior is unnecessary for this first reader. Never overwrite a previously published receipt on failure. Failure to withdraw an owned pass receipt must remain unresolved, not silently treated as clean rollback.

Use fixed public error codes, a nonzero CLI exit on failure, and concise public JSON. Successful inspection sets `retention_verified=true` only for local consistency; restore additionally sets `restoration_completed=true`. Keep `native_execution="not_run"`, `retained_code_executed=false`, `origin_authenticated=false`, and all native/performance/phase acceptance fields false. Do not expose retained names or paths in sanitized stdout/stderr.

Sources: `ci/project/p06_qualified_warm_pack.py` (`package_partial`, `_writer_observations`, `_package`) and guide §5 explain why a valid retained partial attempt, malformed report, packaging-failure receipt, or surviving success-shaped packaging receipt can coexist. Retention inspection must preserve all of these without semantic promotion. In particular, `packaging_passed=true` alone does not override a failed invocation or `published_receipt_withdrawal_unresolved=true`. A complete-original classification belongs to a later separately scoped intake/replay operation that reconciles invocation evidence and exact inventory hashes.

Direct-local payloads use `private/qualified-warm-original.PRIVATE.zip`; hosted payloads use `private/packet/qualified-warm-original.PRIVATE.zip`. Restore actual manifest paths, preserving both layouts. A partial archive stays a partial archive. No native budget, frozen proof, source admission, acceptance gate, or original evidence needs modification for this work.
