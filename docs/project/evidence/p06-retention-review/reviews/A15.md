## Production review coverage

| Area | Review result and relevant boundary |
| --- | --- |
| Admission and absent output | Canonical absolute output validation precedes the reader context. The complete tar, requested hash/revision and optional summary are validated before output creation. Lexical input/output overlap, symlink ancestors and all preexisting output objects fail closed. The absent check is followed by exclusive `mkdir`; no merge or overwrite route is present. |
| Directory ownership | `_open_directory` walks from `/` with directory/no-follow/cloexec flags and records ancestor identities. The owned root descriptor remains held. Created directories are reopened with no-follow, identity checked, made 0700 through the descriptor and checked again. `_open_owned_directory` checks every reopened owned prefix. Duplicate created-directory and observed input/ancestor inode aliases are rejected. |
| Rename handling | Writes occur relative to held owned descriptors. `_verify_root` reopens and compares the full parent identity chain and named root identity before success. Both root-replacement coverage in the existing suite and the independent parent-replacement probe reject the changed pathname without touching an unrelated replacement. These are observed-identity checks, not guarantees against every possible concurrent schedule. |
| Files and modes | Each file is created with `O_RDWR | O_CREAT | O_EXCL | O_NOFOLLOW | O_CLOEXEC`, then descriptor-fchmoded to 0600. Short writes are looped. The writer receives the new descriptor, never a payload-selected absolute destination. Final checks require regular type, original identity, mode 0600, one link, exact size, exact digest and stable metadata. The independent hardlink probe is rejected. |
| Exact bytes and inventory | The original manifest bytes are copied, rather than reserialized. All declared empty directories and files are included under `private/`; retained payload semantics are not interpreted. `_verify_tree` requires the exact child-name set at every level, reopens expected types without following links and rehashes every file. Full checks run with the marker present, then again after its removal. The maximum accepted 4096-byte, 128-component relative member successfully restores through descriptor traversal. |
| Final source and publication ordering | Archive/summary stability checks occur before creation and after copying. The output tree, source and named root are checked before success. Returning the report is outside the reader context, so its final exit-time archive check must also succeed. An injected failure in that final context check produces failure and recreates the incomplete marker. There is no persistent pass receipt to withdraw. |
| Failure retention and cleanup | Exceptions and `KeyboardInterrupt` after root acquisition attempt exclusive marker retention through the owned root descriptor. Partially written payload bytes are retained; the ENOSPC probe confirms the written prefix is preserved. No recursive removal, payload cleanup, `rmtree`, replacement unlink or input mutation appears in the code. The one normal unlink removes the identity-checked owned incomplete marker. Marker creation/recreation is explicitly best effort under filesystem failure. |
| Durability and descriptors | Files are fsynced before verification; complete-tree traversal fsyncs directories and the parent is fsynced before return. No atomic crash guarantee is claimed. Descriptor usage is bounded by depth, not the manifest entry count. The independent success/failure probes left `/proc/self/fd` counts unchanged. |
| Public report and CLI | Argument parsing and caught failures emit fixed-code JSON without user paths, member names, payload bytes or arbitrary exception strings. Success remains local consistency: native execution is `not_run`, and execution/authentication/native/performance/phase acceptance flags stay false. A partial attempt's pass-shaped payload receipt is preserved as bytes and does not become a qualification result. |

## Scope and limits

No tracked file was edited, no commit or push was made, and no agent was spawned.
Only this review note and its small reproduction script were created outside the
checkout. Existing unrelated working-tree changes were preserved.

The source explicitly requires stopping writers. Repeated identities and hashes
cannot exclude every malicious same-user mutation or rename; this review does
not treat that excluded guarantee as a defect. Filesystem failure or abrupt
termination can prevent marker publication or cleanup; output existence and
marker absence are not success evidence. Real age interoperability, actual
maximum-byte archive load, physical filesystem crash recovery, native execution
and full governance were not run by this assignment. No acceptance gate, budget,
frozen proof, original evidence or permission boundary was changed.
