## Findings and qualifications

### A29-F1 — known cleanup error-code wording mismatch; active A27 dependency

The new design's lines 199–202 state that API errors use fixed `RetentionError.code` / `RestoreError.code` values. The source reviewed at the start of this assignment has direct `os.close` calls in cleanup paths which can propagate raw `OSError` outside the convenience API's intended sanitized error boundary. In particular, `restore_archive`'s outer `finally` closes root and parent descriptors after its `except` block; a close failure there bypasses its `RestoreError` conversion and can stop the remaining close loop. Reader `_Input.close` and `RetentionArchive.close` similarly stop at their first close error.

This is the already identified A27 cleanup correction, not a new independent reproduction or a request to change the CLI/schema. The guide's operational requirement to require actual zero exit status plus terminal pass JSON, and its warning that marker absence does not establish success, remain appropriate. Before treating the design's blanket API error-code sentence as verified, the subsequent independent reviewer must confirm A27's final cleanup bytes, remaining-descriptor close attempts, sanitized API errors, and late-failure marker behavior. A29 did not wait for, test, or certify that pending change.

### A29-O1 — inherited replay handoff assumes earlier shell setup (nonblocking; assigned A30)

The hosted guide's section 5 links directly to complete-replay runbook section 5. That command invokes `p06_run_stage` (runbook line 444), whose function is defined earlier at lines 194–217 and depends on `P06_ENV` and `P06_REVIEW_DIRECTORY`. The three proof/prerequisite digest variables are initialized at lines 183–185, and the diagnostic/control archive paths are also established earlier. The hosted guide does not define those items.

All native identities remain correct and the referenced link/anchor is valid. This is an inherited standalone-use assumption, not a retention command/API mismatch. An operator following only the hosted guide and the section-5 anchor in a fresh shell must additionally initialize the replay recorder/environment and prerequisite inputs from the runbook. Disposition: assigned A30. The coordinator accepted this observation and assigned a self-contained independent replay handoff in the hosted guide only: initialize the required reviewer variables/environment and show the direct inert CLI, without native-stage setup or changes to the historical runbook. Those later documentation bytes require a separate review. No document was edited by A29.
