## Root cause and implementation

A24 demonstrated that a real root-directory close followed by an injected
`OSError` escaped the direct restore API as a raw exception and skipped the
parent-directory close. Related reader cleanup loops stopped at the first
failed close, and cleanup during exception unwinding could replace the original
error. Directory-walk handoffs also closed the old descriptor before assigning
the newly opened child to the current owner; if the old close released its fd
and then raised, exception cleanup could retry that uncertain old fd and leave
the child unattempted.

The correction adds one shared attempt-all cleanup loop. It calls each owned
resource exactly once, remembers the first cleanup failure, and suppresses
cleanup failures only when explicitly unwinding an existing failure. Input
objects detach both descriptor fields before attempting either close; archive
objects similarly detach the optional summary and archive objects before
closing them. A repeated `close()` therefore cannot retry a descriptor whose
release is uncertain. Directory walks transfer ownership to the child before
closing the old descriptor, so an error closes the child during unwinding and
does not retry the old descriptor. Restore's initial root-directory `fstat`
also now lies inside its cleanup scope.

Successful-body cleanup paths explicitly track completion. This avoids inferring
failure state from a caller's ambient handled exception and ensures a normal
operation cannot return a pass after its cleanup fails. Exceptional paths retain
their original failure while attempting the other owned inputs and descriptors.

| New cleanup failure at a public operation boundary | Result |
| --- | --- |
| Reader ordinary exception, including `OSError` | Existing fixed `RetentionError("retention-invalid")` |
| Restore descriptor `OSError` | Existing fixed `RestoreError("filesystem-failed")` |
| Restore other ordinary exception | Existing fixed `RestoreError("restore-failed")` |
| Restore descriptor `KeyboardInterrupt` | Existing fixed `RestoreError("interrupted")` |
| Reader close failure while leaving restore's reader context | Existing fixed `RestoreError("retention-rejected")` |
| Any secondary close failure while an operation already fails | Original operation failure keeps precedence, with its existing API mapping |

The fixed error allowlists and CLI parser are unchanged. Reader control
exceptions continue to propagate when no primary failure exists; the existing
restore/CLI boundaries retain their established interrupt handling. The code
does not retry uncertain close results or promise that an fd remains open after
a reported close error.

Best-effort incomplete-marker recreation and private output retention remain
unchanged in meaning. A failure before terminal directory cleanup can recreate
the marker through the still-owned root descriptor. A failure during final
directory close can leave a complete private tree with no marker, but the API
raises and the CLI emits failure. Marker absence is not a success receipt or an
atomicity promise. No failed output or replacement is removed.

Root requested a final marker-close check. The previous `_retain_incomplete`
implementation already swallowed its final close error in a nested
`except BaseException`; it was not another confirmed escape. Its equivalent
best-effort cleanup is now consolidated through the shared suppressing helper,
and the new real-close-then-raise marker test verifies that the original
`RestoreError` object survives.

## New regression coverage

All injected ordinary close errors carry synthetic private exception text and a
synthetic private filename. The hooks call the real close before raising.
Resource accounting compares `/proc/self/fd` sets around the tested operation.
The successful tests leave no extra descriptors in these release-then-error
cases; this does not claim that every real-world close error guarantees release.

The 15 test methods cover:

- Each archive/summary data fd and parent fd failing independently on otherwise
  normal reader completion, plus all four failing together; no inspection pass
  is returned and all four closes are attempted.
- Reader body failures, final integrity failures, real summary-validation
  rejection, and input-initialization rejection retaining the original failure
  while all already-owned resources are attempted.
- Identity-probe cleanup preserving its original integrity error.
- Direct input close and all three directory walkers with a descriptor released,
  immediately reused for an unrelated `/dev/null` handle, then reported as a
  close error; the unrelated replacement remains open and is not retried.
- Final restore root/parent close errors independently and together, fixed
  ordinary-error/interrupt mapping, original-operation failure precedence across
  all reader and restore handles, and sanitized nonzero CLI reporting.
- Reader close failures after payload restoration recreating the incomplete
  marker, with private bytes retained and all final directories attempted.
- Marker recreation's own close error preserving the preceding restore failure.
- New-file cleanup attempting both data and parent fds while preserving the
  first write or close failure, and cleanup of a root fd whose initial stat
  fails.

The tests use a small independent `tarfile.PAX_FORMAT` fixture with opaque
payload bytes and a matching optional consistency summary. They do not execute
retained code or change native/acceptance fields.
