### F0 — Large dynamic labels preserve failures and coverage accounting

`governance_run._subtest_identity` changes only dynamic subtest-label representation. A label at or below 4,096 UTF-8 bytes remains its complete text. An oversized label is bound to SHA-256 over all UTF-8 bytes, with an explicit encoding discriminator and original byte count. Two labels with an identical 4,096-byte prefix and different suffixes therefore do not intentionally collapse through truncation. Repeated identical labels retain separate events and counts.

Canonical discovered test IDs and parent IDs still pass through `_identity`, with the unchanged 4,096-byte rejection. The new helper is selected only for `unittest.case._SubTest`; fixture and parent identity rules remain in effect. Discovery count, ordering, one-start/one-stop/one-success requirements, and all strict-success conditions remain unchanged.

A failing, erroring, or skipped large-label subtest is recorded before the corresponding superclass callback and still increments a non-success subtest counter. `finalize` rejects any such counter even if a later subtest succeeds. A counter or evidence-writer limit exception still propagates into the runner's abort handling and cannot become strict success. The changed `addSkip` uses the already generated bounded identity when replacing the superclass's retained test-object record, avoiding a second call to the canonical identity validator on an intentionally oversized dynamic label.

Negative-result records retain a description string and traceback text, rather than `_SubTest` or parent objects. `getDescription` emits the digest for oversized labels, so the label is not reintroduced as a retained description. The expanded existing lifetime test continues to check release while result/events remain alive and now covers all four oversized-subtest outcome forms. I did not rerun it; the parent owns the focused execution.

The twelve runner limit expressions are byte-for-byte equivalent as AST-unparsed expressions to HEAD: test count, canonical ID bytes, record bytes, log bytes, event count, Git/tool/source sizes, source time, and gitlink count. This review establishes bounded retained label representations, not a hard upper bound on all Python allocations: creating a subtest's `id()` and encoding it necessarily materializes transient data, and pre-existing traceback/skip-reason text behavior is outside this change.
