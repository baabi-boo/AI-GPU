## Why this is valid preservation

The normative evidence guide, `docs/project/evidence/README.md`, requires historical results to remain tied to their tested revision and contract and requires a corrected, reviewable record when an artifact changes. The acceptance policy requires preservation of tested source, raw results, scope and limitations; it prohibits presenting later work as the original successful execution. Neither rule requires a mutable working-tree path to remain frozen forever when its original bytes can be explicitly retained and independently verified.

This repository already applied that interpretation twice to this exact P05-A01 lineage:

1. `docs/project/evidence/p05-torch/a01-retained-binding.json` preserved four original source artifacts at inert retained locations, retained the original acceptance as its 58th artifact, and moved only the canonical P05-A01 evidence pointer. Its independent review is `docs/project/evidence/p05-torch/development/reviews/w03_a3.md`.
2. `docs/project/evidence/p06-serial-workspace/a01-retained-binding.json` preserved one additional original native-binding test while leaving the original and immediate predecessor unchanged. Its `a01-source-retention.json` binds both predecessors and the previous mapping. The review/proof is `docs/project/evidence/p06-serial-workspace/agents/w04_a01.md`.

I independently compared the second successor with its immediate predecessor. Their key sets are identical; the only changed fields are `artifacts`, `limitations`, `record_id`, `reviewer`, and `scope`. Within the artifact array, reversing only index 10's path restores the exact predecessor array. All five prior retained source files equal their original paths at accepted revision `e1420fd550f716df33a2556057b7086a03032cbe`. The current proposal is the same bounded operation for a sixth source artifact.

The checker is correctly detecting a real mismatch. `check_project._artifact` hashes the bytes at each selected artifact path. The remedy can preserve the old digest by giving the successor a stable retained path to the actual old bytes. Editing the old acceptance hash to the current test hash would instead make the historical execution refer to unexecuted changed source and is not acceptable.
