## Pin and archive behavior

`VORTEX_AI_BUNDLE` selects an external receipt only when preparing a fresh
source build. The builder calls `build_binding` and `read_manifest`, validating
source identity and every native artifact before creating the generated header.
It embeds the exact header namespace and six-artifact contract from the
**authoritative amendment** in `interfaces.md`. Unbound builds carry an empty
bundle pin and a populated source pin, per root's explicit clarification.
Other unbound metadata strings and all six artifact entries are empty.

The sdist custom staging command writes only inside its release tree:

- `python/p05_build/p05_build_config.h`
- `python/p05_build/source_inventory.json`
- `python/p05_build/manifest.json` for a bound archive

Offline sdist rebuild validates the exact canonical shipped inventory, receipt,
and deterministic header, and preserves the pin without the original bundle.
An optional external bundle must match the retained pin and pass full artifact
checks. Missing configuration, changed files/header, or a replacement pin fails.
Even an unbound prepared sdist cannot be silently rebound. Generated inputs are
excluded from the source digest to avoid self-reference. Normal builds do not
rewrite tracked source. Setuptools metadata/build directories remain ordinary
generated outputs; the final lightweight sdist command generated ignored
`python/vortex_ai.egg-info` in the working checkout.

The sdist uses an explicit release-tree allowlist, including `LICENSE`, so
setuptools/VCS discovery cannot pull unrelated repository assets into it. It
removes setuptools' generated `setup.cfg` from the archive because static
project metadata already lives in the inventoried inputs. Repackaging retains
identical header/manifest/inventory bytes. It refuses to reuse an existing
sdist staging directory.

Bound wheels receive build tag `1` plus the **complete** bundle SHA-256, at root's
request; the package/API version remains 0.1.0. Unbound wheels have no build tag.
Sdist filenames are still standard name/version filenames, so documentation
requires separate digest-named output directories for different pinned sdists.

A final correction handles stale setuptools output: Python sources are always
recopied; immediately before wheel archive creation the staged payload must be
exactly the three validated Python modules plus the extension, and the shipped
Python byte hashes must match the source inventory. Additional files, stale
Python content, and `--skip-build` are rejected. This prevents a reused
`build/lib` directory from silently invalidating the package's source claim.
