## Findings

1. The original direct `model_run.execute` path is incompatible with the
   unchanged P04 provenance auditor. Importing P05 before P04 snapshots helpers
   captures `ci/project/p05_execute.py` in P04 `LOADED_HELPERS`. A clean P04
   source snapshot does not include that file. The original auditor indexes
   `files[helper['path']]` and requires exact identity, so this packet fails.
   The dirty source checkout can mask this error by including untracked files.
2. Wrapping the original P04 CLI with another unchanged `run_bounded` monitor
   has a real cleanup race. Each inner command creates a new session/PGID;
   both monitors use a one-second TERM grace. Outer KILL can remove P04 before
   its inner monitor KILLs a TERM-resistant native child in the other group.
3. The minimal correction is two separate top-level workflow stages: unchanged
   P04 CLI first, followed by P05 consuming required existing native build and
   packet paths. This preserves accepted P04 helpers, reports, guards and
   process cleanup, and avoids adding a second controller or mutating globals.
   Root owns production/workflow changes; no P05 controller file was created.
4. A monitored producer subprocess would also wrap separately grouped metadata
   probes (`collect_source`/Git and header reproduction). The reviewed correction
   calls `p05_bundle.create_bundle` directly with an explicit validation receipt,
   before any new native build. Its individual metadata probes keep their own
   existing bounds; no outer process cleanup result is invented for validation.
