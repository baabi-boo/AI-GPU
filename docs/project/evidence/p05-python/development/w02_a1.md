## Implemented

- Nineteen specified private extension functions cover build identity, verified session creation/metadata/accounting/close, preallocated matmul handles and submission/wait/close/copied output/trace, preallocated fixed models and create/advance/close/copied output/trace/record, and the ten-case compiled inventory.
- CPython 3.12 C API and C++17 opaque typed capsules own unchanged `ManagedMatmul`, `MatmulOperation`, and `ManagedMlp` objects. No Python integer is interpreted as a pointer.
- Session creation calls native `verify_bundle`, then `load_runtime`, and constructs `ExecutionBinding` only from the returned verified copy. It calls compiled digest getters and does not include the generated build-config header, consult mutable Python verification callbacks, or expose qualification/profile overrides.
- All entry points retain the GIL, reject another interpreter/process or unsupported free-threaded Python, check Python signals around calls, and catch C++ exceptions. Capsule destruction in an inherited fork child intentionally abandons copied native pointers without calling runtime release or drain; the process owns that abandoned child memory until exit.
- Per-owner busy guards prevent reentrancy through buffer callbacks or finalizers. Native statuses and owner pointers are saved into preallocated handles before Python status/result allocation and post-call signal checks.
- Numeric inputs require exact `int`, reject bool/subclasses/negative/overflow, and cap each native wait at one second. Buffer validation requires rank-one, one-byte B/b/c format, positive packed stride, C contiguity, no indirect storage and exact extent. Read-only inputs remain valid; export views stay alive through synchronous native copying.
- Partial-error and timed-out operations remain in their original capsules. Retry success replaces transient timeout snapshots. Terminal session close failures are sticky; requesting session close prevents new submission/model creation. Empty handles may be explicitly closed, allowing recovery after a pre-submission Python failure.
- Matmul output is an independent little-endian FP32 byte copy, requiring complete success and exact observed output extent. Existing native dispatch JSON serialization is reused unchanged.
- Model input/reference arrays come only from exact compiled fixture lookup and must match the session format. Each model creates its own native context and copies trusted record metadata. Model output requires terminal complete success, explicit complete owner close, successful cleanup, actual-data validity, resource restoration, and successful observed native event profiling.
- Model trace and diagnostic record JSON reuse existing serializers. Per root's clarified decision, records may preserve incomplete/failing diagnostics without creating any P04_RESULT/PASSED markers; iteration must be 0/1 and match the model's poison. Calling model_advance after completed close returns the cached native result without new work.
