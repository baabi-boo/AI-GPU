## Recommendation

Add a P05-specific runner and workflow that reuse the unchanged P04 preparation and execution path for **SimX FP16 and BF16 only**, then build and test the copying Python package against those exact fresh native artifacts. Keep P04's four-variant workflow, predicates, native executables, fixtures, compiler validators, and accepted evidence unchanged.

The smallest coherent job is one hosted job that prepares both formats, runs `p04_execute.py run --backend simx --iterations 2` without a format filter, retains its ordinary packet, and continues in a new P05 runner. P04 already creates a separate fresh build tree for each format. The continuation builds the unchanged `ai_matmul` comparison executable in each tree, constructs a trusted single-variant bundle manifest for each format, builds **one distinctly pinned wheel per format from the sdist**, installs each wheel in its own fresh environment outside the checkout, and launches separate Python processes for FP16 and BF16. One variant remains permitted per process. This avoids a second cache restore/dependency setup while retaining exact distinct package and bundle identities.

Integration decision from `/root`: use one wheel per format, exact distinct pins and separate fresh processes/venvs; do not use a multi-variant manifest. Each wheel's embedded manifest pin and hash must be recorded separately. Two different pinned wheels must not be reported as proof that one wheel ran both formats.

This is evidence for the bounded plain-Python slice and potentially P05-A01 after its other obligations and review. It cannot complete P05-A02, P05-A03's framework matrix, or the whole phase. P01 vendor integration and the inherited DSP regression remain unaffected.

## Proposed runner sequence

1. Start from a clean source revision; preserve source, recursive submodule, toolchain and dependency identities. Run unchanged preparation with both SimX formats. Cache miss remains blocked with the existing cache-warming remedy; no whole-toolchain install or dependency rebuild is introduced.
2. Invoke unchanged P04 execution under its established limits, using fresh outside-checkout work/output directories. Require its successful process exit, complete command results and cleanup, both expected variants, the exact five cases per variant, two iterations and revalidated raw model logs. Do not accept a supplied `outcome=pass` field by itself.
3. In each generated variant's `tests/regression/ai_matmul`, build the unchanged application with the exact same `CONFIGS=-DITYPE=<format> -DOTYPE=fp32 -DKUNROLL=1`, bounded jobs and generated Makefile. Validate its own host/kernel/linker stamp separately and hash all new outputs. Building `all` supplies actual kernel build evidence as well as the host binary. Rehash P04's frozen shared artifacts after the extra build; any change invalidates reuse. Do not assume repeated make left the runtime untouched.
4. Use the P04-qualified module explicitly for the shared Python/native comparisons, or explicitly qualify/hash each chosen module if different modules are selected. An `ai_matmul` invocation can accept the P04 module through its unchanged `--module` argument. Never transfer qualification merely because two modules have the same filename or source name. Native comparator output must be tied to the module actually passed.
5. Construct a strict producer-owned bundle manifest from actual source/build/compiler/library identities, not caller-provided booleans. Retain the manifest and embed its SHA-256 plus native-source identity in the extension built below. Produce a separate single-variant manifest/pin for each format, as selected by integration.
6. Build the sdist from a verified source export/staging directory outside the live checkout. This avoids setuptools-generated `egg-info` or build files invalidating source stability. Check every packaged owner source/header/adapter/serializer against its selected source hash; reject missing members, path traversal, symlinks escaping the archive and unexpected source substitutions.
7. Expand that exact sdist into a new directory outside the checkout for each format and build the distinctly pinned wheel there with the pinned build environment. No include/source path may reach back into the original checkout or native build tree. Retain exact compiler/link commands, build-requirement versions and hashes, and the generated producer pin. Check the imported native owner sources are byte-identical to the accepted/current unchanged sources. Keep any generated pin material explicitly distinguished from source inputs.
8. For each format, install only its resulting wheel into its own fresh venv with no system-site-packages, no editable install, no ambient `PYTHONPATH`, and a fresh outside-checkout working directory. Use the installed interpreter's isolated mode for import/qualification. Check both Python module and extension `__file__` resolve inside that venv and verify hashes against the installed distribution and wheel contents. A source-tree import or a direct build-directory extension is not clean-install proof.
9. Demonstrate plain import succeeds without a native bundle/runtime present and performs no native load. Then run native loading and the exact execution matrix with the qualified external bundle. Use separate fresh processes for the two formats; retain stdout/stderr, exit/cleanup status and exact interpreter/package/bundle identities. Exercise the actual installed public API, not a source-only helper that bypasses it.
10. Rehash inputs/bundle/installed artifacts, retain failed attempts, reconcile exact expected observations and publish a P05 packet with `acceptance_claimed=false`. Independent review of numerics, package/build provenance and actual dispatch precedes any acceptance decision.

An extra build command may record a prospective kernel flag line even if only the host target was built. Do not count such a stamp as a second compiled kernel. The sequence above recommends `all` to avoid that ambiguity; alternatively a deliberately reviewed host-only comparison must bind the actual P04 module's kernel record separately.
