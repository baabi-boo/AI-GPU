## Additional native constraint independently confirmed

`ManagedMatmul::submit` creates a separate Queue per operation. Queue launch setup holds its
own `enqueue_mu_`, but `Device::cp_submit_dcr_write` posts each DCR separately through
`cp_submit_cl_`, whose device mutex covers one ring submission. The launch setup sequence
is therefore not serialized across queues. Root imposed one outstanding matmul per session.
Tests now reject a second submit before native queue creation, including after successful wait,
and allow sequential reuse only after explicit close. A rejected preallocated raw capsule can
be reused afterward. The historical two-orphan-operation success is intentionally superseded.
Public conflicts must be `BindingError(kind='state')`; raw native conflict is `BlockingIOError`.
