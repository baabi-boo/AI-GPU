## Implemented interface and trust boundary

The header was written first and communicated to root and the module worker. It defines exactly the amended `VerifiedBundle` metadata/module/library fields and the five requested functions: `verify_bundle`, the two compiled digest getters, `load_runtime`, and `loaded_runtime_paths`.

`verify_bundle` uses only `p05_build_config.h` namespace `vortex_ai_python::build` and its exact `Artifact`/six-row array contract. An empty compiled bundle pin fails with an actionable unbound-wheel message. It validates compiled digest formats, SimX FP16/BF16 metadata, exact artifact roles, canonical role paths, unique role membership, and bounded positive sizes. It hashes the exact manifest bytes against the compiled pin and every library/module against its compiled SHA-256 and exact size. Metadata is copied only from compiled constants; no Python callback or runtime JSON trust path exists. Build preparation remains responsible for validating the manifest schema before deriving those immutable constants.

Reads use directory descriptors, `openat`, `O_NOFOLLOW`, nonblocking opens before regular-file checks, and before/after file identity, size, mtime and ctime comparisons. Root ancestors, the lib directory, and leaf files reject symlinks. Relative roots are normalized through checked directory traversal. Limits are 4 MiB manifest, 16 MiB module, and 256 MiB per DSO; modules must contain at least 16 bytes. The lib directory must contain exactly the five declared regular DSO basenames, with no extra files, subdirectories or symlinks. It is checked before and after artifact hashing. The module is retained as the exact byte copy that was hashed. Failed verification clears the output owner.

`load_runtime` revalidates the bundle immediately before loading and again after successful dynamic loading. It requires ordered absolute library paths and the compiled backend, permits `LD_LIBRARY_PATH` only when absent or exactly canonical bundle/lib, rejects nonempty `LD_PRELOAD`/`LD_AUDIT`, and rejects conflicting `VORTEX_DRIVER`. It loads Ramulator, its extension, libvortex, simulator, then backend with `RTLD_NOW | RTLD_GLOBAL`. All 20 required runtime functions and the backend `vx_dev_init` entry are resolved eagerly. `dlinfo`, `dladdr`, and program-header enumeration validate actual paths; SONAME inspection also detects renamed foreign project libraries.

The initial load rejects any project DSO already loaded outside this binding, including a same-path object whose on-disk file might have been replaced. Repeated sessions through this binding remain permitted. A selected path set is permanent once loading begins, including after failure. Handles and the published function table remain allocated for process lifetime; no `dlclose` is called. Post-fork loader/wrapper use is rejected. Twenty exact-signature forwarding definitions are explicitly hidden even without a global hidden-visibility compiler flag.
