## Reusable controls

Import the helper from `ci/project`:

```python
runtime = build_test_runtime(empty_directory, dtype="fp16")
runtime.run_python(source, env={...}, timeout=30)
```

`TestRuntime` exposes `bundle`, `runtime`, `package_root`, `extension`,
`build_config`, `commands`, and `environment(overrides)`. `run_python` launches
a fresh process with the test package before the source checkout.

In that child:

```python
from p05_test_runtime import FaultControls
controls = FaultControls.activate(bundle_path)
```

Activation loads the bundle through normal native verification by opening and
closing a bootstrap session. It obtains ctypes control symbols using
`RTLD_NOLOAD`, then resets completed fake state. It never preloads a project DSO.

Controls include:

- `fail(name, occurrence=1, code=-1)`: one selected future occurrence, relative
  to existing call counts. Several distinct named failures can coexist.
  Canonical short names and exact `vx_*` function names are accepted.
- Creation/query: `device_open`, `query`, `memory_info`, `module_load`,
  `get_kernel`, `queue_create`, `buffer_create`, `buffer_address`.
- Submission/events: `enqueue`, `enqueue_write`, `enqueue_launch`,
  `enqueue_read`, `event_wait`, `event_value`, `profiling`, `work`.
- Cleanup: individual release names or `cleanup` across all releases. Fake
  resources are actually freed before the configured cleanup error is returned.
- `timeout(budget)`: finite incomplete-wait timeout budget, with resources
  retained. Completed events do not consume the budget.
- `async_failure(event_ordinal, code=6)`: propagate a failure from event 1–5.
- `select_case(name)`: the next successfully opened native device captures that
  immutable case; existing owners retain their own selection. Call before
  `session.model(name)`.
- `bad_address(0..3)`, `threads(count)`, `corrupt_response(stage, word=0,
  xor_bits=1)` for negative validation/model-comparison paths.
- `counter(name, owner=None)`, `counters`, `captures`, `assert_no_resources()`.
  `calls:<name>` returns call counts. `reset()` refuses live resources.

For FIRST-open creation failures, start a fresh child with the fake-DSO-only
`P05_TEST_INITIAL_FAILURE=device_open:1:6`. Attempt `Session.open` first, then
construct `FaultControls(bundle)` after the failing attempt loaded the runtime.
No production package code reads this variable or provides a bypass.
