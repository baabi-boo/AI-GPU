## Implemented contract

`create_bundle(*, source, build, native_output, fmt, destination)` returns the
exact manifest dictionary after creating the new destination. CLI arguments:
`--source-dir`, `--build-dir`, `--native-output`, `--format {fp16,bf16}`, and
`--destination`. CLI success prints manifest path, SHA-256, native binding ID
and `acceptance_claimed: false`; errors print `outcome: blocked` and exit 1.

The producer requires the currently executing source checkout and an unchanged,
completed, passing, nondevelopment P04 packet. It verifies:

- The same clean source snapshot before and after P04 execution, current source
  bytes, retained P04 source/helper bodies, the producer's loaded helper bytes,
  and the current dynamic `_bundle.source_inventory`.
- The immutable profile/fixture identities, complete frozen fixture selection,
  regenerated model adapter, and independently regenerated C++/Verilog config
  and types headers. It also rechecks generated build recipes/configuration.
- The original variant build path, actual live tool inventory against retained
  before/after snapshots, native command completion/cleanup and raw-log hashes,
  configure/build/model argv and environments, separate actual runtime,
  backend, kernel and host stamps through `p03_execution_records.validate_records`,
  and effective-header records through the existing validator.
- Every current native build/dependency artifact against the original P04
  binding and report. The unchanged binding is independently rehashed with the
  existing `qualification_id` function; its `size_bytes` records stay unchanged.
- All five selected-format cases in fixture order with both output poisons.
  Each raw model log passes the unchanged P04 verifier and must reproduce the
  report's observations. A plausible `pass` field alone cannot qualify a bundle.

Exactly the five DSOs and kernel are copied byte-for-byte into `_bundle.ROLES`.
Manifest fields and canonical serialization come from the shared `_bundle`
contract; newly introduced artifact rows use `size`. New outputs, regular files,
strict UTF-8 JSON, duplicate-field rejection, relative contained references,
symlink rejection, bounded reads, file inode/size/time stability and repeated
source/build/packet/tool verification protect the copy boundary. Inputs remain
separate from outputs. Existing destinations are refused. A copy/publication
failure leaves no qualified manifest; partial unqualified output is not reused.

The producer preserves the existing trusted-builder and non-adversarial-filesystem
boundary. It does not authenticate arbitrary fabricated reports/native binaries,
replace independent review, prove installed Python dispatch, or accept P05.
