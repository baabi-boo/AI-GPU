## Host prerequisites fail closed

The hook controls require an actual host C++17 compiler with UBSan. Their class
setup selects `g++` or `clang++`, then compiles the actual wrapper with controlled
processor fixtures using strict warnings, `-Werror`, undefined-behavior sanitizer
and nonrecovering sanitizer behavior. Missing compiler raises `RuntimeError`;
compile failure raises `AssertionError`; command timeout or unsuccessful scenario
execution fails the suite. None is converted into a skip.

The probe host tests use the existing Make-based fixture generator. It requires
Make and a host C++ preprocessor (`g++` or `c++`) and raises on their absence. Its
native compiler variables point to an explicit failing sentinel; only configured
stamps, dry-run command text and host preprocessing are admitted. Host commands
use the existing bounded supervisor, so tool/resource/cleanup failure raises an
assertion. External probe compilation/execution receipts in these unit tests are
mocked and are not native SimX evidence.

A useful distinction is retained: **the governance-tier preflight requires Git;
it inventories Make and host C++ as optional.** Therefore a green preflight step
alone does not certify compiler presence, UBSan support or executed controls.
The mandatory class setups supply the actual fail-closed checks when discovery
runs. The original completed suite log is still required before reporting their
hosted execution. This is unchanged prerequisite behavior, not a weakened gate.

The parent-sensitivity CLI deliberately remains separate from standard shallow-
checkout discovery. It requires a historical Git revision and was executed in
its independently retained local comparison; the eleven normal hook methods
need only current sources. Excluding that explicit historical CLI from discovery
does not remove any of the 80 discovered methods or imply a new hosted parent
comparison.
