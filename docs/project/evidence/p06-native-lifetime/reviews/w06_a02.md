## Input-boundary conclusions

- `p06_native_lifetime_records._split_output` requires an exact string, strict
  UTF-8, a complete output at most 16 MiB, no raw CR/NUL, a terminal newline,
  exactly one literal lifetime marker, and a final line beginning with its
  complete marker-plus-space prefix. It removes only that line and preserves
  every byte of the original prefix for the unchanged parent verifier.
- The actual sidecar JSON decoder is
  `p06_managed_preflight_contract.decode_record`, which bounds the record to
  512 KiB and nesting to 16 before decoding. It rejects duplicate **decoded**
  keys, floating/exponent/nonfinite numbers, oversized integers, invalid UTF-8
  and unpaired escaped Unicode. It uses the standard JSON decoder's complete
  document requirement; a second value or a suffix outside the root cannot be
  silently discarded. This route does not use the generic packet decoder's
  more permissive numerical policy.
- `fields` admits exact object field sets. `fixed` recursively compares exact
  Python types before values, so 0/1 cannot stand in for false/true, and false
  cannot stand in for an integer. `uint` independently requires exact `int`
  and its declared width. Signed architectural `gp` is bounded separately to
  native signed 32-bit values. Decoding a general signed storage minimum does
  not admit that value to an unsigned or signed 32-bit field.
- The sidecar's identity and route are compared with the independently
  supplied invocation. All seven claim fields require literal JSON false;
  the exact three-item unresolved-obligation list remains mandatory. Model,
  run, snapshot, read and destruction fields are exact, with fixed array
  populations and semantic checks after decoding.
- Successful validation of the entire original v1 prefix precedes admitting
  the lifetime object. The sidecar cannot replace bad numerical, completion,
  owner, raw-read or loaded-library evidence. Default v1 interpretation is
  unchanged. A moved new marker before warm operations is rejected by the
  old reader's reserved-marker route, even when its original final marker and
  success sequence are otherwise preserved.
- The reader handles retained data as data. It does not execute retained
  commands, import recorded code, or open transcript library paths. Coherent
  synthetic transcripts can pass, as expected for semantic validation; this
  is not producer authentication or an independently complete archive reader.
