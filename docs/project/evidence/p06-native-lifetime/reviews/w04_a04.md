## Compile and link analysis

The probe revalidates the actual runtime, model and application stamps using
`p06_managed_preflight_build.validate_records` before reusing model flags.
`probe_flags` removes the single exact model `-MF` target and exactly one each
of `-MMD` and `-MP`; it leaves C++17, strict warnings, PIC, optimization, the
checked-counter guard, format/profile macros and ordered include directories
unchanged. That is appropriate for compiling a separate translation unit
against the matching model's `Core::PerfStats`, `PerfCounter`, `SimPlatform`
and generated `VX_config.h`/`VX_types.h`. The source explicitly rejects a
functional kernel, wrong XLEN, multiple workers and CP-on-LLC.

The executable's `Processor`, RAM and Core references require `libsimx.so`, so
normal linker as-needed behavior does not discard that dependency. `-pthread`
and `-ldl` accompany the link. The already validated production model's link
retains both Ramulator libraries, including the extension via its existing
no-as-needed group. The probe does not recompile or replace those libraries.
Absolute build rpath plus a fixed three-directory `LD_LIBRARY_PATH` select the
completed live products; the source callback rejects absent/duplicate library
names and the Python reader compares the emitted paths to that live build's
fixed paths. It does not execute stamp text as shell commands.

Both executables compile the same source. Only the separate always-zero probe
translation unit receives `P06_PENDING_FORCE_ZERO=1`; model storage, model
objects and the managed measurement executable are unchanged. Compiler identity,
model products, source/dependencies and logs/executable bytes are checked before
and after the bounded commands. Dependency compilation provenance remains
explicitly unresolved rather than inferred from these hashes.

## Execution and pending-read analysis

The three-word program is the existing checked-counter native completion
program: ADDI x3,x0,imm12, WSYNC and TMC x0. Masking the requested signed `gp`
into 12 bits correctly encodes both `7` and `-1`; normal RV64 immediate sign
extension yields the intended observed register. The code checks `gp` as data
and calls the actual void `run_checked()` API without inventing a status value.
The 19 launch DCRs reproduce the known native descriptor; KMU descriptor fields
survive reset, so the subsequent checked call has a valid second launch.

A 4 KiB RAM contains the 12-byte program at address 256. RAM is constructed
before Processor and therefore destroyed after it. Each context returns before
the next starts, preserving one live process-global platform. No processor
state is read after destruction.

The getter forwards directly to the owned `perf_mem_pending_reads_`. Existing
request delivery increments that field for reads and response delivery
decrements it; the getter neither seeds nor mutates it. The first stepped run
must encounter actual instruction-fetch traffic. Each sample is from the host
between complete timing-model ticks. Drain uses both `!any_running()` and
`SimPlatform::idle()`, including registered/deferred traffic, rather than the
`cycle()` return alone. The positive observation is mandatory and final pending
is checked zero before the second reset-bearing call. In the always-zero
executable, real model traffic still runs and drains, then the exact positive
observation assertion fails. A compiler/link error, timeout, wrong `gp`, other
assertion or crash cannot count as that expected failure.

Repeated getter samples compare the same selected snapshots before, between
and after reads. This is a bounded observation of those fields, supported by
the static direct-read implementation; it is not an exhaustive dynamic proof
of every model field. No timing path, arbitration or update rule is changed by
the accessor and no parity/performance result is claimed here.
