## Runner coverage

The lifetime harness extends the existing `ManagedHarness`, redirects the new
mode's small fixture directory to the system temporary directory, and simulates
external configure/build/process commands. It executes the real lifetime entry
point, shared orchestration, parent record verifier, and lifetime record verifier.

The positive case verifies all four processes, 132 launches, and 4,224 checked
words; the complete existing counter totals; the distinct lifetime descriptor,
report identity, and nested build/process SHA bindings; explicit leading
`--lifetime` on all four native command vectors; sidecar and parent false claims;
all seven false report claims and three unresolved obligations; retained evidence
hashes; and lifetime helper import before helper/source identity freeze. Separate
tests inspect the real helper inventory and real source snapshot extra-file hashing.

Negative cases remove the sidecar, report a pending read, change its contract
version, or mutate source/build products after a native command. Each attempt
fails after the original first process with no retry. Further cases combine exit
37 with later source or product instability and verify that both the original
native error and final stability failure are retained.

Compatibility checks launch a fresh isolated Python process to ensure the
default preflight import loads no lifetime modules, and execute the default
runner to ensure its report fields and command vectors have no lifetime selector.
