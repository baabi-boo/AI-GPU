## Runtime constraints that the implementation must preserve

`Processor::run_checked()` returns `void` and directly invokes the implementation without interpreting legacy x3/`gp`. A nonzero `exitcode`, including `-1`, must remain a recorded register observation, not a newly invented execution failure. `sw/runtime/common/async_run.h` collects exceptions through `future_.get()` and makes processor failures terminal. Instrumentation must preserve the original thrown error and must not convert failed asynchronous work into a completed successful pair.

`sw/runtime/ai/runtime.cpp` has one process-wide managed-context reservation, a sticky cleanup-error state, and a per-context operation lease. The lease survives successful wait and is released only by completed healthy close. `MatmulOperation::release()` releases events and the queue before buffers and lease; `Queue::~Queue()` joins its worker before unregistering and releasing the device. The terminal witness must bind to that actual ownership sequence. An observer mutex alone does not establish general multi-queue, raw-runtime, or multiple-runtime-copy concurrency support.

`Device::~Device()` quiesces CP before releasing its ring and completion buffers. Observe the live processor immediately before its actual destruction and observe only surviving platform state afterward. Cleanup that discards unfinished state cannot repair an earlier invalid balance. Keep clocks comparable only within one reset generation because full reset rewinds the platform clock.
