## Exact 38-scenario coverage

The Python `cases()` method starts a new subprocess for every scenario and
requires exit zero, the exact `PASS <case>` stdout and empty stderr. Each
process therefore receives fresh static observer and fixture state.

| Property exercised | Fresh scenarios | What the assertions detect |
| --- | ---: | --- |
| Complete 33-run success and legacy gp | 2 | Run admission/completion, exact reset increments, pending zero, gp7/-1 and terminal destruction observation |
| Default v1 isolation | 1 | 34 real runs remain allowed; deliberately nonzero pending state is not queried or newly enforced |
| Before-run guard | 4 | Pending, idle, running and exhausted-reset violations reject before the real reset; pending is not erased |
| After-run guard | 5 | Pending, idle, running, skipped reset and extra reset fail after a returned real call while retaining completed/exception evidence |
| Run exceptions | 6 | Standard, nonstandard, secondary-observation, overflow, underflow and negative-operand errors retain the original exception and classification |
| Read exceptions | 4 | Standard, nonstandard, secondary-observation and typed overflow remain errors with original exception identity |
| Raw/flush pending boundaries | 4 | A pre-read violation prevents the real call; an after-read violation retains the completed call and observed nonzero balance |
| DCR status/absent reply | 3 | Negative status is preserved and a successful status without a reply still records failure |
| Trace capacity | 3 | The 34th run or 513th raw/flush read never enters the real operation; overflow is sticky and out-of-range exports fail |
| Ownership/mode lifetime | 4 | Late or duplicate enable, unrelated owner and replacement construction cannot create a valid lifetime |
| Destructor observation failure | 2 | Nonzero pending and secondary observation failures still invoke disposal once and never read dead processor state |
| **Total** | **38** | **11 unittest methods** |

The fixture's `observe()` explicitly increments `dead_queries` and throws
when the processor is no longer live. Successful and failed disposal checks
assert that this count remains zero, making the dead-object test observable.
`expect_original()` checks the actual standard message, sentinel payload or
checked-counter reason; catching any arbitrary exception is insufficient.

The harness contains a write-exception dispatch branch, but the 38 scenarios
do not invoke it. I did not count it as executed coverage. Likewise, the
capacity checks exercise storage capacity512, while successful transcript
population264 raw reads/33 flushes is enforced by the separate reader tests.

## Probe host tests have useful but separate sensitivity

The 30 methods in `ci/project/test_p06_pending_probe.py` use real Make-generated
configuration stamps and actual file hashing. `ProbeHarness` replaces external
process execution, source checkout collection, loaded-helper enumeration and
resource availability; synthetic products and output records are deliberate.
Its successful mocked receipt is therefore not native execution evidence.

These methods materially check exact output shape, all required context field
types, bounded positive observations, gp ordering, final drain, library paths,
complete JSON framing, exact mutation failure, live compiler/product/source
identity, forbidden flags, fixed resources and retained failure stability.
A timeout, crash, arbitrary nonzero exit, missing cleanup, missing process,
wrong assertion, extra successful context or extra pass record cannot qualify
as the expected always-zero failure. The repaired trailing-wrapper-field bug
has explicit malformed object and list regression inputs.

The real C++ probe's `read_pending()` mutation returns zero only in its
separate translation unit. Its positive path uses the actual accessor and
requires `maximum > 0 && positive_samples > 0`; its negative build must reach
that specific failed assertion after a drained stepped launch. The host
checks validate the runner and parser around this experiment. Actual native
compile/link/run and independent original-artifact review are separate proof
obligations; that artifact was not inspected in this assignment.

The native repeated-read snapshot covers its explicitly listed model fields
and pending return values, not every byte of model storage. Source inspection
of the accessor and the still-open all40-component qualification remain
necessary; no broader read-only or counter-qualification claim is inferred.
