## Behavioral review

### Accessor: actual owned state, no model mutation or scheduling

`Processor::pending_mem_reads() const` delegates to the owned implementation.
The implementation returns `perf_mem_pending_reads_` directly as `uint64_t`.
The ordinary `PerfCounter` is a `uint64_t` alias. The checked implementation's
conversion is `constexpr operator uint64_t() const noexcept` and returns the
stored value without checks or mutation. There is no truncation at RV32, no
signed conversion, and no new configuration-dependent branch in the accessor.
This is static source evidence for ordinary/checked, RV32/RV64 and the existing
kernel variants; it is not a claim that every variant was rebuilt.

The processor diff adds only this observation surface. Existing request-side
`perf_mem_pending_reads_ += !req.is_write()`, response-side decrement,
latency accumulation, and reset-to-zero statements are untouched. No new tick,
reset, flush, allocation, callback, or simulated communication occurs in the
getter. The host observation surface does not cross from one simulated module
to another and introduces no threading vocabulary into SimX model source.

The distinction between host and model contexts is explicit in the SimObject
and architecture rules: host code may read model state between ticks, with
workers parked. Here the hooks retain their existing mutex across actual run
and DCR calls. Their mode is compiled only for checked, timing, RV64, one-worker
execution. The admitted runtime path uses one owned processor and exclusive
submission. `run_checked()` is entered on the runtime's host execution worker;
before/after observations are outside its tick loop. The native probe calls
the getter only before or after an individual `cycle()`/`run_checked()` returns.
This is compatible with the Cardinal Rule. The getter is not a new thread-safe
promise for arbitrary concurrent calls from model components.

Relevant unchanged ownership source was inspected: the native backend's
destructor joins its async run before member destruction; queue destruction
joins its worker before releasing the device; direct-RAM command-processor
transfers do not tick the model. These paths support the admitted host boundary,
without turning a completed wait alone into permission to release all ownership.

### Before reset, after return, and original exception preservation

For lifetime mode the run wrapper allocates its bounded record, observes the
actual before-state, and checks live/idle/not-running/zero-pending before calling
the reset-bearing real function. A nonzero pending balance cannot be erased by
the real reset and then rehabilitated. An exhausted reset generation rejects
before the call, avoiding overflow in the required `before + 1` comparison.
After a real return, it captures the actual after-state, requires drained state,
and requires exactly one reset-generation increment.

`real_call_entered` is set immediately before the real void call. `completed`
is set only when that call returns; it deliberately remains true if a later
observation or guard fails. The catch then sets `exception=true` and increments
error accounting. Thus `completed=true, exception=true` records a returned
call followed by wrapper failure, not success admission. A real execution
exception leaves `completed=false`. A pre-call rejection leaves both
`real_call_entered` and `completed` false.

The native function returns void and discards its implementation's legacy gp
result; the new code does not invent an integer success status. Successful gp
values 7 and -1 remain valid recorded architectural values.

Both failed-run and failed-read observation helpers are `noexcept` and catch
secondary sampling errors. They count those errors and return to the outer
catch's bare `throw`, which preserves the original exception object/type.
Checked overflow/underflow/negative-operand errors retain their reason-specific
counters. Standard and nonstandard execution exceptions cannot become success.

The application consumer's `observation()` rejects any run/read/write error,
checked-counter error, unexpected error, or violation. Final count and overflow
checks also precede witness emission. Constructor/destructor sampling failures
increment sticky errors; later cleanup cannot clear them. A nonzero raw DCR
status or missing output storage remains a recorded failure even when the real
read call returned. The default-mode DCR catch path gains the same original-error
preservation instead of risking replacement by a secondary sampling error.

### Bounded traces and explicit mode

Lifetime selection is rejected if repeated, after construction starts, while
a processor exists, or after a run entry. State defaults leave lifetime mode
disabled. Pending getter calls and new before/after drain guards are gated by
that flag. The default path does not allocate run records or impose the 33-run
capacity; compiled controls exercise 34 default-mode runs with a deliberately
nonzero controlled pending value and zero pending-query calls.

The run trace checks `count >= 33` before indexing and before the next real
call; it sets overflow plus a persistent violation. Both existing read traces
check `count >= 512` before indexing. Export of run entries checks both populated
count and fixed capacity. Read counts cannot advance beyond their checked
capacity. No partial favorable prefix can meet the final mode/count/error rules.

### Destruction

The only new pending observation in destruction occurs before the actual
destructor, while the hook still owns the live processor. Observation failure
is recorded without preventing the real destructor from running. After it
returns, the wrapper inspects only the platform's clock/reset/idle services,
sets the stored pointer to null, and clears the live flag. It does not query
processor/core storage after destruction. The compiled fixture explicitly
counts dead-processor observations and checks actual destructor count one,
including failed pre-destruction observation cases.

### Native accessor property source

The separate native probe constructs real RAM and Processor objects, programs a
small actual instruction stream, and steps the real simulator. It does not
write the pending counter or inject model pending values. It requires at least
one positive pending sample and final zero, repeats the getter around unchanged
model-state snapshots, checks drained state, and uses contexts for gp 7 and -1.
The direct-RAM, checked, timing, RV64, one-worker assertions constrain its scope.

The always-zero control replaces only the probe-side read operation through a
translation-unit define; it requires the exact positive-sample failure. It does
not alter the admitted library. This property would reject a production getter
that always returned zero. The snapshot checks cover the explicitly recorded
clock/reset/core/legacy/running/idle fields; they do not claim to discharge the
separate all-40-component lifetime obligation. Probe source review is not
native execution evidence.
