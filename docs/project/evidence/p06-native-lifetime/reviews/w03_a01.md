# W03-A01 — compiled lifetime-hook controls

## Implemented scope

Added only the assigned test module and controlled fixture directory:

- `ci/project/test_p06_native_lifetime_hooks.py`
- `ci/project/fixtures/p06_native_lifetime_hooks/core.h`
- `ci/project/fixtures/p06_native_lifetime_hooks/processor.h`
- `ci/project/fixtures/p06_native_lifetime_hooks/harness.cpp`

The tests compile the actual `tests/regression/ai_counter_preflight/hooks.cpp`
and its actual header with controlled Core/Processor implementations. They use
the production `sim/common/perf_counter.h` exception type. Compilation uses
C++17, `-Wall -Wextra -Werror`, UBSan with recovery disabled, and pthread support.
Each scenario runs in a fresh process, preserving the hook's single-lifetime
contract. Builds use temporary storage and require no simulator toolchain,
submodule initialization or GPU build.

The test module's default discovery path does not invoke Git or depend on parent
history. Its separate `--parent-control` entry point makes an explicit comparison
against a caller-selected full Git revision and retains source hashes and exact
compile/run observations.

## Executed candidate result

Command:

```sh
python3 -B -m unittest discover -s ci/project -p test_p06_native_lifetime_hooks.py -v
```

**11 test methods passed in 1.314 seconds**, with 38 controlled fresh-process
scenarios and no skips, errors or failures. Original log:
`/tmp/ai-gpu-native-lifetime-dfd857-work/w03_a01-tests.log`.

Covered behaviors:

- Full 33-run traces with successful legacy `gp=7` and `gp=-1`.
- Default v1 execution performs no pending queries or lifetime enforcement and
  remains usable beyond the lifetime trace's 33-run capacity.
- Nonzero pending balance, non-idle state, running work and exhausted reset
  generation reject before a real reset-bearing call.
- Nonzero pending balance or running/non-idle state after a returned call, and
  skipped or extra resets, preserve the actual return observation while marking
  the lifetime invalid.
- Standard and nonstandard real execution errors, all three typed checked
  counter errors, and secondary observation errors preserve the original
  exception instead of silently succeeding or replacing it.
- Raw MPM and flush reads reject pending balances on either side; nonzero DCR
  status and absent reply storage remain errors.
- Run and both read-trace capacities reject before another real operation and
  reject out-of-bounds exports.
- Late or duplicate mode selection, wrong ownership and replacement processor
  construction cannot rehabilitate a lifetime.
- Invalid destructor observations still execute the real destructor exactly
  once. The fixture detects any observation of a dead processor; none occurred.

The fake platform starts at reset generation 11, so these controls do not rely
on the historical native baseline's particular reset-generation value.

## Limits and integration

These are compiled host-wrapper controls with a controlled processor. They do
not execute native SimX, validate the new production accessor against real
memory traffic, establish a no-wrap bound, or qualify performance. The separate
native accessor probe and four-process managed execution remain necessary.
No production source, contract, workflow or existing test was changed by this
assignment; no commits or pushes were made.
