## Recommended bounded host fixture

Add a dedicated fixture that compiles the **actual** `tests/regression/ai_counter_preflight/hooks.cpp` against small test-only `core.h`/`processor.h` headers and actual `perf_counter.h`. Define the five `__real_*` Processor symbols locally, and invoke the production `__wrap_*` functions. Keep native typedef/configuration stubs explicit and fixture-only. Use serial processes: the actual hook singleton permits only one processor lifetime, so do not introduce a production reset API just to reuse it across cases.

Required cases:

| Case | Controlled real operation | Required observation |
| --- | --- | --- |
| Valid pending zero | Real run increments reset generation once, then completes idle | Exactly one complete before/after pair and one reset, pending zero at both boundaries |
| Pending one before run | Real run would clear pending before doing anything else | Wrapper rejects **before** real call count or reset generation changes; pending remains one; invalid lifetime remains invalid |
| Pending one after run | Real run returns with pending one | Actual call occurred, but witness cannot be successful |
| Legacy `gp=7` and `gp=-1` | Real checked run returns `void` normally | Success is retained with exact observed legacy register value; no fabricated status interpretation |
| Typed/standard/nonstandard exception | Real call throws | Original exception/type is rethrown; no completed pair; failure accounting is visible |
| Failure plus observation failure | Real call throws, post-error state getter also throws | Original execution failure is preserved rather than replaced by observation failure |
| Exact capacity | Submit 33 valid pairs, then a 34th | The extra run is rejected before real entry/reset or out-of-bounds write; overflow/violation makes lifetime incomplete |
| Wrong owner | Call run/read with an unowned Processor pointer | Reject before any real operation |
| Flush/read pending | Return one at before/after flush or MPM observation | Exact boundary is retained/rejected; failed DCR status cannot look successful |
| Destruction | Real destructor marks storage dead | Live observation occurs before it; platform-only post-state afterward; no getter reads destroyed storage |

Compile with ordinary warning/error policy and UBSan, and use the existing 1 GiB host-test RSS/disk reserve. Avoid source-text-only checks as substitutes for the executed wrapper behavior.

## Recommended native getter control (hosted, separate from measurement)

Build a small standalone `tests/unittest/...` executable against the normal seed-free production `libsimx` and the same generated RV64/p02-tfr/PERF=1/one-worker/direct-RAM headers. Do not use diagnostic access objects, writable counter references, or special counter limits. It can use the three-word scalar program and descriptor above, with `Processor::cycle()` instead of `run_checked()` so the host can observe transient reads between real ticks.

1. Create real RAM and Processor, attach RAM and install the scalar launch descriptor. Initial pending balance must be zero.
2. Step a bounded number of cycles (a reviewed finite limit such as 200,000; fail on exhaustion). Between explicit calls to `cycle()`, read the getter twice. Snapshot platform cycles/reset generation, `any_running`, and core cycles/instructions around those reads; require equality. The getter itself must not change these observations.
3. Require at least one real observation greater than zero. Instruction-cache misses already issue real memory requests through the production callbacks (`processor.cpp` memory request/response wiring); a constant-zero accessor therefore fails this test.
4. Require a later drained state with no running core, platform idle, pending zero and the expected legacy `gp`. A direct zero before the first tick alone is insufficient.
5. Repeat with a fresh context and `gp=-1`; a normal checked launch can be separately used to confirm the legacy-value semantics. Exact positive pending values or clock constants should not be guessed; bind measured results to the actual configuration.
6. Optionally compare ordinary and checked builds of this same tiny probe with the same inputs. Counts/results must agree; this is supplemental model equality, not physical or RTL evidence.

The accessor test reads actual request/reply transitions without seeding measurement storage. Its probe is a different executable/process from the four managed preflight processes, so keep its counts and scope separate. Existing managed native matrix continues to prove the full 33-run wrapper path.
