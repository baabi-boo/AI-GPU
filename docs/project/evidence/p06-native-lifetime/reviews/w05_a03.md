at the two committed dependency revisions through the connected GitHub reader.

**Recommendation:** after the new native lifetime original has passed independent
review, implement a separately versioned dependency-build provenance packet. Its
first useful result is a fresh, bounded build of the three selected dependency
products with complete transitive source, compile, archive/link and loaded-product

This is a prerequisite plan, not an implementation or a finding that invalidates
the current lifetime contract. That contract explicitly preserves the unresolved
dependency obligation. A successful next packet must still leave full

## What the current chain establishes

`ci/project/p02_matrix.py:DEPENDENCIES` names exactly these reused inputs:

1. `third_party/softfloat/build/Linux-x86_64-GCC/softfloat.a`;
2. `third_party/ramulator/libramulator.so`;
3. `third_party/ramulator_ext/libramulator-vortex.so`.

`p06_managed_preflight_execute.py:execute` retains their bytes and descriptors,
checks before/after stability, includes their hashes in each build binding, and
builds a fresh model per format. `p06_managed_preflight_build.py` admits exactly
43 model translation units, four backend translation units and the model/backend
link commands. `_model_libraries` fixes the SoftFloat archive path, Ramulator
search/rpath, and the extension's `--no-as-needed` linkage. The native transcript
observes five selected dynamic-library paths; the runner binds those paths to
the retained products. These are useful product-identity connections.

The missing edge is how the three dependency products were produced. The build
validator explicitly returns `dependency_compilation_provenance_verified=false`.
`p04_ci_prepare.py` restores cached dependencies and identifies them; it does not
rebuild them. The workflow's dependency-cache key hashes `third_party/Makefile`
and `.gitmodules`, while `.gitmodules` contains URLs rather than the gitlink
revisions or Ramulator's transitive fetched commits. A cache key and a final
library hash cannot replace source-to-compilation evidence.

The fourteen-source runtime stub deserves an explicit join in the new contract
as well. `sw/runtime/stub/Makefile:SRCS` builds `libvortex.so`, and
`tests/regression/common.mk` invokes that build before the app. The present
`validate_host_build` selects and checks the final `ai_counter_preflight` command;
it does not separately admit the stub's complete compile/link command inventory.
Its output is retained, hashed and observed by the loader, but those later facts
do not by themselves prove the preceding compile inventory. This is a remaining
provenance obligation, not a current lifetime-validation failure.

## Smallest implementable route

1. **Freeze a versioned contract and lock first.** Name the three products,
   complete source/build-input closure, exact source/object/archive membership,
   supported compiler/configuration, product installation paths and allowed
   command grammar. Inventory helper scripts and their transitive local imports
   before execution. Add dedicated preparation rather than changing the meaning
   of the existing cached-input preparation contract.

2. **Create a fresh, isolated dependency workspace.** Use selected immutable
   source trees, no prior objects, archives, libraries, CMakeCache or populated
   binary directory. Use no compiler cache. Resolve all network inputs before
   freezing the source snapshot; the compilation phase must use those exact
   local trees without fetching or updating them. Existing pinned toolchain
   restore can remain an identified input; rebuilding the entire compiler is
   outside this task.

3. **Build SoftFloat from its complete reviewed Make inventory.** Preserve
   `SPECIALIZE_TYPE=RISCV`, `SOFTFLOAT_FAST_INT64`, `-fPIC`, round-odd, inline level
   5, the two fast-division flags, and `THREAD_LOCAL=_Thread_local`. The upstream
   Makefile hardcodes `gcc` in `COMPILE_C` and `ar` in `MAKELIB`: merely passing
   `CC=` is insufficient to select a compiler. Either use a reviewed exact
   recipe override or a controlled PATH with separately verified actual tools,
   and retain the command/tool relationship. Record every successful source-to-
   object command and object hash, then exact archive member names, order and
   bytes. Reject thin archives, duplicate members and unlisted/stale objects.

4. **Build Ramulator and its static inputs once.** Preserve Release, PIC,
   C++20, and the selected yaml-cpp/spdlog settings. Explicitly fix shared/static,
   external-fmt, tests/examples, and fetched-source selections; retain CMake
   cache, generated build graph, compile database, actual verbose command
   receipts, depfiles/header closure, all objects/archives, and link commands.
   A compile database describes intended commands; it is not evidence that they
   ran. Bind its source/object map to successful observed execution and produced
   bytes. Use the same resulting dependency products for both format model builds.

5. **Compile and link the existing extension.** Preserve its reviewed C++20,
   `-O3 -DNDEBUG -fPIC` recipe and exact Ramulator/spdlog/yaml include roots.
   Bind `GDDR6.cpp`, included headers, `gddr6.o`, the actual link command and the
   just-built Ramulator bytes to the final extension. A dependency file or
   equivalent header-closure receipt is needed; the existing extension recipe
   alone does not produce one.

6. **Stage only verified products and required headers at the current canonical
   model input paths, then freeze those inputs.** This preserves the existing
   model's exact path and loader expectations. Build in fresh owned workspace
   copies: upstream Ramulator explicitly puts its shared library in its project
   source directory, and SoftFloat expects a local `platform.h`. Bind those
   workspace copies to the selected immutable source trees, use separate binary
   directories, and install by exact byte equality into a fresh measurement
   checkout before its source snapshot. Do not overwrite a user's existing build
   or pretend those upstream output conventions are fully out-of-tree. A future
   explicit dependency-root option is an alternative requiring its own reviewed
   model/link contract change, not an implicit path substitution.

7. **Join to a new managed build without weakening its current checks.** Bind the
   dependency receipt digest into the format build bindings. Retain all 43 model
   objects, actual model static-link evidence, the SoftFloat archive identity,
   Ramulator/extension dynamic requirements, and exact backend/app/stub build
   records. Include the fourteen-source stub command. Link-map or linker-trace
   evidence should bind the actual selected SoftFloat members and static yaml/
   spdlog objects; merely hashing a library beside the linker is insufficient.
   Continue to observe and hash the five selected loaded libraries in the real
   processes, with unchanged path/duplicate/substitution rejection.

8. **Retain and independently replay the complete original.** The reader remains
   inert: strict bounded schemas, no imports or commands from the archive, and
   caller-pinned source/contract expectations. Successful receipt validation is
   evidence consistency, not execution. Actual execution still requires the
   original hosted job and its complete numerical/lifetime records.

## Negative controls that make the new edge meaningful

Require specific failures for: a favorable cached `.so` with no fresh compile
receipts; changed gitlink or transitive source commit with the same cache name;
dirty/ignored source or header substitutions; populated CMakeCache/build objects;
unexpected fetch/update after freeze; omitted, duplicated or reordered required
compile/archive entries; wrong SoftFloat specialization or non-TLS flags;
unapproved external fmt/shared dependency; mismatched compiler/archiver/linker;
an arbitrary successful echo log without corresponding fresh products; an
archive member swapped after compilation; a library changed between dependency
build, model link and launch; old SoftFloat input selected by the real model
link; and an alternate Ramulator found by the actual loader. Preserve the first
build failure and retained logs when final stability checks also fail.

At least one end-to-end sensitivity control should use a freshly built known
different dependency product whose numerical smoke still succeeds, while the
provenance checker rejects its source/recipe/product mismatch. This demonstrates
that favorable numerical results cannot fill the missing provenance edge. Keep
any mutation out of the admitted measurement build.

## Resources and acceptance boundary

The existing dependency recipe contains nested `make -j4`; outer `MAKEFLAGS=-j2`
does not cap that explicit command. The new route must use bounded nested build
parallelism (two jobs), the existing process-group supervision, 15 GiB disk
reserve, 4 GiB RSS budget, single simulation worker and bounded time/log limits.
`run_bounded` is a polled process-group budget, not a cgroup or malicious-process
containment guarantee. If fresh build/retention does not fit, report a resource
block and review a narrower retention design or different provisioned host;
do not silently weaken the budget. No local native capacity is inferred here.

Only after all required source/compile/archive/link/loader joins and independent
original-artifact review should the **new narrowly scoped dependency receipt**
report that its provenance chain passed. Do not retroactively rewrite historical
false flags or remove obligations from the existing v1 contracts. No success
here proves all-40-component monotonic lifetime premises, an absolute no-wrap
bound, a complete trusted toolchain/system-header closure, warm speedup,
P06-A02/A03, vendor hardware emulation or physical-hardware performance. The
seven existing claim fields remain false.
