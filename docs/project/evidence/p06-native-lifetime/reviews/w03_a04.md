## Contract and enforcement assessment

### Every boundary remains explicit

`p06_native_lifetime_records.py` `_model` validates the exact extended field set, delegates the old projection to the old model checker, and separately requires an unsigned, exactly zero pending balance. The field is not inferred from idle state. `_pending_reads` checks exact array length, exact field sets, unsigned types, original sequence identity, and zero on both sides for all 264 raw MPM reads and 33 cache-flush reads. Run count is exactly 33; every ordered run independently requires the successful outcome booleans and exact pre/post DCR and flush counts.

The reader enforces reset generations `R+j-1` and `R+j` on each run and `R+j` on both sides of **every** corresponding flush. Intermediate flush resets cannot be collapsed merely because endpoint snapshots and aggregate run counts remain favorable. Snapshot generations are exactly `[R, R+1, R+33, R+33]`; construction/opening, after-batch/terminal, and terminal/destructor states are joined exactly. The construction baseline is bounded so adding 33 cannot overflow.

### Clock joins are supported by the admitted route

The reader does not require a globally monotone platform clock: each real run resets it. Exact run-after to flush-before and flush-after to next-run-before joins agree with the admitted direct-RAM source paths. In `sw/runtime/simx/vortex.cpp`, non-LLC host transfers access RAM directly; only the excluded LLC branch schedules processor transfer work. The flush implementation ticks until cache and platform work are drained. `CoreImpl::running()` includes scheduler activity, pending instructions, and undrained LSU work, while core-cycle accumulation requires scheduler or instruction activity. Consequently a post-run flush can move platform ticks without retiring more core work. This supports the preserved non-clock model fields across flushes in the selected route. This reasoning does not extend the contract to LLC-client traffic or other excluded configurations.

### Architectural gp is not a return status

The inherited model validator accepts the native signed 32-bit `exitcode`/gp value, including nonzero and negative values. The new contract uses entered/completed/exception observations for the void `run_checked()` call. It does not add a zero-gp requirement. Tests include coherent `-1`, `7`, and signed endpoints. The exact inter-boundary equality preserves gp between real calls without requiring it to stay constant across a run.

### Framing, old validation, and inert retained data

It neither manufactures historical observations nor opens or executes transcript-provided paths or commands. The bounded inherited decoder rejects duplicate keys, floats/nonfinite values, oversized/deep records, invalid UTF-8, and non-object roots.
