## Selector and argument boundaries

The selector is consumed only at `argv[1]`, before either call to the unchanged
warm parser. The shift's final iteration reads `argv[argc]`, the C++ main
argument-vector null sentinel, into the new last slot; decrementing `argc`
restores that same sentinel at the selected invocation's new `argv[argc]`.
`argv[0]` is preserved. Valid parser input then remains exactly 13 arguments,
with six option/value pairs. Missing arguments, duplicate leading selectors,
misplaced extra selectors, unsupported `--lifetime=1`, and a selector replacing
a required option cannot reach the warm operation. Absence of the selector
continues to select default v1 behavior. The inherited `--module` value is an
opaque module path, not an additional option position.

The enable call occurs before processor construction. A failed enable throws;
a later parser failure returns process failure without running native work.
There is one top-level call per process, so the process-local mode bit is not a
cross-invocation state channel. The flag selects actual hook observation and
the additional emitter; it is not parsed and ignored.

## JSON types, framing and complete population

All new integer observations are `uint64_t` and use `PRIu64`. The architectural
legacy register is declared `int` and uses `%d`; it is not cast to unsigned or
misinterpreted as a return status. Boolean JSON tokens come from fixed literal
strings. Identity strings interpolated into JSON are constrained by the
inherited parser: format is one of two fixed labels, policy is one of two fixed
labels, sample ID is an exact constructed identity, and the binding ID is 64
lowercase hexadecimal characters. The module path is not interpolated into
the new sidecar.

The new record includes exactly 33 retained run entries, four fixed snapshot
names, 264 pending-read supplements, 33 flush supplements, construction and
actual destruction observations. Getter failure stops emission with process
failure. Separators are emitted once between rows; all arrays and objects close
once; the sidecar ends in a newline. Field sets, extended model shapes, signed
endpoints, the full uint64 range, seven false claim fields, and all three
unresolved obligations matched the selected descriptor in the focused check.
A stress-shaped emitted sidecar with uint64 maxima was 48,218 bytes, below the
512 KiB limit. This demonstrates serialization bounds for those fixed fields;
it is not a claim that those synthetic observations satisfy native admission.

The original witness is printed first and the new record is printed only for
selected lifetime mode. Every old `print_model` call retains its default
argument, so the pending field is absent from the complete old witness. The
original `print_observation` and `print_read` field inventories do not acquire
the newly added struct members. At source level the old model printer's one
`printf` closing brace becomes a following `fputc` with the same output bytes.
The extracted host control independently compared old/current output bytes.
Default hooks leave the new pending field zero, so adding it to `same_model`
does not introduce an extra query or admission condition in default mode.

## Failure propagation and publication order

`run_preflight` checks the unchanged warm caller's return, sticky observation
errors, exact run/read/flush counts, construction/disposal equality, loader
identity, and selected-mode trace completeness before beginning either final
witness. Per-run flags and detailed joins remain independently enforced by the
new reader; emission alone is not admission. Incomplete retained arrays throw
rather than emitting a favorable shorter population.

All stdout output is followed by both `fflush(stdout)` and `ferror(stdout)`
checks. A failed flush/write throws through the existing top-level exception
handler and returns 1. A buffered output failure can leave a textual prefix or
even a previously emitted line, so the execution receipt must still require
successful process completion, as the reviewed runner does. `SIGPIPE` similarly
cannot become a successful zero-exit receipt. This source review did not inject
an actual native stdout fault, and does not claim such execution evidence.
