## Finding resolved by the implementation owner

**F2 high static-proof — `ci/project/p06_pending_probe.py`, `bounded_json()`**

The wrapper-based JSON parse accepted syntactically invalid standalone input by interpreting fields after the intended top-level object as additional wrapper fields. Before the owner fix, a file containing exactly:

```text
{"outcome":"pass"},"outcome":"fail"
```

returned `{'outcome': 'pass'}` from `bounded_json()`. An expected-list snapshot had the same issue with `[],"extra":1`. This was reproduced directly against the working production implementation, not inferred from a mock. Such input must fail the strict JSON contract instead of silently discarding the suffix.

The implementation owner added the exact wrapper field check `fields(wrapper, ("value",), "bounded JSON wrapper")` before extracting `value`. The new regression test exercises both malformed suffixes, duplicate keys, nonfinite values, multiple values, truncated JSON and empty input. The final focused suite passes with the fix present.

## Native C++ static review

- The accessor delegates to the existing `perf_mem_pending_reads_` storage. The request callback increments for non-write requests and the response callback decrements; `PerfCounter` conversion is a const, noexcept read. No new reset, tick, counter mutation or parallel scheduling is introduced by the accessor.
- The normal probe calls the real accessor. The explicit `P06_PENDING_FORCE_ZERO` variant replaces only the client translation unit's read with zero; the runner validates that this macro is absent from the model stamp and adds it only to the separate negative-control compile.
- Each stepped launch must observe at least one real positive pending value, must drain to zero, and is bounded to 200,000 steps. `ProcessorImpl::cycle()` returns `any_running()` without full fabric drain; the probe correctly ignores that return and uses both `!running` and `SimPlatform::idle()`.
- Two reads are bracketed by three host-side snapshots of global ticks, reset generation, core cycles/instructions, architectural gp, running and idle state. This is consistent with permitted host observations between cycles. It is a check of those named state fields, not a whole-model immutable-storage proof. The existing core perf getter refreshes an aggregate stall field; the evidence must retain its limited scope.
- The encoded three-instruction program and 19 launch descriptors match the existing `simx_completion` positive-control route. Both gp=7 and gp=-1 are data witnesses; `run_checked()` propagates failures while discarding the legacy return value.
- Reset deltas are checked around both stepped and checked launches with `CP_ON_LLC=0`; each must increase by exactly one. `readonly_checks` equals steps plus the two boundary observations.
- Each Processor is destroyed before its RAM and before the next independent context. No captured core/Processor pointer is read after destruction.
- The always-zero process cannot emit a successful context before the required positive-sample assertion. The runner requires exit code 1, reason `nonzero_exit`, complete cleanup, exact loader records and precisely that failure line; timeouts, crashes, unrelated assertions and a success exit do not qualify.
- Loader path observations are in fixed order and bound to the live managed model and selected dependencies. This still does not establish dependency source-to-binary compilation provenance.
