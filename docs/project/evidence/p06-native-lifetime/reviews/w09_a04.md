## Raw framing and caller-supplied identities

The new record reader first requires bounded canonical UTF-8 text, a final
newline, exactly one lifetime marker, and that marker on the final line. It
removes only that final line with `rpartition`, preserving every prefix byte.
It passes the prefix and the caller's original contract, case, format, policy,
binding, sample, process and library-path expectations to the unchanged v1
reader. Only a successful v1 result can be supplemented.

The old reader still requires its own marker to be last and immediately after
the unchanged warm success line. It therefore cannot silently absorb the new
sidecar. Conversely, the lifetime reader cannot admit a v1-only original:
there is no fallback or synthesis of pending zeros or missing run/reset pairs.
The inherited decoder and exact field sets apply before semantic admission;
unknown/missing/duplicate fields and booleans substituted for integers remain
invalid. Extra log text is not normalized away.

Caller expectations are not taken from a favorable witness. The parent reader
validates the caller's sample and process IDs against the fixed format/policy
identity, requires the caller's binding digest in its witness, and compares the
five expected library paths lexically without opening recorded paths. The new
reader compares its distinct identity against the same caller-selected format,
policy and digest. Thus the sidecar must agree with the already admitted parent
identity, while retaining its own contract ID. Shared sample/process names
identify the same numerical population; the contract and canonical execution
binding distinguish the selected evidence format.

For all four actual lifetime-original logs I independently checked the exact
last-line framing, original witness and sidecar field sets, caller/command
identity joins, one explicit flag, report-observation equality, both canonical
build digests and all four execution-binding digests. The prefix was checked as
an exact byte slice of the original, not serialized again. This preserves the
v1 wire format within each run; it does not assert byte equality between logs
from different native executions with different identities and timings.
