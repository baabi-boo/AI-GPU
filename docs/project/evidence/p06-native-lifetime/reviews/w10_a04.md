## Why this is the next useful step

SoftFloat's static archive, Ramulator's shared library and the Vortex Ramulator
extension. The current live producer hashes and retains those inputs before
building fresh format-specific guarded models, then joins final products to the
selected native loaded-library paths. The preparation route inventories restored
products; it does not freshly compile those dependencies.

Both original format bindings explicitly retain
`dependency_compilation_provenance_verified=false`. I read the original
`native-lifetime/report.json` and both build-binding JSON members as data and
checked their bytes against the exact original ZIP. Their four-process /
132-launch / 4,224-word result and stable product hashes therefore do not answer
which source, included headers, tool invocations and archive members generated

not recast it as a failed current lifetime contract.

The proposed chain covers immutable selected inputs, successful observed
compilation, object/archive bytes and membership, actual static-link selection,

different claim from a successful numerical smoke or a compile database that
only describes intended commands. The proposed negative controls distinguish
those claims, including a different freshly built dependency that still passes
the numerical smoke but fails the pinned provenance expectations.

## Actionability, budget and completion gate

order: define the versioned receipt and source lock; acquire and freeze inputs;
build SoftFloat, Ramulator/transitives and the extension in fresh owned workspaces;
stage verified products; freeze the managed source/build; admit the complete

acknowledges which object payloads the current packet does not retain.

one simulation worker, 15 GiB disk reserve, 4 GiB available-memory requirement,
4 GiB RSS limit, 120/1,800/180-second configure/build/run limits, 16 MiB log bound
and 90-minute hosted ceiling. The explicit nested `make -j4` in the current
third-party recipe is real; the handoff correctly requires controlling nested
parallelism rather than assuming outer `MAKEFLAGS=-j2` caps it. It preserves
the supervisor's polled process-group limitations and requires a recorded
resource block if the fresh design cannot fit. Rebuilding the compiler remains
outside this bounded task.

The original report and both bindings retain all seven false qualification,
warm/readiness and acceptance fields. The three unresolved obligations remain
in their original order. The proposed receipt cannot retroactively change those

original/area-finding boundaries intact. No gate relaxation is proposed.
