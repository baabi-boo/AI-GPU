## Configuration conclusions

The fixed expanded map has `VX_CFG_XLEN=64`, one cluster and one core,
`VX_CFG_TCU_TYPE=TFR`, `VX_CFG_FPU_TYPE=STD`, and
`VX_CFG_CP_ON_LLC=0`. L2, L3, VM and WGMMA enabled mirrors are zero.
`sim/simx/constants.h` derives both `CP_ON_L2` and `CP_ON_L3` as zero for this
route; `Processor::cp_llc_client()` therefore selects the direct-RAM runtime path.
Changing any frozen configuration key or introducing a new macro fails the
exact warm inventory, beyond the individual timed feature checks.

One worker is not inferred merely from `THREADS=1`. The compiler checks reject
additional `SIMX_` selectors after removing only the exact checked-counter
selector. `sim/simx/types.h` defaults absent `SIMX_MT` to zero and resolves it
to one worker; the actual hooks additionally `static_assert` one worker and
RV64 and reject `SIMX_FUNCTIONAL`. Timing-mode selection is therefore tied to
source and admitted compiler records. `sim/common/perf_counter.h` uses actual
`uint64_t` storage with 64-bit overflow/underflow checks; it exposes no admitted
small-limit test knob.

Diagnostic source substitution is excluded by the exact 43-TU, backend and
host source/link inventories. Unknown defines, including
`P06_PENDING_FORCE_ZERO`, cannot enter any managed compiler role: the complete
macro dictionaries reject them. The always-zero control is introduced only
later when compiling the separate probe TU; it is outside these four managed
processes and the 132-launch population. This review did not reinterpret that
separate negative control as an admitted measurement binary.

not prove an arbitrary compiler truthful or defeat malicious concurrent file

compile and link provenance. The full 40-component lifetime argument and fresh

this source review can be relabelled as the new native run.
