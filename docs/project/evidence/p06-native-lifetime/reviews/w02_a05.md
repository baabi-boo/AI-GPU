## Reader behavior

`verify_output` has exactly the original preflight reader's keyword interface.
It removes exactly one final bounded `P06_MANAGED_COUNTER_LIFETIME` line and
passes the byte-preserved prefix to the unchanged v1 reader. Missing lifetime
data fails explicitly. The result contains `warm`, `witness`, and `lifetime`.

The reader checks exact types and field sets, strict existing JSON decoding,
identity and route, all seven false claims, all three unresolved obligations,
the exact 33-run population and bounded reset arithmetic. Construction,
snapshots and pre-destruction state project exactly onto their v1 observations.
All 264 MPM and 33 flush supplements match their original sequence and retain
zero pending balance on both sides.

Each run has its exact ordinal, successful void-call/exception observations,
required DCR/flush counts and one reset. Legacy `gp` remains a signed register
observation. Cumulative core counters cannot decrease through a run. Exact
joins bind opening state to the first run, completed run to flush entry,
flush completion to the next run, prime/final snapshots, final cleanup and
destruction. The only admitted inter-run clock advance is the observed flush.

The stronger joins were inspected against `sw/runtime/simx/vortex.cpp`
(direct RAM transfers), `ProcessorImpl::run`/`flush_caches` and core tick
accounting. Parent independently checked and approved these source-bound
equalities before native evaluation. Flush itself may advance platform time;
launch reset may rewind it. No dead processor state is read by this inert
reader, and recorded paths are never opened.

## Synthetic fixture

`raw_records` returns `(case, operations, summary, witness, lifetime)` and
supports format, policy, binding, duration, counter-delta and preflight-contract
inputs. `render_log(operations, summary, witness, lifetime)` emits the unchanged
v1 prefix and new suffix. `BINDING`, `EXPECTED_LIBRARIES` and `synthetic_log`
are available to subsequent tests.

Numerical expectations remain the existing independent fixture. New invented
run/flush timelines preserve the existing public core-counter endpoints,
interpolate cumulative observations between them, reset platform time per
run, and assign a seven-tick synthetic flush. All corresponding original
snapshot/read clocks are reconciled. These are host test data, not measurements.
