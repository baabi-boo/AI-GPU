## Chronology derived from the source

`ai_warm_workspace/main.cpp` invokes 33 serial operations, closes and destroys
each operation, takes snapshots after operation 1 and operation 33, then closes
the owner. Its device-open observer supplies the opening snapshot, while
`observer.cpp::__wrap_vx_device_release` supplies the terminal snapshot before
calling the actual release. Each snapshot has 33 available public queries;
`ai_counter_preflight/main.cpp::query` and `check_half` require exactly two raw
replies per query. The four snapshot populations are therefore 66 raw reads
apiece, with completed-run populations `[0, 1, 33, 33]`.

`Device::cp_ring_append_` marks an appended launch's memory dirty and inserts a
single full flush before the output transfer on the admitted direct-RAM route.
`CommandProcessor::flush_cores_` issues one raw flush read for the selected one
core. The observer records all raw reads in one global sequence, separately
retaining the MPM and flush arrays. This yields:

| Boundary | Completed raw DCR reads before run | Matching flush sequence | Flushes before run |
| --- | ---: | ---: | ---: |
| Prime, ordinal 1 | 66 | 67 | 0 |
| Ordinal j, 2 through 33 | 131 + j | 132 + j | j − 1 |

After flush 1, the 66 prime-snapshot reads finish at sequence 133. Flushes 2
through 33 therefore occupy sequences 134 through 165. The after-batch reads
are sequences 166 through 231, and the terminal reads are 232 through 297.
The inherited reader requires the complete combined sequence 1 through 297,
matching completed-run counts, matching public values and exact inventory.
The new reader binds every added pending pair to its corresponding original
sequence and requires unchanged DCR/flush counts across each real run. No
favorable prefix or reordered reset can satisfy these joins.

## Reset-local clocks and idle intervals

`Processor::run_checked()` returns void and delegates to `ProcessorImpl::run()`.
On this selected route `launch_reset()` calls `reset()`, which invokes
`SimPlatform::reset()`, clears `cycles_`, increments `reset_gen_`, and clears
pending reads. The hook captures and validates pending reads **before** that
call, then requires exactly one reset afterward. It cannot use reset's zeroing
to rehabilitate an outstanding balance.

The reader correctly requires run j's generations to be `R+j−1` and `R+j`,
with snapshots at `R`, `R+1`, `R+33`, `R+33`. It does **not** require a globally
monotone platform clock: the after-clock of a later run can be less than that
run's before-clock because a reset occurred. Conversely, the output flush may
tick the platform, so it admits `flush_after >= flush_before` while requiring
run-after ticks equal flush-entry ticks.

The driver `make_cp_hooks` uses direct `RAM::read/write` or host memcpy when no
CP LLC client is present; those host transfers do not tick SimPlatform. The
ordinary MPM-read path does not flush or tick. `Core::tick` charges core cycles
only while the scheduler or pending-instruction inventory has work, and its
performance fields survive reset. Consequently the next run-before model
must equal the previous run-after model with **only** ticks replaced by the
observed flush-after clock. The prime and final snapshots join the same state.
This argument is conditional on the frozen build/caller route; it is not a
general statement about LLC-enabled CP DMA or every counter field.

## Terminal and destruction joins

`_snapshots` requires after-batch and before-release model states to agree.
`_destruction` then requires the full terminal live model, including zero
pending balance, to equal actual destructor entry. `hooks.cpp` captures that
state before the real destructor; afterward it reads only the live platform.
`SimPlatform::cleanup()` clears the clock and leaves reset generation unchanged,
so the inherited reader correctly requires post-disposal ticks zero and the
same reset generation rather than monotone disposal time.

A coherently repaired terminal/read/destructor tick cannot hide a cleanup tick:
`test_hidden_cleanup_tick_rejects_even_if_terminal_and_disposal_are_repaired`
already constructs that old-reader-admitted case and requires the new
`final cleanup boundary` rejection. Likewise,
`test_v1_accepts_collapsed_intermediate_resets_but_lifetime_rejects_them`
already preserves outer counts/endpoints while collapsing intermediate reset
generations. I inspected these existing controls and did not duplicate their
full-suite execution.

## Exact types and new bounded arithmetic control

The shared `fixed()` first checks **exact** Python types and recursively checks
dictionaries/lists. `uint()` requires `type(value) is int` and the unsigned
bound. Thus bools cannot replace reset counters, ordinals or pending counts,
and numeric zero/one cannot replace completion/exception flags. `_model`
validates each original model field before cross-record equality; `_pending_reads`
validates every sequence and pending field; `_runs` validates ordinals and both
DCR/flush-count sides. Destructor projection is recursively compared with the
already validated parent record.

The explicit construction bound is `R <= UINT64_MAX - 33`. I ran one valid
edge and one coherently repaired invalid edge through both complete readers:

| Synthetic control | Starting R | Original reader | Lifetime reader |
| --- | ---: | --- | --- |
| Last representable 33-reset window | 18446744073709551582 | Admits | Admits |
| Window shifted one further, with overflowing endpoint observations clamped to UINT64_MAX | 18446744073709551583 | Admits | Rejects: `native lifetime reset generation would overflow` |

All reset observations in both the original witness and sidecar were shifted
together. Clamping exists only in the hostile synthetic input construction;
production code was not changed. This specifically verifies the explicit
no-wrap admission bound instead of relying on unrelated malformed-record
rejection. The control completed successfully in 1.631 seconds.
Its script and source-bound receipt are `w05_a06-reset-boundary.py` and
`w05_a06-reset-boundary.json` in the work evidence directory.
