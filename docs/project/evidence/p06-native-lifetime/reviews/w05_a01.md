`p02-tfr`/STD, one-core/one-worker, direct-RAM CP route. VM, L2, L3 and WGMMA

This is 26 single-component selectors plus seven two-component selectors:
`26 + 7 = 33` selectors and `26 + 2×7 = 40` components. The twelve L2/L3
selector rows remain unavailable and must not be queried.

One distinction must survive future audits: the selected external-memory
`TxCrossBar::collisions_` above is checked and reset-preserved. The separate
`CachePortArb::collisions_` in `sim/simx/mem/cache.cpp` is reset to zero and is
used for the unselected cache bank-stall statistic. A name-only search for
`collisions_` would conflate these different owners and invalidate the argument.

## The transient pending-read premise

`ProcessorImpl::perf_mem_pending_reads_` is **not** a 41st cumulative component.
The same request callbacks increment it for reads; response callbacks decrement
it; `ProcessorImpl::reset` assigns zero. Its checked type catches overflow and
underflow but does not establish matching or quiescent reset by itself.

The new `Processor::pending_mem_reads()` forwarding method and const
`ProcessorImpl::pending_mem_reads()` return this exact owned field. The latter
does not tick, reset, flush, schedule work or return a fabricated proxy. The
underlying checked-to-`uint64_t` conversion is const and value-only.

On the admitted direct-RAM route, `ProcessorImpl::launch_reset` takes the full
reset branch. The pre-run observation must therefore occur before that call:
checking only a later zero could conceal an outstanding read that reset erased.
The new wrapper's `require_drained_locked` checks live ownership, platform idle,
no running core and zero pending before entering the real `run_checked` call.
The real call's return or exception remains separately observed.

## What the new witness supplies, once an original native run passes

- Exactly 33 admitted run pairs, each with the real pre-reset pending balance
  and an exact reset-generation increment of one; no missing intermediate
  reset can be repaired merely by matching outer endpoints.
- Zero pending at all 264 raw MPM half-read boundaries and 33 flush-read
  boundaries, the four snapshots, construction, and actual destructor entry.
- Source-consistent chronological joins among runs, output flushes, prime/final
  snapshots and final destruction. Core cycles/instructions are observed as
  cumulative values at these boundaries. Direct-RAM host work does not provide
  an unrecorded tick route under this frozen configuration.
- The complete original v1 transcript is still validated, including the
  required public selector populations and successful transport/ownership
  observations. The added sidecar does not replace that evidence.

These are observations of the stated boundaries and two core cumulative fields;
they are not a direct before/after trace of every one of the 40 backing fields.
They become claims about actual execution only after the fresh native originals
are obtained and reviewed. This assignment did not execute or inspect such an
original.

## Premises that remain open

The conditional theorem in `simx_counter_lifetime_v1.md` still requires an
independent source/binary-bound argument that every selected component begins
at zero, uses checked nonnegative updates, survives every admitted reset,
participates in complete successful terminal aggregation, and cannot change
after terminal readout before its storage is destroyed. The `PerfCounter` type
also supports assignment/subtraction, so its name alone is not a monotonicity
proof. A failing update/run/read invalidates the lifetime even if a later
endpoint appears favorable.

Concrete next prerequisite: bind the current model and its actual loaded
Ramulator/adapter products to a reviewed source → compile → link → loaded-product
chain, then apply the owner/finalizer argument to those exact products. Existing
source manifests, restored-cache identities and loaded-library hashes do not
prove absent dependency compilation steps. A separate final qualification
review must reconcile that chain, this 40-component source map, terminal
ownership and the new native observations. Ordinary measurement binaries cannot
inherit checked-build qualification by label.

Keep all three unresolved obligations and all seven qualification/readiness/
warm/acceptance fields unchanged and false. This review grants no absolute
no-wrap bound, warm speedup, P06-A02/A03, RTL, vendor or hardware acceptance.
