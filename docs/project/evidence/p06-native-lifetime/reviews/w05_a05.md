## Stability and limits

The managed `command` checks helper, source, tool/interpreter and dependency identities before and after commands. Frozen build products are checked before and after each native process, after both policies and again at finalization. Original command logs and retained evidence are rehashed; changed bytes or incomplete counts prevent success. Failure recording preserves the first failure while retaining later stability failures.

The probe snapshots checkout/source files, fixed build inventory, dependencies, compiler, managed report and three retained snapshot files before execution. Each command checks the snapshot before and after, each log is checked against its execution receipt, each produced executable is checked across its run, and finalization checks the inputs again. Native success still requires the exact positive observation; the negative control requires exit 1 with the exact behavioral assertion, not an arbitrary failed launch or compile.

These are identity and stability checks within a trusted source/interpreter/live-build execution route. They do **not** prove that arbitrary forged reports are truthful, defeat a malicious writer that swaps files between observations, establish every compiler support file/system header/loaded system library, or establish fresh dependency source-to-binary compilation. The code explicitly retains those relevant limitations and all qualification/readiness/acceptance fields remain false. Full all-40-component lifetime qualification, complete archival replay of this new contract, native execution and hosted CI result review are separate obligations.
