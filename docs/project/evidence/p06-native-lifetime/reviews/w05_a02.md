## Binding cleanup to the observed lifetime

`main.cpp::same_model` compares live ownership, generation, idle/running,
platform clock, reset generation, cumulative core cycles/instructions, legacy
`gp` and pending balance. The native emitter requires the actual destructor-entry
state to equal the terminal snapshot's after-state, plus one construction,
one destruction, all 33 completed runs, all expected raw reads and no sticky
observation errors. A failure to observe a destructor boundary is not repaired
by normal cleanup.

The new reader independently requires:

- `after_batch.after == before_release.before` including pending balance;
- equality of each snapshot's before and after state;
- `before_release.after == destruction.before` including pending balance;
- projection of those states to the independently validated original v1 witness;
- actual disposal completion, post-disposal idle state, zero platform clock and
  unchanged reset generation through the original reader.

These joins forbid an intervening launch/reset or any change to the included
model fields from being hidden by ordinary owner cleanup. In particular, a
nonzero pending balance cannot be accepted merely because `SimPlatform::cleanup`
subsequently clears abandoned packet accounting. This is not a claim that every
host bookkeeping field or functional CP step is constant between snapshots.

The direct-RAM route matters. `vx_device::make_cp_hooks` uses host copies or RAM
reads/writes when CP is not an LLC client; selected VM/L2/L3/CP-cache restrictions
are established separately by the managed build contract. `Device::memory_info`
is allocator bookkeeping, and the SimX host-memory pull is a no-op. The exact
model-state joins still require original execution observations; this source
argument does not manufacture them.

## Limits and remaining obligations

`Device::cp_quiesce_` is a best-effort teardown function: it returns early on
register errors and has a bounded polling loop. Its mere return, or a public
release return, is **not** general proof of CP drain. The admitted path instead
establishes enabled CP retirement before disable, no live queues/buffers and a
sole device reference, and exact model equality through actual destructor entry.
The existing best-effort teardown behavior is unchanged by this patch and does
not create a new defect in that declared successful path.

Queue-set and reference observations are valid for the bound exclusive caller,
not a concurrency qualification. The source chain relies on the actual linked
implementations matching the reviewed sources. Fresh dependency compilation
through loaded-product provenance remains a separate unresolved obligation,
as do the complete 40-component lifetime argument and independent complete
counter qualification. No native execution, absolute no-wrap guarantee, warm
performance, RTL/hardware outcome, or P06-A02/A03 acceptance is asserted here.
All seven false claim flags and all three unresolved obligations remain required.
