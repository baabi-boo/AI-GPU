# Qualified warm-workspace experiment v1

## Boundary

The explicit qualified warm route composes the frozen warm sampling contract,
the complete dependency build and loader evidence, and a separately pinned
extension of the counter source proof. It evaluates only the recorded SimX
experiment. It does not accept a phase, qualify RTL or measure a physical GPU.

The historical warm-v1 analyzer retains its unconditional high-half rejection.
The original four-process qualification proof and diagnostic/control archives
retain their exact identities and original schemas. A caller must explicitly
choose the new producer or reader; packet fields cannot select the route.

## Reviewed source extension

The original proof binds 69 measurement sources and ten premises covering 33
available selectors and 40 cumulative components. Twelve selectors remain
unavailable. The new proof extends that exact projection at one source:
`tests/regression/ai_counter_preflight/main.cpp`.

Its changes are limited to explicit argument admission and witness identity:

- The canonical prefix is `--lifetime --qualified-warm`. Warm mode requires
  lifetime observation and uses the existing parser for pairs 0 through 5,
  phase, format, allocation policy, sample identity and the prelaunch digest.
- The new managed witness contract is
  `p06-qualified-warm-counter-witness-v1`; its lifetime supplement is
  `p06-qualified-warm-lifetime-witness-v1`. Each process ID equals its unique
  canonical warm sample ID.
- The workload, hooks, runtime, kernel, generated configuration, operation
  count, timing boundaries and counter collection are unchanged. Witness
  serialization occurs after the measured operations and complete disposal.
- Without the explicit flag, the caller retains its pair-zero warm-up
  restriction and original witness identities.

The extension pins both old and new caller bytes. All remaining measurement
sources must match the original proof. Original prerequisite archives are
replayed against the original proof, then the new current projection is checked
separately. A historical prerequisite projection is never presented as the
current build projection. Any further native change requires a new reviewed
pin and another fresh attempt.

## Admission and identities

Before recorded compilation or native execution, live admission checks the
exact published revision, fresh dependency receipt, original source proof,
extended proof, diagnostic original and control original. It reconstructs
their semantic relationships and retains the relevant input identities.
Build and process bindings include the full frozen sampling descriptor and
ordered process plan, as well as the qualification proof and admission.
The process receives the canonical binding digest through `--qualification-id`.

Both policies share one guarded binary per format. Source, tools, dependencies,
proofs, prerequisites and products must remain stable at the existing execution
boundaries and finalization. A failed or interrupted process invalidates the
whole attempt. Failed attempts are retained without replacement samples.

## Inert complete replay

The caller independently pins the archive, source revision, source manifest,
native report, dependency receipt and extended proof, plus both original
prerequisite archives. Replay reconstructs complete source/build/load and raw
process relationships. It opens only selected archives and trusted reader
inputs, executes no retained commands or binaries, and checks all archive
members and trusted input stability.

The new report population needs its own bounded JSON decoder because it
exceeds the original archive helper's 300,000-node limit. The explicitly selected
report decoder limits input to 64 MiB, 750,000 value nodes and nesting depth 64.
It rejects duplicate keys, nonfinite numbers and excessive numeric tokens.
Individual retained records keep their existing parser bounds. Historical
parser bounds remain unchanged.

Successful replay means retained consistency. It reports native execution as
`not_run`, retained code execution as false and origin authentication as false.
The original native attempt supplies execution evidence separately.

## Performance decision

Only a complete qualified population can reach the new analyzer. It uses
exact integer/rational arithmetic for the existing predicates. Batch means
include the 32 primary intervals; all primes and both-format warm-up pairs are
excluded. Each format needs five measured batch means per policy.

The candidate median must be at most 95% of the reference median. Every
measured candidate pair must be no slower in host time and must have no increase
in qualified modeled cycles. Both formats must satisfy the predicates. No
outlier removal, optional stopping, observer subtraction, supervisor-delay
correction or threshold adjustment is allowed. An unsatisfied hypothesis is a
valid experimental outcome and must not be relabelled as a passed optimization.

The primary metric includes submit, wait, exact comparison, explicit close,
success checks and fixed observer bookkeeping. It is instrumented host time,
not uninstrumented runtime latency or physical device performance. Modeled
counter deltas are batch observations, not individual-kernel timing or energy.
P06-A02/A03, vendor integration and physical measurements retain their separate
acceptance obligations.
