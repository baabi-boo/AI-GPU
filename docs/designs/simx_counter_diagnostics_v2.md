# SimX native counter diagnostics v2

## Purpose and boundary

This contract extends the [checked arithmetic prerequisite](simx_checked_counters_v1.md)
with directed access to all **33 available counters** in the exact RV64
`p02-tfr` timing configuration. It distinguishes transport, actual backing-source
aggregate failures, public-runtime containment and terminal observations.
Implementation and executed evidence remain separately recorded in the
[development audit](../project/p06-counter-diagnostics-audit.md).

Diagnostic success never implies warm readiness, a speedup, RTL parity or phase
acceptance. The twelve L2/L3 rows remain unavailable and receive no query.
The historical warm-v1 reader and its unconditional rejection stay unchanged.

## Exact route

The route is RV64 timing SimX, `PERF=1`, TFR tensor and STD scalar arithmetic,
one cluster/core/socket and simulation worker, four warps of four threads,
issue width one, enabled I/D caches and local memory, with VM, L2/L3, WGMMA
and CP-on-LLC excluded. The generated configuration and original compiler
records must establish this route; a profile label alone is insufficient.

The ordinary variant retains the exact `uint64_t` counter alias. The checked
variant uses `SIMX_CHECKED_COUNTERS=1` consistently in all model objects.
Both variants use the same directed boundary inputs. Checked failure controls
are separate processes and may intentionally seed large values; those seeds
must never enter a measurement binary.

## Diagnostic access

Typed accessors under `tests/unittest/checked_counters/` identify actual
component-owned storage. Three wrapper translation units include the unchanged
socket, cache and memory implementation bodies. The TCU diagnostic translation
unit contains the byte-exact original implementation followed by its test-only
accessor footer; this preserves strict main-file linkage diagnostics for its
private buffer type. The generated bytes are retained and validated separately.
A separate helper uses the complete Processor implementation declaration.
C++17 explicit template
instantiation provides typed pointer-to-member access without changing class
definitions, assuming object offsets or disabling access checks. Every model and
diagnostic translation unit retains the exact validated compiler flags.

The diagnostic link substitutes wrapper objects for the corresponding four
production objects. It rejects missing or duplicate implementations, repeated
sources, unrecorded objects and access-control flags on any translation unit.
Production targets retain their existing source lists, objects and flags.
The wrapper, generated source and included production identities are retained;
inclusion or generation is not reported as direct compilation of the original
translation unit.

The 33 selectors have 40 backing components: one I-cache bank, two D-cache
banks per selected D-cache statistic, one source for each other selected value
except two TCU local-read buffer sources. The accessors require this exact
topology. A missing source cannot be represented by a fabricated zero or a
pointer to a temporary statistics value.

## Boundary matrix

Each real component receives the ten frozen numeric vectors, including the
32-bit carry, values above the earlier 44-bit boundary, arbitrary high bits and
`UINT64_MAX`. Other components have bounded nonaliasing values. Each observation
checks both half-read orders, successful status, exact reconstructed value and
restoration of the saved performance class.

Each of the seven two-component selectors also receives split values summing
to `2^32` and `UINT64_MAX`. Launch reset must preserve component storage, and
the preserved total must be read through the actual DCR path. The intended
boundary inventory is **1,788 half reads** per variant: 1,600 component-vector
reads, 56 split-carry reads and 132 reset reads. Exact assertion counts are
versioned with the result schema and checked by the runner.

All-33 transport is reported with the narrowly scoped
`all_available_selector_transport` field. `full_warm_coverage` remains false:
transport inputs do not prove every updater, complete lifetime or warm workload.

## Failure controls

Preserve the earlier primitive and direct completion-owner checks with their
original scope. Additional native aggregate controls seed the actual two-bank
D-cache and two-buffer TCU sources to individually representable values whose
sum exceeds `UINT64_MAX`. The real DCR aggregation must throw
`PerfCounterError` before publishing a result; component values remain intact.
The normal completion owner must retain the failure, suppress later work,
join execution and permit a fresh context only after full disposal.

Public-runtime controls must connect the real Processor/RAM, backend,
command processor and common runtime. Instrumentation belongs only to the
diagnostic backend and must invoke the original methods. A locally constructed
counter exception or substituted Processor cannot be described as a native
backing-source fault. The public destination must stay unchanged when either
counter half fails. Queue-local error consumption must not revive a failed
processor.

## Coherence and terminal observations

Coherence is scoped to one exclusive submitter with all relevant work complete.
The public API is not an atomic snapshot API for arbitrary concurrent callers.
Diagnostic observations bind exact selector tags/replies, counter values and
model advancement across the two-half reads.

Terminal evidence must establish all 33 successful available reads, twelve
unqueried unavailable rows, retired queue workers and synchronous commands,
zero pending reads, final Device ownership and actual destruction. A successful
release call alone is insufficient. The source proof separately establishes
monotone checked components and no updates after terminal observation through
allocator, CP, backend, platform and pinned DRAM finalization.

Repeated matching snapshots provide a diagnostic observation; the complete
source argument supplies the no-later-update premise. Native diagnostic controls
are not a replacement for binding the later measurement executable and its full
process lifetime.

## Evidence and replay

Native records retain clean source revision/tree, required source bodies,
submodule pins, actual generated configuration, original compiler/link commands,
the executing interpreter and PATH interpreter, tools and loaded dependency
identities, actual binary/object identities, raw command logs, resource outcomes
and before/after stability. Fixed negative cells must exit successfully after
observing the expected typed failure. An unrelated crash, timeout or build error
does not satisfy a negative case.

Retained-data verification uses trusted local parsers and treats archived code,
commands and paths as inert data. It must not open recorded absolute paths on
the replay host or execute retained helpers. Missing, malformed, historical,
source/configuration-mismatched and incomplete evidence fails closed.
Successful replay establishes packet consistency; it does not authenticate an
untrusted producer or rehash binary bytes that the archive does not contain.

Every diagnostic and replay result retains `qualified=false`,
`ready_for_warm=false`, `warm_execution=false` and no phase acceptance.
A separately versioned measurement qualification contract remains required.
